DATA STRUCTURES · 10 / 103

滑动窗口最大值

难度： H
核心： Deque / 单调队列
章节： 数组、字符串、矩阵与区间
内容边界： “原稿”部分来自仓库内 PDF 对应题目；“深化解析”是在原稿基础上的扩展讲解，不新增未经来源支持的公司题库归属。

1. 题目

给定数组与窗口大小 k，窗口从左到右滑动，每一步输出窗口最大值。

仓库深化：手推示例

nums=[1,3,-1,-3,5,3,6,7], k=3，输出 [3,3,5,5,6,7]；队列里存下标，过期从头删，被新值支配的候选从尾删。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

2. 面试开始先澄清

  • 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

  • 是否允许修改输入？输出是否要求稳定顺序或去重？

  • 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

3. 基线方案与瓶颈

每个窗口扫描 k 个元素为 O(nk)；用 heap 可到 O(n log n) 或配合延迟删除。

解法演进对比

层级 思路 代价 / 价值
Baseline 每个窗口扫描 k 个元素为 O(nk)；用 heap 可到 O(n log n) 或配合延迟删除。 先保证正确，暴露真正瓶颈
面试目标 围绕 Deque / 单调队列 维护最小必要状态 时间 O(n)，空间 O(k)。

这张表的重点不是“最优解一定唯一”，而是能够解释为什么新结构减少了哪一类重复工作。

深化解析：先定位重复工作

本题所在章节的核心原则是 连续内存、索引关系与单调性。优先检查 Hash、双指针、滑动窗口、前缀和、二分、单调结构与 Sweep Line。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

4. 关键洞察：为什么这个数据结构合适

维护一个下标 deque，使对应值严格/非严格单调递减。新元素进入时，把尾部所有不可能再成为最大值的更 小元素弹出；队首若已经离开窗口则弹出。

结构选择检查表

  • 我们反复查询/维护的信息是什么？ 把它写成一句话。
  • 这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？ 这些性质通常直接决定数据结构。
  • 是否需要在线更新？ 静态问题和动态问题往往需要不同结构。
  • 输出规模是否本身构成复杂度下界？ 返回所有答案时尤其重要。
  • 是否能说明替代结构为什么更差？ 面试官常通过这一问验证理解深度。

5. 不变量与正确性证明

原稿不变量： deque 中下标递增、值递减，且都属于当前窗口；因此队首永远是窗口最大值。每个下 标至多进队出队一次。

正确性证明框架

  1. 初始化： 证明算法开始时不变量成立。
  2. 保持： 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
  3. 终止： 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
  4. 无遗漏/无重复： 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

6. 参考实现（Python）

from collections import deque

def max_sliding_window(nums, k):
    q, ans = deque(), []
    for i, x in enumerate(nums):
        while q and q[0] <= i-k:
            q.popleft()
        while q and nums[q[-1]] <= x:
            q.pop()
        q.append(i)
        if i >= k-1:
            ans.append(nums[q[0]])
    return ans

Code Review 视角

  • 变量名应直接体现状态含义，不要让 i/j/tmp 承担过多语义。
  • 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
  • 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是值、下标、节点还是聚合状态。
  • 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
  • Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，heapq pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

7. 复杂度

时间 O(n)，空间 O(k)。

复杂度审查

维度 需要回答的问题
时间 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？
空间 统计的是额外空间还是包含输出？递归栈算不算？
预处理 排序、建索引、建 Trie/Heap 的成本是否被漏算？
输出下界 若答案本身有 m 项，是否至少需要 O(m)？

8. 高频失分点

  • deque 存值导致无法判断元素是否过期

  • 维护成递增队列却取错端

  • 把 while 写成 if 导致多个过期/劣质元素残留

额外边界测试

  • 最小合法输入与空输入（若题目允许）
  • 重复值/重复状态是否改变算法不变量
  • 端点相等：闭区间/半开区间语义
  • 完全包含、相邻、完全不相交三类区间关系

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

9. 面试官追问与答题方向

  • 如何同时输出 min 和 max？
  • 答题方向： 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。
  • 如果窗口大小动态变化怎么办？
  • 答题方向： 静态预处理通常不再够用；需要支持 update/query 的结构，如 Heap、Fenwick、Segment Tree、平衡树或 DSU（仅适合加边）。
  • 为什么这是一种摊销 O(1) 操作？
  • 答题方向： 先逐项列出 API 的目标复杂度，检查是否需要 Hash + 链表/桶/数组等组合结构，并说明摊销复杂度。

Follow-up 的统一处理方法

不要把追问当成新题。先问：原方案依赖的哪个前提被改变了？ 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

10. 60 秒口述模板

我会先给出一个可工作的基线方案：每个窗口扫描 k 个元素为 O(nk)；用 heap 可到 O(n log n) 或配合延迟删除。 真正 的瓶颈在重复工作，因此优化的核心是：维护一个下标 deque，使对应值严格/非严格单调递减。新元素进入时，把尾部 所有不可能再成为最大值的更小元素弹出；队首若已经离开窗口则弹出。 正确性依赖的不变量是：deque 中下标递增、 值递减，且都属于当前窗口；因此队首永远是窗口最大值。每个下标至多进队出队一次。 最终复杂度为：时间 O(n)，空 间 O(k)。

12. 专业深化：约束驱动的完整面试推导

本节属于 GitHub 仓库深化内容：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 单调队列。出现以下信号时，应主动联想到这一类结构：

  • 询问“下一个/上一个更大更小”
  • 窗口内最大最小值需要随边界移动快速维护
  • 元素一旦被后来的元素支配就永远不会再成为答案

把题目抽象成一句“数据结构需求”会更有效：

栈/队列里只保留“尚有机会成为未来答案”的候选；被新元素支配的状态应一次性删除。

12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

队列中的下标递增、对应值单调递减；队首始终是当前窗口最大值下标。

进一步拆成三个层次：

  1. 输入事实：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
  2. 未来充分统计量：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
  3. 答案状态：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。

12.3 解法谱系与 Trade-off

# 方案 定位
1 每个窗口扫描最大值 O(nk) 基线/对照
2 Heap + lazy deletion O(n log n) 可选方案
3 单调 Deque O(n) 面试主解

选择主解时至少回答三个问题：

  • 它具体消除了基线中的哪一类重复工作？
  • 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
  • 如果这些性质被 follow-up 改掉，哪一层会首先失效？

12.4 针对本题的正确性证明

  • 候选不变量： 队列中的下标递增、对应值单调递减；队首始终是当前窗口最大值下标。
  • 永久淘汰： 当旧候选被新元素支配/被更矮边界结算时，未来位置不会让旧候选重新优于新候选，因此弹出是安全的。
  • 一次性处理： 每个元素最多入结构一次、出结构一次。
  • 答案覆盖： 某元素真正需要的右边界/更优元素第一次出现时，它恰好位于栈顶待结算集合中，因此不会漏解。

面试表达建议： 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：时间 O(n)：每个下标最多入队一次、出队一次；空间 O(k)。

进一步需要注意：

  • 区分“额外空间”与输出空间；若返回 m 个结果，O(m) 输出本身就是不可避免的下界。

专业回答建议写成：

n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）

12.7 代码审查：从 AC 代码提升到面试级实现

  • 通常保存下标而不是仅保存值，才能判断过期/距离
  • 相等元素采用严格还是非严格单调必须统一
  • sentinel 可减少收尾分支，但要解释其语义

此外，对本题代码建议做四次快速 review：

  1. State review：每个变量能否用一句不变量解释？
  2. Boundary review：所有 +1/-1、开闭区间、空结构分支是否统一？
  3. Mutation review：修改容器/指针后，另一个索引或引用是否需要同步更新？
  4. Complexity review：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

12.8 对抗性测试矩阵

测试维度 本题应覆盖的情况 目的
最小/空边界 严格递增/严格递减 验证不变量与边界处理，不只验证最终值
重复/相等状态 全部相等 验证不变量与边界处理，不只验证最终值
结构极端 最大答案在最左/最右边界 验证不变量与边界处理，不只验证最终值
约束破坏/反例 队列存下标，才能判断过期。 验证不变量与边界处理，不只验证最终值

源书稿中的高频失分点也应逐个转成单元测试：

  • 反例化： 队列存下标，才能判断过期。
  • 反例化： 值相等时是否弹出都可，但要保持策略一致。
  • 反例化： 先清过期还是先维护单调性，两种次序都能写对，但边界要清晰。

12.9 Follow-up 深挖：不是换题，而是定位“哪个前提变了”

12.9.1 窗口最小值怎么改？

  • 变化的前提： 这个追问改变了 单调队列 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
  • 推荐方向： 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。

12.9.2 如果要同时返回最大与最小？

  • 变化的前提： 这个追问改变了 单调队列 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
  • 推荐方向： 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。

12.9.3 如果窗口大小动态变化，单调队列是否仍适合？

  • 变化的前提： 原问题从静态查询变成 update + query 混合，预计算结果会频繁失效。
  • 推荐方向： 把静态前缀/排序结构升级为 Fenwick、Segment Tree、平衡树或带索引的 Heap；重新给出 update/query 双复杂度。

12.10 Pattern 迁移：什么时候应该想到它

识别信号：

  • 询问“下一个/上一个更大更小”
  • 窗口内最大最小值需要随边界移动快速维护
  • 元素一旦被后来的元素支配就永远不会再成为答案

迁移方法：

  • 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
  • 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
  • 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
  • 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

12.11 面试官视角：这题真正区分候选人的地方

能力层级 典型表现
只会做 能写出代码，但无法解释为什么该结构成立
合格 能从 baseline 推出 单调队列，复杂度与边界基本正确
较强 能写出不变量/证明，并比较至少一种替代方案
很强 follow-up 改约束后，能明确指出失效的前提并局部替换结构，而不是重新猜算法

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
