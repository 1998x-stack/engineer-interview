两个有序数组的中位数

难度： H+
核心： 二分查找 / 分割
章节： 数组、字符串、矩阵与区间
内容边界： “原稿”部分来自仓库内 PDF 对应题目；“深化解析”是在原稿基础上的扩展讲解，不新增未经来源支持的公司题库归属。

1. 题目

给定两个有序数组，总长度为 m+n，要求 O(log(min(m,n))) 求联合中位数。

仓库深化：手推示例

A=[1,3], B=[2]，中位数为 2。在较短数组 B 上二分 partition，让左半元素总数达到目标并满足交叉有序条件。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

2. 面试开始先澄清

  • 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

  • 是否允许修改输入？输出是否要求稳定顺序或去重？

  • 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

3. 基线方案与瓶颈

直接归并到中位位置需要 O(m+n)；双指针仍是线性。

解法演进对比

层级 思路 代价 / 价值
Baseline 直接归并到中位位置需要 O(m+n)；双指针仍是线性。 先保证正确，暴露真正瓶颈
面试目标 围绕 二分查找 / 分割 维护最小必要状态 时间 O(log(min(m,n)))，空间 O(1)。

这张表的重点不是“最优解一定唯一”，而是能够解释为什么新结构减少了哪一类重复工作。

深化解析：先定位重复工作

本题所在章节的核心原则是 连续内存、索引关系与单调性。优先检查 Hash、双指针、滑动窗口、前缀和、二分、单调结构与 Sweep Line。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

4. 关键洞察：为什么这个数据结构合适

在较短数组上二分切分位置 i，由总左半元素个数推得另一个数组切分 j。寻找满足 A[i-1]<=B[j] 且 B[j-1]<=A[i] 的分割，此时左右两边已经全局有序分离。

结构选择检查表

  • 我们反复查询/维护的信息是什么？ 把它写成一句话。
  • 这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？ 这些性质通常直接决定数据结构。
  • 是否需要在线更新？ 静态问题和动态问题往往需要不同结构。
  • 输出规模是否本身构成复杂度下界？ 返回所有答案时尤其重要。
  • 是否能说明替代结构为什么更差？ 面试官常通过这一问验证理解深度。

5. 不变量与正确性证明

原稿不变量： 二分变量 i 过大时 A[i-1]>B[j]，必须左移；过小时 B[j-1]>A[i]，必须右移。合法分割唯 一地确定中位数。

正确性证明框架

  1. 初始化： 证明算法开始时不变量成立。
  2. 保持： 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
  3. 终止： 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
  4. 无遗漏/无重复： 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

6. 参考实现（Python）

def find_median_sorted_arrays(a, b):
    if len(a) > len(b): return find_median_sorted_arrays(b, a)
    m, n = len(a), len(b)
    total_left = (m+n+1)//2
    lo, hi = 0, m
    while lo <= hi:
        i = (lo+hi)//2
        j = total_left - i
        al = float('-inf') if i == 0 else a[i-1]
        ar = float('inf') if i == m else a[i]
        bl = float('-inf') if j == 0 else b[j-1]
        br = float('inf') if j == n else b[j]
        if al <= br and bl <= ar:
            if (m+n)%2: return max(al, bl)
            return (max(al,bl)+min(ar,br))/2
        if al > br: hi = i-1
        else: lo = i+1

Code Review 视角

  • 变量名应直接体现状态含义，不要让 i/j/tmp 承担过多语义。
  • 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
  • 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是值、下标、节点还是聚合状态。
  • 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
  • Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，heapq pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

7. 复杂度

时间 O(log(min(m,n)))，空间 O(1)。

复杂度审查

维度 需要回答的问题
时间 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？
空间 统计的是额外空间还是包含输出？递归栈算不算？
预处理 排序、建索引、建 Trie/Heap 的成本是否被漏算？
输出下界 若答案本身有 m 项，是否至少需要 O(m)？

8. 高频失分点

  • 没有强制在较短数组上二分

  • 偶数长度时忘记取左右边界平均

  • 大量边界 if 导致代码失控，±inf 能显著简化

额外边界测试

  • 最小合法输入与空输入（若题目允许）
  • 重复值/重复状态是否改变算法不变量
  • k=1、k=n 或候选不足 k 个
  • 大量相同优先级时的 tie-breaking
  • 全相等/单调递增/单调递减
  • 负数、零与极大整数

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

9. 面试官追问与答题方向

  • 如何求两个有序数组联合第 K 小？
  • 答题方向： 利用有序性消除哈希或全量扫描，优先考虑双指针/二分，并重新讨论是否还需要保留下标。
  • 推广到多个有序数组，中位数还能保持对数复杂度吗？
  • 答题方向： 利用有序性消除哈希或全量扫描，优先考虑双指针/二分，并重新讨论是否还需要保留下标。

Follow-up 的统一处理方法

不要把追问当成新题。先问：原方案依赖的哪个前提被改变了？ 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

10. 60 秒口述模板

我会先给出一个可工作的基线方案：直接归并到中位位置需要 O(m+n)；双指针仍是线性。 真正的瓶颈在重复工作，因 此优化的核心是：在较短数组上二分切分位置 i，由总左半元素个数推得另一个数组切分 j。寻找满足 A[i-1]<=B[j] 且 B[j-1]<=A[i] 的分割，此时左右两边已经全局有序分离。 正确性依赖的不变量是：二分变量 i 过大时 A[i-1]>B[j]，必须左 移；过小时 B[j-1]>A[i]，必须右移。合法分割唯一地确定中位数。 最终复杂度为：时间 O(log(min(m,n)))，空间 O(1)。

12. 专业深化：约束驱动的完整面试推导

本节属于 GitHub 仓库深化内容：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 二分分割。出现以下信号时，应主动联想到这一类结构：

  • 只需要 Top-K 而不是全排序
  • 数据在线到达并持续查询当前极值
  • K 路有序流归并或动态中位数

把题目抽象成一句“数据结构需求”会更有效：

堆只保存“仍可能影响答案的边界候选”；size-k heap 的堆顶通常代表当前阈值，而不是最终排序结果。

本题特别说明： 这题的真正难点是把“求中位数”改写成“找合法分割”。建议在白板先画 A/B 的左右两半，再写交叉条件，而不是直接背四个边界变量。

12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

合法分割同时满足左半元素数量正确和交叉有序：A[i-1] <= B[j] 且 B[j-1] <= A[i]。

进一步拆成三个层次：

  1. 输入事实：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
  2. 未来充分统计量：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
  3. 答案状态：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。

12.3 解法谱系与 Trade-off

# 方案 定位
1 合并数组 O(m+n) 基线/对照
2 第 k 小的消元法 O(log k) 可选方案
3 在短数组上二分 partition O(log min(m,n)) 面试主解

选择主解时至少回答三个问题：

  • 它具体消除了基线中的哪一类重复工作？
  • 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
  • 如果这些性质被 follow-up 改掉，哪一层会首先失效？

12.4 针对本题的正确性证明

  • 搜索不变量： 合法分割同时满足左半元素数量正确和交叉有序：A[i-1] <= B[j] 且 B[j-1] <= A[i]。
  • 候选区间： 每轮开始时真正答案仍位于当前搜索区间。
  • 排除正确性： 根据有序性/单调 predicate，能够证明被丢弃半区不可能包含答案。
  • 终止： 搜索区间严格缩小，最终落到唯一合法边界或判定不存在。

面试表达建议： 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：时间 O(log(min(m,n)))，空间 O(1)。

进一步需要注意：

  • 区分“额外空间”与输出空间；若返回 m 个结果，O(m) 输出本身就是不可避免的下界。

专业回答建议写成：

n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）

12.7 代码审查：从 AC 代码提升到面试级实现

  • Python heapq 是最小堆，最大堆常用负号或自定义 key
  • tuple tie-breaker 避免比较不可比较对象
  • 删除任意元素需要 lazy deletion/索引堆/有序多重集合

此外，对本题代码建议做四次快速 review：

  1. State review：每个变量能否用一句不变量解释？
  2. Boundary review：所有 +1/-1、开闭区间、空结构分支是否统一？
  3. Mutation review：修改容器/指针后，另一个索引或引用是否需要同步更新？
  4. Complexity review：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

12.8 对抗性测试矩阵

测试维度 本题应覆盖的情况 目的
最小/空边界 大量相同优先级 验证不变量与边界处理，不只验证最终值
重复/相等状态 K=1/K=n 验证不变量与边界处理，不只验证最终值
结构极端 旧元素离开但尚未到堆顶 验证不变量与边界处理，不只验证最终值
约束破坏/反例 一定在较短数组上二分，才能保证 j 边界可控。 验证不变量与边界处理，不只验证最终值

源书稿中的高频失分点也应逐个转成单元测试：

  • 反例化： 一定在较短数组上二分，才能保证 j 边界可控。
  • 反例化： ±inf 是简化边界的建模技巧。
  • 反例化： 奇偶长度的左半元素数量公式要推导清楚。

12.9 Follow-up 深挖：不是换题，而是定位“哪个前提变了”

12.9.1 如何求两个有序数组合并后的第 k 小？

  • 变化的前提： 输入获得了全局有序性，因此可以用单调指针/二分替代额外索引。
  • 推荐方向： 优先尝试双指针或二分；若仍需返回原始下标，排序时要携带 index。

12.9.2 扩展到多个有序数组怎么办？

  • 变化的前提： 输入获得了全局有序性，因此可以用单调指针/二分替代额外索引。
  • 推荐方向： 优先尝试双指针或二分；若仍需返回原始下标，排序时要携带 index。

12.9.3 如果数组存储在远程机器，怎样减少网络访问？

  • 变化的前提： 比较/随机访问不再是常数成本，网络 round-trip 可能比 CPU 更贵。
  • 推荐方向： 保持对较短数组的 O(log min(m,n)) 探测；批量预取分割点附近元素，减少往返次数，并把通信轮数作为主要复杂度指标。

12.10 Pattern 迁移：什么时候应该想到它

识别信号：

  • 只需要 Top-K 而不是全排序
  • 数据在线到达并持续查询当前极值
  • K 路有序流归并或动态中位数

迁移方法：

  • 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
  • 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
  • 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
  • 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

12.11 面试官视角：这题真正区分候选人的地方

能力层级 典型表现
只会做 能写出代码，但无法解释为什么该结构成立
合格 能从 baseline 推出 二分分割，复杂度与边界基本正确
较强 能写出不变量/证明，并比较至少一种替代方案
很强 follow-up 改约束后，能明确指出失效的前提并局部替换结构，而不是重新猜算法

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
