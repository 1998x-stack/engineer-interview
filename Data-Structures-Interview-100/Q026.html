寻找链表环入口

难度： M
核心： 链表 / Floyd
章节： 链表
内容边界： “原稿”部分来自仓库内 PDF 对应题目；“深化解析”是在原稿基础上的扩展讲解，不新增未经来源支持的公司题库归属。

1. 题目

已知链表可能含环，若有环返回环的第一个节点，否则返回 None。

仓库深化：手推示例

沿用有环示例，入口为值 2 的节点。第一次相遇后，一个指针回到 head，两者同速前进，再次相遇点就是入口。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

2. 面试开始先澄清

  • 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

  • 是否允许修改输入？输出是否要求稳定顺序或去重？

  • 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

  • 链表是否保证无环？节点比较按值还是节点身份？

3. 基线方案与瓶颈

用 HashSet 第一个重复节点即入口，空间 O(n)。

解法演进对比

层级 思路 代价 / 价值
Baseline 用 HashSet 第一个重复节点即入口，空间 O(n)。 先保证正确，暴露真正瓶颈
面试目标 围绕 链表 / Floyd 维护最小必要状态 时间 O(n)，空间 O(1)。

这张表的重点不是“最优解一定唯一”，而是能够解释为什么新结构减少了哪一类重复工作。

深化解析：先定位重复工作

本题所在章节的核心原则是 指针不变量。先画指针关系，再修改 next；Dummy、快慢指针、局部反转是高频基本功。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

4. 关键洞察：为什么这个数据结构合适

先用快慢指针求一个相遇点。设头到入口距离 μ、环长 λ；相遇时 slow 走过 μ+x，fast 走过 2(μ+x)，差值是 λ 的整数倍，因此 μ 与从相遇点继续到入口的距离同余。把一个指针放回 head，两者每次一步，相遇点就是 入口。

结构选择检查表

  • 我们反复查询/维护的信息是什么？ 把它写成一句话。
  • 这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？ 这些性质通常直接决定数据结构。
  • 是否需要在线更新？ 静态问题和动态问题往往需要不同结构。
  • 输出规模是否本身构成复杂度下界？ 返回所有答案时尤其重要。
  • 是否能说明替代结构为什么更差？ 面试官常通过这一问验证理解深度。

5. 不变量与正确性证明

原稿不变量： 第二阶段两指针分别走 μ 步：头指针到入口；环内指针也恰好从相遇点走到入口。

正确性证明框架

  1. 初始化： 证明算法开始时不变量成立。
  2. 保持： 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
  3. 终止： 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
  4. 无遗漏/无重复： 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

6. 参考实现（Python）

def detect_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p, slow = p.next, slow.next
            return p
    return None

Code Review 视角

  • 变量名应直接体现状态含义，不要让 i/j/tmp 承担过多语义。
  • 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
  • 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是值、下标、节点还是聚合状态。
  • 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
  • Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，heapq pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

7. 复杂度

时间 O(n)，空间 O(1)。

复杂度审查

维度 需要回答的问题
时间 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？
空间 统计的是额外空间还是包含输出？递归栈算不算？
预处理 排序、建索引、建 Trie/Heap 的成本是否被漏算？
输出下界 若答案本身有 m 项，是否至少需要 O(m)？

8. 高频失分点

  • 只会背“相遇后回头”但不能给出距离关系

  • 第二阶段 fast 仍走两步

  • 无环时未返回 None

额外边界测试

  • 最小合法输入与空输入（若题目允许）
  • 重复值/重复状态是否改变算法不变量
  • 只有一个节点/容量为 1
  • 头尾节点或删除最后一个元素

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

9. 面试官追问与答题方向

  • 证明可用模运算还是路程方程？
  • 答题方向： 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。
  • 如果链表结构允许多个 outgoing edge，这个技巧为何失效？
  • 答题方向： 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。

Follow-up 的统一处理方法

不要把追问当成新题。先问：原方案依赖的哪个前提被改变了？ 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

10. 60 秒口述模板

我会先给出一个可工作的基线方案：用 HashSet 第一个重复节点即入口，空间 O(n)。 真正的瓶颈在重复工作，因此优 化的核心是：先用快慢指针求一个相遇点。设头到入口距离 μ、环长 λ；相遇时 slow 走过 μ+x，fast 走过 2(μ+x)，差值 是 λ 的整数倍，因此 μ 与从相遇点继续到入口的距离同余。把一个指针放回 head，两者每次一步，相遇点就是入口。 正确性依赖的不变量是：第二阶段两指针分别走 μ 步：头指针到入口；环内指针也恰好从相遇点走到入口。 最终复杂度 为：时间 O(n)，空间 O(1)。

12. 专业深化：约束驱动的完整面试推导

本节属于 GitHub 仓库深化内容：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 Floyd 数学性质。出现以下信号时，应主动联想到这一类结构：

  • 需要 O(1) 改链而不能随机访问
  • 问题与相对位置、环、中点、反转有关
  • 数组移动成本高而节点重连成本低

把题目抽象成一句“数据结构需求”会更有效：

修改指针前先保存仍需访问的 next/prev；把“当前已经处理好的链段”作为不变量，而不是只记几个裸指针。

12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

第二阶段两个指针每轮都缩短各自到入口的剩余路径 1；由第一阶段的模环关系，它们会同时到入口。

进一步拆成三个层次：

  1. 输入事实：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
  2. 未来充分统计量：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
  3. 答案状态：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。

12.3 解法谱系与 Trade-off

# 方案 定位
1 HashSet 第一次重复节点 基线/对照
2 Floyd 相遇 + 数学对齐 O(1) extra 面试主解

选择主解时至少回答三个问题：

  • 它具体消除了基线中的哪一类重复工作？
  • 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
  • 如果这些性质被 follow-up 改掉，哪一层会首先失效？

12.4 针对本题的正确性证明

  • 链形不变量： 第二阶段两个指针每轮都缩短各自到入口的剩余路径 1；由第一阶段的模环关系，它们会同时到入口。
  • 局部安全性： 修改 next/prev 前先保存仍需访问的引用，因此不会丢失未处理链段。
  • 保持： 每一步只把一个节点从“未处理段”移动到“已处理且形状正确的段”，已处理部分不会再被错误改写。
  • 终止： 每个节点恰好处理一次，所有连接关系在退出时满足目标链形。

面试表达建议： 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：时间 O(n)，空间 O(1)。

进一步需要注意：

  • 区分“额外空间”与输出空间；若返回 m 个结果，O(m) 输出本身就是不可避免的下界。

专业回答建议写成：

n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）

每一行都要能够回答：为什么这个状态可以被加入、删除、移动或结算？ 如果答不出来，通常说明不变量还没有真正建立。

12.7 代码审查：从 AC 代码提升到面试级实现

  • Dummy/Sentinel 常用于统一删头、插头和空链边界
  • 节点“值相等”与“对象相同”必须区分
  • 若题目要求 O(1) extra space，递归栈也算额外空间

此外，对本题代码建议做四次快速 review：

  1. State review：每个变量能否用一句不变量解释？
  2. Boundary review：所有 +1/-1、开闭区间、空结构分支是否统一？
  3. Mutation review：修改容器/指针后，另一个索引或引用是否需要同步更新？
  4. Complexity review：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

12.8 对抗性测试矩阵

测试维度 本题应覆盖的情况 目的
最小/空边界 空链/单节点 验证不变量与边界处理，不只验证最终值
重复/相等状态 偶数/奇数长度 验证不变量与边界处理，不只验证最终值
结构极端 环入口在 head 或尾部附近 验证不变量与边界处理，不只验证最终值
约束破坏/反例 这题最好能口头推导距离关系，而不是只背模板。 验证不变量与边界处理，不只验证最终值

源书稿中的高频失分点也应逐个转成单元测试：

  • 反例化： 这题最好能口头推导距离关系，而不是只背模板。
  • 反例化： 第二阶段两个指针都每次一步。
  • 反例化： 无环时必须返回 None。

12.10 Pattern 迁移：什么时候应该想到它

识别信号：

  • 需要 O(1) 改链而不能随机访问
  • 问题与相对位置、环、中点、反转有关
  • 数组移动成本高而节点重连成本低

迁移方法：

  • 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
  • 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
  • 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
  • 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

12.11 面试官视角：这题真正区分候选人的地方

能力层级 典型表现
只会做 能写出代码，但无法解释为什么该结构成立
合格 能从 baseline 推出 Floyd 数学性质，复杂度与边界基本正确
较强 能写出不变量/证明，并比较至少一种替代方案
很强 follow-up 改约束后，能明确指出失效的前提并局部替换结构，而不是重新猜算法

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
