# 深度复盘指南：如何使用每一道 Markdown

仓库第二版把每题从“讲解页”升级成“独立训练单元”。建议不要从头到尾被动阅读，而按四遍法使用。

## 第一遍：只读题目与澄清

隐藏后文，5 分钟内写出：输入规模、是否可修改、重复/空输入、目标复杂度、输出语义。

## 第二遍：从 Baseline 推结构

强制先写一个正确但可能慢的方案，然后明确一句：**它重复做了什么？** 只有定位重复工作后才看“关键洞察”。

## 第三遍：不变量 + 手写代码

不看参考实现，先写 invariant；再让每一行代码都能对应 invariant 中的一次状态更新。写完用对抗性测试矩阵手推。

## 第四遍：只练 Follow-up

每个追问先写“改变了哪个前提”，再回答“原结构哪一层失效”。真正的迁移能力来自局部替换，而不是重新背一道新题。

## 通过标准

一道题达到 `interview-ready`，至少应做到：

- 60 秒讲清 baseline → bottleneck → structure；
- 2 分钟讲清 invariant / correctness；
- 在无 IDE 情况下完成核心实现；
- 给出 worst/average/amortized 中正确的一种复杂度口径；
- 覆盖 3 个对抗性边界；
- 至少完成 2 个 follow-up，且明确指出被改变的前提。
