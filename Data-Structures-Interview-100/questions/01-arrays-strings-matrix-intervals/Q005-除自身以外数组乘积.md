## 1. 题目

返回 answer[i] = nums 中除 nums[i] 外所有元素之积；不允许使用除法。

### 仓库深化：手推示例

> `nums = [1,2,3,4]`，输出 `[24,12,8,6]`。第一遍在答案数组写左侧乘积，第二遍用一个变量维护右侧乘积。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

## 2. 面试开始先澄清

- 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

- 是否允许修改输入？输出是否要求稳定顺序或去重？

- 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

## 3. 基线方案与瓶颈

对每个 i 重新乘其余元素为 O(n^2)。分别构造 prefix 与 suffix 数组可以 O(n) 时间但需要 O(n) 额外空间。

### 解法演进对比

| 层级 | 思路 | 代价 / 价值 |
|---|---|---|
| Baseline | 对每个 i 重新乘其余元素为 O(n^2)。分别构造 prefix 与 suffix 数组可以 O(n) 时间但需要 O(n) 额外空间。 | 先保证正确，暴露真正瓶颈 |
| 面试目标 | 围绕 `数组 / 前缀/后缀` 维护最小必要状态 | 时间 O(n)，除输出外额外空间 O(1)。 |

这张表的重点不是“最优解一定唯一”，而是能够解释**为什么新结构减少了哪一类重复工作**。

### 深化解析：先定位重复工作

本题所在章节的核心原则是 **连续内存、索引关系与单调性**。优先检查 Hash、双指针、滑动窗口、前缀和、二分、单调结构与 Sweep Line。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

## 4. 关键洞察：为什么这个数据结构合适

answer[i] 先保存 i 左侧所有数的乘积，再用一个滚动变量 suffix 从右向左乘入右侧乘积；输出数组不计额外 空间时可做到 O(1)。

### 结构选择检查表

- **我们反复查询/维护的信息是什么？** 把它写成一句话。
- **这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？** 这些性质通常直接决定数据结构。
- **是否需要在线更新？** 静态问题和动态问题往往需要不同结构。
- **输出规模是否本身构成复杂度下界？** 返回所有答案时尤其重要。
- **是否能说明替代结构为什么更差？** 面试官常通过这一问验证理解深度。

## 5. 不变量与正确性证明

> **原稿不变量：** 第二遍处理 i 时，answer[i] 已等于左侧积，suffix 等于严格右侧积，两者乘积恰好排除 nums[i]。

### 正确性证明框架

1. **初始化：** 证明算法开始时不变量成立。
2. **保持：** 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
3. **终止：** 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
4. **无遗漏/无重复：** 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

## 6. 参考实现（Python）

```python
def product_except_self(nums):
    n = len(nums)
    ans = [1] * n
    prefix = 1
    for i in range(n):
        ans[i] = prefix
        prefix *= nums[i]
    suffix = 1
    for i in range(n-1, -1, -1):
        ans[i] *= suffix
        suffix *= nums[i]
    return ans
```

### Code Review 视角

- 变量名应直接体现状态含义，不要让 `i/j/tmp` 承担过多语义。
- 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
- 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是**值、下标、节点还是聚合状态**。
- 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
- Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，`heapq` pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

## 7. 复杂度

时间 O(n)，除输出外额外空间 O(1)。

### 复杂度审查

| 维度 | 需要回答的问题 |
|---|---|
| 时间 | 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？ |
| 空间 | 统计的是额外空间还是包含输出？递归栈算不算？ |
| 预处理 | 排序、建索引、建 Trie/Heap 的成本是否被漏算？ |
| 输出下界 | 若答案本身有 m 项，是否至少需要 O(m)？ |

## 8. 高频失分点

- 使用除法后被 0 卡住

- 第二遍先更新 suffix 再乘，错误地包含自己

- 没有说明输出数组是否计入空间复杂度

### 额外边界测试

- 最小合法输入与空输入（若题目允许）
- 重复值/重复状态是否改变算法不变量
- 全相等/单调递增/单调递减
- 负数、零与极大整数

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

## 9. 面试官追问与答题方向

- 如果数据会溢出怎么办？
  - **答题方向：** 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。
- 如果只允许单遍扫描，能否做到同样复杂度？为什么困难？
  - **答题方向：** 分别给出最坏、平均或摊销复杂度，解释隐藏参数（如 k、V、E、字符串长度 L、窗口 W）。

### Follow-up 的统一处理方法

不要把追问当成新题。先问：**原方案依赖的哪个前提被改变了？** 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

## 10. 60 秒口述模板

我会先给出一个可工作的基线方案：对每个 i 重新乘其余元素为 O(n^2)。分别构造 prefix 与 suffix 数组可以 O(n) 时间 但需要 O(n) 额外空间。 真正的瓶颈在重复工作，因此优化的核心是：answer[i] 先保存 i 左侧所有数的乘积，再用一个 滚动变量 suffix 从右向左乘入右侧乘积；输出数组不计额外空间时可做到 O(1)。 正确性依赖的不变量是：第二遍处理 i 时，answer[i] 已等于左侧积，suffix 等于严格右侧积，两者乘积恰好排除 nums[i]。 最终复杂度为：时间 O(n)，除输 出外额外空间 O(1)。

## 12. 专业深化：约束驱动的完整面试推导

> 本节属于 **GitHub 仓库深化内容**：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

### 12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 **前缀/后缀积**。出现以下信号时，应主动联想到这一类结构：

- 大量连续区间的和/积/频次查询
- 区间量可以由两个前缀状态相减/组合得到
- 需要把“枚举左端点”变成历史状态查询

把题目抽象成一句“数据结构需求”会更有效：

> 定义 prefix[i] 的精确含义（是否含 i），并让区间量可以由两个 prefix 组合得到；下标约定必须始终一致。

### 12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

> 第二趟处理 i 前，right 表示区间 (i,n) 的乘积；answer[i] 已经保存 [0,i) 的乘积。

进一步拆成三个层次：

1. **输入事实**：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
2. **未来充分统计量**：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
3. **答案状态**：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

> **如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。**

### 12.3 解法谱系与 Trade-off

| # | 方案 | 定位 |
|---:|---|---|
| 1 | 每个位置重算左右乘积 O(n²) | 基线/对照 |
| 2 | 显式 prefix[] + suffix[] O(n) 空间 | 可选方案 |
| 3 | 答案数组复用 prefix + 单个 suffix 变量，额外 O(1) | 面试主解 |

选择主解时至少回答三个问题：

- 它具体消除了基线中的哪一类重复工作？
- 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
- 如果这些性质被 follow-up 改掉，哪一层会首先失效？

### 12.4 针对本题的正确性证明

- **前缀状态不变量：** 第二趟处理 i 前，right 表示区间 (i,n) 的乘积；answer[i] 已经保存 [0,i) 的乘积。
- **唯一分解：** 每个连续区间都唯一对应一对前缀边界，因此对历史 prefix 的查询覆盖所有可能左端点。
- **计数正确性：** 若某前缀值出现 c 次，就代表有 c 个不同左边界产生相同区间量，应完整累加而不是只记是否出现。
- **单遍性：** 当前 prefix 只依赖上一步，历史摘要只需增量更新，所以每个元素处理一次。

> **面试表达建议：** 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

### 12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：**时间 O(n)，若输出数组不计额外空间，则 O(1) extra space。**

进一步需要注意：

- 区分“额外空间”与输出空间；若返回 m 个结果，O(m) 输出本身就是不可避免的下界。

专业回答建议写成：

```text
n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）
```

每一行都要能够回答：**为什么这个状态可以被加入、删除、移动或结算？** 如果答不出来，通常说明不变量还没有真正建立。

### 12.7 代码审查：从 AC 代码提升到面试级实现

- 明确 prefix[0] 是否代表空前缀
- 整数溢出在固定宽度语言中要考虑
- 动态更新场景通常要升级到 Fenwick/Segment Tree

此外，对本题代码建议做四次快速 review：

1. **State review**：每个变量能否用一句不变量解释？
2. **Boundary review**：所有 `+1/-1`、开闭区间、空结构分支是否统一？
3. **Mutation review**：修改容器/指针后，另一个索引或引用是否需要同步更新？
4. **Complexity review**：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

### 12.8 对抗性测试矩阵

| 测试维度 | 本题应覆盖的情况 | 目的 |
|---|---|---|
| 最小/空边界 | 从下标 0 开始的区间 | 验证不变量与边界处理，不只验证最终值 |
| 重复/相等状态 | 负数导致滑窗失效但前缀和仍正确 | 验证不变量与边界处理，不只验证最终值 |
| 结构极端 | 多个相同前缀产生多个答案 | 验证不变量与边界处理，不只验证最终值 |
| 约束破坏/反例 | 零元素会让除法方案很麻烦，这正是该方法的优势。 | 验证不变量与边界处理，不只验证最终值 |

源书稿中的高频失分点也应逐个转成单元测试：

- **反例化：** 零元素会让除法方案很麻烦，这正是该方法的优势。
- **反例化：** 输出数组通常不计额外空间，但面试时应说明口径。
- **反例化：** 整数溢出在固定宽度语言里需要讨论。

### 12.9 Follow-up 深挖：不是换题，而是定位“哪个前提变了”

#### 12.9.1 允许除法时如何处理 0？

- **变化的前提：** 这个追问改变了 `前缀/后缀积` 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
- **推荐方向：** 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。
#### 12.9.2 如果数组支持动态更新和查询，应该用什么结构？

- **变化的前提：** 原问题从静态查询变成 update + query 混合，预计算结果会频繁失效。
- **推荐方向：** 把静态前缀/排序结构升级为 Fenwick、Segment Tree、平衡树或带索引的 Heap；重新给出 update/query 双复杂度。
#### 12.9.3 若要求模 M 乘积，哪些细节变化？

- **变化的前提：** 原问题从静态查询变成 update + query 混合，预计算结果会频繁失效。
- **推荐方向：** 把静态前缀/排序结构升级为 Fenwick、Segment Tree、平衡树或带索引的 Heap；重新给出 update/query 双复杂度。

### 12.10 Pattern 迁移：什么时候应该想到它

**识别信号：**

- 大量连续区间的和/积/频次查询
- 区间量可以由两个前缀状态相减/组合得到
- 需要把“枚举左端点”变成历史状态查询

**迁移方法：**

- 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
- 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
- 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
- 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

### 12.11 面试官视角：这题真正区分候选人的地方

| 能力层级 | 典型表现 |
|---|---|
| 只会做 | 能写出代码，但无法解释为什么该结构成立 |
| 合格 | 能从 baseline 推出 `前缀/后缀积`，复杂度与边界基本正确 |
| 较强 | 能写出不变量/证明，并比较至少一种替代方案 |
| 很强 | follow-up 改约束后，能明确指出**失效的前提**并局部替换结构，而不是重新猜算法 |

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
