# Q048 二叉树直径

> **难度：** M  
> **核心：** Tree / Postorder  
> **章节：** Binary Tree / BST  
> **内容边界：** “原稿”部分来自仓库内 PDF 对应题目；“深化解析”是在原稿基础上的扩展讲解，不新增未经来源支持的公司题库归属。

## 1. 题目

二叉树直径定义为任意两个节点间最长路径的边数，路径可经过或不经过根。

### 仓库深化：手推示例

> 树 `[1,2,3]` 的直径为 `2` 条边。每个节点向父返回高度，同时用 `left_height + right_height` 更新全局直径。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

## 2. 面试开始先澄清

- 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

- 是否允许修改输入？输出是否要求稳定顺序或去重？

- 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

- 空树、重复键、深度定义（节点数/边数）以及是否保证节点存在。

## 3. 基线方案与瓶颈

对每个节点重新计算左右高度是 O(n^2)。

### 解法演进对比

| 层级 | 思路 | 代价 / 价值 |
|---|---|---|
| Baseline | 对每个节点重新计算左右高度是 O(n^2)。 | 先保证正确，暴露真正瓶颈 |
| 面试目标 | 围绕 `Tree / Postorder` 维护最小必要状态 | 时间 O(n)，栈 O(h)。 |

这张表的重点不是“最优解一定唯一”，而是能够解释**为什么新结构减少了哪一类重复工作**。

### 深化解析：先定位重复工作

本题所在章节的核心原则是 **递归状态定义**。先定义函数“向父节点返回什么”，再区分全局答案；BST 额外利用有序性。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

## 4. 关键洞察：为什么这个数据结构合适

一次后序 DFS：函数向父节点返回当前子树高度，同时用 leftHeight+rightHeight 更新全局直径。注意“返 回值”和“全局候选”不是同一量。

### 结构选择检查表

- **我们反复查询/维护的信息是什么？** 把它写成一句话。
- **这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？** 这些性质通常直接决定数据结构。
- **是否需要在线更新？** 静态问题和动态问题往往需要不同结构。
- **输出规模是否本身构成复杂度下界？** 返回所有答案时尤其重要。
- **是否能说明替代结构为什么更差？** 面试官常通过这一问验证理解深度。

## 5. 不变量与正确性证明

> **原稿不变量：** 当处理 node 时左右子树高度已准确；经过 node 的最长路径只能由左侧最长向下链 + 右侧最长向下链组成。

### 正确性证明框架

1. **初始化：** 证明算法开始时不变量成立。
2. **保持：** 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
3. **终止：** 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
4. **无遗漏/无重复：** 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

## 6. 参考实现（Python）

```python
def diameter(root):
    best=0
    def height(node):
        nonlocal best
        if not node: return 0
        l,r=height(node.left),height(node.right)
        best=max(best,l+r)
        return 1+max(l,r)
    height(root); return best
```

### Code Review 视角

- 变量名应直接体现状态含义，不要让 `i/j/tmp` 承担过多语义。
- 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
- 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是**值、下标、节点还是聚合状态**。
- 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
- Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，`heapq` pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

## 7. 复杂度

时间 O(n)，栈 O(h)。

### 复杂度审查

| 维度 | 需要回答的问题 |
|---|---|
| 时间 | 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？ |
| 空间 | 统计的是额外空间还是包含输出？递归栈算不算？ |
| 预处理 | 排序、建索引、建 Trie/Heap 的成本是否被漏算？ |
| 输出下界 | 若答案本身有 m 项，是否至少需要 O(m)？ |

## 8. 高频失分点

- 把节点数和边数差 1

- 错误返回 l+r+1 给父节点，导致形成分叉路径

### 额外边界测试

- 最小合法输入与空输入（若题目允许）
- 重复值/重复状态是否改变算法不变量
- 极度偏斜树（退化成链）
- 只有左子树或只有右子树

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

## 9. 面试官追问与答题方向

- 如何返回直径对应的实际路径？
  - **答题方向：** 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。
- N 叉树直径如何改？
  - **答题方向：** 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。

### Follow-up 的统一处理方法

不要把追问当成新题。先问：**原方案依赖的哪个前提被改变了？** 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

## 10. 60 秒口述模板

我会先给出一个可工作的基线方案：对每个节点重新计算左右高度是 O(n^2)。 真正的瓶颈在重复工作，因此优化的核心 是：一次后序 DFS：函数向父节点返回当前子树高度，同时用 leftHeight+rightHeight 更新全局直径。注意“返回 值”和“全局候选”不是同一量。 正确性依赖的不变量是：当处理 node 时左右子树高度已准确；经过 node 的最长路 径只能由左侧最长向下链 + 右侧最长向下链组成。 最终复杂度为：时间 O(n)，栈 O(h)。

## 12. 专业深化：约束驱动的完整面试推导

> 本节属于 **GitHub 仓库深化内容**：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

### 12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 **Postorder Tree DP**。出现以下信号时，应主动联想到这一类结构：

- 问题可分解为左右子树子问题
- 每个节点只需要从孩子获得少量摘要信息
- BST 额外提供全局有序边界

把题目抽象成一句“数据结构需求”会更有效：

> 先定义递归函数“返回给父节点什么”，再定义“当前节点如何更新全局答案”。Tree DP 最常见错误是混淆这两种状态。

### 12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

> height(node) 返回从 node 向下的最大边/节点高度；在 node 处用左右返回值组合成可能穿过 node 的完整路径。

进一步拆成三个层次：

1. **输入事实**：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
2. **未来充分统计量**：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
3. **答案状态**：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

> **如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。**

### 12.3 解法谱系与 Trade-off

| # | 方案 | 定位 |
|---:|---|---|
| 1 | 对每个节点重复求左右高度 O(n²) | 基线/对照 |
| 2 | 一次 Postorder 同时返回高度并更新直径 O(n) | 面试主解 |

选择主解时至少回答三个问题：

- 它具体消除了基线中的哪一类重复工作？
- 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
- 如果这些性质被 follow-up 改掉，哪一层会首先失效？

### 12.4 针对本题的正确性证明

- **递归返回值：** height(node) 返回从 node 向下的最大边/节点高度；在 node 处用左右返回值组合成可能穿过 node 的完整路径。
- **归纳基：** 空树/叶节点时返回值与题意直接一致。
- **归纳假设：** 假设左右子树递归结果已经满足其定义。
- **转移正确性：** 当前节点只使用左右子树的“充分摘要”计算自己的返回值/全局候选，因此没有遗漏跨越当前节点的合法结构。
- **全局性：** 每个节点都恰好作为一次局部组合中心被处理，所以所有可能答案都会在某个节点被考虑。

> **面试表达建议：** 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

### 12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：**时间 O(n)，递归空间 O(h)。**

进一步需要注意：

- 递归栈是额外空间：平衡树约 O(log n)，退化树/深图最坏 O(n)。

专业回答建议写成：

```text
n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）
```

建议在白板手推时至少画下面这张表；列名已经按本题 Pattern 定制：

| node | left state | right state | return state | global/update |
| --- | --- | --- | --- | --- |
| `...` | `...` | `...` | `...` | `...` |
| `...` | `...` | `...` | `...` | `...` |
| `...` | `...` | `...` | `...` | `...` |

每一行都要能够回答：**为什么这个状态可以被加入、删除、移动或结算？** 如果答不出来，通常说明不变量还没有真正建立。

### 12.7 代码审查：从 AC 代码提升到面试级实现

- 极度偏斜树递归深度 O(n)
- BST 判断必须传全局上下界，不能只比较父子
- 若需要重建/序列化，必须明确 null 与重复值语义

此外，对本题代码建议做四次快速 review：

1. **State review**：每个变量能否用一句不变量解释？
2. **Boundary review**：所有 `+1/-1`、开闭区间、空结构分支是否统一？
3. **Mutation review**：修改容器/指针后，另一个索引或引用是否需要同步更新？
4. **Complexity review**：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

### 12.8 对抗性测试矩阵

| 测试维度 | 本题应覆盖的情况 | 目的 |
|---|---|---|
| 最小/空边界 | 空树/单节点 | 验证不变量与边界处理，不只验证最终值 |
| 重复/相等状态 | 全负或全相等 | 验证不变量与边界处理，不只验证最终值 |
| 结构极端 | 退化成链、只有单侧子树 | 验证不变量与边界处理，不只验证最终值 |
| 约束破坏/反例 | 题目问边数还是节点数要确认。 | 验证不变量与边界处理，不只验证最终值 |

源书稿中的高频失分点也应逐个转成单元测试：

- **反例化：** 题目问边数还是节点数要确认。
- **反例化：** 若每个节点重新计算高度会 O(n^2)。
- **反例化：** 返回给父节点不能同时包含左右两支。

### 12.9 Follow-up 深挖：不是换题，而是定位“哪个前提变了”

#### 12.9.1 带权边的树直径？

- **变化的前提：** 这个追问改变了 `Postorder Tree DP` 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
- **推荐方向：** 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。
#### 12.9.2 N 叉树直径？

- **变化的前提：** 当前节点不再只有左右两个 child。
- **推荐方向：** 若路径仍是简单路径，则向父返回最大的单个正 gain；更新全局答案时取所有 child gain 中最大的两个正值与当前节点组合。时间仍可 O(总边数)。
#### 12.9.3 如何返回直径两端节点？

- **变化的前提：** 这个追问改变了 `Postorder Tree DP` 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
- **推荐方向：** 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。

### 12.10 Pattern 迁移：什么时候应该想到它

**识别信号：**

- 问题可分解为左右子树子问题
- 每个节点只需要从孩子获得少量摘要信息
- BST 额外提供全局有序边界

**迁移方法：**

- 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
- 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
- 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
- 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

### 12.11 面试官视角：这题真正区分候选人的地方

| 能力层级 | 典型表现 |
|---|---|
| 只会做 | 能写出代码，但无法解释为什么该结构成立 |
| 合格 | 能从 baseline 推出 `Postorder Tree DP`，复杂度与边界基本正确 |
| 较强 | 能写出不变量/证明，并比较至少一种替代方案 |
| 很强 | follow-up 改约束后，能明确指出**失效的前提**并局部替换结构，而不是重新猜算法 |

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
