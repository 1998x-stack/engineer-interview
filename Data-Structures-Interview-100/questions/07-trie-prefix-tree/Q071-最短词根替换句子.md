# Q071 最短词根替换句子

> **难度：** M  
> **核心：** Trie / 字符串  
> **章节：** Trie / Prefix Tree  
> **内容边界：** “原稿”部分来自仓库内 PDF 对应题目；“深化解析”是在原稿基础上的扩展讲解，不新增未经来源支持的公司题库归属。

## 1. 题目

给定词根词典，把句子中每个单词替换成它最短的、存在于词典中的前缀；若无则保留原词。

### 仓库深化：手推示例

> 词根 `[cat,bat,rat]`，句子 `"the cattle was rattled by the battery"` 替换为 `"the cat was rat by the bat"`。搜索单词时遇到第一个 terminal 就停止。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

## 2. 面试开始先澄清

- 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

- 是否允许修改输入？输出是否要求稳定顺序或去重？

- 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

## 3. 基线方案与瓶颈

对每个单词枚举所有前缀并查 set，最坏 O(L^2) 字符处理。

### 解法演进对比

| 层级 | 思路 | 代价 / 价值 |
|---|---|---|
| Baseline | 对每个单词枚举所有前缀并查 set，最坏 O(L^2) 字符处理。 | 先保证正确，暴露真正瓶颈 |
| 面试目标 | 围绕 `Trie / 字符串` 维护最小必要状态 | 总时间 O(句子字符数) 量级，空间为 Trie。 |

这张表的重点不是“最优解一定唯一”，而是能够解释**为什么新结构减少了哪一类重复工作**。

### 深化解析：先定位重复工作

本题所在章节的核心原则是 **共享公共前缀**。字符串长度 L 往往比词典规模更重要；注意节点空间、终止标记、Top-K 缓存和删除/剪枝。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

## 4. 关键洞察：为什么这个数据结构合适

Trie 从单词第一个字符向下走；一旦到达 terminal，就已经找到最短可行词根，可立即返回。

### 结构选择检查表

- **我们反复查询/维护的信息是什么？** 把它写成一句话。
- **这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？** 这些性质通常直接决定数据结构。
- **是否需要在线更新？** 静态问题和动态问题往往需要不同结构。
- **输出规模是否本身构成复杂度下界？** 返回所有答案时尤其重要。
- **是否能说明替代结构为什么更差？** 面试官常通过这一问验证理解深度。

## 5. 不变量与正确性证明

> **原稿不变量：** 沿单词路径第一次遇到 terminal 的深度最小，因此对应最短前缀。

### 正确性证明框架

1. **初始化：** 证明算法开始时不变量成立。
2. **保持：** 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
3. **终止：** 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
4. **无遗漏/无重复：** 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

## 6. 参考实现（Python）

```python
def replace_words(dictionary, sentence):
    trie=Trie()
    for w in dictionary: trie.insert(w)
    def repl(w):
        p=trie.root; out=[]
        for c in w:
            if c not in p.ch: return w
            out.append(c); p=p.ch[c]
            if p.end: return ''.join(out)
        return w
    return ' '.join(repl(w) for w in sentence.split())
```

### Code Review 视角

- 变量名应直接体现状态含义，不要让 `i/j/tmp` 承担过多语义。
- 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
- 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是**值、下标、节点还是聚合状态**。
- 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
- Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，`heapq` pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

## 7. 复杂度

总时间 O(句子字符数) 量级，空间为 Trie。

### 复杂度审查

| 维度 | 需要回答的问题 |
|---|---|
| 时间 | 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？ |
| 空间 | 统计的是额外空间还是包含输出？递归栈算不算？ |
| 预处理 | 排序、建索引、建 Trie/Heap 的成本是否被漏算？ |
| 输出下界 | 若答案本身有 m 项，是否至少需要 O(m)？ |

## 8. 高频失分点

- 找到更长 root 后才返回，违反“最短”

- 标点/大小写的文本规范化未澄清

### 额外边界测试

- 最小合法输入与空输入（若题目允许）
- 重复值/重复状态是否改变算法不变量
- 空串/前缀本身就是完整词
- 字符集/大小写/Unicode 是否受限

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

## 9. 面试官追问与答题方向

- 如果词根有权重且要选择“最优”而非最短，节点需要存什么？
  - **答题方向：** 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。

### Follow-up 的统一处理方法

不要把追问当成新题。先问：**原方案依赖的哪个前提被改变了？** 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

## 10. 60 秒口述模板

我会先给出一个可工作的基线方案：对每个单词枚举所有前缀并查 set，最坏 O(L^2) 字符处理。 真正的瓶颈在重复工 作，因此优化的核心是：Trie 从单词第一个字符向下走；一旦到达 terminal，就已经找到最短可行词根，可立即返回。 正确性依赖的不变量是：沿单词路径第一次遇到 terminal 的深度最小，因此对应最短前缀。 最终复杂度为：总时间 O(句子字符数) 量级，空间为 Trie。

## 12. 专业深化：约束驱动的完整面试推导

> 本节属于 **GitHub 仓库深化内容**：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

### 12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 **Trie 最短前缀**。出现以下信号时，应主动联想到这一类结构：

- 要求最短距离/最小代价
- 边权非负时可使用贪心确认最短状态
- 无权图可视为每边权重 1

把题目抽象成一句“数据结构需求”会更有效：

> dist[v] 是当前已知最好上界；堆中可能存在 stale entry，弹出时必须与 dist 校验。

### 12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

> 扫描到第 i 个字符时，若此前未遇到 end，则不存在更短的有效词根。

进一步拆成三个层次：

1. **输入事实**：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
2. **未来充分统计量**：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
3. **答案状态**：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

> **如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。**

### 12.3 解法谱系与 Trade-off

| # | 方案 | 定位 |
|---:|---|---|
| 1 | 每个词根逐个比对 | 基线/对照 |
| 2 | HashSet 枚举所有前缀 | 可选方案 |
| 3 | Trie 遇到最早 terminal 立即结束 | 面试主解 |

选择主解时至少回答三个问题：

- 它具体消除了基线中的哪一类重复工作？
- 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
- 如果这些性质被 follow-up 改掉，哪一层会首先失效？

### 12.4 针对本题的正确性证明

- **状态语义：** 扫描到第 i 个字符时，若此前未遇到 end，则不存在更短的有效词根。
- **层序/最短性：** 若使用 BFS，队列按距离非递减顺序展开。某状态第一次被访问时，已经存在一条当前层长度的路径；任何尚未展开路径至少不会更短，因此第一次到达即是最短。
- **覆盖性：** 每个合法邻居都由转移规则生成，visited 只消除重复状态，不删除任何更短的首次到达。
- **终止：** 队列耗尽表示所有可达状态均已处理；若目标未出现，则按当前图模型不可达。

> **面试表达建议：** 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

### 12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：**建 Trie O(词根总字符数)，替换 O(句子总字符数)，空间 O(词根总字符数)。**

进一步需要注意：

- 字符串 key 的比较、切片、构造 signature 往往还有长度 L 的成本，不应只写“哈希 O(1)”。

专业回答建议写成：

```text
n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）
```

每一行都要能够回答：**为什么这个状态可以被加入、删除、移动或结算？** 如果答不出来，通常说明不变量还没有真正建立。

### 12.7 代码审查：从 AC 代码提升到面试级实现

- 负权不能用普通 Dijkstra
- 图很稠密时 O(V^2) 实现可能比 Heap 更合适
- 路径恢复要维护 predecessor

此外，对本题代码建议做四次快速 review：

1. **State review**：每个变量能否用一句不变量解释？
2. **Boundary review**：所有 `+1/-1`、开闭区间、空结构分支是否统一？
3. **Mutation review**：修改容器/指针后，另一个索引或引用是否需要同步更新？
4. **Complexity review**：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

### 12.8 对抗性测试矩阵

| 测试维度 | 本题应覆盖的情况 | 目的 |
|---|---|---|
| 最小/空边界 | 不可达节点 | 验证不变量与边界处理，不只验证最终值 |
| 重复/相等状态 | 多条等长路径 | 验证不变量与边界处理，不只验证最终值 |
| 结构极端 | 零权边与大权值 | 验证不变量与边界处理，不只验证最终值 |
| 约束破坏/反例 | “最短”意味着第一次 terminal 就停止。 | 验证不变量与边界处理，不只验证最终值 |

源书稿中的高频失分点也应逐个转成单元测试：

- **反例化：** “最短”意味着第一次 terminal 就停止。
- **反例化：** 分词规则若不只是空格，需要 tokenizer。
- **反例化：** HashSet 逐前缀查询也可，但会重复构造 substring。

### 12.9 Follow-up 深挖：不是换题，而是定位“哪个前提变了”

#### 12.9.1 改为最长词根？

- **变化的前提：** 这个追问改变了 `Trie 最短前缀` 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
- **推荐方向：** 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。
#### 12.9.2 词根带权重如何选择？

- **变化的前提：** 这个追问改变了 `Trie 最短前缀` 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
- **推荐方向：** 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。
#### 12.9.3 如何支持百万级动态词典？

- **变化的前提：** 原问题从静态查询变成 update + query 混合，预计算结果会频繁失效。
- **推荐方向：** 把静态前缀/排序结构升级为 Fenwick、Segment Tree、平衡树或带索引的 Heap；重新给出 update/query 双复杂度。

### 12.10 Pattern 迁移：什么时候应该想到它

**识别信号：**

- 要求最短距离/最小代价
- 边权非负时可使用贪心确认最短状态
- 无权图可视为每边权重 1

**迁移方法：**

- 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
- 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
- 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
- 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

### 12.11 面试官视角：这题真正区分候选人的地方

| 能力层级 | 典型表现 |
|---|---|
| 只会做 | 能写出代码，但无法解释为什么该结构成立 |
| 合格 | 能从 baseline 推出 `Trie 最短前缀`，复杂度与边界基本正确 |
| 较强 | 能写出不变量/证明，并比较至少一种替代方案 |
| 很强 | follow-up 改约束后，能明确指出**失效的前提**并局部替换结构，而不是重新猜算法 |

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
