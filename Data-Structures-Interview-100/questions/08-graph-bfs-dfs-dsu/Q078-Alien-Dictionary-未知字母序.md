## 1. 题目

给定按某个未知字母顺序排好序的单词列表，推导一种可能的字母顺序；若矛盾返回无解。

### 仓库深化：手推示例

> 单词序列 `[wrt,wrf,er,ett,rftt]` 可推出一种字母序 `wertf`。相邻单词只取第一处不同字符建边，并注意非法前缀如 `abc` 排在 `ab` 前。

手推时不要只算最终输出，建议同步写出核心结构在每一步的状态变化，这比“看懂答案”更接近真实面试。

## 2. 面试开始先澄清

- 输入规模与合法性：是否允许空输入、重复值、负数，是否保证答案存在？

- 是否允许修改输入？输出是否要求稳定顺序或去重？

- 复杂度目标：题目是否明确要求 O(n)、O(log n) 或 O(1) 额外空间？

- 图是有向/无向？是否连通？是否允许重边/自环？边权是否非负？

## 3. 基线方案与瓶颈

比较所有单词对没有必要，也容易产生错误约束。

### 解法演进对比

| 层级 | 思路 | 代价 / 价值 |
|---|---|---|
| Baseline | 比较所有单词对没有必要，也容易产生错误约束。 | 先保证正确，暴露真正瓶颈 |
| 面试目标 | 围绕 `Graph / Topological Sort` 维护最小必要状态 | 建图 O(总字符数)，拓扑 O(V+E)。 |

这张表的重点不是“最优解一定唯一”，而是能够解释**为什么新结构减少了哪一类重复工作**。

### 深化解析：先定位重复工作

本题所在章节的核心原则是 **节点关系与可达性**。无权最短路用 BFS；依赖用拓扑；动态连通用 DSU；正权最短路用 Dijkstra；最小连接成本用 MST。

面试中不要直接报最优结构。先说明基线方案具体重复做了什么，再指出目标结构如何把这部分重复工作缓存、单调淘汰、分层搜索或局部化维护。这样能证明你是在从约束推导算法，而不是背模板。

## 4. 关键洞察：为什么这个数据结构合适

只需比较相邻单词，第一处不同字符决定一条有向边 a→b。特殊无解：较长单词排在其严格前缀之前，如 "abc" 在 "ab" 前。然后对字符图拓扑排序。

### 结构选择检查表

- **我们反复查询/维护的信息是什么？** 把它写成一句话。
- **这个信息是否具有有序性、单调性、前缀性、局部性或等价关系？** 这些性质通常直接决定数据结构。
- **是否需要在线更新？** 静态问题和动态问题往往需要不同结构。
- **输出规模是否本身构成复杂度下界？** 返回所有答案时尤其重要。
- **是否能说明替代结构为什么更差？** 面试官常通过这一问验证理解深度。

## 5. 不变量与正确性证明

> **原稿不变量：** 字典序相邻元素提供了足以约束全局排序的最小关系；第一处差异之前字符相等，之后 差异不再决定两词顺序。

### 正确性证明框架

1. **初始化：** 证明算法开始时不变量成立。
2. **保持：** 假设处理当前元素/节点前不变量成立，说明一次更新后仍成立。
3. **终止：** 结合循环或递归终止条件，说明得到的状态恰好对应题目要求。
4. **无遗漏/无重复：** 如果题目要求枚举答案，额外说明为何每个合法答案都会被访问，且不会被重复输出。

这是面试中比“跑几个样例看起来对”更强的论证方式。

## 6. 参考实现（Python）

```python
from collections import deque

def alien_order(words):
    g={c:set() for w in words for c in w}; indeg={c:0 for c in g}
    for a,b in zip(words,words[1:]):
        m=min(len(a),len(b)); i=0
        while i<m and a[i]==b[i]: i+=1
        if i==m:
            if len(a)>len(b): return ''
        elif b[i] not in g[a[i]]:
            g[a[i]].add(b[i]); indeg[b[i]]+=1
    q=deque(c for c in indeg if indeg[c]==0); out=[]
    while q:
        c=q.popleft(); out.append(c)
        for d in g[c]:
            indeg[d]-=1
            if indeg[d]==0: q.append(d)
    return ''.join(out) if len(out)==len(g) else ''
```

### Code Review 视角

- 变量名应直接体现状态含义，不要让 `i/j/tmp` 承担过多语义。
- 修改共享结构前，先确认是否会丢失后续仍需访问的信息。
- 对 Hash/Heap/Queue/Tree 等结构，明确其中保存的是**值、下标、节点还是聚合状态**。
- 让实现与上面的不变量一一对应；如果代码中存在无法解释的特殊分支，通常意味着状态定义还不够干净。
- Python 内置操作也有复杂度：例如 list 头部删除是 O(n)，`heapq` pop/push 是 O(log n)，dict/set 操作是平均 O(1)。

## 7. 复杂度

建图 O(总字符数)，拓扑 O(V+E)。

### 复杂度审查

| 维度 | 需要回答的问题 |
|---|---|
| 时间 | 是最坏、平均还是摊销？隐藏参数是 n、k、V/E、L 还是窗口 W？ |
| 空间 | 统计的是额外空间还是包含输出？递归栈算不算？ |
| 预处理 | 排序、建索引、建 Trie/Heap 的成本是否被漏算？ |
| 输出下界 | 若答案本身有 m 项，是否至少需要 O(m)？ |

## 8. 高频失分点

- 忽略 prefix invalid case

- 同一边重复加入导致 indegree 重复

- 结果可能不唯一，不应强求某固定字符串

### 额外边界测试

- 最小合法输入与空输入（若题目允许）
- 重复值/重复状态是否改变算法不变量
- 不连通图/孤立节点
- 重复边、自环或环（按题意决定是否合法）

建议面试现场至少手推一个“最小输入”、一个“最容易破坏不变量的输入”和一个“规模极端输入”。

## 9. 面试官追问与答题方向

- 如何判断拓扑序是否唯一？
  - **答题方向：** 先把新增约束写成需要维护的新不变量，再判断原结构能否继续满足；若不能，明确需要替换或组合的结构。

### Follow-up 的统一处理方法

不要把追问当成新题。先问：**原方案依赖的哪个前提被改变了？** 然后只替换受到影响的那一层结构。例如从离线变在线，通常保留问题定义而替换状态维护方式；从单机变分布式，则新增分片、一致性和容错约束。

## 10. 60 秒口述模板

我会先给出一个可工作的基线方案：比较所有单词对没有必要，也容易产生错误约束。 真正的瓶颈在重复工作，因此优 化的核心是：只需比较相邻单词，第一处不同字符决定一条有向边 a→b。特殊无解：较长单词排在其严格前缀之前，如 "abc" 在 "ab" 前。然后对字符图拓扑排序。 正确性依赖的不变量是：字典序相邻元素提供了足以约束全局排序的最小关 系；第一处差异之前字符相等，之后差异不再决定两词顺序。 最终复杂度为：建图 O(总字符数)，拓扑 O(V+E)。

## 12. 专业深化：约束驱动的完整面试推导

> 本节属于 **GitHub 仓库深化内容**：在源 PDF 的题意、洞察、不变量与代码之上补充更严格的算法论证、替代方案、测试与工程边界；不新增未经来源支持的公司题库归属。

### 12.1 先从约束识别 Pattern，而不是从题名背模板

本题的目标结构是 **建图 + Topological Sort**。出现以下信号时，应主动联想到这一类结构：

- “先做 A 再做 B”的依赖关系
- 需要检测有向图环
- 要求输出一个满足所有偏序约束的顺序

把题目抽象成一句“数据结构需求”会更有效：

> indegree 只表示尚未移除的前驱数量；Kahn 队列中的节点必须是当前 indegree=0 的可执行任务。

> **本题特别说明：** 建图比拓扑排序本身更难。尤其 `abc` 在 `ab` 前是直接矛盾；相邻词只看第一处不同，因为之后字符顺序已不再由这两个词的字典序决定。

### 12.2 状态最小化：到底必须记住什么

源书稿给出的核心不变量是：

> 每对相邻词只贡献第一处差异；后续字符不能再提供排序信息。

进一步拆成三个层次：

1. **输入事实**：当前扫描到的元素、节点、边或操作，哪些信息一旦过去就不会再改变？
2. **未来充分统计量**：未来决策真正需要历史中的哪些摘要？只保存这些，而不是保存“所有历史以防万一”。
3. **答案状态**：区分“用于继续计算的状态”和“已经闭合的最终候选”。Tree DP、Heap、窗口和复合结构题尤其容易把两者混在一起。

面试时可以直接用下面这句话验证自己的状态设计：

> **如果我删除当前结构中的某一类信息，未来是否存在一个合法输入让我无法正确决定？如果不存在，它就不应该被保存。**

### 12.3 解法谱系与 Trade-off

| # | 方案 | 定位 |
|---:|---|---|
| 1 | 比较所有单词对没有必要 | 基线/对照 |
| 2 | 相邻词第一差异建边 + topo | 可选方案 |
| 3 | 要最小合法序可对零入度集用 min-heap | 面试主解 |

选择主解时至少回答三个问题：

- 它具体消除了基线中的哪一类重复工作？
- 它依赖哪些输入性质（有序、非负、单调、树结构、固定窗口等）？
- 如果这些性质被 follow-up 改掉，哪一层会首先失效？

### 12.4 针对本题的正确性证明

- **状态语义：** 每对相邻词只贡献第一处差异；后续字符不能再提供排序信息。
- **安全选择：** indegree=0 的节点当前没有未满足前驱，因此现在输出它不会违反任何依赖。
- **保持：** 删除该节点的出边只会让后继的剩余依赖数减少；新变成 0 的节点恰好成为下一批合法选择。
- **环判定：** 若最终输出节点数少于总节点数，则剩余子图没有 indegree=0 节点，沿前驱不断回溯必重复某节点，因此存在环。

> **面试表达建议：** 不要说“代码跑样例是对的”。先说状态语义，再说一次更新为什么保持语义，最后说明终止时为何覆盖所有合法答案。

### 12.5 复杂度：除了 Big-O 还要说明参数和模型

源书稿结论：**建图 O(总字符数)，拓扑 O(V+E)，空间 O(V+E)。**

进一步需要注意：

- 字符串 key 的比较、切片、构造 signature 往往还有长度 L 的成本，不应只写“哈希 O(1)”。
- 题目存在业务/输入模型参数，最好给出符号定义（如 K、F、L、m、W），避免用一个 n 模糊所有规模。

专业回答建议写成：

```text
n = 主输入规模
k / L / V / E / W = 题目中真正影响结构规模的辅助参数
Time = ...（说明 worst / average / amortized）
Aux Space = ...（不含/包含输出，明确递归栈）
Preprocess = ...（若存在排序、压缩、建索引）
```

### 12.7 代码审查：从 AC 代码提升到面试级实现

- 重复边不能重复增加 indegree
- 若要字典序最小顺序，将普通队列改成 min-heap
- 唯一性可通过每一步可选零入度节点数量判断

此外，对本题代码建议做四次快速 review：

1. **State review**：每个变量能否用一句不变量解释？
2. **Boundary review**：所有 `+1/-1`、开闭区间、空结构分支是否统一？
3. **Mutation review**：修改容器/指针后，另一个索引或引用是否需要同步更新？
4. **Complexity review**：有没有隐藏的切片、排序、线性删除、重复 DFS 让宣称复杂度失真？

### 12.8 对抗性测试矩阵

| 测试维度 | 本题应覆盖的情况 | 目的 |
|---|---|---|
| 最小/空边界 | 单链依赖 | 验证不变量与边界处理，不只验证最终值 |
| 重复/相等状态 | 多个合法顺序 | 验证不变量与边界处理，不只验证最终值 |
| 结构极端 | 有向环、非法前缀/重复边 | 验证不变量与边界处理，不只验证最终值 |
| 约束破坏/反例 | prefix invalid case 是高频失分点。 | 验证不变量与边界处理，不只验证最终值 |

源书稿中的高频失分点也应逐个转成单元测试：

- **反例化：** prefix invalid case 是高频失分点。
- **反例化：** 重复边不能重复增加 indegree。
- **反例化：** 若存在多种合法顺序，任意一种通常可接受。

### 12.9 Follow-up 深挖：不是换题，而是定位“哪个前提变了”

#### 12.9.1 如何返回字典序最小合法顺序？

- **变化的前提：** 从“任意合法解”增加确定性的最小序约束。
- **推荐方向：** 在所有当前合法候选中用 min-heap 选择最小者；证明只改变 tie-breaking，不破坏原合法性。
#### 12.9.2 如何判断顺序是否唯一？

- **变化的前提：** 不只要求存在一个合法解，还要判断是否存在第二种选择。
- **推荐方向：** 在构造过程中记录每一步可选候选数；一旦某步有多个独立合法选择，通常意味着结果不唯一（需结合题目结构证明）。
#### 12.9.3 输入存在噪声时如何找最少需删除的约束？

- **变化的前提：** 这个追问改变了 `建图 + Topological Sort` 方案依赖的某个约束；先指出哪个不变量失效，再决定是否替换数据结构。
- **推荐方向：** 保留原问题中仍成立的部分，只新增满足新约束的最小状态；最后重新分析时间、空间和边界。

### 12.10 Pattern 迁移：什么时候应该想到它

**识别信号：**

- “先做 A 再做 B”的依赖关系
- 需要检测有向图环
- 要求输出一个满足所有偏序约束的顺序

**迁移方法：**

- 先保留本题的不变量形式，再替换数据载体。例如数组窗口换成字符流，核心仍是“进入/离开时可增量更新的统计”。
- 如果从静态变动态，问“原预处理为什么失效”，再引入可更新结构；不要直接跳到更复杂数据结构。
- 如果从单答案变所有答案，先把输出规模写进复杂度，再讨论去重、predecessor 或路径恢复。
- 如果从算法题变系统级 follow-up，明确算法层与工程层边界：算法不变量仍要成立，工程层再叠加并发、分片、缓存与容错。

### 12.11 面试官视角：这题真正区分候选人的地方

| 能力层级 | 典型表现 |
|---|---|
| 只会做 | 能写出代码，但无法解释为什么该结构成立 |
| 合格 | 能从 baseline 推出 `建图 + Topological Sort`，复杂度与边界基本正确 |
| 较强 | 能写出不变量/证明，并比较至少一种替代方案 |
| 很强 | follow-up 改约束后，能明确指出**失效的前提**并局部替换结构，而不是重新猜算法 |

建议复盘时把目标定为最后两档，而不是“AC 即完成”。
