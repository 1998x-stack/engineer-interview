# 使用说明：这不是“背答案”的题库

本仓库采用《剑指 Offer》式的**问题驱动**组织方式，但目标岗位是 Quantitative Research、Financial ML、Algorithm Developer、Systematic Research 与 Derivatives Quant。它不是金融术语百科，也不是“100 个标准答案”的背诵材料；真正训练的是一套可迁移的研究方法：

> **formalize → derive → interpret → falsify → implement → communicate**

## 1. 这套题库希望训练什么

面对一个陌生量化问题，理想的思考顺序是：

1. **定义对象**：随机变量、状态、时间轴、信息集、目标函数分别是什么？
2. **列出假设**：IID、stationary、Gaussian、no-arbitrage、PIT availability 等是否成立？
3. **给出 baseline**：先用最简单、可解释、可验证的方法建立基线。
4. **从第一原则推导**：不要只报公式，要知道公式为什么成立。
5. **寻找反例/边界**：哪一个假设被破坏时，结论会最先失效？
6. **设计验证**：OOS、walk-forward、block bootstrap、simulation、replay、parity test 应该用哪一种？
7. **表达结论**：30 秒能说核心，3 分钟能说推导、风险和扩展。

高级 Quant 面试真正区分候选人的，通常不是掌握了多少模型名称，而是：**能不能对一个看起来很好的结果保持怀疑，并构造证据链证明它可信。**

## 2. “真题”口径

来源标注严格区分：

- **官方公开题型**：公司官方 guide / mock interview / 官方学习材料明确公开的题或题型；
- **高可信重构题型**：依据官方公开面试范围、岗位能力要求与量化研究核心知识结构构造；
- 不把论坛传闻、匿名题库或无法核验的归因写成“某公司真题”。

能力范围依据见 [官方题型与岗位能力依据](../references/official-sources.md)。

## 3. 每题应该怎么学

V2 每题有 14 个部分。建议不要一次从头读到尾，而分三遍：

### 第一遍：独立作答

只看题目，限制 5–15 分钟。记录：

- 你首先定义了什么；
- 卡在哪里；
- 是否主动问了题目假设。

### 第二遍：理解模型

重点看：

- `Formalization`
- `标准推导`
- `Why`
- `边界条件、失效场景与模型风险`

目标是能够**不用原文措辞重新推导**。

### 第三遍：模拟面试

只看：

- `30 秒版本`
- `追问树`
- `3 分钟专业回答模板`

目标是让答案从“笔记语言”变成“现场交流语言”。

## 4. 两档回答标准

### 30 秒

**定义 → 结论/算法 → 最关键假设 → 一个坑。**

30 秒版不追求完整，而追求让面试官立即确认你抓住了问题结构。

### 3 分钟

**Formalization → 主推导 → Why → 边界 → 验证/工程化 → 自然追问。**

如果 3 分钟仍然只是在复述定义，通常说明掌握还停留在 Level 1。

## 5. 数学题和研究题的差别

数学题的主要错误通常是：样本空间、条件、定理前提、代数或算法不对。

研究题的主要错误更隐蔽：

- timestamp 语义错；
- PIT 数据被修订；
- train/test 存在实体或窗口重叠；
- multiple testing 没被记录；
- fill/cost model 过度乐观；
- offline/prod feature 不一致；
- 一个经验关系被误写成稳定机制。

因此本仓库会反复出现 OOS、PIT、replay、parity、simulation、model risk 等词。这是刻意设计，不是重复。

## 6. 掌握标准

一题真正掌握，至少应满足：

- [ ] 能独立得到基础结论；
- [ ] 能写出关键式子/数据结构；
- [ ] 能解释 Why，而不是只背公式；
- [ ] 能给出一个反例或失效条件；
- [ ] 能回答原题全部追问；
- [ ] 能把问题迁移到一个真实 Quant 场景；
- [ ] 能提出一个最小验证实验。

达到这七项后，题目才从“知识点”变成“能力”。
