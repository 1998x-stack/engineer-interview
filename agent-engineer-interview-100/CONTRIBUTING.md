# Contributing

这个仓库的目标不是无限增加题量，而是持续提高 **工程真实性、可解释性和面试训练价值**。

## 内容修改原则

1. **Know-Why 优先**：先解释为什么这个问题会在 Production Agent 中发生。
2. **Know-How 可落地**：答案必须落到状态、控制点、协议、指标、恢复或验证机制。
3. **不要只加框架名**：除非框架机制本身是题目重点。
4. **区分来源**：PDF 原始内容修订与仓库新增扩展要明确区分。
5. **尽量给 failure mode**：一个好答案至少说明“什么会坏”。
6. **保持一题一文件**：现有 Q001–Q100 题号是稳定 ID，不因排序变化重编号。

## 提交前检查

```bash
python scripts/validate_repo.py
python scripts/build_index.py --check
```

## 新题建议

100 题是当前 PDF 基线。如果要增加新题，优先作为 Issue 讨论，再决定是否进入 `extras/` 或下一版题库，避免破坏 Q001–Q100 的稳定链接。
