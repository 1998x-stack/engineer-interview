编辑距离 / Edit Distance

定位：Medium · 优先级 S · 高频经典母题（H） · 2D Alignment DP 章节：动态规划、贪心与区间 冻结版：内容源自 docs/assets/algorithm-interview-100-2026.pdf，本页在其基础上扩写。

1. 题目概括

插入、删除、替换一个字符代价 1，把 word1 变 word2 的最少操作数。

本仓库不复制 LeetCode 完整题面；正式练习时请从原题链接确认输入输出细节。

2. 面试官在考什么

这题表面考 2D Alignment DP，更深层通常考三件事：

  1. 能否从基线解法中识别重复工作；
  2. 能否把关键约束写成稳定的不变量；
  3. 能否在写完代码后解释复杂度、边界与约束变化。

PDF 核心突破： dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。

3. 先做约束澄清

面试开始先确认：输入规模、是否保证存在答案、是否允许修改输入、是否包含重复值/负数，以及返回值对顺序是否有要求。不同约束可能改变最优方案或实现边界。

建议现场至少问/确认 2-3 个与本题最相关的条件，而不是直接开始编码。

4. 暴力基线与瓶颈

暴力递归重复求解相同子问题。DP 的第一步不是写数组，而是定义“未来决策最少需要记住什么”。

基线方案的作用不是“凑一个答案”，而是暴露优化方向：到底重复枚举了候选、重复查询了历史、还是重复计算了子问题。

5. 关键观察与不变量

问题特定观察： dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。

家族级不变量： state 定义、transition、base case、计算顺序四件事必须自洽；压缩空间前先证明只依赖哪些旧状态。

在真正写代码前，应该能把不变量压缩成一句话；如果一句话说不清，通常说明边界语义还没有定稳。

6. 最优解法推导

PDF 给出的最优路径： 字符同取 dp[i-1][j-1]；不同 1+min(dp[i-1][j],dp[i][j-1],dp[i-1][j-1])。

可以按下面顺序推导，而不是直接背模板：

  1. 写出基线中被重复处理的对象；
  2. 找到能复用的历史状态或单调结构；
  3. 明确更新顺序与循环边界；
  4. 证明每次丢弃/合并/移动都不会漏掉可能答案；
  5. 最后才落到代码。

7. 正确性说明

按计算顺序归纳：所有依赖状态已正确，因此当前状态由最优子结构/计数转移得到正确值。

针对本题，证明时应把“dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。”对应到代码中的具体状态更新。面试中不必写形式化证明，但要能解释为什么优化后没有漏解、重复计数或错误淘汰候选。

8. 复杂度

冻结版结论： O(mn) / O(mn)，可压一维

面试中不要只报 Big-O：还要说清复杂度来自哪里。例如线性算法要解释每个元素被推进/入栈/出栈/访问的次数；堆算法要解释为什么是 log k 而不是 log n。

9. Python 参考实现

from __future__ import annotations
class Solution:
    def minDistance(self, word1: str, word2: str) -> int:
        prev=list(range(len(word2)+1))
        for i,a in enumerate(word1,1):
            cur=[i]+[0]*len(word2)
            for j,b in enumerate(word2,1):
                if a==b: cur[j]=prev[j-1]
                else: cur[j]=1+min(prev[j],cur[j-1],prev[j-1])
            prev=cur
        return prev[-1]

独立源码：solutions/python/092-edit-distance.py

代码以面试可读性为优先；LeetCode 中的 ListNode / TreeNode / Node / rand7 等由题目环境提供。

10. Dry-run：怎样检查代码

画 dp 表/数组，先填写 base，再按计算顺序填 3-5 个状态，明确每个格子的来源。

建议把每一步的关键状态写在纸上，不只看最终输出。

11. 边界与测试清单

  • 空输入
  • 单元素
  • 目标为 0
  • 不可达状态/负值

再增加一个“最容易触发本题高频 bug”的定向样例。

12. 高频失误

初始化 dp[i][0]=i,dp[0][j]=j；混淆操作方向。

此外还要检查：

  • 是否偷偷依赖题目没有承诺的条件；
  • 查询和更新顺序是否改变了允许使用的数据范围；
  • 返回值、下标和区间端点是否与题意一致；
  • 是否为了省几行代码牺牲了可解释性。

13. 面试追问

PDF 追问： 不同操作不同权重；如何回溯具体编辑脚本？

进一步建议主动训练：

  • 如果内存限制为当前的 1/100，方案怎么改？
  • 如果数据不断到来，需要在线回答，哪些状态保留？
  • 如果输入分散在多台机器，局部结果能否合并成全局结果？
  • 如果只需要近似答案，能否换取更低延迟/内存？

14. 算法岗工程化升级

把输入规模放大 1000 倍，讨论当前方案首先受 CPU、内存还是 I/O 限制；再考虑输入改为在线数据流或分片数据后，哪些状态能够增量维护。

这一步是算法岗区别于纯刷题的重要训练：从“单机、静态、小数据”的 LeetCode 假设继续推到在线、流式、分布式或 ML 系统约束。

15. 30 秒口述模板

“我先给出基线方案，再利用 2D Alignment DP 去掉重复工作。核心不变量是：dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。。代码完成后我会用普通样例和极端边界 dry-run，并说明复杂度与追问变体。”

16. 迁移训练

  • 同模式变体：保持 2D Alignment DP 不变，改变“求数量 / 求最长 / 求最短 / 返回路径”等目标。
  • 约束变体：加入重复值、负数、动态更新、内存限制或流式输入。
  • 实现变体：用另一种数据结构重做，并比较复杂度与代码风险。
  • 表达训练：不看代码，只用 90 秒讲清“基线 -> 瓶颈 -> 不变量 -> 最优解”。

17. 解法谱系：从“能做”到“面试最优”

这一节的目标是避免“只背一个答案”。真正的算法面试通常会沿着 baseline → 瓶颈 → 优化 → trade-off 继续追问。

层级 方案 复杂度/代价 面试价值
暴力递归 每次字符不同分三支：删/插/替 指数级 直接暴露重复子问题
Memo DFS 缓存 (i,j) O(mn)/O(mn) 最容易从递归推导
二维 DP dp[i][j]=word1[:i]→word2[:j] 最少操作 O(mn)/O(mn) 便于回溯编辑脚本
一维滚动 只保存上一行 O(mn)/O(n) 只求距离时空间最优

怎样在白板上自然推到推荐解

  1. 先承认基线是正确的：不要一上来赌最优模板；先建立 correctness anchor。
  2. 指出真正浪费：本题最值得消掉的重复工作可以概括为：dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。
  3. 选择结构而不是背 API：说明 2D Alignment DP 为什么正好承载需要保留的信息。
  4. 先说 invariant，再写循环：循环条件、更新顺序和边界全部应该从 invariant 推出来。
  5. 最后比较替代方案：什么时候愿意多用空间换更低延迟？什么时候输入已排序/流式/内存受限会换算法？

18. 状态设计与不变量审计

状态 精确定义 必须保持的性质
state 子问题的精确定义 一句话必须包含索引和答案语义
transition 从已知状态到当前状态 覆盖且不重复所有决策
base case 最小子问题 决定边界行/列
order 依赖必须先计算 空间压缩尤其依赖更新顺序

本题的一句话不变量

dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。

这句话必须能对应到代码中的某个具体变量、容器或返回值。若只能说“这里用一个 Hash/DP/Heap”，但说不出其中存的精确语义，通常还没有真正掌握。

写代码前的三问

  • 状态何时有效？ 当前元素加入之前还是之后？
  • 状态是否包含当前元素？ 这会直接决定 query-before-update 还是 update-before-query。
  • 丢弃的信息为何永远不再需要？ 若无法回答，空间优化或指针移动可能是不安全的。

19. 正确性证明：面试版 + 严谨版

19.1 面试版证明骨架

  1. 初始化成立：循环/递归开始前，状态满足定义。
  2. 保持性成立：假设处理前缀/子树前 invariant 成立，本轮按照 2D Alignment DP 更新后仍成立。
  3. 不漏解：被跳过、弹出、剪枝、覆盖或淘汰的候选，都可以证明不可能产生更优合法答案。
  4. 终止得到答案：扫描结束/递归返回时，所有需要考虑的候选已经被覆盖。

19.2 本题证明抓手

  • 关键事实：dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。
  • 转移/操作：字符同取 dp[i-1][j-1]；不同 1+min(dp[i-1][j],dp[i][j-1],dp[i-1][j-1])。
  • 最容易被质疑的点：初始化 dp[i][0]=i,dp[0][j]=j；混淆操作方向。

面试时不需要写形式化定理，但至少要能给出一个反事实解释：如果不按当前更新顺序/移动规则做，会在哪个最小反例上出错。

20. 复杂度深拆：不要只背 Big-O

目标结论： O(mn) / O(mn)，可压一维

时间 = 可达状态数 × 每个状态转移数；空间压缩只有在当前层不再依赖更老状态时合法，更新方向本身也是正确性的一部分。

复杂度回答建议

  • 时间：说明循环/递归总共访问多少状态，每个状态执行哪些 O(1)/O(log n) 操作。
  • 空间：区分“输出空间”“输入原地修改”“显式辅助结构”“递归调用栈”。
  • 最坏 vs 平均/期望：Hash、QuickSelect、随机采样等题不要把平均/期望复杂度说成确定最坏上界。
  • 隐藏主项：如果方案需要排序、建图、预处理，必须把它计入总复杂度。

21. 测试工程：从样例测试升级为 bug 定向测试

基础测试矩阵

  • [ ] 空输入
  • [ ] 单元素/单字符
  • [ ] base row/column
  • [ ] 不可达状态
  • [ ] 答案需要负无穷/正无穷初始化
  • [ ] 空间压缩后的更新顺序

本题 bug 定向测试

高频失误是：初始化 dp[i][0]=i,dp[0][j]=j；混淆操作方向。

因此至少手工设计一个样例，让错误实现稳定触发这个问题。测试目标不是“多测几个数”，而是让每个 case 对应一个风险：初始化、边界、重复、更新顺序、数据结构不变量、返回语义。

推荐测试层次

  1. Minimal：最小合法输入；
  2. Boundary：答案卡在边界；
  3. Adversarial：专门攻击高频错误；
  4. Structure：构造最坏形态，如退化树、单调数组、长链、全重复；
  5. Random differential test：小规模随机输入，与暴力基线对拍。

对拍尤其适合 Hard：先写一个慢但显然正确的 reference，再随机生成小输入比较数千次，往往能快速找出边界 bug。

22. 代码 Review Checklist

提交代码前逐项检查：

  • [ ] 函数/变量名能直接表达状态语义，而不是 a/b/tmp1/tmp2。
  • [ ] 初始化值来自 state 定义，而不是“记得模板这么写”。
  • [ ] 查询与更新顺序符合“当前元素能否参与当前答案”的语义。
  • [ ] 每个 while 都能解释终止性；每个 continue/break 都有正确性依据。
  • [ ] 没有把平均 O(1) Hash、期望 O(1) sampling 等误报为绝对最坏复杂度。
  • [ ] 没有漏算排序、建图、递归栈、输出容器等成本。
  • [ ] 至少 dry-run 一个普通样例和一个 adversarial 样例。

Medium / S 级要求： Medium 是算法岗 live coding 主战场：通常要求在 15–25 分钟内完成“推导 + 代码 + dry-run”。

23. Follow-up Tree：面试官可以怎样继续加压

Level 1：证明与边界

  • 为什么当前 invariant 足以保证不漏解？
  • 把更新顺序交换一下会发生什么？给一个最小反例。
  • 输入为空、重复很多、极端长度时，代码哪一行最容易出错？

Level 2：替代算法

  • 不允许使用当前主要辅助结构时，退化到什么方案？复杂度如何变化？
  • 如果输入额外满足“有序 / 值域小 / 全正 / 静态 / 可修改”等条件，能否换更简单或更快的方案？
  • 如果除了答案值还要求恢复具体路径/下标/操作序列，需要额外保存什么？

Level 3：本题经典追问

不同操作不同权重；如何回溯具体编辑脚本？

Level 4：算法工程约束

  • 数据量扩大 1000 倍，CPU、内存、I/O 哪一个先成为瓶颈？
  • 输入变为无限流后，哪些状态还能增量维护？
  • 数据分片到多机后，局部结果是否具有可合并性？若不能，需要交换什么中间状态？

24. 算法工程化：从 LeetCode 假设走向真实系统

  • 状态空间过大时，先找稀疏状态、滚动数组、bitset、剪枝或状态压缩。
  • GPU/并行 DP 的关键是依赖方向；存在强串行依赖时并行收益有限。
  • 很多序列 DP 在工业中会用带宽限制、近似匹配或分块来控制 O(mn) 成本。

一个通用的系统化分析框架

维度 LeetCode 默认 工业追问
数据规模 单机内存可放 超内存、分片、冷热分层
到达方式 静态数组/字符串 流式、乱序、动态更新
正确性 精确答案 是否允许近似、误差界多大
延迟 单次运行 P50/P95/P99、持续 QPS
状态 进程内临时变量 checkpoint、恢复、TTL、并发一致性
输出 一个答案 Top-K、路径、解释、可审计中间状态

25. 同类题迁移导航

掌握本题后，不要立即跳到完全无关题型。优先练同章节不同约束，确认你掌握的是模式而不是题目答案：

  • 091. LC1143 最长公共子序列 / Longest Common Subsequence — 2D Sequence DP
  • 093. LC139 单词拆分 / Word Break — Prefix DP
  • 090. LC300 最长递增子序列 / Longest Increasing Subsequence — DP + Patience Binary Search
  • 094. LC416 分割等和子集 / Partition Equal Subset Sum — 0/1 Knapsack

迁移时强制改变一个条件

  • 把“是否存在”改成“计数 / 最短 / 最长”；
  • 把离线输入改成 online stream；
  • 把精确解改成允许近似；
  • 把单机改成分片后合并；
  • 把只返回数值改成恢复路径/方案。

26. 面试评分 Rubric

表现层级 你需要做到什么
2/5 - 能写出正确基线 能复述题意并给出可运行但非最优方案；复杂度分析基本正确。
3/5 - 能识别模式 能主动指出重复工作，选择合适数据结构/算法范式，并在少量提示下写出最优解。
4/5 - 面试可过 无提示定义不变量、写出边界正确的代码、完成 dry-run，并能解释正确性和复杂度来源。

对于 S 级题，目标至少达到 4/5；因为 S 级的意义不是题更难，而是该 pattern 的覆盖率、迁移价值和追问空间更高。

27. 复习卡片 / Active Recall

Q1. 看到怎样的信号应该想到 2D Alignment DP？ A. 当题目出现与“dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。”相同的结构时，优先尝试该模式；先写清状态和不变量，再写模板。

Q2. 这题最关键的一句话 invariant 是什么？ A. dp[i][j] 表示前缀转换成本；末字符不同时比较删除、插入、替换三个前驱状态。

Q3. 推荐解的复杂度为什么是 O(mn) / O(mn)，可压一维？ A. 不只记结论；按第 20 节把“状态数、每状态操作、辅助结构、递归栈/排序成本”完整说一遍。

Q4. 最容易写错的地方？ A. 初始化 dp[i][0]=i,dp[0][j]=j；混淆操作方向。

Q5. 面试官把规模放大 1000 倍时，第一反应是什么？ A. 先识别当前方案的主要状态与随机访问结构，再判断 CPU、内存还是 I/O 先爆；随后讨论 streaming / sharding / approximation。
