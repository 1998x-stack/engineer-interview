重排链表 / Reorder List

定位：Medium · 优先级 A · 高频经典母题（H） · Middle + Reverse + Merge 章节：链表与缓存设计 冻结版：内容源自 docs/assets/algorithm-interview-100-2026.pdf，本页在其基础上扩写。

1. 题目概括

将链表重排为 L0,Ln,L1,Ln-1...

本仓库不复制 LeetCode 完整题面；正式练习时请从原题链接确认输入输出细节。

2. 面试官在考什么

这题表面考 Middle + Reverse + Merge，更深层通常考三件事：

  1. 能否从基线解法中识别重复工作；
  2. 能否把关键约束写成稳定的不变量；
  3. 能否在写完代码后解释复杂度、边界与约束变化。

PDF 核心突破： 分解成三道母题：找中点、反转后半段、交替合并。

3. 先做约束澄清

面试开始先确认：输入规模、是否保证存在答案、是否允许修改输入、是否包含重复值/负数，以及返回值对顺序是否有要求。不同约束可能改变最优方案或实现边界。

建议现场至少问/确认 2-3 个与本题最相关的条件，而不是直接开始编码。

4. 暴力基线与瓶颈

枚举所有配对/区间通常重复读取历史信息。先写 O(n²) 基线，再问历史状态能否压缩成 O(1) 平均查询。

基线方案的作用不是“凑一个答案”，而是暴露优化方向：到底重复枚举了候选、重复查询了历史、还是重复计算了子问题。

5. 关键观察与不变量

问题特定观察： 分解成三道母题：找中点、反转后半段、交替合并。

家族级不变量： 哈希表中只保存“已经扫描完、且未来仍有用”的状态；查询和写入顺序必须与是否允许使用当前元素一致。

在真正写代码前，应该能把不变量压缩成一句话；如果一句话说不清，通常说明边界语义还没有定稳。

6. 最优解法推导

PDF 给出的最优路径： Floyd 找中点；断开；reverse second；交错 merge。

可以按下面顺序推导，而不是直接背模板：

  1. 写出基线中被重复处理的对象；
  2. 找到能复用的历史状态或单调结构；
  3. 明确更新顺序与循环边界；
  4. 证明每次丢弃/合并/移动都不会漏掉可能答案；
  5. 最后才落到代码。

7. 正确性说明

证明重点是：任何合法答案在扫描到其右端点时，左端所需信息已经存在于哈希表中，因此不会漏解。

针对本题，证明时应把“分解成三道母题：找中点、反转后半段、交替合并。”对应到代码中的具体状态更新。面试中不必写形式化证明，但要能解释为什么优化后没有漏解、重复计数或错误淘汰候选。

8. 复杂度

冻结版结论： O(n) / O(1)

面试中不要只报 Big-O：还要说清复杂度来自哪里。例如线性算法要解释每个元素被推进/入栈/出栈/访问的次数；堆算法要解释为什么是 log k 而不是 log n。

9. Python 参考实现

from __future__ import annotations
class Solution:
    def reorderList(self, head: 'ListNode | None') -> None:
        if not head or not head.next: return
        slow = fast = head
        while fast.next and fast.next.next:
            slow = slow.next; fast = fast.next.next
        second = slow.next; slow.next = None
        prev = None
        while second:
            nxt = second.next; second.next = prev; prev, second = second, nxt
        first, second = head, prev
        while second:
            n1, n2 = first.next, second.next
            first.next = second; second.next = n1
            first, second = n1, n2

独立源码：solutions/python/027-reorder-list.py

代码以面试可读性为优先；LeetCode 中的 ListNode / TreeNode / Node / rand7 等由题目环境提供。

10. Dry-run：怎样检查代码

选择一个存在答案的普通样例，再选择“重复值/目标等于 2*x/不存在答案”的样例，逐步记录哈希状态。

建议把每一步的关键状态写在纸上，不只看最终输出。

11. 边界与测试清单

  • 空输入或最小规模
  • 大量重复值
  • 答案不存在/唯一性假设
  • 负数与零

再增加一个“最容易触发本题高频 bug”的定向样例。

12. 高频失误

奇偶长度断点；忘记断开造成环。

此外还要检查：

  • 是否偷偷依赖题目没有承诺的条件；
  • 查询和更新顺序是否改变了允许使用的数据范围；
  • 返回值、下标和区间端点是否与题意一致；
  • 是否为了省几行代码牺牲了可解释性。

13. 面试追问

PDF 追问： 如何不修改节点值；能否递归？

进一步建议主动训练：

  • 如果内存限制为当前的 1/100，方案怎么改？
  • 如果数据不断到来，需要在线回答，哪些状态保留？
  • 如果输入分散在多台机器，局部结果能否合并成全局结果？
  • 如果只需要近似答案，能否换取更低延迟/内存？

14. 算法岗工程化升级

把输入规模放大 1000 倍，讨论当前方案首先受 CPU、内存还是 I/O 限制；再考虑输入改为在线数据流或分片数据后，哪些状态能够增量维护。

这一步是算法岗区别于纯刷题的重要训练：从“单机、静态、小数据”的 LeetCode 假设继续推到在线、流式、分布式或 ML 系统约束。

15. 30 秒口述模板

“我先给出基线方案，再利用 Middle + Reverse + Merge 去掉重复工作。核心不变量是：分解成三道母题：找中点、反转后半段、交替合并。。代码完成后我会用普通样例和极端边界 dry-run，并说明复杂度与追问变体。”

16. 迁移训练

  • 同模式变体：保持 Middle + Reverse + Merge 不变，改变“求数量 / 求最长 / 求最短 / 返回路径”等目标。
  • 约束变体：加入重复值、负数、动态更新、内存限制或流式输入。
  • 实现变体：用另一种数据结构重做，并比较复杂度与代码风险。
  • 表达训练：不看代码，只用 90 秒讲清“基线 -> 瓶颈 -> 不变量 -> 最优解”。

17. 解法谱系：从“能做”到“面试最优”

这一节的目标是避免“只背一个答案”。真正的算法面试通常会沿着 baseline → 瓶颈 → 优化 → trade-off 继续追问。

层级 方案 复杂度/代价 面试价值
基线 复制节点值到数组后处理，再重建/回写 O(n) 额外空间 方便验证目标顺序，但没有体现链表优势
中间解 递归或辅助栈保存访问顺序 O(n) 栈/辅助空间 代码短，但面试官常继续追问 O(1) 空间
推荐解 直接重连 next/prev 指针，复杂题拆成定位、局部变换、重新连接。本题落地为：Floyd 找中点；断开；reverse second；交错 merge。 通常 O(n) / O(1) 围绕 Middle + Reverse + Merge 的关键不变量说明为什么安全。

怎样在白板上自然推到推荐解

  1. 先承认基线是正确的：不要一上来赌最优模板；先建立 correctness anchor。
  2. 指出真正浪费：本题最值得消掉的重复工作可以概括为：分解成三道母题：找中点、反转后半段、交替合并。
  3. 选择结构而不是背 API：说明 Middle + Reverse + Merge 为什么正好承载需要保留的信息。
  4. 先说 invariant，再写循环：循环条件、更新顺序和边界全部应该从 invariant 推出来。
  5. 最后比较替代方案：什么时候愿意多用空间换更低延迟？什么时候输入已排序/流式/内存受限会换算法？

18. 状态设计与不变量审计

状态 精确定义 必须保持的性质
prev/current/next 局部三节点关系 先保存 next 再改边
dummy/sentinel 统一头部边界 减少特殊分支
连接点 局部操作前后的外部接口 变换后必须重新接回主链

本题的一句话不变量

分解成三道母题：找中点、反转后半段、交替合并。

这句话必须能对应到代码中的某个具体变量、容器或返回值。若只能说“这里用一个 Hash/DP/Heap”，但说不出其中存的精确语义，通常还没有真正掌握。

写代码前的三问

  • 状态何时有效？ 当前元素加入之前还是之后？
  • 状态是否包含当前元素？ 这会直接决定 query-before-update 还是 update-before-query。
  • 丢弃的信息为何永远不再需要？ 若无法回答，空间优化或指针移动可能是不安全的。

19. 正确性证明：面试版 + 严谨版

19.1 面试版证明骨架

  1. 初始化成立：循环/递归开始前，状态满足定义。
  2. 保持性成立：假设处理前缀/子树前 invariant 成立，本轮按照 Middle + Reverse + Merge 更新后仍成立。
  3. 不漏解：被跳过、弹出、剪枝、覆盖或淘汰的候选，都可以证明不可能产生更优合法答案。
  4. 终止得到答案：扫描结束/递归返回时，所有需要考虑的候选已经被覆盖。

19.2 本题证明抓手

  • 关键事实：分解成三道母题：找中点、反转后半段、交替合并。
  • 转移/操作：Floyd 找中点；断开；reverse second；交错 merge。
  • 最容易被质疑的点：奇偶长度断点；忘记断开造成环。

面试时不需要写形式化定理，但至少要能给出一个反事实解释：如果不按当前更新顺序/移动规则做，会在哪个最小反例上出错。

20. 复杂度深拆：不要只背 Big-O

目标结论： O(n) / O(1)

每个节点被访问/重连常数次，因此时间通常 O(n)；若递归则额外使用 O(n) 最坏调用栈，迭代可降到 O(1) 辅助空间。

复杂度回答建议

  • 时间：说明循环/递归总共访问多少状态，每个状态执行哪些 O(1)/O(log n) 操作。
  • 空间：区分“输出空间”“输入原地修改”“显式辅助结构”“递归调用栈”。
  • 最坏 vs 平均/期望：Hash、QuickSelect、随机采样等题不要把平均/期望复杂度说成确定最坏上界。
  • 隐藏主项：如果方案需要排序、建图、预处理，必须把它计入总复杂度。

21. 测试工程：从样例测试升级为 bug 定向测试

基础测试矩阵

  • [ ] 空链表
  • [ ] 单节点
  • [ ] 两节点
  • [ ] 操作区间含头/尾
  • [ ] 长度不是 k 的整数倍
  • [ ] 环/共享节点不在题目保证内时如何处理

本题 bug 定向测试

高频失误是：奇偶长度断点；忘记断开造成环。

因此至少手工设计一个样例，让错误实现稳定触发这个问题。测试目标不是“多测几个数”，而是让每个 case 对应一个风险：初始化、边界、重复、更新顺序、数据结构不变量、返回语义。

推荐测试层次

  1. Minimal：最小合法输入；
  2. Boundary：答案卡在边界；
  3. Adversarial：专门攻击高频错误；
  4. Structure：构造最坏形态，如退化树、单调数组、长链、全重复；
  5. Random differential test：小规模随机输入，与暴力基线对拍。

对拍尤其适合 Hard：先写一个慢但显然正确的 reference，再随机生成小输入比较数千次，往往能快速找出边界 bug。

22. 代码 Review Checklist

提交代码前逐项检查：

  • [ ] 函数/变量名能直接表达状态语义，而不是 a/b/tmp1/tmp2。
  • [ ] 初始化值来自 state 定义，而不是“记得模板这么写”。
  • [ ] 查询与更新顺序符合“当前元素能否参与当前答案”的语义。
  • [ ] 每个 while 都能解释终止性；每个 continue/break 都有正确性依据。
  • [ ] 没有把平均 O(1) Hash、期望 O(1) sampling 等误报为绝对最坏复杂度。
  • [ ] 没有漏算排序、建图、递归栈、输出容器等成本。
  • [ ] 至少 dry-run 一个普通样例和一个 adversarial 样例。

Medium / A 级要求： Medium 是算法岗 live coding 主战场：通常要求在 15–25 分钟内完成“推导 + 代码 + dry-run”。

23. Follow-up Tree：面试官可以怎样继续加压

Level 1：证明与边界

  • 为什么当前 invariant 足以保证不漏解？
  • 把更新顺序交换一下会发生什么？给一个最小反例。
  • 输入为空、重复很多、极端长度时，代码哪一行最容易出错？

Level 2：替代算法

  • 不允许使用当前主要辅助结构时，退化到什么方案？复杂度如何变化？
  • 如果输入额外满足“有序 / 值域小 / 全正 / 静态 / 可修改”等条件，能否换更简单或更快的方案？
  • 如果除了答案值还要求恢复具体路径/下标/操作序列，需要额外保存什么？

Level 3：本题经典追问

如何不修改节点值；能否递归？

Level 4：算法工程约束

  • 数据量扩大 1000 倍，CPU、内存、I/O 哪一个先成为瓶颈？
  • 输入变为无限流后，哪些状态还能增量维护？
  • 数据分片到多机后，局部结果是否具有可合并性？若不能，需要交换什么中间状态？

24. 算法工程化：从 LeetCode 假设走向真实系统

  • 真实系统里链表常受对象分配和 cache miss 影响，理论 O(1) 不等于低延迟。
  • 并发 LRU/链表需要锁、分段或无锁设计，指针修改的原子性成为新约束。
  • 内存池/侵入式链表可减少 allocator 压力。

一个通用的系统化分析框架

维度 LeetCode 默认 工业追问
数据规模 单机内存可放 超内存、分片、冷热分层
到达方式 静态数组/字符串 流式、乱序、动态更新
正确性 精确答案 是否允许近似、误差界多大
延迟 单次运行 P50/P95/P99、持续 QPS
状态 进程内临时变量 checkpoint、恢复、TTL、并发一致性
输出 一个答案 Top-K、路径、解释、可审计中间状态

掌握本题后，不要立即跳到完全无关题型。优先练同章节不同约束，确认你掌握的是模式而不是题目答案：

迁移时强制改变一个条件

  • 把“是否存在”改成“计数 / 最短 / 最长”；
  • 把离线输入改成 online stream；
  • 把精确解改成允许近似；
  • 把单机改成分片后合并；
  • 把只返回数值改成恢复路径/方案。

26. 面试评分 Rubric

表现层级 你需要做到什么
2/5 - 能写出正确基线 能复述题意并给出可运行但非最优方案；复杂度分析基本正确。
3/5 - 能识别模式 能主动指出重复工作，选择合适数据结构/算法范式，并在少量提示下写出最优解。
4/5 - 面试可过 无提示定义不变量、写出边界正确的代码、完成 dry-run，并能解释正确性和复杂度来源。
5/5 - 强算法岗表现 能比较替代方案、回答约束变化、指出工程 trade-off，并把母题迁移到流式/分布式/ML 系统场景。

对于 S 级题，目标至少达到 4/5；因为 S 级的意义不是题更难，而是该 pattern 的覆盖率、迁移价值和追问空间更高。

27. 复习卡片 / Active Recall

Q1. 看到怎样的信号应该想到 Middle + Reverse + Merge？ A. 当题目出现与“分解成三道母题：找中点、反转后半段、交替合并。”相同的结构时，优先尝试该模式；先写清状态和不变量，再写模板。

Q2. 这题最关键的一句话 invariant 是什么？ A. 分解成三道母题：找中点、反转后半段、交替合并。

Q3. 推荐解的复杂度为什么是 O(n) / O(1)？ A. 不只记结论；按第 20 节把“状态数、每状态操作、辅助结构、递归栈/排序成本”完整说一遍。

Q4. 最容易写错的地方？ A. 奇偶长度断点；忘记断开造成环。

Q5. 面试官把规模放大 1000 倍时，第一反应是什么？ A. 先识别当前方案的主要状态与随机访问结构，再判断 CPU、内存还是 I/O 先爆；随后讨论 streaming / sharding / approximation。
