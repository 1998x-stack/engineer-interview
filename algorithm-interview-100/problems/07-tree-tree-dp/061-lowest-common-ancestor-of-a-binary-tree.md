# 061. LC 236 - 二叉树最近公共祖先 / Lowest Common Ancestor of a Binary Tree

> **定位**：Medium · 优先级 **S** · 高频经典母题（H） · `Recursive Information Merge`
> **章节**：二叉树与 Tree DP
> **冻结版**：内容源自 `docs/assets/algorithm-interview-100-2026.pdf`，本页在其基础上扩写。

## 1. 题目概括

给定 p,q，找最近公共祖先。

> 本仓库不复制 LeetCode 完整题面；正式练习时请从原题链接确认输入输出细节。

## 2. 面试官在考什么

这题表面考 `Recursive Information Merge`，更深层通常考三件事：

1. 能否从基线解法中识别重复工作；
2. 能否把关键约束写成稳定的不变量；
3. 能否在写完代码后解释复杂度、边界与约束变化。

**PDF 核心突破：** dfs 返回“当前子树是否找到了 p/q/祖先”；若左右分别非空，当前节点就是汇合点。

## 3. 先做约束澄清

面试开始先确认：输入规模、是否保证存在答案、是否允许修改输入、是否包含重复值/负数，以及返回值对顺序是否有要求。不同约束可能改变最优方案或实现边界。

建议现场至少问/确认 2-3 个与本题最相关的条件，而不是直接开始编码。

## 4. 暴力基线与瓶颈

枚举所有配对/区间通常重复读取历史信息。先写 O(n²) 基线，再问历史状态能否压缩成 O(1) 平均查询。

基线方案的作用不是“凑一个答案”，而是暴露优化方向：到底重复枚举了候选、重复查询了历史、还是重复计算了子问题。

## 5. 关键观察与不变量

**问题特定观察：** dfs 返回“当前子树是否找到了 p/q/祖先”；若左右分别非空，当前节点就是汇合点。

**家族级不变量：** 哈希表中只保存“已经扫描完、且未来仍有用”的状态；查询和写入顺序必须与是否允许使用当前元素一致。

在真正写代码前，应该能把不变量压缩成一句话；如果一句话说不清，通常说明边界语义还没有定稳。

## 6. 最优解法推导

**PDF 给出的最优路径：** 若 node 为 None/p/q 返回 node；left=dfs,right=dfs；若都非空返回 node，否则返回非空者。

可以按下面顺序推导，而不是直接背模板：

1. 写出基线中被重复处理的对象；
2. 找到能复用的历史状态或单调结构；
3. 明确更新顺序与循环边界；
4. 证明每次丢弃/合并/移动都不会漏掉可能答案；
5. 最后才落到代码。

## 7. 正确性说明

证明重点是：任何合法答案在扫描到其右端点时，左端所需信息已经存在于哈希表中，因此不会漏解。

针对本题，证明时应把“dfs 返回“当前子树是否找到了 p/q/祖先”；若左右分别非空，当前节点就是汇合点。”对应到代码中的具体状态更新。面试中不必写形式化证明，但要能解释为什么优化后没有漏解、重复计数或错误淘汰候选。

## 8. 复杂度

**冻结版结论：** `O(n) / O(h)`

面试中不要只报 Big-O：还要说清复杂度来自哪里。例如线性算法要解释每个元素被推进/入栈/出栈/访问的次数；堆算法要解释为什么是 `log k` 而不是 `log n`。

## 9. Python 参考实现

```python
from __future__ import annotations
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode':
        if not root or root is p or root is q: return root
        left=self.lowestCommonAncestor(root.left,p,q)
        right=self.lowestCommonAncestor(root.right,p,q)
        if left and right: return root
        return left or right
```

## 17. 解法谱系：从“能做”到“面试最优”

> 这一节的目标是避免“只背一个答案”。真正的算法面试通常会沿着 **baseline → 瓶颈 → 优化 → trade-off** 继续追问。

| 层级 | 方案 | 复杂度/代价 | 面试价值 |
|---|---|---|---|
| 基线 | 直接枚举候选或使用额外结构完整记录状态 | 通常 O(n²) 或 O(n) 额外空间 | 先保证正确，再识别“历史查询/状态存储”是否重复 |
| 中间解 | 排序、辅助数组或显式标记，换取更规则的访问模式 | 常见 O(n log n) 或 O(n) 空间 | 适合解释为什么还可以继续优化 |
| 推荐解 | 利用 Hash、值域到下标映射、输入状态复用等方式消除重复工作。本题落地为：若 node 为 None/p/q 返回 node；left=dfs,right=dfs；若都非空返回 node，否则返回非空者。 | 通常 O(n) 时间 | 围绕 `Recursive Information Merge` 的关键不变量说明为什么安全。 |

### 怎样在白板上自然推到推荐解

1. **先承认基线是正确的**：不要一上来赌最优模板；先建立 correctness anchor。
2. **指出真正浪费**：本题最值得消掉的重复工作可以概括为：**dfs 返回“当前子树是否找到了 p/q/祖先”；若左右分别非空，当前节点就是汇合点。**
3. **选择结构而不是背 API**：说明 `Recursive Information Merge` 为什么正好承载需要保留的信息。
4. **先说 invariant，再写循环**：循环条件、更新顺序和边界全部应该从 invariant 推出来。
5. **最后比较替代方案**：什么时候愿意多用空间换更低延迟？什么时候输入已排序/流式/内存受限会换算法？

## 18. 状态设计与不变量审计

| 状态 | 精确定义 | 必须保持的性质 |
|---|---|---|
| 扫描位置 `i` | 已处理前缀边界 | 每轮单调前进 |
| 状态表/原数组 | 历史信息或值域映射 | 只保存未来仍会被查询的信息 |
| 答案 | 已完成前缀的最优/计数结果 | 更新顺序与“能否使用当前元素”一致 |

### 本题的一句话不变量

> **dfs 返回“当前子树是否找到了 p/q/祖先”；若左右分别非空，当前节点就是汇合点。**

这句话必须能对应到代码中的某个具体变量、容器或返回值。若只能说“这里用一个 Hash/DP/Heap”，但说不出其中存的**精确语义**，通常还没有真正掌握。

### 写代码前的三问

- **状态何时有效？** 当前元素加入之前还是之后？
- **状态是否包含当前元素？** 这会直接决定 query-before-update 还是 update-before-query。
- **丢弃的信息为何永远不再需要？** 若无法回答，空间优化或指针移动可能是不安全的。

## 19. 正确性证明：面试版 + 严谨版

### 19.1 面试版证明骨架

1. **初始化成立**：循环/递归开始前，状态满足定义。
2. **保持性成立**：假设处理前缀/子树前 invariant 成立，本轮按照 `Recursive Information Merge` 更新后仍成立。
3. **不漏解**：被跳过、弹出、剪枝、覆盖或淘汰的候选，都可以证明不可能产生更优合法答案。
4. **终止得到答案**：扫描结束/递归返回时，所有需要考虑的候选已经被覆盖。

### 19.2 本题证明抓手

- **关键事实**：dfs 返回“当前子树是否找到了 p/q/祖先”；若左右分别非空，当前节点就是汇合点。
- **转移/操作**：若 node 为 None/p/q 返回 node；left=dfs,right=dfs；若都非空返回 node，否则返回非空者。
- **最容易被质疑的点**：题目是否保证 p,q 存在；BST 版本可利用值域。

面试时不需要写形式化定理，但至少要能给出一个**反事实解释**：如果不按当前更新顺序/移动规则做，会在哪个最小反例上出错。

## 20. 复杂度深拆：不要只背 Big-O

**目标结论：** `O(n) / O(h)`

把总操作数拆成“状态数量 × 每个状态的操作代价”，并单独说明辅助空间。

### 复杂度回答建议

- **时间**：说明循环/递归总共访问多少状态，每个状态执行哪些 O(1)/O(log n) 操作。
- **空间**：区分“输出空间”“输入原地修改”“显式辅助结构”“递归调用栈”。
- **最坏 vs 平均/期望**：Hash、QuickSelect、随机采样等题不要把平均/期望复杂度说成确定最坏上界。
- **隐藏主项**：如果方案需要排序、建图、预处理，必须把它计入总复杂度。
