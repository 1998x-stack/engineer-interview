# 072. LC 994 - 腐烂的橘子 / Rotting Oranges

## 1. 题目概括

腐烂同时向四周传播，求全部腐烂所需最少分钟。

## 5. 关键观察与不变量

**问题特定观察：** 所有初始腐烂点是同一时刻的 BFS 第 0 层，所以要一起入队，而不是逐个 BFS。

**家族级不变量：** BFS 队列保存下一层边界；DFS visited 防重复；拓扑维护入度；并查集维护集合代表。

在真正写代码前，应该能把不变量压缩成一句话；如果一句话说不清，通常说明边界语义还没有定稳。

## 6. 最优解法推导

**PDF 给出的最优路径：** 统计 fresh；所有 rotten 入队；按层扩散并 fresh--；fresh=0 时返回分钟。

可以按下面顺序推导，而不是直接背模板：

1. 写出基线中被重复处理的对象；
2. 找到能复用的历史状态或单调结构；
3. 明确更新顺序与循环边界；
4. 证明每次丢弃/合并/移动都不会漏掉可能答案；
5. 最后才落到代码。

## 7. 正确性说明

图算法正确性依赖访问/松弛/合并规则不会遗漏可达状态，并且每个边/点被有限次处理。

针对本题，证明时应把“所有初始腐烂点是同一时刻的 BFS 第 0 层，所以要一起入队，而不是逐个 BFS。”对应到代码中的具体状态更新。面试中不必写形式化证明，但要能解释为什么优化后没有漏解、重复计数或错误淘汰候选。

## 8. 复杂度

**冻结版结论：** `O(mn) / O(mn)`

面试中不要只报 Big-O：还要说清复杂度来自哪里。例如线性算法要解释每个元素被推进/入栈/出栈/访问的次数；堆算法要解释为什么是 `log k` 而不是 `log n`。

## 9. Python 参考实现

```python
from __future__ import annotations
from collections import deque

class Solution:
    def orangesRotting(self, grid: list[list[int]]) -> int:
        m,n=len(grid),len(grid[0]); q=deque(); fresh=0
        for r in range(m):
            for c in range(n):
                if grid[r][c]==2: q.append((r,c))
                elif grid[r][c]==1: fresh+=1
        minutes=0
        while q and fresh:
            for _ in range(len(q)):
                r,c=q.popleft()
                for dr,dc in ((1,0),(-1,0),(0,1),(0,-1)):
                    nr,nc=r+dr,c+dc
                    if 0<=nr<m and 0<=nc<n and grid[nr][nc]==1:
                        grid[nr][nc]=2; fresh-=1; q.append((nr,nc))
            minutes+=1
        return minutes if fresh==0 else -1
```

## 17. 解法谱系：从“能做”到“面试最优”

> 这一节的目标是避免“只背一个答案”。真正的算法面试通常会沿着 **baseline → 瓶颈 → 优化 → trade-off** 继续追问。

| 层级 | 方案 | 复杂度/代价 | 面试价值 |
|---|---|---|---|
| 基线 | 枚举路径、从每个节点重复搜索或两两判断连接 | 常见 O(V·(V+E)) 或更高 | 先识别问题类型 |
| 中间解 | 一次 DFS/BFS + visited 解决可达/连通 | O(V+E) | 最短无权路用 BFS，不能随意换 DFS |
| 推荐解 | 按问题选择多源 BFS、拓扑、并查集、带权图搜索等。本题落地为：统计 fresh；所有 rotten 入队；按层扩散并 fresh--；fresh=0 时返回分钟。 | 通常 O(V+E) 或近线性 | 围绕 `Multi-source BFS` 的关键不变量说明为什么安全。 |

### 怎样在白板上自然推到推荐解

1. **先承认基线是正确的**：不要一上来赌最优模板；先建立 correctness anchor。
2. **指出真正浪费**：本题最值得消掉的重复工作可以概括为：**所有初始腐烂点是同一时刻的 BFS 第 0 层，所以要一起入队，而不是逐个 BFS。**
3. **选择结构而不是背 API**：说明 `Multi-source BFS` 为什么正好承载需要保留的信息。
4. **先说 invariant，再写循环**：循环条件、更新顺序和边界全部应该从 invariant 推出来。
5. **最后比较替代方案**：什么时候愿意多用空间换更低延迟？什么时候输入已排序/流式/内存受限会换算法？

## 18. 状态设计与不变量审计

| 状态 | 精确定义 | 必须保持的性质 |
|---|---|---|
| visited/state | 节点是否已处理/当前颜色 | 防重复或检测环 |
| frontier | 当前 DFS 栈/BFS 队列/拓扑零入度点 | 定义下一步可扩展集合 |
| graph representation | 邻接表/边集/并查集 | 与稀疏度和操作类型匹配 |

### 本题的一句话不变量

> **所有初始腐烂点是同一时刻的 BFS 第 0 层，所以要一起入队，而不是逐个 BFS。**

这句话必须能对应到代码中的某个具体变量、容器或返回值。若只能说“这里用一个 Hash/DP/Heap”，但说不出其中存的**精确语义**，通常还没有真正掌握。

### 写代码前的三问

- **状态何时有效？** 当前元素加入之前还是之后？
- **状态是否包含当前元素？** 这会直接决定 query-before-update 还是 update-before-query。
- **丢弃的信息为何永远不再需要？** 若无法回答，空间优化或指针移动可能是不安全的。

## 19. 正确性证明：面试版 + 严谨版

### 19.1 面试版证明骨架

1. **初始化成立**：循环/递归开始前，状态满足定义。
2. **保持性成立**：假设处理前缀/子树前 invariant 成立，本轮按照 `Multi-source BFS` 更新后仍成立。
3. **不漏解**：被跳过、弹出、剪枝、覆盖或淘汰的候选，都可以证明不可能产生更优合法答案。
4. **终止得到答案**：扫描结束/递归返回时，所有需要考虑的候选已经被覆盖。

### 19.2 本题证明抓手

- **关键事实**：所有初始腐烂点是同一时刻的 BFS 第 0 层，所以要一起入队，而不是逐个 BFS。
- **转移/操作**：统计 fresh；所有 rotten 入队；按层扩散并 fresh--；fresh=0 时返回分钟。
- **最容易被质疑的点**：分钟数 off-by-one；没有新鲜橘子应返回0。

## 20. 复杂度深拆：不要只背 Big-O

**目标结论：** `O(mn) / O(mn)`

邻接表下遍历复杂度通常 O(V+E)，前提是 visited 让每个节点/边只处理有限次；并查集带路径压缩和按秩合并为近似 O(α(n))。

### 复杂度回答建议

- **时间**：说明循环/递归总共访问多少状态，每个状态执行哪些 O(1)/O(log n) 操作。
- **空间**：区分“输出空间”“输入原地修改”“显式辅助结构”“递归调用栈”。
- **最坏 vs 平均/期望**：Hash、QuickSelect、随机采样等题不要把平均/期望复杂度说成确定最坏上界。
- **隐藏主项**：如果方案需要排序、建图、预处理，必须把它计入总复杂度。
