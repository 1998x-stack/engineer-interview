## 1. 题目概括

给出 a/b=k 的关系，回答若干 x/y。

> 本仓库不复制 LeetCode 完整题面；正式练习时请从原题链接确认输入输出细节。

## 2. 面试官在考什么

这题表面考 `Weighted Graph`，更深层通常考三件事：

1. 能否从基线解法中识别重复工作；
2. 能否把关键约束写成稳定的不变量；
3. 能否在写完代码后解释复杂度、边界与约束变化。

**PDF 核心突破：** 把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。

## 3. 先做约束澄清

面试开始先确认：输入规模、是否保证存在答案、是否允许修改输入、是否包含重复值/负数，以及返回值对顺序是否有要求。不同约束可能改变最优方案或实现边界。

建议现场至少问/确认 2-3 个与本题最相关的条件，而不是直接开始编码。

## 4. 暴力基线与瓶颈

直接按权重展开数组或简单取模常引入空间浪费/分布偏差。需要把均匀随机源映射到目标分布。

基线方案的作用不是“凑一个答案”，而是暴露优化方向：到底重复枚举了候选、重复查询了历史、还是重复计算了子问题。

## 5. 关键观察与不变量

**问题特定观察：** 把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。

**家族级不变量：** 必须明确样本空间大小、每个目标事件对应的等概率原子数，以及被拒绝区域。

在真正写代码前，应该能把不变量压缩成一句话；如果一句话说不清，通常说明边界语义还没有定稳。

## 6. 最优解法推导

**PDF 给出的最优路径：** 建邻接表；每个 query DFS/BFS，沿边乘 product；不可达返回 -1。

可以按下面顺序推导，而不是直接背模板：

1. 写出基线中被重复处理的对象；
2. 找到能复用的历史状态或单调结构；
3. 明确更新顺序与循环边界；
4. 证明每次丢弃/合并/移动都不会漏掉可能答案；
5. 最后才落到代码。

## 7. 正确性说明

正确性不是“看起来随机”，而是证明每个输出拥有相同/指定概率。

针对本题，证明时应把“把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。”对应到代码中的具体状态更新。面试中不必写形式化证明，但要能解释为什么优化后没有漏解、重复计数或错误淘汰候选。

## 8. 复杂度

**冻结版结论：** `每查询 O(V+E) / O(V)`

面试中不要只报 Big-O：还要说清复杂度来自哪里。例如线性算法要解释每个元素被推进/入栈/出栈/访问的次数；堆算法要解释为什么是 `log k` 而不是 `log n`。

## 9. Python 参考实现

```python
from __future__ import annotations
from collections import defaultdict

class Solution:
    def calcEquation(self, equations: list[list[str]], values: list[float], queries: list[list[str]]) -> list[float]:
        g=defaultdict(list)
        for (a,b),v in zip(equations,values): g[a].append((b,v)); g[b].append((a,1/v))
        def solve(s,t):
            if s not in g or t not in g: return -1.0
            stack=[(s,1.0)]; seen={s}
            while stack:
                u,val=stack.pop()
                if u==t: return val
                for v,w in g[u]:
                    if v not in seen: seen.add(v); stack.append((v,val*w))
            return -1.0
        return [solve(a,b) for a,b in queries]
```

## 17. 解法谱系：从“能做”到“面试最优”

> 这一节的目标是避免“只背一个答案”。真正的算法面试通常会沿着 **baseline → 瓶颈 → 优化 → trade-off** 继续追问。

| 层级 | 方案 | 复杂度/代价 | 面试价值 |
|---|---|---|---|
| 基线 | 按权重展开样本或直接取模 | 可能空间巨大或产生分布偏差 | 先讨论为什么“看起来随机”不等于分布正确 |
| 中间解 | 构造等概率原子空间或累计权重空间 | 预处理/单次采样折中 | 明确样本空间与映射关系 |
| 推荐解 | 拒绝采样、prefix+binary search、Alias 等按约束选择。本题落地为：建邻接表；每个 query DFS/BFS，沿边乘 product；不可达返回 -1。 | 常见期望 O(1) 或 O(log n) | 围绕 `Weighted Graph` 的关键不变量说明为什么安全。 |

### 怎样在白板上自然推到推荐解

1. **先承认基线是正确的**：不要一上来赌最优模板；先建立 correctness anchor。
2. **指出真正浪费**：本题最值得消掉的重复工作可以概括为：**把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。**
3. **选择结构而不是背 API**：说明 `Weighted Graph` 为什么正好承载需要保留的信息。
4. **先说 invariant，再写循环**：循环条件、更新顺序和边界全部应该从 invariant 推出来。
5. **最后比较替代方案**：什么时候愿意多用空间换更低延迟？什么时候输入已排序/流式/内存受限会换算法？

## 18. 状态设计与不变量审计

| 状态 | 精确定义 | 必须保持的性质 |
|---|---|---|
| sample space | 等概率原子或累计权重区间 | 先定义再映射 |
| random source | 唯一随机性来源 | 不引入取模偏差 |
| accept/map rule | 原子→目标事件 | 概率质量严格匹配 |

### 本题的一句话不变量

> **把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。**

这句话必须能对应到代码中的某个具体变量、容器或返回值。若只能说“这里用一个 Hash/DP/Heap”，但说不出其中存的**精确语义**，通常还没有真正掌握。

### 写代码前的三问

- **状态何时有效？** 当前元素加入之前还是之后？
- **状态是否包含当前元素？** 这会直接决定 query-before-update 还是 update-before-query。
- **丢弃的信息为何永远不再需要？** 若无法回答，空间优化或指针移动可能是不安全的。

## 19. 正确性证明：面试版 + 严谨版

### 19.1 面试版证明骨架

1. **初始化成立**：循环/递归开始前，状态满足定义。
2. **保持性成立**：假设处理前缀/子树前 invariant 成立，本轮按照 `Weighted Graph` 更新后仍成立。
3. **不漏解**：被跳过、弹出、剪枝、覆盖或淘汰的候选，都可以证明不可能产生更优合法答案。
4. **终止得到答案**：扫描结束/递归返回时，所有需要考虑的候选已经被覆盖。

### 19.2 本题证明抓手

- **关键事实**：把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。
- **转移/操作**：建邻接表；每个 query DFS/BFS，沿边乘 product；不可达返回 -1。
- **最容易被质疑的点**：浮点误差；x==x 但变量未出现时仍应 -1。

面试时不需要写形式化定理，但至少要能给出一个**反事实解释**：如果不按当前更新顺序/移动规则做，会在哪个最小反例上出错。

## 20. 复杂度深拆：不要只背 Big-O

**目标结论：** `每查询 O(V+E) / O(V)`

拒绝采样要讨论“期望调用次数”而不是最坏有限次数；prefix sampling 的复杂度是预处理 O(n) + 每次查询 O(log n)。

### 复杂度回答建议

- **时间**：说明循环/递归总共访问多少状态，每个状态执行哪些 O(1)/O(log n) 操作。
- **空间**：区分“输出空间”“输入原地修改”“显式辅助结构”“递归调用栈”。
- **最坏 vs 平均/期望**：Hash、QuickSelect、随机采样等题不要把平均/期望复杂度说成确定最坏上界。
- **隐藏主项**：如果方案需要排序、建图、预处理，必须把它计入总复杂度。

### 本题 bug 定向测试

高频失误是：**浮点误差；x==x 但变量未出现时仍应 -1。**

因此至少手工设计一个样例，让错误实现稳定触发这个问题。测试目标不是“多测几个数”，而是让每个 case 对应一个风险：**初始化、边界、重复、更新顺序、数据结构不变量、返回语义**。

### 推荐测试层次

1. **Minimal**：最小合法输入；
2. **Boundary**：答案卡在边界；
3. **Adversarial**：专门攻击高频错误；
4. **Structure**：构造最坏形态，如退化树、单调数组、长链、全重复；
5. **Random differential test**：小规模随机输入，与暴力基线对拍。

> 对拍尤其适合 Hard：先写一个慢但显然正确的 reference，再随机生成小输入比较数千次，往往能快速找出边界 bug。

## 27. 复习卡片 / Active Recall

**Q1. 看到怎样的信号应该想到 `Weighted Graph`？**

A. 把变量作节点，a->b 权重 k，b->a 权重 1/k；查询就是找一条路径并累乘权重。

**Q3. 推荐解的复杂度为什么是 `每查询 O(V+E) / O(V)`？**
