# 面试表达策略：一题答五层

技术面试的高分答案通常不是“最长”，而是层次清楚、能随追问逐步展开。

## 1. 30 秒：只回答题目

结构：**定义 + 核心机制 + 一句工程意义**。

不要在第一句话就展开所有寄存器、公式和异常。先确认面试官是否继续追问。

## 2. 60 秒：加机制

把结论落到可观察对象：frame 字段、bit、sample point、error counter、DBC layout、Filter/FIFO 或软件调用链。

## 3. 3 分钟：加工程案例

采用固定链路：

```text
输入/条件
  ↓
总线事实
  ↓
Controller / 软件栈
  ↓
Application
  ↓
输出与证据
```

如果题目涉及故障，追加 **Recovery**。

## 4. 追问层：说边界

面试官常用边界判断是否真的理解：

- ACK 能证明什么，不能证明什么？
- DBC 能定义什么，不能定义什么？
- vcan 能验证什么，不能验证什么？
- CAN FD 的 8 Byte 能否仅凭长度判断格式？
- API E_OK 与 TxConfirmation/ACK/功能成功分别是什么？

能主动说清边界，通常比多背一个名词更有区分度。

## 5. 项目层：用证据说话

避免：

> 我看了下应该是 CAN 没收到。

推荐：

> 我先在源通道 Trace 确认 frame 存在且周期正确；目标通道没有对应帧，于是把范围缩小到 Gateway/route/network state。随后双侧同步抓 Trace，最终发现目标网络未激活。

## 6. 不知道精确细节时怎么答

可以明确层级而不编造：

> 这个控制器具体 TEC/REC 寄存器名我需要查芯片手册，但协议层我会先确认当前 Error Active/Passive/Bus-Off 状态，再结合发送/接收错误计数定位。

专业并不意味着假装记住所有厂商寄存器。
