路由器为什么使用最长前缀匹配？

定位：进阶 · 面试频率：★★★★★ · 标签：Routing / LPM
本章：第二章 IP、NAT 与路由 · 返回总目录

面试官到底在考什么

这道题不只考定义。面试官通常希望确认你能否把 Routing / LPM 放进真实协议栈/系统调用/故障场景中解释，并且在追问发生时仍保持同一个心智模型，而不是切换成互相矛盾的八股结论。

30 秒标准回答（PDF 原内容）

一个目的地址可能同时匹配默认路由、汇总路由和更具体路由。最长前缀匹配选择最具体的可达规则，使路由既能聚合又能做局部精细控制。例如 10.1.2.3 同时匹配 /8、/16、/24 时选择 /24。

深度解析：Know-How + Know-Why（PDF 原内容）

  1. 路由控制平面生成 RIB，转发平面通常使用优化后的 FIB。
  2. 默认路由 0.0.0.0/0 能匹配所有 IPv4 目的，但优先级最低。
  3. ECMP 可以让同一前缀存在多条等价下一跳。

二次深化：工程上还必须知道什么

本题的高级回答应主动说明适用范围和观测边界：协议规范描述的是语义与状态机，真实 Linux/云网络实现还会受到内核版本、offload、中间盒、代理和应用框架的影响。面试中若无法确定实现细节，应明确“规范保证”和“常见实现”分别是什么。

本章共同的工程视角

  • 把控制平面和转发平面分开：路由协议决定“学到什么路由”，FIB 决定“某个包下一跳去哪”。
  • 任何 NAT/路由问题都先写出五元组、路由表命中项和下一跳，避免靠口头直觉猜。
  • 公网故障常有非对称路径、ECMP、NAT/conntrack 和 ICMP 策略，单点抓包不能自动代表端到端事实。

V2 深入：Longest Prefix Match 决定“候选路由里谁更具体”

第一性原理

  • 路由查找首先在能够匹配 destination 的前缀中选择最长前缀；它表示“更具体的目标范围”。
  • metric、administrative distance、BGP attributes 等通常是在路由协议产生/安装候选 route 时参与选择，不应和数据平面 LPM 混成一个步骤。
  • RIB 是控制平面学习/选择的路由视图，FIB 是为高速 forwarding 下发/优化后的数据平面表。

例子

如果同时存在 0.0.0.0/0 → A、10.0.0.0/8 → B、10.1.0.0/16 → C，访问 10.1.2.3 选 /16。这也是为什么更具体 prefix leak/hijack 能吸引流量：数据平面天然偏好更具体前缀。

ECMP 与乱序

多个等价 next-hop 可做 ECMP，但通常按 flow hash 让同一 flow 稳定落在同一路径，避免逐包 load balancing 导致 TCP reordering。硬件 FIB 常用 TCAM/trie 等结构加速 LPM。

线上案例推演

“明明有默认路由却不走默认网关”时，第一步就是查更具体 route。若 ip route get <dst> 与预期不同，继续查 policy rule/VRF/FIB，而不是从 DNS 开始排查。

面试现场推荐回答结构

  1. 先给结论：用 2-4 句话回答“路由器为什么使用最长前缀匹配？”，避免一上来陷入历史背景。
  2. 再给机制：围绕 Routing、LPM 说明关键状态、字段或数据路径。
  3. 补 Why：解释为什么协议/内核这样设计，以及少一步或改一种设计会出现什么正确性/性能问题。
  4. 落到证据：至少给出一个可观察信号或实验，例如 ip route。

可观测性：如何证明自己的判断

层次 工具 / 信号
首选 ip route
辅助 ip route get <dst>
性能/路径 traceroute / mtr
深挖 conntrack -S

关键原则：先用低成本指标定位层次，再用抓包/trace/内核指标证明。不要看到一个 Retransmission、TIME_WAIT 或 5xx 就直接宣布根因。

面试官常见追问（PDF 原题 + 回答方向）

追问 1：行政距离、metric 与最长前缀谁先决定？

参考回答：/32表示单一主机前缀，/31常用于点到点链路；路由转发对所有匹配前缀执行最长前缀匹配，选择最具体的路由。 epoll把interest set保存在内核，不需要每轮重新提交全部fd；ET强调边沿变化，必须drain到EAGAIN。EPOLLONESHOT常用于多线程下保证一个fd一次只被一个worker处理。poll在fd数量不大时足够简单可靠，kqueue与epoll都属于事件通知接口但具体语义不同。

追问 2：FIB 与 RIB 的区别？

参考回答：RIB是控制平面维护的路由信息集合，FIB是面向高速转发优化后的实际查找表；路由协议/策略先决定候选和最优路由，再下发到 FIB。

追问 3：ECMP 如何避免单个 flow 乱序？

参考回答：ECMP对等价下一跳常按五元组哈希分流，使同一 flow 尽量固定走同一下一跳，避免逐包负载均衡造成严重乱序。 TCP ACK通常是累计确认：ACK=N表示 N 之前连续字节已收到。乱序时 ACK 可能停在缺口处并产生重复 ACK；SACK可额外报告已收到的非连续区间。

高频易错点（PDF 原内容）

  • ❌ 看到更低 metric 就忽略前缀长度。
  • ❌ 把路由表理解成按从上到下第一条匹配。

动手验证 / 抓包实验（PDF 原内容）

用 ip route get <dst> 查看内核对具体目标的下一跳决策。

实验验收标准

能用路由表、路径探测或 conntrack 解释“为什么走这条路/为什么被改写”，而不是只给结论。

建议把实验结果记录成：命令/抓包过滤器 → 观察到的字段/状态 → 与理论的对应关系 → 仍不能证明的部分。这比只保存一张截图更接近线上排障习惯。
