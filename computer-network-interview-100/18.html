OSPF 与 BGP 的定位和核心思想有什么不同？

定位：进阶 · 面试频率：★★★★☆ · 标签：IGP / EGP / 路由协议
本章：第二章 IP、NAT 与路由 · 返回总目录

面试官到底在考什么

这道题不只考定义。面试官通常希望确认你能否把 IGP / EGP / 路由协议 放进真实协议栈/系统调用/故障场景中解释，并且在追问发生时仍保持同一个心智模型，而不是切换成互相矛盾的八股结论。

30 秒标准回答（PDF 原内容）

OSPF 是典型 IGP，服务自治系统内部的链路状态路由与最短路径计算；BGP 是域间路径向量/策略路由协议，核心是可扩展的前缀传播和商业/策略控制，而不是简单“全网最短路”。

深度解析：Know-How + Know-Why（PDF 原内容）

  1. OSPF 通过 LSA 构造链路状态数据库，再运行 SPF。
  2. BGP 通过 UPDATE 传播 NLRI 与路径属性，路由选择高度受 LOCAL_PREF、AS_PATH、MED 等策略影响。
  3. 互联网自治系统之间需要可表达商业关系的策略，这正是 BGP 的核心价值。

二次深化：工程上还必须知道什么

本题的高级回答应主动说明适用范围和观测边界：协议规范描述的是语义与状态机，真实 Linux/云网络实现还会受到内核版本、offload、中间盒、代理和应用框架的影响。面试中若无法确定实现细节，应明确“规范保证”和“常见实现”分别是什么。

本章共同的工程视角

  • 把控制平面和转发平面分开：路由协议决定“学到什么路由”，FIB 决定“某个包下一跳去哪”。
  • 任何 NAT/路由问题都先写出五元组、路由表命中项和下一跳，避免靠口头直觉猜。
  • 公网故障常有非对称路径、ECMP、NAT/conntrack 和 ICMP 策略，单点抓包不能自动代表端到端事实。

V2 深入：OSPF 优化自治系统内部收敛，BGP表达跨自治系统策略

第一性原理

  • OSPF 是 link-state IGP：在一个管理域内传播拓扑信息、运行 SPF，目标是快速、一致地计算内部路径。
  • BGP 是 path-vector/policy protocol：跨 AS 传播可达前缀和属性，核心不是物理最短，而是商业与运营策略可控。
  • 互联网不能简单用一个全局 OSPF：拓扑规模、故障泛洪、信任边界、策略需求都不允许。

收敛与扩展

OSPF 通过 area 限制 LSDB/flooding 范围，BGP 则用增量 UPDATE、route policy、aggregation 和 route reflector 等扩展。BGP 的收敛通常更保守，因为跨组织策略和 path exploration 比一个园区内 SPF 更复杂。

iBGP / eBGP

eBGP 在不同 AS 之间交换路由；iBGP 在同一 AS 内分发外部路由和策略。iBGP 本身不等于 IGP，通常仍依赖 OSPF/IS-IS 提供 next-hop reachability。

线上案例推演

如果内部机房链路故障后路由几秒内切换，更多是 IGP/FIB 问题；如果只有某 ISP/地区用户绕路数分钟甚至更久，需检查 BGP announcement、policy、community、upstream path，而不是只看 OSPF。

面试现场推荐回答结构

  1. 先给结论：用 2-4 句话回答“OSPF 与 BGP 的定位和核心思想有什么不同？”，避免一上来陷入历史背景。
  2. 再给机制：围绕 IGP、EGP、路由协议 说明关键状态、字段或数据路径。
  3. 补 Why：解释为什么协议/内核这样设计，以及少一步或改一种设计会出现什么正确性/性能问题。
  4. 落到证据：至少给出一个可观察信号或实验，例如 ip route。

可观测性：如何证明自己的判断

层次 工具 / 信号
首选 ip route
辅助 ip route get <dst>
性能/路径 traceroute / mtr
深挖 conntrack -S

关键原则：先用低成本指标定位层次，再用抓包/trace/内核指标证明。不要看到一个 Retransmission、TIME_WAIT 或 5xx 就直接宣布根因。

面试官常见追问（PDF 原题 + 回答方向）

追问 1：为什么不能用 OSPF 直接跑整个互联网？

参考回答：OSPF是自治系统内部的链路状态 IGP，依赖全域拓扑数据库和 SPF 计算；互联网域间规模、策略和商业关系使其不适合作为全球路由协议。

追问 2：BGP 收敛为什么通常比 IGP 慢？

参考回答：OSPF是自治系统内部的链路状态 IGP，依赖全域拓扑数据库和 SPF 计算；互联网域间规模、策略和商业关系使其不适合作为全球路由协议。 eBGP用于自治系统之间交换路由，iBGP在同一 AS 内传播外部/策略路由；BGP强调策略、稳定性与可扩展性，收敛通常比 IGP 慢且受策略链影响。

追问 3：iBGP 与 eBGP 有什么差别？

参考回答：eBGP用于自治系统之间交换路由，iBGP在同一 AS 内传播外部/策略路由；BGP强调策略、稳定性与可扩展性，收敛通常比 IGP 慢且受策略链影响。 BGP路由选择是策略驱动的：LOCAL_PREF常表达本 AS 出站偏好，AS_PATH兼具路径信息和环路检测，MED表达邻居进入本 AS 的入口偏好，Community用于批量打标签和策略控制。Route leak是错误传播本不该传播的合法前缀，hijack则是未经授权地宣告他人前缀。

高频易错点（PDF 原内容）

  • ❌ 把 BGP 说成“Dijkstra 的互联网版本”。
  • ❌ 认为 AS_PATH 最短永远最高优先级。

动手验证 / 抓包实验（PDF 原内容）

阅读本机/实验路由器的 OSPF/BGP 路由表，比较同一前缀的 next-hop 与属性。

实验验收标准

能用路由表、路径探测或 conntrack 解释“为什么走这条路/为什么被改写”，而不是只给结论。

建议把实验结果记录成：命令/抓包过滤器 → 观察到的字段/状态 → 与理论的对应关系 → 仍不能证明的部分。这比只保存一张截图更接近线上排障习惯。
