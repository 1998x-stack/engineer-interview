什么是 TCP Half-close？什么时候有用？

定位：进阶 · 面试频率：★★★☆☆ · 标签：shutdown / 半关闭
本章：第三章 TCP 连接、状态机与可靠性 · 返回总目录

面试官到底在考什么

这道题不只考定义。面试官通常希望确认你能否把 shutdown / 半关闭 放进真实协议栈/系统调用/故障场景中解释，并且在追问发生时仍保持同一个心智模型，而不是切换成互相矛盾的八股结论。

30 秒标准回答（PDF 原内容）

TCP 的两个方向可独立关闭。调用 shutdown(SHUT_WR) 会发送 FIN，表示本端不再写，但仍可继续 recv 对端剩余数据。这对“发送完请求后继续读取直到 EOF”的协议、代理和流式处理很有价值。

深度解析：Know-How + Know-Why（PDF 原内容）

  1. close() 通常释放整个 socket 引用，而 shutdown() 可以精确控制读/写方向。
  2. 收到 FIN 只影响对端的发送方向，并不自动阻止本端继续 send。
  3. 半关闭是理解 FIN 状态机和四次挥手的关键。

二次深化：工程上还必须知道什么

本题的高级回答应主动说明适用范围和观测边界：协议规范描述的是语义与状态机，真实 Linux/云网络实现还会受到内核版本、offload、中间盒、代理和应用框架的影响。面试中若无法确定实现细节，应明确“规范保证”和“常见实现”分别是什么。

本章共同的工程视角

  • TCP 是有状态的可靠字节流；状态机、序号空间、ACK 语义和定时器是理解所有 TCP 题的共同底座。
  • 不要把“内核收到”“对端 TCP 确认”“对端应用读到”“业务处理成功”混成一个层次。
  • 排障时必须把主动关闭方、连接状态、Seq/Ack 时间线和应用生命周期放在一起看。

V2 深入：Half-close 让“发送完成”和“接收完成”成为两个独立事件

第一性原理

  • shutdown(SHUT_WR) 发送 FIN，告诉 peer 本端不会再发送，但本端仍可以 read() peer 后续 response。
  • 收到 peer FIN 后，应用把缓冲数据读完，再读通常得到 EOF（read() 返回 0），这不是 error。
  • 这种语义适合“请求体以 EOF 结束、仍等待服务端结果”等协议设计。

close()、shutdown() 与引用

close(fd) 是描述符生命周期操作；若多个 fd/reference 指向同一 socket，实际 protocol close 语义还与引用计数有关。SO_LINGER 可以改变 close 在有未发送数据时的阻塞/复位行为，因此不能把 close() 永远等同“优雅 FIN”。

RST 为什么不同

RST 表示连接状态异常/无效，接收端通常得到 reset error，而不是先消费全部有序数据再 EOF；因此无法替代 half-close 的协议语义。

线上案例推演

自定义 RPC 若 Client 发完 request 后需要告诉 Server“请求完整结束”但还要继续收 response，可以用 length framing，也可以设计 half-close；若使用 RST 作为“结束标记”，很容易把正常关闭变成错误路径。

面试现场推荐回答结构

  1. 先给结论：用 2-4 句话回答“什么是 TCP Half-close？什么时候有用？”，避免一上来陷入历史背景。
  2. 再给机制：围绕 shutdown、半关闭 说明关键状态、字段或数据路径。
  3. 补 Why：解释为什么协议/内核这样设计，以及少一步或改一种设计会出现什么正确性/性能问题。
  4. 落到证据：至少给出一个可观察信号或实验，例如 ss -tanpi。

面试官常见追问（PDF 原题 + 回答方向）

追问 1：read() 在收到 FIN 后返回什么？

参考回答：FIN表示一个方向“不会再发送更多字节”，支持半关闭和有序收尾；RST表示异常终止/立即重置连接，通常不提供优雅 half-close 语义。shutdown(SHUT_WR)只关闭发送方向，close()则释放文件描述符并进入完整关闭流程。

追问 2：SO_LINGER 会如何影响 close？

参考回答：FIN表示一个方向“不会再发送更多字节”，支持半关闭和有序收尾；RST表示异常终止/立即重置连接，通常不提供优雅 half-close 语义。shutdown(SHUT_WR)只关闭发送方向，close()则释放文件描述符并进入完整关闭流程。

追问 3：为什么 RST 不提供优雅 half-close 语义？

参考回答：FIN表示一个方向“不会再发送更多字节”，支持半关闭和有序收尾；RST表示异常终止/立即重置连接，通常不提供优雅 half-close 语义。shutdown(SHUT_WR)只关闭发送方向，close()则释放文件描述符并进入完整关闭流程。

高频易错点（PDF 原内容）

  • ❌ 把 FIN 理解成“整个连接双向立刻结束”。
  • ❌ 认为 shutdown 和 close 完全等价。

动手验证 / 抓包实验（PDF 原内容）

实现一个客户端发送请求后 shutdown(SHUT_WR)，服务端继续返回大响应，验证客户端仍可接收。

实验验收标准

能从 TCP 状态、Seq/Ack、重传/窗口和应用 close/read/write 行为形成一致时间线。

建议把实验结果记录成：命令/抓包过滤器 → 观察到的字段/状态 → 与理论的对应关系 → 仍不能证明的部分。这比只保存一张截图更接近线上排障习惯。
