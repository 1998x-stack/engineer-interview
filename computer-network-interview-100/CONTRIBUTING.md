# Contributing

## 内容原则

1. 协议语义优先引用 IETF/RFC。
2. Linux 实现优先引用 Linux Kernel Documentation / man-pages。
3. 区分“规范保证”“主流实现”“经验参数”。
4. 性能数字必须说明环境，避免把 benchmark 当普遍定律。
5. 纠错最好附抓包、最小复现或源码位置。

## 文件结构

一个问题一个 Markdown；不要把多个题目合并。题号与路径由 `manifest.json` 固定。

## 提交前

```bash
python scripts/check_repo.py
```

## V2 内容质量门槛

新增或修改题解时，不能只补充“更多名词”。至少满足以下三项：

1. 明确一个可长期成立的**协议/系统不变量**；
2. 给出一个容易答错的**边界条件或反例**；
3. 给出可执行或可抓包的**验证方法**，并说明该证据“能证明什么、不能证明什么”。

涉及会变化的实现状态（Linux 默认值、IETF Draft、浏览器支持）必须标明时间/版本或链接到权威资料，不把当前实现写成永久协议保证。
