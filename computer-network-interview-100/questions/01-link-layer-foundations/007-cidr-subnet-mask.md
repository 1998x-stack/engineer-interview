# 007. 子网掩码 / CIDR 前缀到底解决什么问题？

> **定位**：基础 · **面试频率**：★★★★☆ · **标签**：CIDR / 子网  
> **本章**：[第一章 网络分层、链路与二层基础](README.md) · [返回总目录](../../README.md)

## 面试官到底在考什么

这道题不只考定义。面试官通常希望确认你能否把 **CIDR / 子网** 放进真实协议栈/系统调用/故障场景中解释，并且在追问发生时仍保持同一个心智模型，而不是切换成互相矛盾的八股结论。

## 30 秒标准回答（PDF 原内容）

> CIDR 前缀把 IP 地址拆成“网络前缀 + 主机部分”，主机据此判断目标是否属于本地网络，路由器也据此前缀聚合路由。/24 表示前 24 位是网络前缀，而不是“固定能用 254 台机器”的同义词。

## 深度解析：Know-How + Know-Why（PDF 原内容）

1. 主机通过 `(dst & mask) == (local & mask)` 判断本地子网。
2. CIDR 允许可变长度前缀，避免传统 A/B/C 类地址的严重浪费。
3. 路由汇总能减少全局路由表规模。

## 二次深化：工程上还必须知道什么

本题的高级回答应主动说明适用范围和观测边界：协议规范描述的是语义与状态机，真实 Linux/云网络实现还会受到内核版本、offload、中间盒、代理和应用框架的影响。面试中若无法确定实现细节，应明确“规范保证”和“常见实现”分别是什么。

### 本章共同的工程视角

- 始终区分“最终目的”与“当前下一跳”：IP 负责跨网络寻址，二层地址负责当前链路交付。
- 回答时要把数据单位说清楚：Application Data → Segment/Datagram → IP Packet → Frame。
- 遇到“为什么”题，不只背协议名称，要解释分层如何降低耦合、让每一层独立演进。

## V2 深入：CIDR 的本质是把地址空间变成可聚合的前缀集合

### 第一性原理

- 前缀长度决定“网络部分有多少 bit”，并用于本机 on-link 判断与路由聚合。
- 路由选择不是“看前三段 IP 是否相同”，而是对 destination 与候选 prefix 做 bit-level prefix matching。
- CIDR 同时解决地址分配灵活性与路由表聚合问题，是现代 IP 路由的基础。

### 特殊前缀

`/32` 表示单个 IPv4 host route；`/31` 可用于点对点链路（没有传统意义上的网络/广播地址浪费）；默认路由是 `/0`。所以“每个 subnet 固定减 2 个地址”并不是所有前缀的普遍法则。

云平台还会为网关、DNS、平台基础设施等保留地址，能分配给用户的数量取决于平台约束，而不是只算 `2^(host bits)-2`。

### 与路由系统的关系

CIDR 允许把多个更具体前缀汇总成 aggregate，降低全球路由表规模；但若某个更具体 prefix 被单独发布，Longest Prefix Match 会优先选它，这也是流量工程和 prefix hijack 分析的基础。

### 线上案例推演

如果新加的 `/24` 路由没有生效，不能只看“有没有默认路由”；需要同时检查是否存在更具体 `/25`、policy routing、VRF、rule priority，以及最终 FIB 实际选择。

## 面试现场推荐回答结构

1. **先给结论**：用 2-4 句话回答“子网掩码 / CIDR 前缀到底解决什么问题？”，避免一上来陷入历史背景。
2. **再给机制**：围绕 CIDR、子网 说明关键状态、字段或数据路径。
3. **补 Why**：解释为什么协议/内核这样设计，以及少一步或改一种设计会出现什么正确性/性能问题。
4. **落到证据**：至少给出一个可观察信号或实验，例如 `tcpdump -e -nn`。

## 可观测性：如何证明自己的判断

| 层次 | 工具 / 信号 |
|---|---|
| 首选 | `tcpdump -e -nn` |
| 辅助 | `ip neigh` |
| 性能/路径 | `ip link` |
| 深挖 | `ip addr` |

**关键原则**：先用低成本指标定位层次，再用抓包/trace/内核指标证明。不要看到一个 `Retransmission`、`TIME_WAIT` 或 `5xx` 就直接宣布根因。

## 面试官常见追问（PDF 原题 + 回答方向）

### 追问 1：/31、/32 有什么用途？

**参考回答**：`/32` 是单主机路由；`/31` 可用于点对点链路并让两地址都可作为 endpoint，不按传统子网‘网络地址/广播地址’浪费。

### 追问 2：为什么云厂商一个 /24 未必能分配 254 个用户地址？

**参考回答**：云平台通常额外保留 gateway、DNS、平台基础设施等地址，所以可分配给用户的数量由平台规则决定，不只由 `2^(host bits)-2` 决定。

### 追问 3：最长前缀匹配如何利用 CIDR？

**参考回答**：CIDR 产生可变长度前缀；转发时在所有匹配 destination 的 route 中选择最长前缀，因此更具体的路由会覆盖更粗的汇总路由。

## 高频易错点（PDF 原内容）

- ❌ 机械套用 `2^hostbits - 2` 到所有现代网络场景。
- ❌ 把子网掩码与默认网关混为一谈。
