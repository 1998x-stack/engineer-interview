Detectability 是什么？为什么观测器不一定要求完全可观？

难度：进阶 · 高频度：★★★★☆ · PDF 页码：56 · 章节：可控可观、观测器与 Kalman

导航：← Q063 · 题库总索引 · Q065 →

面试官为什么问这题

这道题属于 可控可观、观测器与 Kalman 的核心知识链。面试官通常不只检查定义，而是通过连续追问观察你是否能把数学结构、物理直觉、工程约束和验证方法连接起来。建议先用 30 秒给结论，再根据追问展开公式与边界条件。

PDF 原始内容（完整保留）

本节逐项保留 PDF 中该题的结构化内容；后面的“仓库增强”属于扩展讲解。

标准回答

Detectability 是 observability 的稳定性版本：所有不可观模态都必须稳定。即使某些稳定快速模态永远无法从输出恢复，只要它们自己会衰减，仍可以构造使估计误差趋零的 observer。真正危险的是不可观且不稳定的模态，因为误差会增长而传感器又看不到。

公式与推导

对所有 $\Re(\lambda)\ge0$，若 $$ \operatorname{rank}\begin{bmatrix}\lambda I-A\C\end{bmatrix}=n, $$ 则 $(A,C)$ detectable。

工程直觉

看不见一个自己会消失的误差通常没问题；看不见一个会增长的误差就无法纠正。

常见误区 / Gotcha

不要把 detectability 和 “传感器检测故障”混淆，它是线性系统的结构定义。

高频追问

  • 为什么 Kalman filter 常要求 detectability？
  • detectability 与 stabilizability 如何对偶？
  • 不可观稳定模态会留在估计误差中多久？

30 秒口述版

Detectability 要求不可观模态至少是稳定的，因此 observer 仍能让总体估计误差衰减。不可观且不稳定的模态才无法估计。

仓库增强：深度展开

可控/可观问题不要只报 rank。rank test 是代数判据，真正的工程问题是：某个模态能否被执行器影响？某个模态能否在传感器数据中留下可辨识痕迹？ 稳定但不可控/不可观的模态有时可接受，不稳定模态则必须分别满足 stabilizable/detectable。

观测器设计还必须考虑噪声与模型误差；把 observer pole 设得极快虽然名义收敛快，却会显著放大 measurement noise，并暴露离散采样和数值问题。

针对本题的进一步理解

detectable 只要求不可观模态稳定，正好对应“能否构造收敛状态估计器”的最小结构条件。

从面试表达角度，建议把本题组织成四层：

  1. 定义层：先说明对象、变量和适用条件；
  2. 数学层：给最小但足够的关键公式，并解释每一项；
  3. 物理层：把公式映射成能量、时间尺度、频率或信息流；
  4. 工程层：主动说明噪声、延迟、饱和、模型误差或采样等边界。

工程场景

以车辆横向控制为例，部分状态可能不能直接测量；观测器用车辆模型与 IMU/GNSS/方向盘传感器融合估计侧偏等内部状态。

将这个场景与当前问题连接时，重点不是套算法名称，而是问：这个概念会改变哪个闭环信号路径、哪个动态时间尺度、哪个约束余量？ 这能把抽象理论转成可验证的设计判断。

1. 核心边界：可控可观与估计

rank test 给二元结论，Gramian/噪声/conditioning 决定工程难度。实际设计不仅问‘能不能’，还问‘代价多大、对噪声多敏感’。

针对 Q064 的专家补充： Detectability 只要求所有不可观模态稳定，因此即使不能重构每个稳定内部模态，估计误差仍可收敛到可接受行为。它是 observer/Kalman 存在性的更弱、更实用条件。

2. 推导路线与适用条件

  1. 先写 controllability/observability 或 error dynamics。
  2. 用 rank/PBH/Gramian 给结构结论，再讨论 conditioning。
  3. 估计器问题继续写 innovation 与噪声协方差，说明 bandwidth-noise trade-off。

在白板面试中，建议把“公式”与“成立条件”写在同一块区域。例如写出一个二阶近似或稳定性结论后，紧跟一句：假设高阶模态足够远、没有显著 RHP 零点/纯延迟、执行器未饱和。这能明显区分“会背公式”和“会使用模型”。

3. 一个可计算的小例子

对同一二阶系统只测位置 $C=[1,0]$，计算 observability rank；给 measurement noise 方差从 $10^{-4}$ 增加到 $10^{-2}$，比较高增益 Luenberger 与 Kalman estimator 的速度和噪声。

这个例子的目的不是训练固定数字，而是练习从 模型 → 指标 → 非理想因素 → 结论变化 的完整链路。建议在 Python/MATLAB 中把关键参数做 sweep，而不是只跑一个点。

5. 高频追问详答

1. 为什么 Kalman filter 常要求 detectability？

若某不可观模态本身不稳定，任何 measurement update 都无法修正该方向的估计误差，协方差会发散。Detectability 保证所有看不到的模态至少稳定，因此稳定 Kalman observer 才可能存在。

2. detectability 与 stabilizability 如何对偶？

Detectability 与 stabilizability 是转置意义下的对偶：$(A,C)$ detectable 等价于 $(A^T,C^T)$ stabilizable。前者要求所有不可观模态稳定，后者要求所有不可控模态稳定；这正是 observer 与 state-feedback 存在条件的镜像结构。

3. 不可观稳定模态会留在估计误差中多久？

它不能被 measurement correction 直接消除，只按自身稳定 dynamics 自然衰减。若 pole 很接近虚轴/单位圆，误差可能持续很久，因此 detectability 虽保证最终稳定，不保证估计速度好。

6. 反例与失效条件

  • 模型层失效：如果出现未建模柔性模态、显著时延、RHP 零点、强耦合或工作点迁移，原题中的低阶/线性结论可能只在局部成立。
  • 实现层失效：sampling、quantization、filter、scheduler、actuator saturation/rate limit 会改变实际闭环，不应被当作“软件细节”。
  • 评价层失效：只看一个 step response 或单一 PM/GM 容易漏掉噪声、控制努力、内部状态和 worst-case parameter spread。
  • 验证原则：每个重要结论至少对应一个可证伪预测；例如“若根因是 delay margin 不足，则降低 crossover 或减少 latency 后振荡应系统性减弱”。

7. 面试回答的三档深度

30 秒： 先复述上面的“30 秒口述版”，只讲定义、关键公式和一个 trade-off。

2 分钟： 增加推导路线中的 2–3 步，并主动说明一个适用条件/反例；这是大多数技术面最合适的深度。

5 分钟以上： 画框图或 pole/Bode/state diagram，把工程验证矩阵讲出来；如果面试官继续追问，再进入数值例子、robustness 或 implementation details。
