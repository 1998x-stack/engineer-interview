自适应控制和鲁棒控制有何本质不同？

难度：进阶 · 高频度：★★★★☆ · PDF 页码：68 · 章节：最优、MPC、鲁棒与自适应

导航：← Q078 · 题库总索引 · Q080 →

面试官为什么问这题

这道题属于 最优、MPC、鲁棒与自适应 的核心知识链。面试官通常不只检查定义，而是通过连续追问观察你是否能把数学结构、物理直觉、工程约束和验证方法连接起来。建议先用 30 秒给结论，再根据追问展开公式与边界条件。

PDF 原始内容（完整保留）

本节逐项保留 PDF 中该题的结构化内容；后面的“仓库增强”属于扩展讲解。

标准回答

鲁棒控制通常假设参数属于已知不确定集合，并设计固定控制器对整个集合工作；自适应控制则在线利用输入输出更新参数估计或控制律，让控制器随对象变化。前者强调 worst-case 保证，后者强调在线学习/调整。自适应并不意味着“自动更鲁棒”，还需要 excitation、稳定性证明和参数漂移管理。

公式与推导

一般可写为： $$ \dot{\hat\theta}=\Gamma\phi e $$ 之类 adaptation law，再由 $\hat\theta$ 更新 control law。

工程直觉

鲁棒像提前准备一件能适应各种天气的外套；自适应像根据实时温度不断调整衣服。

常见误区 / Gotcha

没有 persistent excitation 时参数可能不收敛；控制性能收敛和参数真值收敛不是同一件事。

30 秒口述版

鲁棒控制用固定 K 覆盖不确定集合；自适应控制在线更新参数/控制律。自适应要额外处理 excitation、噪声和参数漂移，不能等同于“自动调参 PID”。

仓库增强：深度展开

现代控制算法不要用“高级程度”排序，而要按它们解决的问题排序：Pole placement 解决极点位置，LQR 解决二次代价下的反馈权衡，Kalman 解决随机估计，MPC 解决有限时域优化与显式约束，鲁棒控制解决模型族的最坏情况，自适应控制解决在线参数变化。

面试时最有价值的回答通常是“为什么需要它，而不是更简单的方法”。如果没有约束，MPC 未必优于精心设计的 LQR；如果模型不确定性很小，也未必需要 $H_\infty$。

针对本题的进一步理解

自适应控制在线调整参数并不意味着自动鲁棒；parameter convergence 往往需要 persistent excitation，且 transient safety 仍需额外设计。

从面试表达角度，建议把本题组织成四层：

  1. 定义层：先说明对象、变量和适用条件；
  2. 数学层：给最小但足够的关键公式，并解释每一项；
  3. 物理层：把公式映射成能量、时间尺度、频率或信息流；
  4. 工程层：主动说明噪声、延迟、饱和、模型误差或采样等边界。

工程场景

以自动驾驶轨迹控制为例，LQR 可在局部线性模型下快速给出反馈；加入方向盘角度/变化率和道路边界约束后，MPC 的优势才真正出现。

将这个场景与当前问题连接时，重点不是套算法名称，而是问：这个概念会改变哪个闭环信号路径、哪个动态时间尺度、哪个约束余量？ 这能把抽象理论转成可验证的设计判断。

1. 核心边界：最优、鲁棒与约束

所谓最优都依赖代价、模型和假设；成熟回答要同时讨论 Q/R 或权重、约束、模型误差和在线计算。

针对 Q079 的专家补充： Robust control 用一个固定控制器覆盖参数集合；adaptive control 在线更新参数/控制律。MRAC 通过 reference model 定义期望动态，persistent excitation 决定参数能否真正收敛；σ-modification 可改善噪声/未建模动态下的漂移。

2. 推导路线与适用条件

  1. 先把目标写成 cost、约束或 uncertainty set。
  2. 推导最优/鲁棒条件（Riccati、receding horizon、small-gain 或 weighted norm）。
  3. 再说明模型假设、在线计算、constraint 和 robustness 的边界。

在白板面试中，建议把“公式”与“成立条件”写在同一块区域。例如写出一个二阶近似或稳定性结论后，紧跟一句：假设高阶模态足够远、没有显著 RHP 零点/纯延迟、执行器未饱和。这能明显区分“会背公式”和“会使用模型”。

3. 一个可计算的小例子

对双积分器 $\dot x=[0\;1;0\;0]x+[0,1]^Tu$，比较 $Q=\mathrm{diag}(1,1),R=1$ 与 $Q=\mathrm{diag}(100,1),R=0.1$。记录 poles、settling time、peak u；再加入 $|u|\le1$ 看为什么 unconstrained LQR 与 MPC 的结论不同。

这个例子的目的不是训练固定数字，而是练习从 模型 → 指标 → 非理想因素 → 结论变化 的完整链路。建议在 Python/MATLAB 中把关键参数做 sweep，而不是只跑一个点。

5. 高频追问详答

1. MRAC 的 reference model 做什么？

Reference model 明确定义希望闭环呈现的目标动态 x_m。Adaptive law 根据 tracking error 调整 controller 参数，使 plant output/state 跟随该 model，而不是直接追求某个固定 gain。

2. persistent excitation 为什么重要？

PE 意味着回归向量在时间上提供足够丰富方向信息，使未知参数可辨识。没有 PE 时 adaptive controller 仍可能实现 tracking，但参数估计不一定收敛到真实值。

3. sigma modification 有什么作用？

σ-modification 在参数更新律中加入泄漏项如 $-\sigma\hat\theta$，抑制噪声和未建模动态导致的 parameter drift，代价是引入小的稳态偏差。

6. 反例与失效条件

  • 模型层失效：如果出现未建模柔性模态、显著时延、RHP 零点、强耦合或工作点迁移，原题中的低阶/线性结论可能只在局部成立。
  • 实现层失效：sampling、quantization、filter、scheduler、actuator saturation/rate limit 会改变实际闭环，不应被当作“软件细节”。
  • 评价层失效：只看一个 step response 或单一 PM/GM 容易漏掉噪声、控制努力、内部状态和 worst-case parameter spread。
  • 验证原则：每个重要结论至少对应一个可证伪预测；例如“若根因是 delay margin 不足，则降低 crossover 或减少 latency 后振荡应系统性减弱”。

7. 面试回答的三档深度

30 秒： 先复述上面的“30 秒口述版”，只讲定义、关键公式和一个 trade-off。

2 分钟： 增加推导路线中的 2–3 步，并主动说明一个适用条件/反例；这是大多数技术面最合适的深度。

5 分钟以上： 画框图或 pole/Bode/state diagram，把工程验证矩阵讲出来；如果面试官继续追问，再进入数值例子、robustness 或 implementation details。
