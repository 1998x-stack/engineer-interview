仿真稳定但实机振荡，系统化排查顺序是什么？

难度：工程 · 高频度：★★★★★ · PDF 页码：86 · 章节：非线性与系统级工程面试

导航：← Q097 · 题库总索引 · Q099 →

面试官为什么问这题

这道题属于 非线性与系统级工程面试 的核心知识链。面试官通常不只检查定义，而是通过连续追问观察你是否能把数学结构、物理直觉、工程约束和验证方法连接起来。建议先用 30 秒给结论，再根据追问展开公式与边界条件。

PDF 原始内容（完整保留）

本节逐项保留 PDF 中该题的结构化内容；后面的“仓库增强”属于扩展讲解。

标准回答

第一步确认反馈符号、单位、坐标和传感器方向；第二步核对实际 sample time、end-to-end delay 和 jitter；第三步检查 actuator amplitude/rate saturation 与 anti-windup；第四步比较 raw/filtered sensor noise、bias 和 timestamp；第五步做低幅辨识或扫频找未建模柔性模态；第六步把真实这些因素逐项加回仿真，建立能复现故障的 model。只有能在模型中复现，调参才不是盲调。

公式与推导

推荐日志至少包含： $$ r,e,y_{raw},y_{filt},\hat x,u_{raw},u_{sat},\text{timing}. $$

工程直觉

实机问题常不在“控制公式”，而在公式和世界之间的接口：单位、时间戳、限幅、传感器和未建模结构。

常见误区 / Gotcha

不要一开始就重新调 PID。调参会改变症状，反而可能把根因隐藏。

30 秒口述版

按“符号/单位 -> 时序 -> 饱和 -> 传感器 -> 未建模动态”排查，并把发现逐项加入仿真直到能复现。先找根因，再调 controller。

仓库增强：深度展开

非线性控制题最重要的是说明局部结论和全局结论的边界。Jacobian 线性化给局部模型，Lyapunov 可以直接证明更大区域的稳定性，feedback linearization/backstepping/sliding mode 则利用结构主动设计非线性反馈。

系统级工程题则考证据链。优秀调试不是“猜一个参数再试”，而是从日志、频谱、残差、饱和统计和时序数据提出可证伪假设，再通过 A/B 实验把根因固化成 regression test。

针对本题的进一步理解

诊断振荡时先找频率归属，再找能量来源。频率接近 crossover、机械共振或 Nyquist 各自对应不同根因树。

从面试表达角度，建议把本题组织成四层：

  1. 定义层：先说明对象、变量和适用条件；
  2. 数学层：给最小但足够的关键公式，并解释每一项；
  3. 物理层：把公式映射成能量、时间尺度、频率或信息流；
  4. 工程层：主动说明噪声、延迟、饱和、模型误差或采样等边界。

工程场景

以机械臂为例，大范围运动时惯性矩阵与重力项显著非线性；局部线性控制可做定点稳定，而 computed-torque/feedback-linearization 类方法会显式利用动力学结构。

将这个场景与当前问题连接时，重点不是套算法名称，而是问：这个概念会改变哪个闭环信号路径、哪个动态时间尺度、哪个约束余量？ 这能把抽象理论转成可验证的设计判断。

专家版扩展 v2

内容边界：本节是仓库第二版扩展，基于经典控制理论与工程实践补充；它不改写上面的 PDF 原始内容。若扩展结论需要额外假设，会在正文中显式说明。

1. 核心边界：非线性与系统级验证

局部线性结论、全局稳定性、执行器非线性和现场数据诊断必须区分。工程问题最终要落到可验证假设和安全试验。

针对 Q098 的专家补充： 仿真到实机的差异优先检查 sign/scale/timestamp/saturation，再看 delay、sensor/actuator dynamics 和未建模共振。最小安全激励应限制幅值、频段和 operating envelope，同时记录 raw sensor 与 actual actuator 而非只有高层命令。

2. 推导路线与适用条件

  1. 明确非线性结构、平衡点/轨迹和约束。
  2. 选择 Lyapunov、feedback linearization、sliding/backstepping 或诊断 residual 建立可证明/可证伪链。
  3. 最后检查 region of attraction、saturation、sensor/actuator dynamics 和实机安全验证。

在白板面试中，建议把“公式”与“成立条件”写在同一块区域。例如写出一个二阶近似或稳定性结论后，紧跟一句：假设高阶模态足够远、没有显著 RHP 零点/纯延迟、执行器未饱和。这能明显区分“会背公式”和“会使用模型”。

3. 一个可计算的小例子

构造一个含 saturation、10–20 ms delay、measurement noise 的二阶/倒立摆最小模型。先在理想条件下验证理论，再逐个打开非线性和实现因素；每次只改一个变量并记录 residual，从而区分理论失效与实现失效。

这个例子的目的不是训练固定数字，而是练习从 模型 → 指标 → 非理想因素 → 结论变化 的完整链路。建议在 Python/MATLAB 中把关键参数做 sweep，而不是只跑一个点。

4. 工程验证矩阵

验证层 建议实验 想证明什么
Theory Lyapunov/非线性条件 证明或局部边界
Non-ideal saturation/delay/noise 发现 limit cycle
Evidence logs/FRF/residual 形成可证伪根因

5. 高频追问详答

1. 如何设计最小安全激励做 system identification？

先定义幅值、rate、频率和 operating envelope 限制，再选择低能量 chirp/PRBS/sine；在线监测 saturation、temperature、state limit，并设置立即退出条件。辨识不是越大激励越好，而是信噪比与安全的折中。

2. 如何区分 sensor resonance 与 mechanical resonance？

机械共振会真实出现在 plant motion/actuator load 中，通常可被独立传感器、外部激光/视觉或多位置测量共同看到；sensor resonance 可能只在某个传感器通道出现，物理输出并未同步共振。可比较 raw sensor、另一种 sensing modality、actuator current/force 与 FRF 的相干性，并做传感器安装/滤波 A/B test。

3. 为什么日志要同时记录 raw 与 saturated command？

只记录 raw command 不知道执行器是否真正实现；只记录 saturated/actual command 又看不到控制器内部想要多少。二者差值正是 saturation/windup/actuator-lag 诊断的重要 residual。

6. 反例与失效条件

  • 模型层失效：如果出现未建模柔性模态、显著时延、RHP 零点、强耦合或工作点迁移，原题中的低阶/线性结论可能只在局部成立。
  • 实现层失效：sampling、quantization、filter、scheduler、actuator saturation/rate limit 会改变实际闭环，不应被当作“软件细节”。
  • 评价层失效：只看一个 step response 或单一 PM/GM 容易漏掉噪声、控制努力、内部状态和 worst-case parameter spread。
  • 验证原则：每个重要结论至少对应一个可证伪预测；例如“若根因是 delay margin 不足，则降低 crossover 或减少 latency 后振荡应系统性减弱”。

7. 面试回答的三档深度

30 秒： 先复述上面的“30 秒口述版”，只讲定义、关键公式和一个 trade-off。

2 分钟： 增加推导路线中的 2–3 步，并主动说明一个适用条件/反例；这是大多数技术面最合适的深度。

5 分钟以上： 画框图或 pole/Bode/state diagram，把工程验证矩阵讲出来；如果面试官继续追问，再进入数值例子、robustness 或 implementation details。

  • 先建立一个最小可复现实验，只保留与本题相关的动态；
  • 同时画时域与频域结果，不要只看单一阶跃曲线；
