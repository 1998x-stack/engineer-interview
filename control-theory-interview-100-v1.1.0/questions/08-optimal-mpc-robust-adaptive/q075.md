# Q075. MPC 和 LQR 最大区别是什么？

## PDF 原始内容（完整保留）

### 标准回答

MPC 每个采样时刻基于当前状态，求有限预测时域内的最优控制序列，并显式加入输入、状态和输出约束；只执行第一步，然后滚动重算。无约束线性二次、足够合适终端 cost 的极限情形与 LQR 密切相关。MPC 的核心优势是约束处理与未来预测，代价是在线优化和模型依赖。

### 公式与推导

$$
\min_{u_0\ldots u_{N-1}}\sum_{k=0}^{N-1}(x_k^TQx_k+u_k^TRu_k)+x_N^TPx_N
$$
subject to dynamics and constraints.

### 工程直觉

LQR 给一个固定线性反馈律；MPC 每一步都“看未来 N 步并考虑道路边界/执行器上限”，然后只走第一步。

### 常见误区 / Gotcha

MPC 不是“有优化器就一定更好”。若模型差、solver deadline 不可靠或 horizon/terminal design 不当，同样可能表现很差。

### 30 秒口述版

> MPC 的关键是 receding horizon + explicit constraints。它每次优化未来 N 步，只实施第一个动作，再用新测量滚动重算；非常适合受约束 MIMO 系统。

## 仓库增强：深度展开

现代控制算法不要用“高级程度”排序，而要按它们解决的问题排序：Pole placement 解决极点位置，LQR 解决二次代价下的反馈权衡，Kalman 解决随机估计，MPC 解决有限时域优化与显式约束，鲁棒控制解决模型族的最坏情况，自适应控制解决在线参数变化。

面试时最有价值的回答通常是“为什么需要它，而不是更简单的方法”。如果没有约束，MPC 未必优于精心设计的 LQR；如果模型不确定性很小，也未必需要 $H_\infty$。

### 针对本题的进一步理解

MPC 每次求有限时域最优轨迹，只执行第一步再滚动重算。它最值得付出计算代价的场景通常是多变量耦合和显式约束。

从面试表达角度，建议把本题组织成四层：

1. **定义层**：先说明对象、变量和适用条件；
2. **数学层**：给最小但足够的关键公式，并解释每一项；
3. **物理层**：把公式映射成能量、时间尺度、频率或信息流；
4. **工程层**：主动说明噪声、延迟、饱和、模型误差或采样等边界。

### 工程场景

以自动驾驶轨迹控制为例，LQR 可在局部线性模型下快速给出反馈；加入方向盘角度/变化率和道路边界约束后，MPC 的优势才真正出现。

将这个场景与当前问题连接时，重点不是套算法名称，而是问：**这个概念会改变哪个闭环信号路径、哪个动态时间尺度、哪个约束余量？** 这能把抽象理论转成可验证的设计判断。

### 1. 核心边界：最优、鲁棒与约束

所谓最优都依赖代价、模型和假设；成熟回答要同时讨论 Q/R 或权重、约束、模型误差和在线计算。

**针对 Q075 的专家补充：** MPC 每次求有限时域约束优化，只执行第一个控制量，再用新状态滚动重算，因此天然形成 feedback。terminal cost/set 对递归可行性和稳定性很重要；explicit MPC 则预先离线求出分段仿射控制律。

### 2. 推导路线与适用条件

1. 先把目标写成 cost、约束或 uncertainty set。
2. 推导最优/鲁棒条件（Riccati、receding horizon、small-gain 或 weighted norm）。
3. 再说明模型假设、在线计算、constraint 和 robustness 的边界。

在白板面试中，建议把“公式”与“成立条件”写在同一块区域。例如写出一个二阶近似或稳定性结论后，紧跟一句：**假设高阶模态足够远、没有显著 RHP 零点/纯延迟、执行器未饱和**。这能明显区分“会背公式”和“会使用模型”。

### 3. 一个可计算的小例子

对双积分器 $\dot x=[0\;1;0\;0]x+[0,1]^Tu$，比较 $Q=\mathrm{diag}(1,1),R=1$ 与 $Q=\mathrm{diag}(100,1),R=0.1$。记录 poles、settling time、peak u；再加入 $|u|\le1$ 看为什么 unconstrained LQR 与 MPC 的结论不同。

这个例子的目的不是训练固定数字，而是练习从 **模型 → 指标 → 非理想因素 → 结论变化** 的完整链路。建议在 Python/MATLAB 中把关键参数做 sweep，而不是只跑一个点。

### 5. 高频追问详答

#### 1. 为什么只执行第一步？

执行后系统会收到新 measurement，模型误差和扰动使原先整条 open-loop optimal sequence 不再最优。只执行第一步并滚动重算，才能把优化器变成 feedback controller。

#### 2. terminal cost/terminal set 有什么作用？

Terminal cost 常近似剩余无限时域 cost，terminal set 则保证在预测末端存在一个局部控制律可持续满足约束。两者用于建立递归可行性与稳定性证明，而不只是数值调参。

#### 3. explicit MPC 是什么？

对线性系统、二次 cost 和多面体约束，可离线求解参数化 QP，把状态空间划分成多个 polyhedral regions，每个区域控制律是仿射函数。在线只需区域查找，适合算力有限但维数不高的系统。

### 6. 反例与失效条件

- **模型层失效**：如果出现未建模柔性模态、显著时延、RHP 零点、强耦合或工作点迁移，原题中的低阶/线性结论可能只在局部成立。
- **实现层失效**：sampling、quantization、filter、scheduler、actuator saturation/rate limit 会改变实际闭环，不应被当作“软件细节”。
- **评价层失效**：只看一个 step response 或单一 PM/GM 容易漏掉噪声、控制努力、内部状态和 worst-case parameter spread。
- **验证原则**：每个重要结论至少对应一个可证伪预测；例如“若根因是 delay margin 不足，则降低 crossover 或减少 latency 后振荡应系统性减弱”。
