# Q100. 终极调试题：闭环性能突然变差，你如何用数据而不是猜测定位？

## 面试官为什么问这题

这道题属于 **非线性与系统级工程面试** 的核心知识链。面试官通常不只检查定义，而是通过连续追问观察你是否能把**数学结构、物理直觉、工程约束和验证方法**连接起来。建议先用 30 秒给结论，再根据追问展开公式与边界条件。

## PDF 原始内容（完整保留）

### 标准回答

先建立“变化发生前后”的对照数据：reference、error、raw measurement、state estimate、P/I/D 或 feedback components、feedforward、raw/saturated actuator、CPU timing 和关键 operating conditions。用频谱/FRF 看新增频率成分，用 residual/innovation 看 sensor/model 是否异常，用 saturation statistics 看 actuator margin，用 timing histogram 看实时性。然后一次只修改一个假设，做可重复 A/B 实验。最终输出应是可证伪的根因链，而不是“参数不合适”。

### 公式与推导

诊断可分成四类残差：
$$
\text{tracking residual},\quad
\text{model/innovation residual},\quad
\text{actuator residual}=u_{raw}-u_{act},\quad
\text{timing residual}.
$$

### 工程直觉

控制调试本质上是闭环系统辨识：哪些信号先异常、在哪个频率异常、是否伴随饱和/延迟，能把根因空间快速缩小。

### 常见误区 / Gotcha

只看 y(t) 一条曲线几乎无法诊断。没有内部 control components、actual actuator 和 timestamps 的日志，很多问题只能猜。

## 仓库增强：深度展开

非线性控制题最重要的是说明**局部结论和全局结论的边界**。Jacobian 线性化给局部模型，Lyapunov 可以直接证明更大区域的稳定性，feedback linearization/backstepping/sliding mode 则利用结构主动设计非线性反馈。

系统级工程题则考证据链。优秀调试不是“猜一个参数再试”，而是从日志、频谱、残差、饱和统计和时序数据提出可证伪假设，再通过 A/B 实验把根因固化成 regression test。

### 针对本题的进一步理解

数据驱动调试要构造可证伪假设。一次只改一个变量，记录前后对照，并把最终根因转成自动 regression test，才算完成工程闭环。

从面试表达角度，建议把本题组织成四层：

1. **定义层**：先说明对象、变量和适用条件；
2. **数学层**：给最小但足够的关键公式，并解释每一项；
3. **物理层**：把公式映射成能量、时间尺度、频率或信息流；
4. **工程层**：主动说明噪声、延迟、饱和、模型误差或采样等边界。

### 工程场景

以机械臂为例，大范围运动时惯性矩阵与重力项显著非线性；局部线性控制可做定点稳定，而 computed-torque/feedback-linearization 类方法会显式利用动力学结构。

将这个场景与当前问题连接时，重点不是套算法名称，而是问：**这个概念会改变哪个闭环信号路径、哪个动态时间尺度、哪个约束余量？** 这能把抽象理论转成可验证的设计判断。

## 专家版扩展 v2

> **内容边界**：本节是仓库第二版扩展，基于经典控制理论与工程实践补充；它不改写上面的 PDF 原始内容。若扩展结论需要额外假设，会在正文中显式说明。

### 1. 核心边界：非线性与系统级验证

局部线性结论、全局稳定性、执行器非线性和现场数据诊断必须区分。工程问题最终要落到可验证假设和安全试验。

**针对 Q100 的专家补充：** 高级控制调试的核心是建立时间同步的证据链：reference/error、raw/filtered sensor、state estimate、各控制分量、raw/actual actuator、saturation、timestamp、operating condition。任何根因都应对应可证伪预测，并最终沉淀成自动 regression test。

### 2. 推导路线与适用条件

1. 明确非线性结构、平衡点/轨迹和约束。
2. 选择 Lyapunov、feedback linearization、sliding/backstepping 或诊断 residual 建立可证明/可证伪链。
3. 最后检查 region of attraction、saturation、sensor/actuator dynamics 和实机安全验证。

在白板面试中，建议把“公式”与“成立条件”写在同一块区域。例如写出一个二阶近似或稳定性结论后，紧跟一句：**假设高阶模态足够远、没有显著 RHP 零点/纯延迟、执行器未饱和**。这能明显区分“会背公式”和“会使用模型”。

### 3. 一个可计算的小例子

构造一个含 saturation、10–20 ms delay、measurement noise 的二阶/倒立摆最小模型。先在理想条件下验证理论，再逐个打开非线性和实现因素；每次只改一个变量并记录 residual，从而区分理论失效与实现失效。

这个例子的目的不是训练固定数字，而是练习从 **模型 → 指标 → 非理想因素 → 结论变化** 的完整链路。建议在 Python/MATLAB 中把关键参数做 sweep，而不是只跑一个点。

### 4. 工程验证矩阵

| 验证层 | 建议实验 | 想证明什么 |
|---|---|---|
| Theory | Lyapunov/非线性条件 | 证明或局部边界 |
| Non-ideal | saturation/delay/noise | 发现 limit cycle |
| Evidence | logs/FRF/residual | 形成可证伪根因 |

### 5. 高频追问详答

#### 1. 如何设计 control KPI 自动监控？

KPI 应同时覆盖 performance、robustness proxy 和 implementation：RMS/peak tracking error、settling/overshoot、control RMS/peak/rate、saturation duty、innovation NIS/whiteness、timing jitter/deadline miss、关键频段 PSD。并按 operating condition 分桶，避免平均值掩盖局部故障。

#### 2. innovation 变大通常意味着什么？

Innovation 变大表示 measurement 与 model prediction 的不一致增加，可能来自 sensor bias/noise 变化、模型参数漂移、外扰、时间戳错位或 Q/R 过小导致过度自信。应同时看 innovation mean、covariance、频谱和 NIS，而不是仅看绝对值。

#### 3. 如何把一次现场故障转成长期 regression test？

保存能复现故障的最小数据/场景和 software/calibration version，定义一个在旧版本失败、新版本通过的量化 KPI，再加入 SIL/HIL/CI 自动执行。这样现场故障才真正转化为长期工程资产。

### 6. 反例与失效条件

- **模型层失效**：如果出现未建模柔性模态、显著时延、RHP 零点、强耦合或工作点迁移，原题中的低阶/线性结论可能只在局部成立。
- **实现层失效**：sampling、quantization、filter、scheduler、actuator saturation/rate limit 会改变实际闭环，不应被当作“软件细节”。
- **评价层失效**：只看一个 step response 或单一 PM/GM 容易漏掉噪声、控制努力、内部状态和 worst-case parameter spread。
- **验证原则**：每个重要结论至少对应一个可证伪预测；例如“若根因是 delay margin 不足，则降低 crossover 或减少 latency 后振荡应系统性减弱”。

### 7. 面试回答的三档深度

**30 秒：** 先复述上面的“30 秒口述版”，只讲定义、关键公式和一个 trade-off。

**2 分钟：** 增加推导路线中的 2–3 步，并主动说明一个适用条件/反例；这是大多数技术面最合适的深度。

**5 分钟以上：** 画框图或 pole/Bode/state diagram，把工程验证矩阵讲出来；如果面试官继续追问，再进入数值例子、robustness 或 implementation details。

### 8. 自测题

1. 不看笔记，用 60 秒回答：**终极调试题：闭环性能突然变差，你如何用数据而不是猜测定位？**
2. 把答案中的一个理想假设替换成非理想条件（delay / saturation / noise / model uncertainty / sampling），结论如何变化？
3. 给出一个你会记录的日志/频域/状态变量，用于验证答案不是纸面推导。

## 实验 / 仿真建议

- 先建立一个**最小可复现实验**，只保留与本题相关的动态；
- 同时画时域与频域结果，不要只看单一阶跃曲线；
- 对关键参数做至少一个数量级内的 sweep，观察结论是否稳健；
- 主动加入一种非理想因素（noise / delay / saturation / model error / sampling），验证理论边界；
- 将结论写成“可证伪预测”，例如：如果根因是 phase margin 不足，那么降低 crossover 后振荡应按可预期方式减弱。
