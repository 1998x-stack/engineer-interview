Constant Memory 什么访问模式最快？

一句话核心：constant memory 最理想是 warp 内 broadcast 同一地址；若每个 lane 访问不同 constant 地址，访问可能被序列化，优势会消失。

章节：第 2 章 · GPU Memory Hierarchy
难度：★☆☆ · 频率：高 · 标签：Constant / Broadcast

PDF 基线题解

考察意图

考察特殊 memory path 的访问模式。

思路拆解

Constant cache 特别适合一个 warp 中许多线程读取相同地址，因为硬件可广播。若 32 lanes 读取 32 个不同 constant addresses，访问可能被序列化，优势消失。

标准回答

  • 适合小型只读参数、查表常量、每 warp 一致的标量。
  • “只读”不是选择 constant memory 的充分条件；关键是 warp 内地址是否高度一致。
  • 容量与 cache 资源有限，不适合大规模随机 lookup。

Gotchas：常见失分点

  • 回答“所有只读数组都应该放 constant memory”。

面试官可能继续追问

  • constant 与 __ldg/read-only cache 的差别？
  • 每个 lane 不同地址时会发生什么？

深入分析

constant memory 最理想是 warp 内 broadcast 同一地址；若每个 lane 访问不同 constant 地址，访问可能被序列化，优势会消失。

深入理解：性能首先是“数据在哪里”

内存层级题要用 容量、作用域、管理方式、延迟/带宽、可见性、占用资源 六个维度比较，而不是简单排序“register 最快、HBM 最慢”。很多优化本质是把数据从低复用、高成本层级搬到高复用、低成本层级，并控制搬运次数。

HBM/DRAM → L2 → L1/Shared → Register
                ↑ programmer-managed reuse often happens here

同时要记住：register/shared 是稀缺的片上资源，它们会反过来限制 residency；因此数据越靠近计算单元并不自动意味着 kernel 越快。

实战验证建议

建议为本题建立一个最小可复现实验（microbenchmark）：

  1. 写一个正确但未优化的 baseline。
  2. 只改变一个变量（访问模式、tile、block size、register budget、pipeline stage 等）。
  3. 使用 CUDA Event 做设备侧计时，至少 warm-up 后重复多次。
  4. 使用 Nsight Compute 收集与本题直接相关的指标：register count / spill、shared-memory usage、L1/L2 hit rate、DRAM bytes。
  5. 把结果写成“假设 → 指标变化 → 时间变化 → 结论”，而不是只保存最终最快参数。

专业增强版 V2：机制、量化与验证

本节是在 PDF 基线题解之上的仓库扩展。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

1. 硬件机制与核心心智模型

Constant memory 的经典优势是 warp-uniform address：多个 lane 读取同一地址时可 broadcast。若同 warp 访问许多不同 constant 地址，访问会分成多个请求，优势显著下降。

2. 定量推导 / 性能模型

可把一个 warp 的 distinct constant addresses 数记为 $D$；理想 $D=1$ 近似 broadcast，$D$ 增大时序列化/请求数随之增加。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

3. 代码 / 白板核心片段

__constant__ float coeff[64];
float c = coeff[k_uniform]; // warp 内 k_uniform 相同最理想

白板代码优先保证：边界正确、同步范围正确、地址模式可解释。如果为了展示优化而省略边界处理，要主动说明省略条件。

4. Nsight 证据链：怎样证明你的判断

  • Constant cache / memory-related counters（按工具版本）
  • Kernel time 对不同 distinct-address 数的敏感性
  • SASS/Source：确认访问确实使用 constant path

推荐把分析写成四列：

假设 预期指标变化 实测指标变化 结论
当前瓶颈是本题讨论的问题 指标应出现可预测变化 benchmark 后填写 接受 / 推翻假设
优化应减少对应硬件成本 时间与因果指标同向改善 benchmark 后填写 是否保留优化

5. 架构迁移视角

constant memory 是长期稳定的特殊只读空间；现代通用 L1/L2 更强后，其收益更依赖“warp 广播”而非简单的“只读”。

这里要区分两类知识：

  • 稳定原理：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
  • 架构实现：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

6. 可复现实验（建议真的做）

让 warp 分别访问 1、2、4、8、32 个不同 constant 地址，测时间并与普通 global readonly 数据比较。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
