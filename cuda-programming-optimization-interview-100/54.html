手写 Parallel Scan / Prefix Sum：Hillis-Steele 与 Blelloch 如何比较？

一句话核心：Hillis-Steele 结构简单但 work 为 O(N log N)；Blelloch 可做到 O(N) work，通过 upsweep/downsweep 适合并行 prefix。

章节：第 6 章 · 经典 CUDA Kernel 现场编程
难度：★★★ · 频率：高 · 标签：Coding / Scan

PDF 基线题解

考察意图

考察经典并行算法与 work efficiency。

思路拆解

Hillis-Steele 易写但做 O(N log N) work；Blelloch 采用 up-sweep + down-sweep，work O(N)，更适合构建高效 block scan。实际工程优先 CUB BlockScan/DeviceScan。

标准回答

  • Hillis-Steele 每轮 offset 加倍，轮数 O(log N)，但每轮很多元素做加法。

  • Blelloch up-sweep 构建 reduction tree，down-sweep 传播 prefix，可实现 exclusive scan。

  • 大数组通常分块：block scan + block sums scan + uniform add。
  • shared-memory 实现需要处理 bank conflict；warp scan 可用 shuffle 优化。

代码 / 白板骨架

// Warp inclusive scan 核心片段
unsigned mask = __activemask();
for (int offset = 1; offset < 32; offset <<= 1) {
float y = __shfl_up_sync(mask, x, offset);
if ((threadIdx.x & 31) >= offset) x += y;
}

Gotchas：常见失分点

  • 把 inclusive/exclusive scan 混淆。
  • 忘记多 block 的 block sums 二次扫描。

面试官可能继续追问

  • scan 为什么是 stream compaction 的核心？
  • segmented scan 怎么做？

深入分析

Hillis-Steele 结构简单但 work 为 O(N log N)；Blelloch 可做到 O(N) work，通过 upsweep/downsweep 适合并行 prefix。工程上还要处理 block 间 scan 与 segmented scan。

深入理解：经典算法题考的是“逐版优化能力”

现场 coding 题通常不要求一步写出最优 kernel，而是考察你能否从正确的 baseline 出发，逐个消除瓶颈：

Correct baseline
→ coalesced access
→ shared/register reuse
→ reduce divergence/barriers
→ warp primitive
→ vectorization / multi-element per thread
→ device-wide library / architecture specialization

每一版都要能说明：减少了什么成本、引入了什么新约束、用什么指标验证。

实战验证建议

建议为本题建立一个最小可复现实验（microbenchmark）：

  1. 写一个正确但未优化的 baseline。
  2. 只改变一个变量（访问模式、tile、block size、register budget、pipeline stage 等）。
  3. 使用 CUDA Event 做设备侧计时，至少 warm-up 后重复多次。
  4. 使用 Nsight Compute 收集与本题直接相关的指标：kernel time、memory throughput、branch/barrier stalls、atomic throughput、correctness error。
  5. 把结果写成“假设 → 指标变化 → 时间变化 → 结论”，而不是只保存最终最快参数。

专业增强版 V2：机制、量化与验证

本节是在 PDF 基线题解之上的仓库扩展。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

1. 硬件机制与核心心智模型

Hillis–Steele scan 实现直观、每轮所有元素参与，work 为 $O(N\log N)$；Blelloch 通过 up-sweep/down-sweep 做 work-efficient scan，总 work $O(N)$，但同步和索引更复杂。现代库通常使用分层 warp/block/device scan。

2. 定量推导 / 性能模型

Hillis–Steele 约 $N\log_2 N$ 次 combine；Blelloch 约 $2(N-1)$ 次 combine，深度同为 $O(\log N)$。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

4. Nsight 证据链：怎样证明你的判断

  • Barrier count
  • Shared bank conflicts
  • Work efficiency / instruction count
  • Device-wide multi-block scan 的 extra passes

推荐把分析写成四列：

假设 预期指标变化 实测指标变化 结论
当前瓶颈是本题讨论的问题 指标应出现可预测变化 benchmark 后填写 接受 / 推翻假设
优化应减少对应硬件成本 时间与因果指标同向改善 benchmark 后填写 是否保留优化

5. 架构迁移视角

Warp shuffle 可显著优化 warp-local scan；CUB BlockScan/DeviceScan 已实现复杂架构优化，工程优先使用。

这里要区分两类知识：

  • 稳定原理：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
  • 架构实现：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

6. 可复现实验（建议真的做）

对 N=1K~100M 比较 Hillis–Steele、Blelloch、CUB；同时报告 work count 与实际时间，说明理论 work efficiency 如何落到硬件。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
