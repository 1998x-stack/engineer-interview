# Q031｜Shared Memory Bank 是什么？

> **一句话核心**：shared bank 可理解为并行服务的地址分片。
>
> **章节**：第 4 章 · Shared Memory、Warp 与 Divergence  
> **难度**：★☆☆ · **频率**：极高 · **标签**：Bank / Shared Memory

## PDF 基线题解

## 考察意图
考察 shared-memory 并发访问的硬件组织。

## 思路拆解
Shared memory 被划分为多个可并行服务的 banks。对 CC 5.x+ 的常见模型，32 banks、连续 32-bit words 映射到连续
banks，与 32-lane warp 对齐。

## 标准回答
- 如果 warp 的 32 个请求落在 32 个不同 banks，可高度并行服务。
- 地址到 bank 的直观映射可近似理解为 `(address/4) mod 32`（针对 32-bit word 的常见情形）。
- 具体低层行为与访问宽度/架构有关，因此公式是分析起点而不是所有情况的完备模型。

## Gotchas：常见失分点
- 把 bank 当成 cache line。

## 面试官可能继续追问
- 64-bit access 怎么分析？
- swizzle 为什么能替代简单 padding？

## 深入分析

shared bank 可理解为并行服务的地址分片。最常见 32-bit word 情况下，用 word index 对 bank count 取模即可快速判断典型 conflict。

### 深入理解：Shared Memory 不是“自动高速缓存”

Shared memory 的价值来自可控复用与线程协作，但必须同时处理 **bank mapping、同步、layout**。分析 bank conflict 时，应写出每个 lane 的 word address，再做 `bank = word_index mod bank_count` 的映射。

Warp-level primitive 则是在“线程之间交换数据”这个问题上绕开 shared-memory round trip；其代价是作用域更小，并要求正确的 active mask 与同步语义。

### 架构视角

bank 组织和共享内存能力随架构演进，但“按 lane 地址映射 bank、避免同 bank 不同地址冲突”的分析方法稳定。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

Shared memory 被划分为多个 bank，以便一个 warp 的不同地址并行服务。核心不是“shared 很快”，而是让 lane→bank 映射尽量均匀；同一 bank 的不同地址会被拆成多次 conflict-free 请求。

### 2. 定量推导 / 性能模型

32-bit word 常用简化映射 $bank=(address/4)\bmod32$；对 stride 为 $s$ words 的访问，冲突度与 $gcd(s,32)$ 密切相关。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
int bank = (word_index) & 31; // 教学上的简化映射
// 实际分析按数据宽度和指令访问粒度确认。
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Shared Load/Store transactions per request`
- `Bank conflict counters`
- `Shared throughput`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

CUDA Best Practices 对 CC 5.x+ 的经典模型仍是 32 banks、连续 32-bit words 映射连续 bank；特殊指令/更宽访问要结合实际指令分析。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

让 warp 以 shared stride=1,2,4,8,16,32 访问，测 conflict 与 latency。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
