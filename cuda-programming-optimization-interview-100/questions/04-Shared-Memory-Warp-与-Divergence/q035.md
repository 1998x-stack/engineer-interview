# Q035｜什么是 Warp Divergence？

> **一句话核心**：divergence 是同一 warp 的 lane 走不同控制流路径。
>
> **章节**：第 4 章 · Shared Memory、Warp 与 Divergence  
> **难度**：★☆☆ · **频率**：极高 · **标签**：Divergence / Warp

## PDF 基线题解

## 考察意图
考察控制流效率。

## 思路拆解
Divergence 是同一 warp 内 active lanes 需要执行不同控制流路径。硬件会分别执行这些路径并用 mask 屏蔽不参与的
lanes，所以有效 lane utilization 下降。

## 标准回答
- 关键是“同一 warp 内”是否分歧，而不是是否存在 branch。
- 若整个 warp 条件一致，即使不同 warps 走不同分支，也不会产生 warp 内 divergence。
- 长且代价相近的两条路径最容易造成明显浪费；短分支可能被 predication。

## Gotchas：常见失分点
- “有 if 就 divergence”。

## 面试官可能继续追问
- 数据排序能否减少 divergence？
- divergence 与 memory coalescing 会如何耦合？

---

## 深入分析

divergence 是同一 warp 的 lane 走不同控制流路径。成本取决于各路径的执行比例和重汇合，不是看到 branch 就自动判定慢。

### 深入理解：Shared Memory 不是“自动高速缓存”

Shared memory 的价值来自可控复用与线程协作，但必须同时处理 **bank mapping、同步、layout**。分析 bank conflict 时，应写出每个 lane 的 word address，再做 `bank = word_index mod bank_count` 的映射。

Warp-level primitive 则是在“线程之间交换数据”这个问题上绕开 shared-memory round trip；其代价是作用域更小，并要求正确的 active mask 与同步语义。

### 架构视角

bank 组织和共享内存能力随架构演进，但“按 lane 地址映射 bank、避免同 bank 不同地址冲突”的分析方法稳定。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

Warp divergence 是同一 warp 的 lane 在某段控制流上需要执行不同路径。硬件使用 active mask/predication 分阶段完成各路径，所以总耗时更接近各被执行路径成本之和，而不是最大值。

### 2. 定量推导 / 性能模型

两条路径成本 $C_A,C_B$，且都被 warp 中至少一个 lane 采用时，粗略执行成本接近 $C_A+C_B$；若只有一条路径被采用则没有 divergence penalty。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
if ((threadIdx.x & 31) < 16) A();
else B();
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Branch Efficiency / divergent branches`
- `Warp execution efficiency / active lanes`
- `Instruction count per warp`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

Independent thread scheduling 改善灵活性但不消除 divergence 的吞吐代价；数据/任务重排仍是关键。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

同 warp 与跨 warp 两种分组方式执行同样 50/50 A/B 任务，证明“分支比例相同”但 divergence 不同。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
