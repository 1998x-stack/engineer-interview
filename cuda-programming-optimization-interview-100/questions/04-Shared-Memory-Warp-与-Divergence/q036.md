# Q036｜`if` 一定产生 Divergence 吗？如何重构控制流？

> **一句话核心**：`if` 的条件若在 warp 内一致就没有 divergence。
>
> **章节**：第 4 章 · Shared Memory、Warp 与 Divergence  
> **难度**：★☆☆ · **频率**：高 · **标签**：Branch / Predication

## PDF 基线题解

## 考察意图
考察能否把条件表达式映射到 warp lane 分布。

## 思路拆解
例如条件以 warpId 为单位变化时，warp 内所有 lanes 一致，不产生 divergence。重构时可以通过数据分组、warp-
granular mapping 或把短分支交给 predication，减少分歧。

## 标准回答
- 分析 predicate 在 32 lanes 上的分布。
- 尽量让同类数据由同一 warp 处理；必要时先 compaction/bucketing。
- 不要为了消 branch 引入大量额外 arithmetic 或 memory traffic。

## Gotchas：常见失分点
- 用 branchless 技巧导致更多指令，但没有 benchmark。

## 面试官可能继续追问
- 什么时候 branchless 反而更慢？
- Nsight 哪些指标显示 branch efficiency？

## 深入分析

`if` 的条件若在 warp 内一致就没有 divergence。重构方法包括按数据分组、改变 thread mapping、把短分支交给 predication，或减少路径长度差。

### 深入理解：Shared Memory 不是“自动高速缓存”

Shared memory 的价值来自可控复用与线程协作，但必须同时处理 **bank mapping、同步、layout**。分析 bank conflict 时，应写出每个 lane 的 word address，再做 `bank = word_index mod bank_count` 的映射。

Warp-level primitive 则是在“线程之间交换数据”这个问题上绕开 shared-memory round trip；其代价是作用域更小，并要求正确的 active mask 与同步语义。

### 性能因果链

```text
题目现象 / 代码模式
        ↓
定位真实硬件行为
        ↓
识别主要资源或依赖
        ↓
提出一个可证伪优化假设
        ↓
修改实现
        ↓
Profiler 指标 + Kernel Time 验证
```

对于本题，建议至少观察：`shared bank conflicts`、`warp execution efficiency`、`branch efficiency`、`barrier stalls`。

### 架构视角

bank 组织和共享内存能力随架构演进，但“按 lane 地址映射 bank、避免同 bank 不同地址冲突”的分析方法稳定。

1. 写一个**正确但未优化**的 baseline。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

`if` 只有在同 warp lane 条件不同且编译成控制流时才产生 divergence。若条件在 warp 内 uniform，或者短分支被 predication，`if` 几乎不带传统 divergence 成本。重构应围绕 lane grouping、work compaction，而非删除语法。

### 2. 定量推导 / 性能模型

判断条件是否 uniform 可考虑 $U=|\{predicate_i\}|$；$U=1$ 时 warp 内无路径分裂，$U>1$ 才有潜在 divergence。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
// warp-uniform
if ((threadIdx.x >> 5) < 4) A();
// lane-divergent
if ((threadIdx.x & 31) < 16) A();
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Branch statistics`
- `Source/SASS 是否使用 branch 或 predication`
- `Active threads per warp`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

Volta+ 的独立调度让不安全的隐式 warp 同步更值得警惕，但并没有把 divergence 变免费。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

把随机 flags 先 prefix-sum/partition，再处理两类任务，对比直接 branch 与 compaction 的收益和额外数据移动成本。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
