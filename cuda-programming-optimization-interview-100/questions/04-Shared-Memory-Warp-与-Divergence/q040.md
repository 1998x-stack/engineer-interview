# Q040｜如何写一个 Warp-Level Reduction？

> **一句话核心**：warp reduction 通常做 log2(32)=5 轮 shuffle-down。
>
> **章节**：第 4 章 · Shared Memory、Warp 与 Divergence  
> **难度**：★★☆ · **频率**：极高 · **标签**：Reduction / Shuffle

## PDF 基线题解

## 考察意图
考察你能否把树形 reduction 映射为 5 次 shuffle。

## 思路拆解
32-lane warp 的和可以按 offset 16、8、4、2、1 做 `__shfl_down_sync`，每轮让低 lane 累加来自更高 lane 的值。完
整 block reduction 通常先每 warp reduction，再把 warp sums 合并。

## 标准回答
- 32 个值归约到 1 个需要 log2(32)=5 轮。
- partial warp 要用 `__activemask()` 或 `__ballot_sync` 构造有效 mask。
- 对于 floating-point sum，树形顺序与串行顺序不同，数值结果可能有舍入差异。

## 代码 / 白板骨架

```cpp
__device__ float warp_sum(float x, unsigned mask) {
for (int offset = 16; offset > 0; offset >>= 1)
x += __shfl_down_sync(mask, x, offset);
return x;
}

```

- 只会写 shared-memory reduction。

## 深入分析

warp reduction 通常做 log2(32)=5 轮 shuffle-down。partial warp 必须构造正确 mask，并避免让 inactive lane 的值参与结果。

### 深入理解：Shared Memory 不是“自动高速缓存”

Shared memory 的价值来自可控复用与线程协作，但必须同时处理 **bank mapping、同步、layout**。分析 bank conflict 时，应写出每个 lane 的 word address，再做 `bank = word_index mod bank_count` 的映射。

Warp-level primitive 则是在“线程之间交换数据”这个问题上绕开 shared-memory round trip；其代价是作用域更小，并要求正确的 active mask 与同步语义。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

Warp reduction 的关键是确定参与 lane 的 mask、用 shuffle-down 构建树，并明确结果最终位于哪个 lane。对于 partial warp，必须保证读取的 source lane 是有效参与者。

### 2. 定量推导 / 性能模型

完整 32-lane reduction 需要 5 轮；复杂度每 warp $O(\log W)$ steps，总算术 work 仍为 $W-1$ 次加法。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
unsigned mask = __ballot_sync(0xffffffff, valid);
float v = valid ? x : 0.f;
for (int off=16; off>0; off>>=1)
  v += __shfl_down_sync(mask, v, off);
if ((threadIdx.x & 31) == 0) out[warp_id] = v;
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Instruction count`
- `Warp active mask/correctness`
- `Shared/barrier 指令为零或显著减少`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

大规模 block/device reduction 通常把 warp reduction 作为最后一级 primitive；工程上 CUB 的 warp/block reduction 更值得直接使用。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

实现 full warp、partial warp、非连续 active mask 三种情况；对照 CPU sum 验证 mask 处理。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
