# Q059｜如何实现 Stream Compaction？

> **一句话核心**：stream compaction 的标准分解是 predicate → prefix sum → scatter。
>
> **章节**：第 6 章 · 经典 CUDA Kernel 现场编程  
> **难度**：★★☆ · **频率**：高 · **标签**：Coding / Scan

## PDF 基线题解

## 考察意图
考察 predicate→scan→scatter 的标准并行模式。

## 思路拆解
先为每个元素计算 keep flag（0/1），对 flags 做 exclusive scan 得到每个保留元素的目标位置，再并行 scatter。若保留
比例很低，也可讨论 warp ballot/atomic chunk allocation。

## 标准回答
- flags[i] = predicate(x[i])。
- pos = exclusive_scan(flags)。
- 若 flags[i]=1，则 out[pos[i]]=x[i]。
- 输出总数 = pos[N-1]+flags[N-1]。
- 工程上可使用 CUB DeviceSelect；自写时重点是 scan 和 memory traffic。

## Gotchas：常见失分点
- 每个保留元素直接 global atomic 申请位置而不讨论 contention。

## 面试官可能继续追问
- warp ballot 如何做小规模 compaction？
- 稳定 compaction 与不稳定 compaction 的区别？

## 深入分析

stream compaction 的标准分解是 predicate → prefix sum → scatter。面试深入点包括：如何减少中间数组、如何用 warp ballot/popc 做局部 compaction。

### 深入理解：经典算法题考的是“逐版优化能力”

现场 coding 题通常不要求一步写出最优 kernel，而是考察你能否从正确的 baseline 出发，逐个消除瓶颈：

```text
Correct baseline
→ coalesced access
→ shared/register reuse
→ reduce divergence/barriers
→ warp primitive
→ vectorization / multi-element per thread
→ device-wide library / architecture specialization
```

每一版都要能说明：**减少了什么成本、引入了什么新约束、用什么指标验证**。

### 性能因果链

```text
题目现象 / 代码模式
        ↓
定位真实硬件行为
        ↓
识别主要资源或依赖
        ↓
提出一个可证伪优化假设
        ↓

        ↓

```

对于本题，建议至少观察：`kernel time`、`memory throughput`、`branch/barrier stalls`、`atomic throughput`、`correctness error`。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

Stream compaction 通常是 predicate→scan→scatter：predicate 产生 0/1 flags，exclusive scan 给每个保留元素唯一输出位置，scatter 完成稳定压缩。优化重点是避免额外 passes、提升 scan 和 memory coalescing。

### 2. 定量推导 / 性能模型

输出大小 $M=\sum_i flag_i$；exclusive position $pos_i=\sum_{j<i} flag_j$。这两个量自然由 reduction/scan 得到。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
flag = pred(x[i]);
// pos = exclusive_scan(flag)
if(flag) out[pos[i]] = x[i];
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Number of passes / DRAM bytes`
- `Scan throughput`
- `Scatter coalescing 与 output density`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

稀疏/高选择率场景可考虑 warp ballot + local prefix 来减少全局 scan 压力；工程上 CUB DeviceSelect 是基线。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

保留率 1%、10%、50%、90% 下比较 full scan、warp-aggregated、CUB；解释选择率对最优策略的影响。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
