# Q081｜为什么 GEMM 是 CUDA 性能优化的“综合大题”？

> **一句话核心**：GEMM 把 coalescing、shared/register reuse、tiling、Tensor Core、pipeline、occupancy、epilogue 全部集中在一个 kernel，是最典型的综合性能题。
>
> **章节**：第 9 章 · GEMM、Tensor Core 与 CUTLASS  
> **难度**：★★☆ · **频率**：极高 · **标签**：GEMM / 综合

## PDF 基线题解

## 考察意图
考察能否把 memory hierarchy 与 compute pipeline 串起来。

## 思路拆解
GEMM 同时要求 global coalescing、shared-memory tiling、register blocking、Tensor Core/MMA、software
pipeline、occupancy/ILP、epilogue 和 scheduler。它几乎覆盖现代 CUDA kernel 的全部核心主题。

## 标准回答
- 数据路径：HBM/L2 → shared → registers/TMEM → Tensor Core。
- 并行层次：CTA tile → warp/warp-group tile → MMA tile → thread/register fragment。
- 控制层：async copy/TMA、barrier、multi-stage pipeline、warp specialization。
- 因此“会写 naive tiled GEMM”和“理解 CUTLASS 级 GEMM”是两个层次。

## Gotchas：常见失分点
- 只会 shared-memory textbook GEMM，就认为掌握现代 GEMM。

## 面试官可能继续追问
- CUTLASS mainloop 与 epilogue 分别做什么？
- 为什么 attention 优化也大量借鉴 GEMM tiling？

## 深入分析

GEMM 把 coalescing、shared/register reuse、tiling、Tensor Core、pipeline、occupancy、epilogue 全部集中在一个 kernel，是最典型的综合性能题。

### 深入理解：GEMM 是“数据移动 + 复用 + 专用计算单元”的综合优化

现代 GEMM 的关键不是三重 for-loop，而是让 A/B 数据沿 **HBM → shared → register/TMEM → Tensor Core** 的路径被尽量多次复用，并通过多级 tiling 与 pipeline 保持计算单元持续供料。

CUTLASS/CuTe 的价值就在于把 tile shape、copy atom、MMA atom、pipeline、scheduler、epilogue 拆成可组合策略；面试中要能解释这些抽象对应什么硬件约束。

### 性能因果链

```text
题目现象 / 代码模式
        ↓
定位真实硬件行为
        ↓
识别主要资源或依赖
        ↓
提出一个可证伪优化假设
        ↓
修改实现
        ↓
Profiler 指标 + Kernel Time 验证
```

对于本题，建议至少观察：Tensor Core utilization、DRAM/shared traffic、arithmetic intensity、pipeline stalls。

### 架构视角

Hopper 的 warp-specialized GEMM 与 Blackwell SM100 的结构不同；不能把某代 CUTLASS kernel 机械迁移。

## 实战验证建议

建议为本题建立一个最小可复现实验（microbenchmark）：

1. 写一个**正确但未优化**的 baseline。
2. 只改变一个变量（访问模式、tile、block size、register budget、pipeline stage 等）。
3. 使用 CUDA Event 做设备侧计时，至少 warm-up 后重复多次。
4. 使用 Nsight Compute/Systems 收集与本题直接相关的指标：Tensor Core utilization、DRAM/shared traffic、arithmetic intensity、pipeline stalls。
5. 把结果写成“假设 → 指标变化 → 时间变化 → 结论”，而不是只保存最终最快参数。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

GEMM 是综合题，因为它同时要求层次化 data reuse、coalesced global load、shared/register layout、Tensor Core 指令、latency hiding、pipeline、warp scheduling 和 epilogue fusion。每一层资源都会约束下一层 tile。

### 2. 定量推导 / 性能模型

$C_{M\times N}=A_{M\times K}B_{K\times N}$ 需要约 $2MNK$ FLOPs；朴素 bytes 很大，而 tiling 让 A/B 被重复使用，使 AI 随 tile 增大显著提升。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
// hierarchy: CTA tile -> warp/warpgroup tile -> MMA tile -> register/TMEM accumulators
// global -> shared -> registers/TMEM -> Tensor Core
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Tensor Core utilization`
- `Arithmetic intensity / DRAM bytes`
- `smem/register resource`
- `pipeline wait / scheduler`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

Ampere、Hopper、Blackwell 的最优 GEMM kernel 结构变化很大：cp.async→TMA/WGMMA→TCGen05/TMEM/CLC，但“分层 tile + overlap + load balance”原则稳定。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

从 naive SGEMM 到 tiled scalar，再与 cuBLAS/CUTLASS 对比并读一个高性能 kernel 的 tile/stage 配置。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
