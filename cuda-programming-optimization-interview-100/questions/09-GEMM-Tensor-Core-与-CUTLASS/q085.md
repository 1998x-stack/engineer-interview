# Q085｜FP32、TF32、FP16、BF16、FP8、FP4 怎么选？

> **一句话核心**：精度选择是 range、mantissa、带宽、Tensor Core throughput 与数值稳定性的权衡。
>
> **章节**：第 9 章 · GEMM、Tensor Core 与 CUTLASS  
> **难度**：★★★ · **频率**：极高 · **标签**：Precision / AI

## PDF 基线题解

## 考察意图
考察性能、范围、精度与硬件吞吐的联合判断。

## 思路拆解
低精度通常同时减少 memory bytes 并提高 Tensor Core throughput，但可能带来范围/舍入误差，需要 scaling、
accumulation dtype 与数值验证。选 dtype 是模型/算法约束，不是单纯性能选项。

## 标准回答
- FP32：通用精度；TF32 用于部分 FP32 matrix math，保留较大指数范围但尾数更少。
- BF16 指数范围接近 FP32，常用于训练；FP16 尾数/指数配置不同。
- FP8/FP4 对 scaling 和量化策略更敏感，在 Blackwell 等架构可提供更高 AI 吞吐。

- 很多 kernel 采用低精度 input + 更高精度 accumulation。

## Gotchas：常见失分点
- 只比较 bit 数，不谈动态范围、accumulator 和 scaling。

## 面试官可能继续追问
- 为什么 BF16 训练常比 FP16 更稳？
- block scaling 是什么？

---

## 深入分析

精度选择是 range、mantissa、带宽、Tensor Core throughput 与数值稳定性的权衡。面试时应结合训练/推理、accumulation precision、scaling strategy。

### 深入理解：GEMM 是“数据移动 + 复用 + 专用计算单元”的综合优化

现代 GEMM 的关键不是三重 for-loop，而是让 A/B 数据沿 **HBM → shared → register/TMEM → Tensor Core** 的路径被尽量多次复用，并通过多级 tiling 与 pipeline 保持计算单元持续供料。

CUTLASS/CuTe 的价值就在于把 tile shape、copy atom、MMA atom、pipeline、scheduler、epilogue 拆成可组合策略；面试中要能解释这些抽象对应什么硬件约束。

### 性能因果链

```text
题目现象 / 代码模式
        ↓
定位真实硬件行为
        ↓
识别主要资源或依赖
        ↓
提出一个可证伪优化假设
        ↓
修改实现
        ↓
Profiler 指标 + Kernel Time 验证
```

对于本题，建议至少观察：achieved Tensor Core throughput、bytes/element、numerical error、conversion overhead。

### 架构视角

Hopper 的 warp-specialized GEMM 与 Blackwell SM100 的结构不同；不能把某代 CUTLASS kernel 机械迁移。

## 实战验证建议

建议为本题建立一个最小可复现实验（microbenchmark）：

1. 写一个**正确但未优化**的 baseline。
2. 只改变一个变量（访问模式、tile、block size、register budget、pipeline stage 等）。
3. 使用 CUDA Event 做设备侧计时，至少 warm-up 后重复多次。
4. 使用 Nsight Compute/Systems 收集与本题直接相关的指标：achieved Tensor Core throughput、bytes/element、numerical error、conversion overhead。
5. 把结果写成“假设 → 指标变化 → 时间变化 → 结论”，而不是只保存最终最快参数。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

dtype 选择是精度、动态范围、吞吐、内存带宽和硬件支持的联合决策。FP16 与 BF16 都 16-bit，但 BF16 exponent 更宽；TF32 是针对 Tensor Core 的 FP32-range/较低 mantissa 路径；FP8/FP4 往往需要 scaling。

### 2. 定量推导 / 性能模型

仅从 storage 看，FP32→FP16/BF16 bytes 减半，→FP8 四分之一，→FP4 八分之一；但实际速度还受 convert、scale metadata、Tensor Core throughput 与数值稳定性限制。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

// 面试回答要包含：input dtype / accumulation dtype / scaling / error tolerance

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `Tensor Core throughput by dtype`
- `DRAM bytes`
- `Conversion/scaling overhead`
- `Accuracy/error metrics`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

Blackwell/CUTLASS 支持更多 block-scaled FP4/FP6/FP8 格式；格式能力快速演进，因此具体支持矩阵要以目标 CUDA/CUTLASS/GPU 文档为准。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

对一个 GEMM/MLP 层比较 FP32、TF32、BF16/FP16、FP8（环境允许），同时测速度、显存和相对误差。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
