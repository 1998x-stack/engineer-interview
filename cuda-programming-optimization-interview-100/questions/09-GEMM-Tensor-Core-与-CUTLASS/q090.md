# Q090｜什么是 Split-K / Stream-K？什么时候能解决 GEMM 利用率问题？

> **一句话核心**：Split-K 把 K 维拆成多个 partial sums 并归约；Stream-K 更强调把总工作均匀切成连续工作单元以减少 tile quantization。
>
> **章节**：第 9 章 · GEMM、Tensor Core 与 CUTLASS  
> **难度**：★★★ · **频率**：高 · **标签**：Stream-K / GEMM

## PDF 基线题解

## 考察意图
考察非标准形状下的并行度。

## 思路拆解
当 M×N tiles 数不足以填满 GPU，而 K 很大时，可以把 K 维也拆分给多个 workers，产生 partial sums，再归并。Split-
K 通常静态拆 K；Stream-K 更强调把 K 维 work units 连续分配以改善 wave/tile imbalance。

## 标准回答
- 收益：增加并行 work units，改善小 M/N、大 K 的 GPU utilization。
- 代价：partial sums reduction、额外 memory/atomic/synchronization。
- 是否值得取决于 shape、dtype、epilogue 与 reduction 成本。

## Gotchas：常见失分点
- 只说“把 K 分块”，不提 partial reduction。

## 面试官可能继续追问
- 为什么普通 data-parallel GEMM 不需要跨 block reduction？
- Stream-K 如何缓解 wave quantization？

---

## 深入分析

Split-K 把 K 维拆成多个 partial sums 并归约；Stream-K 更强调把总工作均匀切成连续工作单元以减少 tile quantization。收益来自增加并行度，代价是 reduction/同步。

### 深入理解：GEMM 是“数据移动 + 复用 + 专用计算单元”的综合优化

现代 GEMM 的关键不是三重 for-loop，而是让 A/B 数据沿 **HBM → shared → register/TMEM → Tensor Core** 的路径被尽量多次复用，并通过多级 tiling 与 pipeline 保持计算单元持续供料。

CUTLASS/CuTe 的价值就在于把 tile shape、copy atom、MMA atom、pipeline、scheduler、epilogue 拆成可组合策略；面试中要能解释这些抽象对应什么硬件约束。

### 架构视角

Hopper 的 warp-specialized GEMM 与 Blackwell SM100 的结构不同；不能把某代 CUTLASS kernel 机械迁移。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

Split-K 把同一个 C tile 的 K 维切给多个 CTA，产生 partial sums 再归并；Stream-K 更强调把 K 方向工作以更细粒度流式分配，改善 tile 数不足/尾部不均衡。代价是额外 reduction/atomic/workspace。

### 2. 定量推导 / 性能模型

若 M×N tiles 只有 $Q$ 个而 SM 数为 S，$Q\ll S$ 会并行度不足；把 K 切成 p 份可把并行任务增至约 pQ，但新增 partial accumulation 成本。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
// partial C_t = A[:, k0:k1] * B[k0:k1, :]
// final C = sum_t partial C_t
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `SM utilization / waves`
- `Partial reduction bytes`
- `Atomic/workspace overhead`
- `Shape-specific speedup`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

CUTLASS Blackwell scheduler 支持 CLC-based dynamic persistence 和 Stream-K；现代实现将它视为 load-balancing/scheduling 问题。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

固定 K 很大，逐步减小 M/N，比较 no-split、split-K、library Stream-K 的利用率和 overhead。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
