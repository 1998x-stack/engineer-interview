# Q092｜什么是 Distributed Shared Memory（DSM）？

> **一句话核心**：DSM 让 cluster 内 block 可以访问彼此的 shared-memory address space，适合跨 CTA reduction/producer-consumer；它不是 L2，也不是把所有 shared memory 变成全局共享。
>
> **章节**：第 10 章 · Hopper、Blackwell 与 CUDA 13.x  
> **难度**：★★★ · **频率**：高 · **标签**：DSM / Hopper

## PDF 基线题解

## 考察意图
考察 cluster 内跨 block 数据共享。

## 思路拆解
DSM 把 cluster 中各 blocks 的 shared-memory segments 组成分布式地址空间，使 cluster 内线程可以对远端 block 的
shared memory 做 load/store/atomic，避免部分通信绕到 global memory。

## 标准回答
- 每 block 的 shared size 仍是独立配置，DSM 总容量约为 cluster blocks × per-block shared。
- 使用 remote DSM 前必须保证相关 blocks 已存在，并用 cluster sync 等正确管理 lifetime。
- 典型应用：大 histogram、跨 block reduction/aggregation、cluster data exchange。
- DSM 是低延迟中间层，但仍比本地 shared 更远，需谨慎布局。

## Gotchas：常见失分点
- 认为 DSM 是所有 SM 全局共享的巨大 shared memory。

## 面试官可能继续追问
- 远端 DSM 与 local shared latency 是否相同？
- histogram bins 什么时候适合 DSM？

## 深入分析

DSM 让 cluster 内 block 可以访问彼此的 shared-memory address space，适合跨 CTA reduction/producer-consumer；它不是 L2，也不是把所有 shared memory 变成全局共享。

### 深入理解：Hopper/Blackwell 的本质是“更强的数据移动与协作原语”

现代架构题不要只背新名词。应把每个能力放进数据流：

```text
HBM --TMA--> Shared/DSM --(copy/MMA path)--> Register or TMEM --> Tensor Core
          ↑ cluster scope / async barriers / producer-consumer pipeline ↑
```

TMA 是数据移动引擎；DSM 是 cluster 级共享地址空间能力；TMEM 是 Blackwell 的 tensor-oriented memory locale。三者角色完全不同。

### 性能因果链

```text
题目现象 / 代码模式
        ↓

        ↓
识别主要资源或依赖
        ↓

        ↓

```

对于本题，建议至少观察：DSM traffic、cluster barrier wait、shared-memory footprint、cross-CTA latency。

### 架构视角

Hopper/Blackwell 特性需要匹配 compute capability、Toolkit、driver 与编译目标；优化必须明确目标架构。

## 专业增强版 V2：机制、量化与验证

> 本节是在 PDF 基线题解之上的**仓库扩展**。目标是把“能背答案”升级为“能解释硬件因果、能量化、能用 profiler 证伪”。

### 1. 硬件机制与核心心智模型

DSM 是一个 cluster 内“所有 blocks 的 shared memory 地址空间可互访”的机制。它扩大 shared-memory 协作范围，但远程 DSM access 与本地 shared 的成本、同步要求不同；生命周期仍受 cluster/block 运行约束。

### 2. 定量推导 / 性能模型

若 cluster 有 C 个 blocks、每 block 分配 S bytes shared，则逻辑可寻址 DSM 容量可达约 C×S（受架构/配置限制），但并非单一物理大 SRAM。

面试时不要只报公式。至少说明：公式里的变量对应什么硬件资源、哪些是假设、实际值应该如何由 profiler 或 microbenchmark 得到。

### 3. 代码 / 白板核心片段

```cpp
// 通过 Cooperative Groups / cluster APIs 映射访问 peer block shared
// 使用前后必须满足 cluster-level synchronization/ownership 语义。
```

白板代码优先保证：**边界正确、同步范围正确、地址模式可解释**。如果为了展示优化而省略边界处理，要主动说明省略条件。

### 4. Nsight 证据链：怎样证明你的判断

- `DSM/shared traffic（可用指标）`
- `Cluster barrier stalls`
- `Global traffic 是否减少`

推荐把分析写成四列：

| 假设 | 预期指标变化 | 实测指标变化 | 结论 |
|---|---|---|---|
| 当前瓶颈是本题讨论的问题 | 指标应出现可预测变化 | benchmark 后填写 | 接受 / 推翻假设 |
| 优化应减少对应硬件成本 | 时间与因果指标同向改善 | benchmark 后填写 | 是否保留优化 |

### 5. 架构迁移视角

DSM 随 thread-block cluster 在 CC 9.0+ 提供；适合跨 block 局部聚合/交换，但不能把它当全 grid 共享内存。

这里要区分两类知识：

- **稳定原理**：warp 粒度、数据复用、依赖、Roofline、资源平衡等；
- **架构实现**：具体指令、cache/SM 资源、TMA/TMEM/cluster/TCGen05 等。

面试中如果不确定某代 GPU 的精确容量或吞吐，不要猜数字；说明“会查目标 compute capability / tuning guide 并重新 profile”比报错数字更专业。

### 6. 可复现实验（建议真的做）

cluster histogram：每 block 处理输入，cluster 内 DSM 合并 vs 每 block global atomic，测 contention/traffic。

实验至少记录：GPU 型号、compute capability、CUDA/driver、编译参数、输入 shape/dtype、warm-up、迭代次数、median/p95、correctness tolerance，以及关键 Nsight 指标。
