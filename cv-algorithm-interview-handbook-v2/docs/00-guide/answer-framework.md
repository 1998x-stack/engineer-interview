# 面试回答框架：从“知道”到“可证伪”

这套题库不鼓励背诵论文摘要。高质量面试回答应同时展示：**概念准确、机制理解、边界意识、实验能力和工程判断**。

## 一、技术原理题：七层回答

1. **定义**：一句话说明对象、输入和输出。
2. **关键公式 / shape**：只写决定机制的式子，并解释变量、维度和口径。
3. **设计动机**：前一代方法的哪个 failure mode 促成了它？
4. **机制**：它具体改变了信息流、梯度、几何、搜索空间还是数据分布？
5. **Trade-off**：精度、稳定性、显存、吞吐、数据需求分别付出什么代价？
6. **边界条件 / 反例**：什么时候不成立、不稳定或不值得？
7. **验证**：在自己的数据和硬件上用什么切片、消融和 profiler 证明？

推荐口述链：

```text
定义 → 公式/结构 → 动机 → 机制 → 优势 → 边界 → 工程验证
```

## 二、比较题：禁止“绝对优劣”

比较 A/B 时至少固定四个维度：

| 维度 | 要问的问题 |
|---|---|
| 表示能力 | 两者表达什么先验/结构？ |
| 优化 | 梯度、正负样本、收敛有什么差异？ |
| 计算 | FLOPs、memory、kernel/并行度如何？ |
| 数据/场景 | 在小数据、长尾、域偏移、密集目标下谁更脆弱？ |

如果没有控制参数量、训练预算和预训练数据，尽量不要宣称“架构 X 一定优于 Y”。

## 三、项目题：黄金因果链

```text
Failure → Hypothesis → Change → Ablation → Cost → Regression → Business Decision
```

### 一个合格的 3 分钟项目回答

1. Baseline 是什么，数据规模和主指标是什么；
2. 发现哪个具体 failure slice；
3. 为什么怀疑某机制；
4. 做了什么最小改动；
5. 用哪些 control/ablation 排除其他原因；
6. 提升了哪些 slice，又退化了什么；
7. latency/memory/成本变化多少；
8. 为什么业务接受这一 trade-off。

## 四、系统题：先 SLA 后模型

```text
失败成本 → 指标/SLA → 数据覆盖 → 模型 → 阈值/拒识 → 部署 → 监控 → 数据回流
```

必须主动问/声明：目标硬件、输入尺寸、precision、batch、并发、P95/P99、可接受漏检/误报成本。

## 五、公式题：先口径再计算

面试中常见“算错”其实来自口径不同。建议先说：

- FLOPs：multiply-add 算 1 MAC 还是 2 FLOPs？
- bbox：坐标是连续坐标还是像素闭区间，面积是否 `+1`？
- normalization：统计轴是什么，训练/推理是否一致？
- AP：COCO 还是 VOC，IoU 阈值和插值规则是什么？

## 六、回答自检

- [ ] 我是否给出了定义而非堆名词？
- [ ] 我是否能解释“为什么”，而不是只说“更好”？
- [ ] 我是否指出至少一个失败模式？
- [ ] 我是否说明一个可执行实验？
- [ ] 我是否区分理论复杂度和真实硬件性能？
- [ ] 我是否把结果与业务指标连接起来？
