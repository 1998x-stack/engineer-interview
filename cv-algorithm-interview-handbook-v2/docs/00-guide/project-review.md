# 项目复盘模板：把经历变成可验证的技术故事

每个简历项目都建议在面试前写出下面这张“证据卡”。

## 1. 一句话任务定义

```text
在 <场景/设备/流量> 上，识别/检测/分割 <目标>，主要业务失败成本是 <FN/FP/延迟/人工成本>。
```

## 2. 数据事实

- 样本/图像/视频数量，训练/验证/测试如何拆分；
- 类别、尺寸、设备、时间、地域等长尾；
- 标注规范、漏标/错标率与版本；
- 是否存在重复数据、近重复、跨 split 泄漏；
- 线上输入与训练数据有哪些明确差异。

## 3. Baseline

- 模型与输入尺寸；
- 训练 recipe；
- 总体指标 + 关键 slice；
- 参数、FLOPs、显存、目标硬件 latency；
- 最大的 3 类 FP/FN。

## 4. Failure → Hypothesis

每个改进必须对应具体失败：

| Failure | 证据 | Hypothesis |
|---|---|---|
| 小目标漏检 | APs/可视化 | stride 太大，P3 信息不足 |
| 密集目标被抑制 | NMS 前后 recall | NMS 阈值/策略过强 |
| 线上反光失败 | 设备切片 | train domain 缺反光样本 |

## 5. Ablation 设计

至少准备：baseline、单变量改动、参数/FLOPs 匹配 control、多个 seed（若涨点较小）、关键 slice 和端到端成本。

## 6. Failure Migration

不要只展示成功案例。列出：

- 新增 TP；
- 新增 FP；
- 仍无法解决的 FN；
- 哪个类别/设备/光照变差；
- 为什么业务仍接受。

## 7. 上线与监控

- 导出/量化/后端；
- numerical parity；
- P50/P95/P99；
- reject/human review；
- 输入质量和 score drift；
- 数据回流与版本回滚。

## 8. 面试前最终检查

能否不看材料回答：**为什么是这个模型、为什么涨点、如何证明、成本多少、失败在哪里、如果再做一遍会改什么？**
