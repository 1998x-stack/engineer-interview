## 2-5 分钟标准回答

### 1. 核心要点

训练：xhat=(x-μB)/sqrt(varB+eps)，y=γxhat+β

**深入理解：** 归一化题要同时说清统计轴、可学习 affine、训练/推理状态以及小 batch 行为。工程事故经常来自 train/eval 状态、running statistics 或导出融合不一致。

### 2. 核心要点

γ/β 使网络可学回任意尺度，不强迫恒定零均值单位方差

**深入理解：** 这一章不要停留在“模块是什么”。面试中更重要的是解释它如何改变前向信号、反向梯度、参数效率和硬件执行；同时能说清 train/eval 差异与数值稳定性。

### 3. 核心要点

BN 更适合理解为改善优化条件、降低尺度敏感性并带来 batch noise 正则；小 batch 可用 SyncBN/GN/FrozenBN

**深入理解：** 归一化题要同时说清统计轴、可学习 affine、训练/推理状态以及小 batch 行为。工程事故经常来自 train/eval 状态、running statistics 或导出融合不一致。

## 关键公式 / 数学口径

训练时：

$$
\hat{x}=\frac{x-\mu_B}{\sqrt{\sigma_B^2+\epsilon}},\qquad y=\gamma\hat{x}+\beta
$$

推理时将 $\mu_B,\sigma_B^2$ 换成训练过程中累计的 running statistics。

## 代码 / 伪代码

```python
def bn_train(x, gamma, beta, eps=1e-5):
    # x: [N, C, H, W]
    mean = x.mean(dim=(0, 2, 3), keepdim=True)
    var = x.var(dim=(0, 2, 3), unbiased=False, keepdim=True)
    x_hat = (x - mean) / (var + eps).sqrt()
    return gamma[None, :, None, None] * x_hat + beta[None, :, None, None]
```

## 高频追问与参考答案

### 追问 1：running mean/var 怎么更新？

训练时用 batch mean/var 做当前归一化，同时用动量更新 running statistics；推理固定使用 running statistics。不同框架的 `momentum` 参数含义可能相反，要看公式。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 追问 2：为什么 γ/β 必须可学？

归一化若没有 γ/β 会强制所有层保持零均值单位方差，限制表达。可学习 affine 允许网络在需要时恢复原始尺度或学到新的通道缩放/偏移。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 追问 3：batch size=1 会怎样？

普通 BN 的 batch statistics 极不稳定；CNN 里虽然还能跨 H/W 统计，但分布噪声往往过大。检测/分割常改用 GN、SyncBN 或冻结 BN。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 1. 更精确的技术表述

- BN 在训练时用当前 mini-batch 统计并更新 running statistics；推理时使用冻结的 running mean/variance，因此 train/eval mode 错误会直接造成线上偏差。
- BN 的收益更适合表述为改善优化条件、平滑参数尺度敏感性和引入 batch-noise regularization，而不必依赖“减少 internal covariate shift”这一单一解释。
- 小 batch 或分布式训练下需考虑 SyncBN、FrozenBN、GN；数据分布变化时 running stats 也可能成为 domain shift 来源。

### 2. 回答时必须显式声明的前提

- 写清 tensor shape、参数量/FLOPs 口径、前向信息流和反向梯度路径。
- 把“优化更容易”落到方差、Jacobian、条件数、梯度范数或训练曲线，而不是口号。
- 理论计算量与真实硬件 latency 分开讨论；移动端尤其关注 memory access 和算子支持。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。
