## 30 秒回答

它们通过限制通道连接稀疏度换计算效率；Depthwise 把空间卷积和通道混合解耦。

如果只能再补一句：**Group 控制通道连接，Depthwise 拆开空间与通道混合。**

## 关键公式 / 数学口径

标准卷积与 depthwise separable convolution 参数量：

$$
K^2C_{in}C_{out}
$$

vs.

$$
K^2C_{in}+C_{in}C_{out}
$$

## 高频追问与参考答案

### 追问 1：为什么 1×1 可能占 MobileNet 大部分计算？

1×1 卷积不做空间邻域混合，但会对每个位置的通道向量做线性变换，因此能完成通道融合、升/降维和 bottleneck 设计。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 追问 2：Depthwise 为什么实际不一定快？

它算术强度低、内存访问占比高，且某些硬件 kernel 优化不足，所以理论 MAC 很低却可能无法充分利用计算单元。

## V2 专业深化

### 1. 更精确的技术表述

- Group Conv 将输入/输出 channel 分组，参数和计算约缩小到普通卷积的 $1/G$；Depthwise 是 groups=$C_{in}$ 的极端情况。
- Depthwise 只做每通道空间过滤，通常再用 1×1 pointwise 完成跨通道混合；这正是 depthwise separable conv 的关键分解。
- FLOPs 大幅下降不等于设备上等比例加速，depthwise 常受 memory bandwidth、kernel occupancy 和小矩阵效率限制。

### 2. 回答时必须显式声明的前提

- 写清 tensor shape、参数量/FLOPs 口径、前向信息流和反向梯度路径。
- 把“优化更容易”落到方差、Jacobian、条件数、梯度范数或训练曲线，而不是口号。
- 理论计算量与真实硬件 latency 分开讨论；移动端尤其关注 memory access 和算子支持。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。
