# Q026 · Two-stage 和 One-stage Detector 的核心区别是什么？

## 30 秒回答

Two-stage 先生成候选再精修；One-stage 直接做 dense prediction。现代精度/速度边界已不再绝对。

如果只能再补一句：**Two-stage 先候选后精修；One-stage 直接 dense 预测。**

## 面试官真正想听什么

这题不是只检查名词记忆，而是在看你能否把**机制、边界条件和工程后果**连起来。一个高质量回答至少覆盖下面三个层次：

1. **定义/结构**：先说明对象是什么，避免一上来堆历史或模块名。
2. **为什么有效**：用关键公式或信息流解释机制，而不是只说“效果更好”。
3. **什么时候会失效**：主动给出 trade-off、数据条件与部署注意事项。

### 1. 核心要点

Faster R-CNN: RPN proposals→ROI head，候选少、精修充分但 pipeline 复杂

### 2. 核心要点

**深入理解：** 检测中的表示、匹配、后处理和评测是耦合的：改变一个阈值可能同时移动 recall/precision。回答时最好明确“训练阶段的匹配”与“评测/部署阶段的匹配或去重”不是同一个概念。

### 3. 核心要点

## 高频追问与参考答案

### 追问 1：RetinaNet 为什么是里程碑？

RetinaNet 证明 one-stage detector 的主要障碍之一是极端前景/背景不平衡；Focal Loss 让 one-stage 在当时达到接近 two-stage 的精度，成为重要里程碑。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 追问 2：DETR 还适合用 one-stage/two-stage 二分吗？

先回到本题的核心机制：Faster R-CNN: RPN proposals→ROI head，候选少、精修充分但 pipeline 复杂。回答这个追问时建议按“直接机制 → 边界条件/反例 → 对训练或部署的影响”三步展开；不要只给结论，至少说明一个会改变答案的条件。

## 常见失分点

- 只说“two-stage 准、one-stage 快”太机械。
- 只背结论，不解释“为什么”，或没有指出结论成立的前提。
- 论文/离线结论直接套到自己的数据，却没有给出切片实验或消融。

## V2 专业深化

> 这一节是在 PDF/原题解基础上的**专业扩展**：用于把“会答”提升到“能推导、能诊断、能做工程决策”。其中的扩展内容属于通用计算机视觉与工程知识，不用于声称某家公司曾逐字问过这些内容。

### 1. 更精确的技术表述

- Two-stage 先产生 proposal 再做精细分类/回归；one-stage 直接在 dense locations/queries 上预测，历史上的速度/精度边界已被现代架构显著模糊。
- 真正差异还包括正负样本构造、候选数量、head 计算、后处理与训练复杂度；不要只用“二阶段准、一阶段快”一句话概括。
- 选型应结合目标尺度、类别数、部署 SLA、标注规模和是否需要实例级高精度特征。

### 2. 回答时必须显式声明的前提

- 检测问题统一沿“表示→匹配/assignment→分类/回归→后处理→评测”定位。
- 始终区分训练正负样本匹配、推理 threshold/NMS、评测 IoU matching，这三者语义不同。
- 至少报告一个尺寸/遮挡/类别切片，避免总体 mAP 掩盖真实 failure mode。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。

### 3. 从“结论”推进到“机制”的推理链

针对 **Two-stage 和 One-stage Detector 的核心区别是什么？**，推荐强制自己完成以下链条：

```text
现象/任务约束
  → 数学对象或网络中的信息流
  → 为什么当前设计能改变梯度/表示/几何/搜索空间
  → 得到什么收益
  → 付出什么代价
  → 哪些数据分布下会失效
  → 用什么切片实验和 profiler 证明
```

不要把“论文上更好”当作最后一层证据。真正专业的答案需要把方法映射到**具体 failure mode**，再设计能证伪自己的实验。

### 4. 工程诊断矩阵

| 观察到的现象 | 优先怀疑 | 最小验证实验 |
|---|---|---|
| Recall 低 | 漏标、assignment、score/NMS 或小目标信息丢失 | 建立 FN taxonomy 并分别扫描 conf/NMS threshold |
| AP75 低但 AP50 尚可 | 定位精度不足 | 检查 bbox error、输入分辨率与回归 loss/ROI alignment |

如果这两行都无法解释项目中的真实失败，再继续向数据版本、标注协议、随机性、导出后端或线上流量结构扩展，而不是直接堆更多模型模块。

### 5. 建议做的最小消融

- **Control**：保留原 baseline 的训练预算、数据版本、输入尺寸和评测脚本，只改变与本题直接相关的一项。
- **Slice**：至少增加一个与本题机制直接相关的子集指标；例如尺寸、遮挡、边界、长尾、噪声或设备域。
- **Cost**：同时记录参数量/FLOPs 之外的真实成本：显存、wall-clock、目标硬件 latency、P95/P99 或后处理开销。
- **Regression**：列出方案新增的 FP/FN 或退化场景，避免只展示改善样本。
- **Repeatability**：若提升幅度较小，使用多随机种子或 bootstrap 置信区间，判断收益是否超出自然波动。
