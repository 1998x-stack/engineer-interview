## 2-5 分钟标准回答

### 1. 核心要点

按 score 降序，取最高分框；算它与剩余框 IoU；删除 IoU>threshold 的框并循环

**深入理解：** 检测中的表示、匹配、后处理和评测是耦合的：改变一个阈值可能同时移动 recall/precision。回答时最好明确“训练阶段的匹配”与“评测/部署阶段的匹配或去重”不是同一个概念。

### 2. 核心要点

naive worst-case O(N²)，实际先做 confidence/top-k 并可向量化/GPU 加速

**深入理解：** 这类结论必须先声明计算口径和 tensor shape。面试时把“公式”继续落到显存访问、并行度和目标硬件；否则只能说明理论工作量，不能推出真实 latency。

### 3. 核心要点

class-aware 与 class-agnostic NMS 会产生不同跨类抑制行为

**深入理解：** 检测中的表示、匹配、后处理和评测是耦合的：改变一个阈值可能同时移动 recall/precision。回答时最好明确“训练阶段的匹配”与“评测/部署阶段的匹配或去重”不是同一个概念。

## 代码 / 伪代码

```python
def nms(boxes, scores, iou_thr=0.5):
    order = scores.argsort(descending=True)
    keep = []
    while order.numel():
        i = order[0]
        keep.append(i.item())
        if order.numel() == 1:
            break
        rest = order[1:]
        iou = batch_iou(boxes[i:i+1], boxes[rest])[0]
        order = rest[iou <= iou_thr]
    return keep
```

## 高频追问与参考答案

### 追问 1：阈值高/低如何影响 recall/precision？

confidence threshold 提高通常减少 FP、提高 precision 但降低 recall；NMS IoU threshold 提高会保留更多重叠框，可能提高密集目标 recall 但增加 duplicate FP。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

## V2 专业深化

> 这一节是在 PDF/原题解基础上的**专业扩展**：用于把“会答”提升到“能推导、能诊断、能做工程决策”。其中的扩展内容属于通用计算机视觉与工程知识，不用于声称某家公司曾逐字问过这些内容。

### 1. 更精确的技术表述

- NMS 是 score-ordered greedy set selection：每轮保留最高分框，并按 IoU 阈值抑制其余候选；naive 最坏 $O(N^2)$。
- class-aware NMS 按类别分别处理，class-agnostic NMS 可抑制跨类别重复；二者在类别易混淆或层级标签场景会产生不同错误模式。
- 工程实现通常先 confidence filter/top-k 减少候选，再用向量化或 GPU kernel；阈值必须与 score calibration 和目标拥挤度联合调。

### 2. 回答时必须显式声明的前提

- 检测问题统一沿“表示→匹配/assignment→分类/回归→后处理→评测”定位。
- 始终区分训练正负样本匹配、推理 threshold/NMS、评测 IoU matching，这三者语义不同。
- 至少报告一个尺寸/遮挡/类别切片，避免总体 mAP 掩盖真实 failure mode。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。

### 4. 工程诊断矩阵

| 观察到的现象 | 优先怀疑 | 最小验证实验 |
|---|---|---|
| Recall 低 | 漏标、assignment、score/NMS 或小目标信息丢失 | 建立 FN taxonomy 并分别扫描 conf/NMS threshold |
| AP75 低但 AP50 尚可 | 定位精度不足 | 检查 bbox error、输入分辨率与回归 loss/ROI alignment |

如果这两行都无法解释项目中的真实失败，再继续向数据版本、标注协议、随机性、导出后端或线上流量结构扩展，而不是直接堆更多模型模块。

### 5. 建议做的最小消融

- **Control**：保留原 baseline 的训练预算、数据版本、输入尺寸和评测脚本，只改变与本题直接相关的一项。
- **Slice**：至少增加一个与本题机制直接相关的子集指标；例如尺寸、遮挡、边界、长尾、噪声或设备域。
- **Cost**：同时记录参数量/FLOPs 之外的真实成本：显存、wall-clock、目标硬件 latency、P95/P99 或后处理开销。
- **Regression**：列出方案新增的 FP/FN 或退化场景，避免只展示改善样本。
- **Repeatability**：若提升幅度较小，使用多随机种子或 bootstrap 置信区间，判断收益是否超出自然波动。
