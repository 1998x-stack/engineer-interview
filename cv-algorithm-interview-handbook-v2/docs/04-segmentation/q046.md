## 关键公式 / 数学口径

Dice：

$$
\mathrm{Dice}=\frac{2|P\cap G|}{|P|+|G|}
$$

常用 loss 为 $1-\mathrm{Dice}$ 或其平滑版本。

## 代码 / 伪代码

```python
def dice_loss(logits, target, eps=1e-6):
    prob = logits.sigmoid()
    dims = tuple(range(1, prob.ndim))
    inter = (prob * target).sum(dims)
    denom = prob.sum(dims) + target.sum(dims)
    dice = (2 * inter + eps) / (denom + eps)
    return 1 - dice.mean()
```

### 追问 1：Dice 与 IoU 如何换算？

## V2 专业深化

### 1. 更精确的技术表述

- Dice 直接比较预测和 GT 的重叠比例，对前景极少时不像像素 CE 那样被海量 background 主导。
- Soft Dice 需要明确对 logits 先 sigmoid/softmax、平滑常数和 batch/class 聚合方式；这些实现细节会改变梯度。
- Dice 与 CE 常组合使用：CE 提供逐像素分类信号，Dice 提供全局区域重叠信号；细长/极小目标还可考虑 Tversky/Focal Tversky。

### 2. 回答时必须显式声明的前提

- 分割问题要同时考虑区域、边界、分辨率与 topology；单一像素 loss 往往不能覆盖全部目标。
- 前景占比、ignore region、空 mask 和 label interpolation 都会改变训练/评测。
- 高分辨率带来精度与显存/吞吐冲突，必须讨论 crop/tiling 与 seam artifact。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。
