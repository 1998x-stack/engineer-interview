# Q066 · SAM 的核心架构是什么？

- **面试频度**：★★★★★

## 30 秒回答

SAM 统一为 promptable segmentation：Image Encoder 预计算图像 embedding，Prompt Encoder 编码点/框/mask，Mask Decoder 输出候选 masks 与质量。

如果只能再补一句：**SAM = 图像一次编码，prompt+轻 decoder 多次交互。**

## 面试官真正想听什么

这题不是只检查名词记忆，而是在看你能否把**机制、边界条件和工程后果**连起来。一个高质量回答至少覆盖下面三个层次：

1. **定义/结构**：先说明对象是什么，避免一上来堆历史或模块名。
2. **为什么有效**：用关键公式或信息流解释机制，而不是只说“效果更好”。
3. **什么时候会失效**：主动给出 trade-off、数据条件与部署注意事项。

## 2-5 分钟标准回答

### 1. 核心要点

Image encoder 成本高但同图可复用 embedding

**深入理解：** 视觉基础模型题的重点不是背架构，而是比较 inductive bias、tokenization、attention 复杂度、预训练目标和开放词汇/提示式接口。还要知道 foundation model 不等于任何场景都优于专用模型。

### 2. 核心要点

Prompt encoder 分 sparse prompts 与 dense mask prompt

**深入理解：** 视觉基础模型题的重点不是背架构，而是比较 inductive bias、tokenization、attention 复杂度、预训练目标和开放词汇/提示式接口。还要知道 foundation model 不等于任何场景都优于专用模型。

### 3. 核心要点

Mask decoder 让 prompt tokens 与 image embedding 交互，输出多个候选以处理提示歧义，并预测 mask quality

**深入理解：** 这类结构应从信息交互图理解：谁作为 query、能访问哪些 key/value、token 数如何增长、位置/局部先验如何注入。这样才能自然解释复杂度与泛化差异。

## 常见失分点

- SAM 不是“万能 semantic segmentation”，不会自动给业务类别。
- 只背结论，不解释“为什么”，或没有指出结论成立的前提。
- 论文/离线结论直接套到自己的数据，却没有给出切片实验或消融。

## V2 专业深化

> 这一节是在 PDF/原题解基础上的**专业扩展**：用于把“会答”提升到“能推导、能诊断、能做工程决策”。其中的扩展内容属于通用计算机视觉与工程知识，不用于声称某家公司曾逐字问过这些内容。

### 1. 更精确的技术表述

- SAM 将昂贵 image encoder、轻量 prompt encoder 与 mask decoder 解耦；同一图像 embedding 可对多个 point/box/mask prompt 重复使用。
- promptable segmentation 把多种交互式分割任务统一为 `(image,prompt)→mask`，mask decoder 还可输出多个候选以处理歧义。
- 部署时应把 image embedding 缓存成本、prompt latency、mask 数量和输入分辨率分别 profile，而不是只报单次模型 FLOPs。

### 2. 回答时必须显式声明的前提

- 视觉基础模型问题从 tokenization、位置/局部先验、attention interaction、预训练目标与迁移接口五层回答。
- 所有 scaling 结论都要带 token 数、分辨率、训练数据与计算预算，不做脱离配置的比较。
- zero-shot/open-vocabulary 是能力边界扩大，不代表专业闭集任务必然更优。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。

### 3. 从“结论”推进到“机制”的推理链

针对 **SAM 的核心架构是什么？**，推荐强制自己完成以下链条：

```text
现象/任务约束
  → 数学对象或网络中的信息流
  → 为什么当前设计能改变梯度/表示/几何/搜索空间
  → 得到什么收益
  → 付出什么代价
  → 哪些数据分布下会失效
  → 用什么切片实验和 profiler 证明
```

不要把“论文上更好”当作最后一层证据。真正专业的答案需要把方法映射到**具体 failure mode**，再设计能证伪自己的实验。

### 4. 工程诊断矩阵

| 观察到的现象 | 优先怀疑 | 最小验证实验 |
|---|---|---|
| 高分辨率 OOM/慢 | token 数与 attention 激活增长 | 计算 N 并 profile attention/MLP 显存占比 |
| zero-shot 不稳定 | prompt/域偏移/概念覆盖不足 | prompt ensemble + 专业域切片 + linear probe 对照 |

如果这两行都无法解释项目中的真实失败，再继续向数据版本、标注协议、随机性、导出后端或线上流量结构扩展，而不是直接堆更多模型模块。

### 5. 建议做的最小消融

- **Control**：保留原 baseline 的训练预算、数据版本、输入尺寸和评测脚本，只改变与本题直接相关的一项。
- **Slice**：至少增加一个与本题机制直接相关的子集指标；例如尺寸、遮挡、边界、长尾、噪声或设备域。
- **Cost**：同时记录参数量/FLOPs 之外的真实成本：显存、wall-clock、目标硬件 latency、P95/P99 或后处理开销。
- **Regression**：列出方案新增的 FP/FN 或退化场景，避免只展示改善样本。
- **Repeatability**：若提升幅度较小，使用多随机种子或 bootstrap 置信区间，判断收益是否超出自然波动。
