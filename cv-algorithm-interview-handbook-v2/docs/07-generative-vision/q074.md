## 30 秒回答

Editing 不仅要满足指令，还要保持未修改区域的身份、几何和背景，是“改对 + 保住”的双目标。

如果只能再补一句：**编辑的难点不是生成，而是只改该改的。**

## 面试官真正想听什么

这题不是只检查名词记忆，而是在看你能否把**机制、边界条件和工程后果**连起来。一个高质量回答至少覆盖下面三个层次：

1. **定义/结构**：先说明对象是什么，避免一上来堆历史或模块名。
2. **为什么有效**：用关键公式或信息流解释机制，而不是只说“效果更好”。
3. **什么时候会失效**：主动给出 trade-off、数据条件与部署注意事项。

## 高频追问与参考答案

### 追问 1：identity preservation 如何评价？

可用人脸/物体 embedding 相似度、局部结构/关键点一致性和人工偏好综合评价；单一 CLIP 相似度很容易忽略身份细节。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 追问 2：为什么 VAE round-trip 会影响未编辑区域？

即使不编辑，图像先 encode 再 decode 也会有有损重建误差，因此编辑系统要把 VAE round-trip 本身造成的变化与真正 edit 区域变化分开评估。

## 常见失分点

- 只用 CLIP score 评价 editing 会忽略 preservation。
- 只背结论，不解释“为什么”，或没有指出结论成立的前提。
- 论文/离线结论直接套到自己的数据，却没有给出切片实验或消融。

## 工程 / 项目视角

真实产品还要处理局部边界、颜色一致、高分辨率与文字保持。

建议把自己的项目补成以下四个事实：

- **数据条件**：这个机制在哪些尺寸/类别/光照/噪声/设备上最重要？
- **评价切片**：不能只看总体均值，至少有一个与本题机制直接相关的 slice。
- **成本**：训练显存、参数量、FLOPs、目标硬件 latency、前后处理成本至少知道一个。
- **回归**：新增方案让哪些场景变差？上线前如何兜底？

## V2 专业深化

> 这一节是在 PDF/原题解基础上的**专业扩展**：用于把“会答”提升到“能推导、能诊断、能做工程决策”。其中的扩展内容属于通用计算机视觉与工程知识，不用于声称某家公司曾逐字问过这些内容。

### 1. 更精确的技术表述

- Text-to-Image 主要优化从文本生成合理图像；Editing 还必须同时满足指令修改和原图身份/结构/未编辑区域保持。
- 编辑评估天然是多目标：edit success、preservation、identity、locality、aesthetics 可能相互冲突。
- 数据构造要有 before/instruction/after 三元关系，且需要区分局部编辑、全局风格、对象增删和几何变化等任务类型。

### 2. 回答时必须显式声明的前提

- 严格区分 forward/noise process、训练 parameterization、sampler、conditioning 与 evaluation。
- 生成质量、语义对齐、多样性与延迟是多目标，任何单一指标都不足以定论。
- 生成系统的性能常由采样步数、CFG、latent 分辨率和 backbone 共同决定。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。

### 3. 从“结论”推进到“机制”的推理链

针对 **Image Editing 与 Text-to-Image 最大区别是什么？**，推荐强制自己完成以下链条：

```text
现象/任务约束
  → 数学对象或网络中的信息流
  → 为什么当前设计能改变梯度/表示/几何/搜索空间
  → 得到什么收益
  → 付出什么代价
  → 哪些数据分布下会失效
  → 用什么切片实验和 profiler 证明
```

不要把“论文上更好”当作最后一层证据。真正专业的答案需要把方法映射到**具体 failure mode**，再设计能证伪自己的实验。

### 4. 工程诊断矩阵

| 观察到的现象 | 优先怀疑 | 最小验证实验 |
|---|---|---|
| 图像好看但不听 prompt | guidance/condition/data 对齐不足 | 分开评估 alignment 与 aesthetics，扫描 CFG/condition strength |
| 采样过慢 | steps/CFG/backbone/分辨率 | 逐项 profile 并做步数-质量 Pareto |

如果这两行都无法解释项目中的真实失败，再继续向数据版本、标注协议、随机性、导出后端或线上流量结构扩展，而不是直接堆更多模型模块。

### 5. 建议做的最小消融

- **Control**：保留原 baseline 的训练预算、数据版本、输入尺寸和评测脚本，只改变与本题直接相关的一项。
- **Slice**：至少增加一个与本题机制直接相关的子集指标；例如尺寸、遮挡、边界、长尾、噪声或设备域。
- **Cost**：同时记录参数量/FLOPs 之外的真实成本：显存、wall-clock、目标硬件 latency、P95/P99 或后处理开销。
- **Regression**：列出方案新增的 FP/FN 或退化场景，避免只展示改善样本。
- **Repeatability**：若提升幅度较小，使用多随机种子或 bootstrap 置信区间，判断收益是否超出自然波动。

### 7. 面试表达升级模板

> “我先明确这里的实现/评价口径。核心机制是 **A**，它通过 **B** 改变了 **C**，所以在 **D 类数据**上预期有效；代价是 **E**。如果这是我的项目，我会用 **一个控制实验 + 一个关键切片 + 一个真实硬件/线上指标** 来验证，而不是只看总体平均分。”
