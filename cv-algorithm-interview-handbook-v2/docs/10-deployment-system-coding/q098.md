## 关键公式 / 数学口径

NCHW 的 BatchNorm 通常对 `(N,H,W)` 统计，每个 channel 得到独立的均值/方差：reduce axes 为 `(0,2,3)`。

## 代码 / 伪代码

```python
def bn_forward(x, gamma, beta, running_mean=None, running_var=None,
               training=True, eps=1e-5):
    if training:
        mean = x.mean((0, 2, 3), keepdim=True)
        var = x.var((0, 2, 3), unbiased=False, keepdim=True)
    else:
        mean = running_mean[None, :, None, None]
        var = running_var[None, :, None, None]
    xhat = (x - mean) / torch.sqrt(var + eps)
    return gamma[None,:,None,None] * xhat + beta[None,:,None,None]
```

> 面试手撕时先说明输入 shape、坐标/数值口径和边界条件，再写主逻辑。正确性优先于过早微优化。

## 高频追问与参考答案

### 追问 1：为什么 eps 在 sqrt 内？

BN 标准化需要避免方差接近 0 时除零，通常计算 `sqrt(var + eps)`；把 eps 放在 sqrt 外会得到不同数值尺度，尤其小方差时差异明显。

**回答加分点：** 最后补一句它会如何改变指标、训练稳定性或部署成本；若答案依赖实现约定，先声明约定。

### 1. 更精确的技术表述

- 对于 NCHW 的 BatchNorm2d，每个 channel 的统计轴通常是 N、H、W，即得到 C 个均值/方差；gamma/beta 也是每 channel。
- 训练用 batch stats 并更新 running stats；推理用 running stats。PyTorch 默认方差估计与 running variance 更新存在实现细节，手写时需声明简化口径。
- 数值稳定要用 epsilon，混合精度中统计常以更高精度累积；错误 reshape/broadcast 是手撕高频坑。

### 2. 回答时必须显式声明的前提

- 系统题先固定硬件、batch、输入尺寸、precision、并发和 SLA，再谈模型快慢。
- 理论 FLOPs/参数量、kernel profile、端到端 latency 是三层不同证据，不能混为一谈。
- 任何导出/量化/加速都必须配 numerical parity 与业务指标回归。

面试中尤其建议先把输入/输出、坐标或 tensor shape、训练/推理阶段以及评价口径说清楚。很多看似“知识点错误”的争论，本质是双方默认的实现约定不同。

### 5. 建议做的最小消融

- **Control**：保留原 baseline 的训练预算、数据版本、输入尺寸和评测脚本，只改变与本题直接相关的一项。
- **Slice**：至少增加一个与本题机制直接相关的子集指标；例如尺寸、遮挡、边界、长尾、噪声或设备域。
- **Cost**：同时记录参数量/FLOPs 之外的真实成本：显存、wall-clock、目标硬件 latency、P95/P99 或后处理开销。
