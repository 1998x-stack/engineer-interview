## 2. 30 秒回答 — PDF Core

> 内参 K 描述焦距和主点等成像参数；外参 R,t 描述相机坐标系相对世界/机器人坐标系的位置和姿态。

## 6. 工程实现与系统接口 — Repository Expansion

工程上应明确 sensor frame、timestamp、标定版本和观测置信度。传统几何与学习感知往往互补：VLM 给语义，RGB-D/SLAM/EKF 给可测量的几何与状态。

### 建议关注的指标

- 重投影误差 / 外参残差

- 点云配准误差

- ATE/RPE 或定位漂移

- 状态估计协方差与失效恢复时间

### 最小验证实验

1. 先构造一个可控、可复现的最小场景作为 baseline。
2. 只改变一个变量做 A/B；记录均值之外的失败分布。
3. 对边界条件或 OOD 场景单独建立回归测试。
4. 最后才进入全系统实机验证，并保留日志、视频和时序数据以便复盘。

### 13.1 从定义升级到问题建模

针孔模型中 K 负责 camera coordinates→pixel，外参负责 world/base→camera。内参是成像几何，外参是坐标系关系；畸变参数又是第三类。

标定误差会被深度和距离放大。Manipulation 中应把 reprojection error 转换成末端位置误差来评估，而不是只报告平均像素误差。

面试时建议主动定义四件事：**输入是什么、输出是什么、变量属于哪个空间/时间尺度、成功由什么指标判定**。这会显著减少后续追问中的歧义。

### 13.2 Why：这个机制为什么有效？

1. **先找瓶颈/约束**：本题的方法不是孤立技巧，而是在特定假设下消除一个明确瓶颈。
2. **再找替代方案**：至少能说出一种替代路线，并说明它在数据、计算、稳定性、实时性或泛化上的取舍。
3. **最后落到闭环**：真正机器人系统最终都会回到 `感知 → 状态 → 决策 → 动作 → 控制 → 新观测`；任何局部优化都要验证是否提高闭环 task metric。

一个常用的工程化表达是：

```text
离线指标改善
   ↓（必要但不充分）
模块级接口正确
   ↓
闭环 rollout 稳定
   ↓
OOD / 长尾仍成立
   ↓
实机 SLO / 安全约束满足
```

### 13.4 失败模式：不要只会解释“成功时为什么工作”

| 失败类型 | 典型现象 | 优先检查的证据 |
|---|---|---|
| F1 | 时间同步错误 | 最小可复现实验 + 原始时序日志 |
| F2 | 外参漂移/坐标系写反 | 边界条件 / OOD 分桶统计 |
| F3 | 传感器在特殊材质/遮挡下系统失效 | 模块输入输出与数值范围 |
| F4 | 估计器置信度失真但下游仍强制使用 | 闭环回放、视频、控制/系统 telemetry |

专业回答应避免“模型效果不好”这种不可诊断描述，而是把失败拆成可观测类别，并给每一类一个证据链。

### 13.5 指标体系：怎样证明你的答案在工程上成立？

本题至少建议关注：**reprojection/pose error、ATE/RPE、innovation/NIS、tracking continuity、latency 与置信度校准**。

评估时优先使用：

- **均值 + 分位数/置信区间**，避免只报单个平均数；
- **按场景分桶**：seen / OOD、短时 / 长时、成功 / near-miss；
- **A/B 单变量实验**：一次只改一个核心变量；
- **闭环指标优先于离线 proxy**：离线 loss/accuracy 只能解释部分问题。

### 13.8 一页速记

- **一句话本质**：针孔模型中 K 负责 camera coordinates→pixel，外参负责 world/base→camera。
- **最容易答错**：只背术语，不定义 frame / state / action / time scale / metric。
- **工程优先级**：先验证输入输出和时序，再优化模型；先建立 failure taxonomy，再增加数据/参数。
- **面试高分信号**：能给公式或结构图 + 能说替代方案 + 能给失败证据 + 能设计 A/B。
