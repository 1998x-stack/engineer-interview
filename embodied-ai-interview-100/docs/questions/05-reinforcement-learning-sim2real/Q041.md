### 为什么重要 — Repository Expansion

机器人 RL 面试最看重“目标函数—采样—奖励—安全—Sim2Real”的闭环。算法公式只是起点，关键是怎样获得稳定、可解释、可迁移的策略改进。

这题建议始终放回具身闭环理解：**Observation → State/Representation → Policy/Planner → Action → Controller → Robot → New Observation**。面试官通常会从定义继续追到“如果真的上机器人，接口、误差和失败模式是什么”。

## 2. 30 秒回答 — PDF Core

> MDP=(S,A,P,R,γ)，Markov 性要求当前状态足以决定下一状态分布。真实机器人只看到图像/传感器，完整世界状态不可见，因此更接近 POMDP，需要 history/belief/memory。

## 6. 工程实现与系统接口 — Repository Expansion

并行仿真用于提高样本吞吐，系统辨识与 domain randomization 用于缩小 reality gap；在线实机 RL 需要安全约束、reset 机制和 demonstration regularization。

### 建议关注的指标

- episodic return / success rate

- 样本效率

- 策略 KL / entropy

- 真实部署成功率与安全事件

### 最小验证实验

1. 先构造一个可控、可复现的最小场景作为 baseline。
2. 只改变一个变量做 A/B；记录均值之外的失败分布。
3. 对边界条件或 OOD 场景单独建立回归测试。
4. 最后才进入全系统实机验证，并保留日志、视频和时序数据以便复盘。

## 13. 深度增强题解 — Repository Expansion v2.0

> 本节是 GitHub 版二次研究扩展，不替代前面的 PDF Core。目标是把“知道概念”提升到“能推导、能实现、能定位实机失败”。

### 13.1 从定义升级到问题建模

MDP 假设当前 state 足以决定未来分布；真实机器人常只有 partial observation，因此更接近 POMDP。相机帧看不到遮挡物、历史接触或任务进度，需要 belief/memory/history。

面试中可以解释 state 与 observation 的区别：仿真能访问 privileged state，但部署只能访问 sensors。训练时使用 privileged critic 也要说明 sim-only 信息不会泄漏给 actor。

面试时建议主动定义四件事：**输入是什么、输出是什么、变量属于哪个空间/时间尺度、成功由什么指标判定**。这会显著减少后续追问中的歧义。

### 13.2 Why：这个机制为什么有效？

1. **先找瓶颈/约束**：本题的方法不是孤立技巧，而是在特定假设下消除一个明确瓶颈。
2. **再找替代方案**：至少能说出一种替代路线，并说明它在数据、计算、稳定性、实时性或泛化上的取舍。
3. **最后落到闭环**：真正机器人系统最终都会回到 `感知 → 状态 → 决策 → 动作 → 控制 → 新观测`；任何局部优化都要验证是否提高闭环 task metric。

一个常用的工程化表达是：

```text
离线指标改善
   ↓（必要但不充分）
模块级接口正确
   ↓
闭环 rollout 稳定
   ↓
OOD / 长尾仍成立
   ↓
实机 SLO / 安全约束满足
```

### 13.4 失败模式：不要只会解释“成功时为什么工作”

| 失败类型 | 典型现象 | 优先检查的证据 |
|---|---|---|
| F1 | reward hacking | 最小可复现实验 + 原始时序日志 |
| F2 | 训练曲线升高但 task success 不升 | 边界条件 / OOD 分桶统计 |
| F3 | sim distribution 与 real support 不重叠 | 模块输入输出与数值范围 |
| F4 | 策略更新过大导致已有技能退化 | 闭环回放、视频、控制/系统 telemetry |

专业回答应避免“模型效果不好”这种不可诊断描述，而是把失败拆成可观测类别，并给每一类一个证据链。

### 13.5 指标体系：怎样证明你的答案在工程上成立？

本题至少建议关注：**task success、return、sample efficiency、policy KL/entropy、sim-to-real delta、safety violation**。

评估时优先使用：

- **均值 + 分位数/置信区间**，避免只报单个平均数；
- **按场景分桶**：seen / OOD、短时 / 长时、成功 / near-miss；
- **A/B 单变量实验**：一次只改一个核心变量；
- **闭环指标优先于离线 proxy**：离线 loss/accuracy 只能解释部分问题。

### 13.8 一页速记

- **一句话本质**：MDP 假设当前 state 足以决定未来分布；真实机器人常只有 partial observation，因此更接近 POMDP。
- **最容易答错**：只背术语，不定义 frame / state / action / time scale / metric。
- **工程优先级**：先验证输入输出和时序，再优化模型；先建立 failure taxonomy，再增加数据/参数。
- **面试高分信号**：能给公式或结构图 + 能说替代方案 + 能给失败证据 + 能设计 A/B。
