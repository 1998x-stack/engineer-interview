## 1. 这道题在考什么？ — PDF Core

考察 generalist robot policy 的另一条路线。

### 为什么重要 — Repository Expansion

VLA 题真正考的是 modality gap：语义视觉语言知识怎样转成低层、连续、具身相关的动作。回答要覆盖输入表示、融合、action head、训练数据、控制接口和泛化维度。

这题建议始终放回具身闭环理解：**Observation → State/Representation → Policy/Planner → Action → Controller → Robot → New Observation**。面试官通常会从定义继续追到“如果真的上机器人，接口、误差和失败模式是什么”。

## 2. 30 秒回答 — PDF Core

> Octo 更像 robot-policy-first 的 generalist transformer，使用 Open X-Embodiment 约 800k trajectories，支持 language/goal image conditioning，并强调对新传感器和 action space 的快速适配。

### 3.X 专题增强 — Repository Expansion

- OpenVLA 的研究价值在于开放 7B VLA 及 fine-tuning 路径。面试可重点讨论 VLM backbone 与 action tokenization 的接口、数据混合和实机 adaptation，而不是只背参数量。

### 建议关注的指标

### 最小验证实验

1. 先构造一个可控、可复现的最小场景作为 baseline。
2. 只改变一个变量做 A/B；记录均值之外的失败分布。
3. 对边界条件或 OOD 场景单独建立回归测试。
4. 最后才进入全系统实机验证，并保留日志、视频和时序数据以便复盘。

## 13. 深度增强题解 — Repository Expansion v2.0

> 本节是 GitHub 版二次研究扩展，不替代前面的 PDF Core。目标是把“知道概念”提升到“能推导、能实现、能定位实机失败”。

### 13.1 从定义升级到问题建模

Octo 更像 robot-policy-first 的 generalist diffusion policy：较小 Transformer backbone、可变 observation/task 输入、diffusion action head，强调对新 sensor/action schema 的快速适配。

与 OpenVLA 比较时不要只说参数量；要比较 pretraining objective、action representation、adaptation path、robot data dependency 和 inference latency。

面试时建议主动定义四件事：**输入是什么、输出是什么、变量属于哪个空间/时间尺度、成功由什么指标判定**。这会显著减少后续追问中的歧义。

### 13.2 Why：这个机制为什么有效？

1. **先找瓶颈/约束**：本题的方法不是孤立技巧，而是在特定假设下消除一个明确瓶颈。
2. **再找替代方案**：至少能说出一种替代路线，并说明它在数据、计算、稳定性、实时性或泛化上的取舍。
3. **最后落到闭环**：真正机器人系统最终都会回到 `感知 → 状态 → 决策 → 动作 → 控制 → 新观测`；任何局部优化都要验证是否提高闭环 task metric。

一个常用的工程化表达是：

```text
离线指标改善
   ↓（必要但不充分）
模块级接口正确
   ↓
闭环 rollout 稳定
   ↓
OOD / 长尾仍成立
   ↓
实机 SLO / 安全约束满足
```

### 13.3 白板 / 实现骨架

```text
Images / Proprio / Language / Embodiment
                ↓
       Multimodal backbone
                ↓
      fused task representation
                ↓
 discrete token head OR continuous action expert
                ↓
     action chunk + controller
```
训练和部署都要固定 **action schema / normalization / rate / frame**。

**白板必画**：画 VLA 的 vision/language/proprio→backbone→action head，并标注 action chunk、controller、embodiment adapter。

### 13.4 失败模式：不要只会解释“成功时为什么工作”

| 失败类型 | 典型现象 | 优先检查的证据 |
|---|---|---|
| F1 | 语言/视觉理解对但动作失败 | 最小可复现实验 + 原始时序日志 |
| F2 | action normalization/schema 错 | 边界条件 / OOD 分桶统计 |
| F3 | cross-embodiment 数据互相干扰 | 模块输入输出与数值范围 |
| F4 | 模型 latency 与 control rate 不匹配 | 闭环回放、视频、控制/系统 telemetry |

专业回答应避免“模型效果不好”这种不可诊断描述，而是把失败拆成可观测类别，并给每一类一个证据链。

### 13.5 指标体系：怎样证明你的答案在工程上成立？

本题至少建议关注：**seen/OOD/compositional success、cross-embodiment transfer、action latency、control rate、data efficiency**。

评估时优先使用：

- **均值 + 分位数/置信区间**，避免只报单个平均数；
- **按场景分桶**：seen / OOD、短时 / 长时、成功 / near-miss；
- **A/B 单变量实验**：一次只改一个核心变量；
- **闭环指标优先于离线 proxy**：离线 loss/accuracy 只能解释部分问题。

- **Octo 如何处理不同 action space？**：先给 1 句结论；再回到本题的核心变量/公式；最后给一个可测的实机或离线证据。不要只复述名词。
- **goal image conditioning 有什么价值？**：先给 1 句结论；再回到本题的核心变量/公式；最后给一个可测的实机或离线证据。不要只复述名词。

进一步的 Senior 追问通常会变成：

1. **如果这个方法不起作用，你如何判断是数据、模型、控制还是系统问题？**
2. **如果算力减半 / 数据减半 / 延迟预算减半，你会保留什么？**
3. **如何设计最小 ablation 证明改进来自你声称的机制，而不是额外参数量或更多数据？**
4. **这个结论在哪些 robot / task / control regime 下可能失效？**

### 13.8 一页速记

- **一句话本质**：Octo 更像 robot-policy-first 的 generalist diffusion policy：较小 Transformer backbone、可变 observation/task 输入、diffusion action head，强调对新 sensor/action schema 的快速适配。
- **最容易答错**：只背术语，不定义 frame / state / action / time scale / metric。
- **工程优先级**：先验证输入输出和时序，再优化模型；先建立 failure taxonomy，再增加数据/参数。
- **面试高分信号**：能给公式或结构图 + 能说替代方案 + 能给失败证据 + 能设计 A/B。
