GAME ENGINE · GRAPHICS · 47 / 100

所有节点出度 1，如何寻找最长环？

[!IMPORTANT] 内容分层：PDF 核心内容严格以仓库附带的原 PDF 为基线；专业扩展是为了让题目达到更强的工程面试深度，来自通用工程知识与下方列出的官方/权威资料。两者刻意分开，便于追踪来源。

章节：数据结构与算法
学习级别：Intermediate（仓库学习分级，不是对 PDF 星级符号的重解释）
PDF 位置：物理页 49
来源口径：公开面经/官方资料可核验 · [M3]

1. 这道题在考什么

这题属于 数据结构与算法。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

  1. 机制：数据/状态究竟怎样流动；
  2. 成本：CPU、GPU、内存、同步或数值误差的成本在哪里；
  3. Trade-off：什么场景适合，什么场景会失败；
  4. Engine Context：在真实 renderer / core / asset / simulation 中怎么落地；
  5. Evidence：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：开放世界寻路/空间查询、碰撞 broad phase、可见性与加速结构。

2. 30 秒回答（PDF 核心内容）

由于每个节点最多一个后继，图是若干“链进入环”的函数图。可用访问时间戳记录当前 DFS 路径，回到本轮路径节点时用时间差得到环长；整体 O(V)。

3. PDF 深入拆解（Source-derived）

另一种思路是 Kahn 式拓扑剥离：统计入度，不断删除入度为 0 的节点，剩余节点全部在环上， 再遍历各环长度。时间同样 O(V)，实现简单且容易证明。该题很适合展示你能否利用“出度 1” 这个特殊结构，而不是套一般图算法。

PDF 核心抓手

  • 函数图结构
  • 时间戳 DFS
  • 入度剥离后剩余即环
  • 整体 O(V)

PDF 工程 Gotcha

对每个起点重新 DFS，造成 O(V^2)。

PDF 面试官在听什么

能否抓住题目特殊约束降复杂度。

4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 可实现、可测量、可讨论 trade-off 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

4.1 先修知识与概念边界

  • functional graph
  • DFS color
  • 拓扑剥离
  • 时间戳

4.2 核心心智模型

每节点出度≤1 构成 functional graph：每个连通分量是“一棵或多棵入树指向一个环”，或最终指向空。利用这个结构可以 O(N) 找环，而无需一般图的复杂算法。

4.3 底层机制：逐层拆开

  • DFS color：0未访问、1当前路径、2完成；沿唯一 next 前进，遇 color=1 节点说明回到当前路径，时间戳差即环长。
  • 也可记录本次 traversal id + step index，遇同 traversal id 计算长度。
  • 若每节点恰好出度1，可用 indegree Kahn 剥掉所有非环节点，剩余节点全在环上，再计各环长度。
  • 路径处理完成后标 finished，避免后续重复遍历。

4.4 必须守住的不变量 / 正确性条件

  • 必须区分“遇到已访问节点”与“遇到当前 DFS 栈节点”；前者可能进入之前处理完的链而不是新环。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

4.5 Trade-off：什么时候该用，什么时候不该用

  • timestamp iterative 实现最简单且避免递归深度。
  • Kahn 法需要 indegree 数组，适合还想标记所有环节点。

4.6 在真实游戏引擎中的落点

  • 状态机/资源引用图中 functional mapping 检测循环。
  • 任务重定向/父级索引错误检查。

4.7 最小实现 / 数学骨架

runId++
while v!=-1 and state[v]==0:
  state[v]=runId; step[v]=d++; v=next[v]
if state[v]==runId: cycle=d-step[v]

面试建议：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

4.8 Profiling / Validation：如何证明你的判断

  • O(N) 时间与 O(N) state；测试 self-loop、长链进环、链入旧环。

4.9 常见错误答案与为什么错

  • “只要碰到 visited 就是环。”——可能只是接到已经处理完成的路径。
  • 用 Floyd 对每个起点都跑会退化到 O(N²)。

4.10 Senior 级追问与参考思路

  1. 如果要找每个节点离环距离？
    先标环节点，再在反向图 BFS/DP 传播距离。
  2. 出度不再≤1 怎么办？
    回到一般有向图 SCC/Tarjan/Kosaraju 或 DFS cycle detection。

4.11 推荐实战

实现 timestamp 法并输出最长环和各节点所属环 ID/距环距离。

完成实战时建议保留 baseline、指标、实验变量、结果、结论 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

5. 如何验证，而不是“凭感觉优化”

  • 先写正确性测试与边界样例，再做复杂度/性能基线
  • 记录 N、K、分布等输入特征，避免脱离规模谈算法
  • 对空间结构同时测 build/update/query 成本

推荐实战

实现算法并构造随机/极端测试；同时记录输入规模与耗时曲线。

6. 工程 Gotchas（扩展）

  • 先澄清输入规模/在线离线/是否有序等约束，再选算法
  • 复杂度相同的数据结构可能有完全不同 cache 行为
