GAME ENGINE · GRAPHICS · 8 / 100

AABB 和 OBB 的区别？

[!IMPORTANT] 内容分层：PDF 核心内容严格以仓库附带的原 PDF 为基线；专业扩展是为了让题目达到更强的工程面试深度，来自通用工程知识与下方列出的官方/权威资料。两者刻意分开，便于追踪来源。

章节：3D 数学与几何
学习级别：Intermediate（仓库学习分级，不是对 PDF 星级符号的重解释）
PDF 位置：物理页 61
来源口径：高频能力重构

1. 这道题在考什么

这题属于 3D 数学与几何。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

  1. 机制：数据/状态究竟怎样流动；
  2. 成本：CPU、GPU、内存、同步或数值误差的成本在哪里；
  3. Trade-off：什么场景适合，什么场景会失败；
  4. Engine Context：在真实 renderer / core / asset / simulation 中怎么落地；
  5. Evidence：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：camera/view/projection、碰撞与 picking、raster attribute interpolation。

2. 30 秒回答（PDF 核心内容）

AABB 与世界轴对齐，存储/更新/测试快但旋转后包围会变松；OBB 随对象方向，通常更紧但相交测试昂贵。

3. PDF 深入拆解（Source-derived）

AABB-AABB 只需比较每个轴的区间；OBB-OBB 常用 Separating Axis Theorem，在 3D 中需要检查两盒自身轴以及轴叉乘产生的候选分离轴。碰撞系统通常 broad phase 用 AABB，narrow phase 再用精确形状/OBB，因为 broad phase 更重视快速拒绝而非最紧包围。

PDF 核心抓手

  • AABB 便宜且适合 broad phase
  • OBB 更紧但更新/测试贵
  • SAT 用分离轴判断凸体不相交

PDF 工程 Gotcha

认为 OBB “一定更好”，忽略它的 CPU 成本。

PDF 面试官在听什么

是否会根据碰撞阶段选择包围体。

4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 可实现、可测量、可讨论 trade-off 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

4.1 先修知识与概念边界

  • bounding volume
  • SAT
  • transform
  • broad phase

4.2 核心心智模型

AABB 便宜、易 union、易 BVH；OBB 更贴合旋转对象但测试更贵。问题不在谁“更准确”，而在 broad-phase false positive 与更新/测试成本之间的平衡。

4.3 底层机制：逐层拆开

  • AABB 由 min/max 或 center/extents 表示，overlap 只需各轴区间比较。
  • OBB 由 center、3正交轴、half-extents 表示；两 OBB 常用 SAT，3D 最多测试 15 个候选分离轴（3+3+9 cross）。
  • 旋转对象的 world AABB 可由 abs(R)*localExtents 快速计算，不必变换8角。
  • BVH 通常仍用 AABB，因为 union 和 ray box test 高效。

4.4 必须守住的不变量 / 正确性条件

  • Broad phase 包围体允许误报但不能漏报。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

4.5 Trade-off：什么时候该用，什么时候不该用

  • OBB 更紧可减少 narrow-phase，但更新和 overlap test 成本更高。
  • Capsule/sphere 对角色等形状可能比 OBB 更合适且旋转不敏感。

4.6 在真实游戏引擎中的落点

  • Physics broad phase AABB，narrow phase 用真实 shape/OBB。
  • Frustum culling 常 sphere/AABB。
  • Ray tracing BVH node 几乎总 AABB。

4.7 最小实现 / 数学骨架

e_{world}=|R|\,e_{local}

面试建议：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

4.8 Profiling / Validation：如何证明你的判断

  • 统计 broad-phase candidate ratio 与每 pair 测试成本；看更紧 volume 是否真的节省总 CPU。

4.9 常见错误答案与为什么错

  • “OBB 永远比 AABB 好因为更紧。”——整体成本可能更差。
  • “旋转 AABB 要逐角变换。”——可用 abs(rotation matrix)×extents。

4.10 Senior 级追问与参考思路

  1. SAT 为什么完整？
    若两个凸多面体不相交，存在一个分离轴；对 OBB，面法线和边叉积构成候选集合。
  2. BVH 可用 OBB 吗？
    可以但 traversal/intersection 与构建更贵，收益取决于几何各向异性。

4.11 推荐实战

实现 AABB overlap 与 OBB SAT，构造长细旋转物体比较 false candidate 与总成本。

完成实战时建议保留 baseline、指标、实验变量、结果、结论 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

5. 如何验证，而不是“凭感觉优化”

  • 用已知几何构造单元测试：单位矩阵、极端角度、退化三角形
  • 显式固定坐标系 convention 并在 debug draw 中可视化
  • 检查浮点 epsilon、归一化与数值稳定性

推荐实战

用 Python/C++ 写数值单元测试，并做 debug draw 可视化几何结果。

6. 工程 Gotchas（扩展）

  • 先声明坐标系与矩阵 convention，否则公式可能“都对但互相矛盾”
  • 对退化/近平行/极小角度等数值边界要有处理策略

8. 面试评分 Rubric

层级 面试表现
0 - 记忆点 只能给出一个术语或结论，无法解释原因。
1 - 原理 能解释核心机制与至少一个关键不变量。
2 - 工程 能讨论 trade-off、边界条件，并把它落到真实引擎模块。
3 - Senior signal 能给出可测量的成本模型、profiling/验证方法和替代方案。
