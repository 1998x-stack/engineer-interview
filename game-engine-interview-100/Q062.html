Cook-Torrance BRDF 怎么理解？

[!IMPORTANT] 内容分层：PDF 核心内容严格以仓库附带的原 PDF 为基线；专业扩展是为了让题目达到更强的工程面试深度，来自通用工程知识与下方列出的官方/权威资料。两者刻意分开，便于追踪来源。

章节：PBR、阴影、GI 与 Ray Tracing
学习级别：Advanced（仓库学习分级，不是对 PDF 星级符号的重解释）
PDF 位置：物理页 77
来源口径：公开面经/官方资料可核验 · [M1], [M2], [M3]

1. 这道题在考什么

这题属于 PBR、阴影、GI 与 Ray Tracing。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

  1. 机制：数据/状态究竟怎样流动；
  2. 成本：CPU、GPU、内存、同步或数值误差的成本在哪里；
  3. Trade-off：什么场景适合，什么场景会失败；
  4. Engine Context：在真实 renderer / core / asset / simulation 中怎么落地；
  5. Evidence：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

2. 30 秒回答（PDF 核心内容）

微表面镜面项常写 fs = D(h)F(v,h)G(l,v,h) / [4(n·l)(n·v)]；D 描述微表面法线分布，F 是 Fresnel， G 是遮蔽/阴影。

3. PDF 深入拆解（Source-derived）

D 决定高光形状，实时 PBR 常用 GGX；F 表示入射越掠射反射越强，常用 Schlick 近似；G 修正微表面之间的 masking-shadowing。分母来自微表面几何与变量变换。完整材质通常还需要 diffuse term，并满足能量守恒。面试应能解释 roughness 改变的是微表面分布，而不是简单“降低高光亮度”。

PDF 核心抓手

  • D/F/G 各有明确物理角色
  • GGX 常见于实时渲染
  • Schlick Fresnel 是高效近似
  • roughness 会让高光更宽更低

PDF 工程 Gotcha

把 metallic 当“高光强度滑杆”或把 roughness 当“模糊贴图”。

PDF 面试官在听什么

是否理解现代 PBR 的微表面模型。

4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 可实现、可测量、可讨论 trade-off 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

4.1 先修知识与概念边界

  • microfacet theory
  • NDF
  • Fresnel
  • masking-shadowing

4.2 核心心智模型

Cook-Torrance 是微表面镜面 BRDF：假设宏观粗糙表面由大量微镜面组成。D 描述有多少微表面朝向 half-vector，F 描述界面反射比例，G 描述微表面互相遮挡，分母负责从微表面统计变换到宏观 BRDF。

4.3 底层机制：逐层拆开

  • D(h) 常用 GGX/Trowbridge-Reitz，roughness 越低分布越尖，highlight 越集中。
  • Fresnel 常用 Schlick F=F0+(1-F0)(1-V·H)^5；掠射角趋近1。
  • Geometry term 常用 Smith masking-shadowing，将 view/light 两侧可见性组合。
  • 分母 4(N·L)(N·V) 来自微表面投影/概率变换；不能随意省略，否则能量和角度行为错误。

4.4 必须守住的不变量 / 正确性条件

  • N/L/V/H 都应在同一坐标空间并归一化。
  • N·L 或 N·V ≤0 时该 reflection configuration 不贡献。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

4.5 Trade-off：什么时候该用，什么时候不该用

  • GGX 尾部较长，视觉上更符合粗糙表面但会有强高光 tail。
  • 实时实现用近似 G/F/LUT，换少量物理误差为性能。

4.6 在真实游戏引擎中的落点

  • Metallic-roughness PBR 的 specular lobe。
  • IBL prefilter 需与同一 BRDF roughness convention 匹配。
  • Material authoring 中 perceptual roughness 常再映射到 alpha。

4.7 最小实现 / 数学骨架

f_s=\frac{D(h)F(v,h)G(l,v,h)}{4(n\cdot l)(n\cdot v)}

面试建议：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

4.8 Profiling / Validation：如何证明你的判断

  • 用 white furnace test 检查能量行为。
  • 扫 roughness/NoV/F0 参数网格，检查 highlight 连续性与数值 NaN。

4.9 常见错误答案与为什么错

  • “D/F/G 三项都是经验参数。”——它们有明确 microfacet/statistical 物理意义。
  • “roughness 直接等于 GGX alpha。”——不同引擎常用 alpha=roughness² 等映射。

4.10 Senior 级追问与参考思路

  1. 为什么 diffuse 和 specular 需要能量耦合？
    Fresnel 反走的能量不能再作为 diffuse 穿入表面；常用 (1-F) 缩减 diffuse。
  2. 为什么多重散射 microfacet 会影响高 roughness？
    单次 microfacet BRDF 会丢失被微表面多次反射的能量，粗糙表面可能变暗，需要补偿。

4.11 推荐实战

写 GGX D、Smith G、Schlick F，并做 furnace test；比较 roughness=0.1/0.5/1.0。

完成实战时建议保留 baseline、指标、实验变量、结果、结论 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

5. 如何验证，而不是“凭感觉优化”

  • 用 reference/path tracer 或离线 ground truth 做视觉对比
  • 同时观察 variance、bias、sample count 与 GPU cost
  • 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

推荐实战

实现一个 CPU reference 或 shader demo，对照公式和可视化结果验证。

6. 工程 Gotchas（扩展）

  • “物理正确”与“实时可承受”之间总有采样/近似预算
  • 任何 sampling 技术都要同时说明 PDF、bias/variance 与 estimator

  2. Smith G 如何工作？
