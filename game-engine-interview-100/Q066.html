GAME ENGINE · GRAPHICS · 66 / 100

Shadow Acne 和 Peter Panning 为什么出现？

[!IMPORTANT] 内容分层：PDF 核心内容严格以仓库附带的原 PDF 为基线；专业扩展是为了让题目达到更强的工程面试深度，来自通用工程知识与下方列出的官方/权威资料。两者刻意分开，便于追踪来源。

章节：PBR、阴影、GI 与 Ray Tracing
学习级别：Intermediate（仓库学习分级，不是对 PDF 星级符号的重解释）
PDF 位置：物理页 81
来源口径：公开面经/官方资料可核验 · [M1]

1. 这道题在考什么

这题属于 PBR、阴影、GI 与 Ray Tracing。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

  1. 机制：数据/状态究竟怎样流动；
  2. 成本：CPU、GPU、内存、同步或数值误差的成本在哪里；
  3. Trade-off：什么场景适合，什么场景会失败；
  4. Engine Context：在真实 renderer / core / asset / simulation 中怎么落地；
  5. Evidence：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

2. 30 秒回答（PDF 核心内容）

离散 shadow depth 与浮点/采样误差使表面自比较时产生假阴影；加 bias 可缓解，但 bias 过大让阴影与物体分离，形成 Peter Panning。

3. PDF 深入拆解（Source-derived）

常见 bias 包括 constant depth bias、slope-scaled bias 和 normal offset。斜表面尤其容易出现 depth gradient 误差，因此 slope bias 根据表面倾斜程度增加偏移。PCF/软阴影扩大采样范围后 bias 需求也可能变化。没有一个固定 bias 对所有 cascades/距离都最佳，常需按 texel world size 缩放。

PDF 核心抓手

  • acne 是自阴影误判
  • bias 是精度补偿
  • slope/normal bias 各有用途
  • bias 与 shadow texel size 应关联

PDF 工程 Gotcha

只把 bias 数值调大直到 acne 消失，导致远距离阴影漂浮。

PDF 面试官在听什么

是否能把视觉伪影追溯到采样/精度。

4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 可实现、可测量、可讨论 trade-off 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

4.1 先修知识与概念边界

  • shadow map quantization
  • depth bias
  • surface slope
  • normal bias

4.2 核心心智模型

Shadow Acne 来自“同一个表面在 shadow pass 与 camera pass 的离散深度/采样不完全相同”，比较时会错误认为自身更远。Bias 把 receiver/caster 深度人为分离；太大就让阴影脱离，形成 Peter Panning。

4.3 底层机制：逐层拆开

  • Constant depth bias 对所有 fragment 加固定偏移，简单但斜面所需偏移不同。
  • Slope-scaled bias 与 max depth slope 相关，斜视 surface 需要更大偏移。
  • Normal bias 沿 receiver normal 偏移 sample point，在斜面更直观但会改变几何位置。
  • Shadow map texel footprint/PCF kernel 变大时，所需 receiver-plane bias 也可能变化。

4.4 必须守住的不变量 / 正确性条件

  • 没有一个 bias 数值对所有 cascade、分辨率、光角度都完美。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

4.5 Trade-off：什么时候该用，什么时候不该用

  • 小 bias→acne；大 bias→detached shadow/light leak。
  • 提高 shadow resolution 减少量化问题但不能完全消除 slope mismatch。

4.6 在真实游戏引擎中的落点

  • CSM 每 cascade 使用不同 world-units-per-texel，因此 bias 常随 cascade scale。
  • Contact shadow/SS shadow 可补偿大 bias 造成的接触缺失。

4.7 最小实现 / 数学骨架

shadowed = currentDepth - bias > sampledDepth
Bias often = constant + slopeScale * slope (+ normal offset)

面试建议：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

4.8 Profiling / Validation：如何证明你的判断

  • 提供 bias debug sliders 和 cascade-specific visualization。
  • 构造 grazing-angle plane/细小接触物 stress test。

4.9 常见错误答案与为什么错

  • “Peter Panning 是 PCF 导致。”——根因通常是过大的 bias/几何偏移。
  • “把 bias 调到没有 acne 就结束。”——必须检查接触、远近 cascade、不同光角。

4.10 Senior 级追问与参考思路

  1. Receiver-plane depth bias 是什么？
    利用 receiver plane 在 shadow-map footprint 内的深度变化估计每个 sample 需要的偏移，比固定 bias 更自适应。
  2. 为什么 normal bias 会让 thin geometry 出问题？
    沿 normal 移动 receiver 可穿过薄表面/边界，导致漏光或形状变化。

4.11 推荐实战

做 bias lab：constant/slope/normal 三种开关，记录 acne 与 contact error 随光角和分辨率的变化。

完成实战时建议保留 baseline、指标、实验变量、结果、结论 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

5. 如何验证，而不是“凭感觉优化”

  • 用 reference/path tracer 或离线 ground truth 做视觉对比
  • 同时观察 variance、bias、sample count 与 GPU cost
  • 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

推荐实战

实现一个 CPU reference 或 shader demo，对照公式和可视化结果验证。

6. 工程 Gotchas（扩展）

  • “物理正确”与“实时可承受”之间总有采样/近似预算
  • 任何 sampling 技术都要同时说明 PDF、bias/variance 与 estimator

7. 高频追问树

  1. receiver-plane depth bias 是什么？
    先给结论，再说明机制、一个边界条件，以及在引擎中的实际后果；必要时用上方 Senior 级参考思路展开。
  2. Reverse-Z shadow map 会改变 bias 方向吗？
    先给结论，再说明机制、一个边界条件，以及在引擎中的实际后果；必要时用上方 Senior 级参考思路展开。
