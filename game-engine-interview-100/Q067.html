GAME ENGINE · GRAPHICS · 67 / 100

PCF 和 PCSS 有什么区别？

[!IMPORTANT] 内容分层：PDF 核心内容严格以仓库附带的原 PDF 为基线；专业扩展是为了让题目达到更强的工程面试深度，来自通用工程知识与下方列出的官方/权威资料。两者刻意分开，便于追踪来源。

章节：PBR、阴影、GI 与 Ray Tracing
学习级别：Advanced（仓库学习分级，不是对 PDF 星级符号的重解释）
PDF 位置：物理页 82
来源口径：公开面经/官方资料可核验 · [M6]

1. 这道题在考什么

这题属于 PBR、阴影、GI 与 Ray Tracing。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

  1. 机制：数据/状态究竟怎样流动；
  2. 成本：CPU、GPU、内存、同步或数值误差的成本在哪里；
  3. Trade-off：什么场景适合，什么场景会失败；
  4. Engine Context：在真实 renderer / core / asset / simulation 中怎么落地；
  5. Evidence：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

2. 30 秒回答（PDF 核心内容）

PCF 对邻域多个深度比较结果做平均，模糊硬 shadow edge；PCSS 先搜索 blocker，估计 penumbra 大小，再用与软影宽度相关的可变半径 PCF，近似 area light“近硬远软”。

3. PDF 深入拆解（Source-derived）

PCF 不是对深度本身简单 blur，而是对 comparison result/filterable depth representation 做过滤。PCSS 的 blocker search 与 filter 都有多次采样，成本高且容易噪声/抖动，实际会用 Poisson disk、rotated pattern、temporal filtering。对于大面积软影，现代引擎也可能使用 VSM、ray traced shadow 等方案。

PDF 核心抓手

  • PCF= 固定/有限 filter kernel
  • PCSS=blocker search + penumbra estimate + variable PCF
  • 采样模式影响噪声与条纹

PDF 工程 Gotcha

说 PCSS 只是“更大的 PCF”。它的核心是根据 blocker distance 改变半影宽度。

PDF 面试官在听什么

是否理解软阴影的几何来源。

4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 可实现、可测量、可讨论 trade-off 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

4.1 先修知识与概念边界

  • shadow comparison
  • filter kernel
  • area light penumbra
  • blocker search

4.2 核心心智模型

PCF 是“对 binary shadow test 做空间平均”，得到抗锯齿/固定宽软边；PCSS 进一步估算 blocker 距离，用面积光源几何关系动态决定 filter radius，近接触硬、远离 blocker 软。

4.3 底层机制：逐层拆开

  • PCF 对多个偏移位置做 depth compare，平均 0/1 visibility，而不是先平均 depth 再比较。
  • PCSS 第一步在较小区域 search blockers，计算平均 blocker depth。
  • 根据 receiver-blocker 距离和 light size 估计 penumbra radius。
  • 最后用与估计 penumbra 对应的可变半径 PCF。

4.4 必须守住的不变量 / 正确性条件

  • PCF filter 的对象是比较结果；直接线性滤 depth 语义不同（VSM/EVSM 等另说）。
  • PCSS 是近似 area-light soft shadow，不是精确积分。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

4.5 Trade-off：什么时候该用，什么时候不该用

  • PCF 采样数稳定、便宜；PCSS blocker search+可变 kernel 更贵且噪声/带宽高。
  • VSM/EVSM 用 moments 允许可滤纹理，但有 light bleeding 风险。

4.6 在真实游戏引擎中的落点

  • Sun/spot soft shadow。
  • Poisson disk/rotated kernel + temporal accumulation 降采样。
  • Contact-hardening shadow。

4.7 最小实现 / 数学骨架

PCF : average(compare(z_receiver, z_shadow_i))
PCSS: blocker search -> penumbra estimate -> variable-radius PCF

面试建议：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

4.8 Profiling / Validation：如何证明你的判断

  • 统计 shadow texture samples/pixel、cache hit、penumbra artifact。
  • 不同 light size/blocker distance 与 path-traced reference 对比。

4.9 常见错误答案与为什么错

  • “PCF 把 shadow depth 模糊后比较。”——标准 PCF 是先比较再过滤结果。
  • “PCSS 只是更大的 PCF kernel。”——关键是 blocker-based variable radius。

4.10 Senior 级追问与参考思路

  1. 为什么 PCSS blocker search 难？
    真正 blocker 分布复杂，单平均深度是粗近似；采样不足会抖动。
  2. Temporal PCF/PCSS 如何做？
    每帧少量随机样本 + reprojection/history filter，需处理 disocclusion/ghosting。

4.11 推荐实战

实现 3×3/Poisson PCF，再实现简化 PCSS，比较固定 filter 与 contact-hardening。

完成实战时建议保留 baseline、指标、实验变量、结果、结论 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

5. 如何验证，而不是“凭感觉优化”

  • 用 reference/path tracer 或离线 ground truth 做视觉对比
  • 同时观察 variance、bias、sample count 与 GPU cost
  • 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

推荐实战

实现一个 CPU reference 或 shader demo，对照公式和可视化结果验证。

6. 工程 Gotchas（扩展）

  • “物理正确”与“实时可承受”之间总有采样/近似预算
  • 任何 sampling 技术都要同时说明 PDF、bias/variance 与 estimator
