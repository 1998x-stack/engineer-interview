Path Tracing 为什么会有噪声？收敛速度如何理解？

[!IMPORTANT] 内容分层：PDF 核心内容严格以仓库附带的原 PDF 为基线；专业扩展是为了让题目达到更强的工程面试深度，来自通用工程知识与下方列出的官方/权威资料。两者刻意分开，便于追踪来源。

章节：PBR、阴影、GI 与 Ray Tracing
学习级别：Advanced（仓库学习分级，不是对 PDF 星级符号的重解释）
PDF 位置：物理页 83
来源口径：公开面经/官方资料可核验 · [M4]

1. 这道题在考什么

这题属于 PBR、阴影、GI 与 Ray Tracing。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

  1. 机制：数据/状态究竟怎样流动；
  2. 成本：CPU、GPU、内存、同步或数值误差的成本在哪里；
  3. Trade-off：什么场景适合，什么场景会失败；
  4. Engine Context：在真实 renderer / core / asset / simulation 中怎么落地；
  5. Evidence：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

2. 30 秒回答（PDF 核心内容）

Path Tracing 用 Monte Carlo 随机估计高维光传输积分。估计量方差导致图像噪声；独立样本标准误差通常按 1/√N 下降，所以想把噪声标准差减半约需 4 倍样本。

3. PDF 深入拆解（Source-derived）

路径追踪每个像素随机采样方向、光源和路径长度。无偏意味着期望值正确，不等于有限样本没有误差；很多工业技巧会接受轻微偏差换更低方差。Russian Roulette 用概率终止长路径同时保持期望；denoising 则利用空间/时间先验在少样本下重建。核心是“方差管理”，不是单纯增加 spp。

PDF 核心抓手

  • Monte Carlo 方差来源
  • 标准误差 ~1/√N
  • 无偏与低方差是不同目标
  • Russian Roulette 保持期望同时控制路径长度

PDF 工程 Gotcha

认为“无偏 = 每一帧都是正确答案”。

PDF 面试官在听什么

是否理解随机积分而非把 Path Tracing 当黑盒。

4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 可实现、可测量、可讨论 trade-off 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

4.1 先修知识与概念边界

  • Monte Carlo estimator
  • variance
  • law of large numbers
  • path throughput

4.2 核心心智模型

Path Tracing 的噪声来自 Monte Carlo 方差：有限样本随机估计高维光传输积分。若样本独立同分布，标准误差通常按 1/sqrt(N) 收敛，因此把噪声减半需要约4倍样本。

4.3 底层机制：逐层拆开

  • Estimator I_hat=1/N Σ f(x_i)/p(x_i) 在采样覆盖 integrand 且权重正确时可无偏。
  • 高方差来源包括小面积强光、specular-diffuse-caustic 稀有路径、bad sampling distribution。
  • Russian Roulette 可随机终止低 throughput 路径并用 survival probability 补权，保持无偏但改变方差。
  • Next Event Estimation/Importance Sampling/MIS 都是在降低方差，而不是改变真实积分目标。

4.4 必须守住的不变量 / 正确性条件

  • 低 bias 不等于低 variance；“无偏但很噪”与“有偏但稳定”是不同轴。
  • 采样 pdf 为0的区域若 integrand 非0，会产生不可恢复 bias/漏项。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

4.5 Trade-off：什么时候该用，什么时候不该用

  • 实时 RT 常接受 denoiser/temporal reuse 引入 bias 以大幅降低样本数。
  • 更多 bounce 增加高阶 GI 但成本和方差上升。

4.6 在真实游戏引擎中的落点

  • Offline reference renderer。
  • 1 spp real-time RT + denoise。
  • Progressive accumulation photo mode。

4.7 最小实现 / 数学骨架

\hat I=\frac{1}{N}\sum_{i=1}^N\frac{f(X_i)}{p(X_i)},\qquad
\sigma_{mean}\propto\frac{1}{\sqrt N}

面试建议：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

4.8 Profiling / Validation：如何证明你的判断

  • 对固定 pixel/scene 画 sample count→MSE/variance 曲线。
  • 用 reference image 分离 bias 和 temporal noise。

4.9 常见错误答案与为什么错

  • “Path tracing 噪声是浮点误差。”——主要是随机采样方差。
  • “样本翻倍噪声减半。”——标准误差约下降 sqrt(2) 倍。

4.10 Senior 级追问与参考思路

  1. Firefly 为什么产生？
    少量样本获得极大 f/p 权重，常见于高亮 specular/小光源/bad pdf。
  2. Clamp firefly 有什么代价？
    降低方差但引入 bias，可能压暗真实高能路径。

4.11 推荐实战

对 Cornell box 跑 1/4/16/64/256 spp，计算 MSE，验证近似 1/sqrt(N) 规律。

完成实战时建议保留 baseline、指标、实验变量、结果、结论 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

5. 如何验证，而不是“凭感觉优化”

  • 用 reference/path tracer 或离线 ground truth 做视觉对比
  • 同时观察 variance、bias、sample count 与 GPU cost
  • 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

推荐实战

实现一个 CPU reference 或 shader demo，对照公式和可视化结果验证。

  • “物理正确”与“实时可承受”之间总有采样/近似预算
  • 任何 sampling 技术都要同时说明 PDF、bias/variance 与 estimator
