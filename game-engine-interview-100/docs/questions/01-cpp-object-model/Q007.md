## 2. 30 秒回答（PDF 核心内容）

容量不足时 vector 申请更大的连续区域，把旧元素 move/copy 到新区域，销毁旧元素并释放旧存储；发生 reallocation 时所有指针、引用和 iterator 都会失效。

---

## 3. PDF 深入拆解（Source-derived）

vector 的优势是连续内存；代价是容量增长时必须整体迁移。增长倍率由实现决定，不应假设严格 2 倍。reserve 可以提前规划容量，减少分配和迁移；但 reserve 过大也会增加常驻内存。对于非平凡类型，移动是否 noexcept 会影响迁移选择。引擎代码还要警惕把 vector 元素地址长期注册到其他系统。

### PDF 核心抓手
- size 与 capacity 的区别
- reserve 不改变 size
- reallocation 的 iterator invalidation
- emplace_back 也可能触发整体迁移

### PDF 工程 Gotcha

认为“尾部 push_back 永远 O(1)”。准确说是 amortized O(1)，单次扩容可能 O(n)。

### PDF 面试官在听什么

是否能把容器语义与对象生命周期、缓存和引擎指针稳定性联系起来。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- 连续容器
- allocator
- 迭代器失效规则
- move/copy exception guarantee

### 4.2 核心心智模型

vector 的关键不变量是“元素连续”。当 capacity 不足，必须迁移整个存储区；因此性能与正确性都围绕 realloc、元素搬迁和 iterator/reference invalidation 展开。

### 4.3 底层机制：逐层拆开

- 增长因子由实现决定，通常是几何增长以保证 amortized O(1) push_back；不能假设固定 2x。
- 扩容申请新连续块，然后 move/copy 构造旧元素，销毁旧元素并释放旧块。
- 发生 reallocation 时所有指针、引用、迭代器失效；未 reallocate 的插入也可能使插入点及其后的 iterator 失效。
- 元素 move 是否 noexcept 会影响迁移策略与异常保证；对 trivially relocatable 类型未来/扩展实现还可能更高效。

### 4.4 必须守住的不变量 / 正确性条件

- size ≤ capacity；元素区间 `[data, data+size)` 连续。
- 任何保存 vector element address 的系统都必须显式管理 reallocation 风险。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- `reserve` 减少 realloc，但过度 reserve 会提高峰值内存。
- 稳定地址需求可用 deque、pool、slot map/handle，而不是强行依赖 vector 指针。

### 4.6 在真实游戏引擎中的落点

- Render item 列表每帧可预测上限时 reserve，减少 frame hitch。
- Entity storage 常用 chunk/archetype 或 slot-map，避免外部持 vector 元素裸指针。
- GPU upload batch 使用 vector 时要在提交前冻结容量，防止记录的 pointer/span 失效。

### 4.7 最小实现 / 数学骨架

```cpp
std::vector<RenderItem> items;
items.reserve(expectedVisible);
// reserve 后仍不要假设永不扩容：上限策略必须可观测。
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 统计每帧 capacity growth 事件，把 realloc 作为 profiler counter。
- 用 allocator instrumentation 记录 copy/move bytes 与峰值 capacity。

### 4.9 常见错误答案与为什么错

- “vector push_back 是 O(1)，所以永远没有尖峰。”——是 amortized O(1)，单次扩容 O(n)。
- “reserve(n) 会把 size 变成 n。”——只改变 capacity。

### 4.10 Senior 级追问与参考思路

1. **为什么 stable pointer 很重要？**  
   很多引擎系统跨阶段保存引用；vector relocation 可制造隐蔽悬空指针，handle/indirection 更稳。
2. **如何选择 growth policy？**  
   标准 vector 不允许直接控制；自研容器需在 allocation 次数、峰值内存和搬迁成本之间平衡。

### 4.11 推荐实战

> 为每帧 visible object vector 加 capacity telemetry，构造高速转向场景触发峰值，找出 reserve 策略和内存预算的平衡点。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 查看对象布局/生成汇编，确认假设是否成立
- 对 microbenchmark 与真实 frame profile 做区分
- 用 ASan/UBSan/TSan 等工具验证生命周期或并发错误

### 推荐实战

> 写一个最小 C++ 程序，用编译器输出/汇编验证对象布局或生命周期假设；记录优化前后差异。
