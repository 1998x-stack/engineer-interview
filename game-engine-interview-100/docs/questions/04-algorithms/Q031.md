## 1. 这道题在考什么

这题属于 **数据结构与算法**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

## 2. 30 秒回答（PDF 核心内容）

流式场景维护大小 K 的小顶堆：前 K 个建堆，后续元素若大于堆顶则替换并下沉；复杂度 O(N log K)，空间 O(K)。

---

## 3. PDF 深入拆解（Source-derived）

如果数据全在内存且只需无序 Top-K，可用 QuickSelect 平均 O(N) 把第 K 大元素定位，再处理一侧；如果需要最终排序，则还需 O(K log K)。面试应先问清楚 N、K、是否流式、是否允许修改原数组、是否要有序输出。工程化时还要考虑 SIMD、并行 partition 或分块 local top-K 再 merge。

### PDF 核心抓手
- 先澄清 streaming vs offline
- 小顶堆适合在线 Top-K
- QuickSelect 适合离线无序选择
- 最终排序是额外成本

### PDF 工程 Gotcha

一上来就排序全部数据 O(N log N)，没有利用 K 远小于 N。

### PDF 面试官在听什么

是否会从约束出发选算法，而不是背固定模板。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- heap
- QuickSelect
- Top-K
- 复杂度与数据流

### 4.2 核心心智模型

Top-K 的正确答案取决于数据是否流式、是否要排序、K/N 比例、内存约束。面试不仅要给小顶堆，还要能比较 heap、QuickSelect、partial_sort 和分布式方案。

### 4.3 底层机制：逐层拆开

- 维护 K 大小 min-heap：前 K 建堆，之后每个 x 若大于 heap top 则替换并下沉；O(N logK)，空间 O(K)。
- QuickSelect 基于 partition，在平均 O(N) 找到第 N-K 个 order statistic，再取右侧 K 个；最坏 O(N²)，可随机化/median-of-medians。
- 若最终还要有序，heap 方案额外 O(K logK)，QuickSelect 后也需排序 K。
- 流式/无限数据无法 QuickSelect 全量，heap 是自然在线算法。

### 4.4 必须守住的不变量 / 正确性条件

- Top-K “集合”与“有序 Top-K”是不同需求。
- K 接近 N 时，直接 sort/partial_sort 的常数和实现优化可能更好。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- heap 更新分支多、随机一些；对于整数有限范围可用 counting/bucket。
- GPU/并行场景可分块局部 Top-K，再 merge 局部结果。

### 4.6 在真实游戏引擎中的落点

- LOD candidate/最重要 lights 选择。
- Telemetry 中 top slow frames/functions。
- 邻近对象筛选中先粗排再取 K nearest。

### 4.7 最小实现 / 数学骨架

```cpp
priority_queue<int, vector<int>, greater<int>> h;
for (int x: a) {
  if (h.size()<K) h.push(x);
  else if (x>h.top()) { h.pop(); h.push(x); }
}
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 根据 N/K 画算法 crossover，不能只背复杂度。
- 若数据量大，测 memory bandwidth 和 cache behavior。

### 4.9 常见错误答案与为什么错

- “最大的 K 个用大顶堆。”——维护候选集时通常用小顶堆才能 O(1) 查看当前门槛。
- “QuickSelect 永远 O(N)。”——平均 O(N)，经典实现最坏 O(N²)。

### 4.10 Senior 级追问与参考思路

1. **分布式 Top-K 怎么做？**  
   每 shard 先局部 Top-K，汇总最多 shards×K 个候选再做全局 Top-K；正确因为非局部 Top-K 不可能进入全局 Top-K。
2. **K 很小且 SIMD/branch 成本重要呢？**  
   可用固定排序网络/小数组插入，K=4/8 时比通用 heap 更快。

### 4.11 推荐实战

> 对 N=1e5, K=1e4 与 K=32 分别比较 heap、nth_element、partial_sort，写出选择规则。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 先写正确性测试与边界样例，再做复杂度/性能基线
- 记录 N、K、分布等输入特征，避免脱离规模谈算法
- 对空间结构同时测 build/update/query 成本

### 推荐实战

> 实现算法并构造随机/极端测试；同时记录输入规模与耗时曲线。
