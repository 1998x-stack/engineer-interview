# Q032 · 实现 A*，为什么它比 Dijkstra 更适合游戏寻路？

## 2. 30 秒回答（PDF 核心内容）

A* 使用 f(n)=g(n)+h(n)，用启发函数把搜索集中到目标方向；当 h=0 时退化为 Dijkstra。若 h 可采纳且满足相应条件，可保持最优性。

---

## 3. PDF 深入拆解（Source-derived）

游戏地图中的核心是 heuristic。栅格上 Manhattan/Euclidean 距离要和允许移动方式匹配；过大的 h 会更贪心但可能失去最优性。open set 常用优先队列，closed set 记录已处理节点。工业实现还关心节点内存、重复 decrease-key、路径平滑以及 navmesh polygon graph 上的 funnel。

### PDF 核心抓手
- f=g+h
- admissible heuristic 不高估真实剩余代价
- Dijkstra 是 h=0 的特例
- 启发越强通常扩展节点越少

### PDF 工程 Gotcha

只说“A* 更快”，不说明快来自搜索方向性，也不说明启发函数的正确性条件。

### PDF 面试官在听什么

是否理解算法性质而非只会写模板。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- 图搜索
- Dijkstra
- heuristic
- priority queue

### 4.2 核心心智模型

A* = Dijkstra 的真实代价 g + 目标导向 heuristic h。正确性和效率取决于 heuristic：admissible 保证不高估；consistent 让 f 沿路径不下降并减少 reopen。

### 4.3 底层机制：逐层拆开

- open set 按最小 f=g+h 取节点；若发现更低 g，更新 parent/g 并调整优先级。
- h=0 退化 Dijkstra；h 越接近真实剩余成本且不高估，搜索范围越小。
- consistent 条件 `h(n) ≤ c(n,n') + h(n')`，对 graph search 可保证节点首次 closed 即最优。
- 网格 4 邻域常用 Manhattan，8 邻域用 octile/Euclidean；heuristic 要匹配移动代价。

### 4.4 必须守住的不变量 / 正确性条件

- 最短路径保证依赖边权非负及 heuristic 条件。
- priority queue 中 decrease-key 可用重复 push + stale-check 简化实现。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- Weighted A* 用 `f=g+w*h, w>1` 换更快搜索但可能非最优。
- 动态世界中重复完整 A* 成本高，可用 D*/LPA*/局部修复。

### 4.6 在真实游戏引擎中的落点

- NavMesh polygon graph A*，随后 funnel 平滑。
- RTS grid pathfinding 与 hierarchical sector graph。
- AI cost field 可把危险区/拥堵编码进 edge cost。

### 4.7 最小实现 / 数学骨架

```text
f(n)=g(n)+h(n)
while open:
  n=pop_min_f()
  if n==goal: reconstruct
  relax neighbors
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 统计 expanded nodes、open-set peak、path suboptimality、search time P99。
- 在障碍稀疏/迷宫/长距离场景比较 heuristic 质量。

### 4.9 常见错误答案与为什么错

- “A* 一定比 Dijkstra 快。”——差 heuristic 或特殊图上可能相近，额外 h 还有成本。
- “Euclidean 永远 admissible。”——要看 edge cost 定义。

### 4.10 Senior 级追问与参考思路

1. **consistent 为什么比 admissible 更强？**  
   consistent 推出 admissible，并使 f 不递减，graph search 通常无需 reopen closed node。
2. **如何处理多 agent pathfinding？**  
   共享 flow field、hierarchical path、reservation/cooperative A* 或局部避障，不能每 agent 每帧全图 A*。

### 4.11 推荐实战

> 实现 grid A*，支持 Manhattan/Euclidean/weighted heuristic，输出 expanded nodes 与最优性误差。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 先写正确性测试与边界样例，再做复杂度/性能基线
- 记录 N、K、分布等输入特征，避免脱离规模谈算法
- 对空间结构同时测 build/update/query 成本

### 推荐实战

> 在 grid 和 NavMesh-like graph 上分别实现 A*，对不同 heuristic 比较 expanded nodes。
