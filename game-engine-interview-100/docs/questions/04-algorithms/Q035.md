## 1. 这道题在考什么

这题属于 **数据结构与算法**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：开放世界寻路/空间查询、碰撞 broad phase、可见性与加速结构。

## 2. 30 秒回答（PDF 核心内容）

一般二叉树可递归：若当前节点是 p/q 就返回；分别搜索左右子树，若两边都非空则当前节点为 LCA，否则返回非空一侧。时间 O(N)。

---

## 3. PDF 深入拆解（Source-derived）

如果是 BST，可利用有序性根据 p/q 值决定向左或右；如果有 parent pointer，可把问题变成两条祖先链求交；如果需要大量 LCA 查询，则可预处理 binary lifting 或 Euler Tour + RMQ。 面试官常看你能否根据“单次/多次查询、树性质”选择不同方案。

### PDF 核心抓手
- 一般树递归 O(N)
- BST 可利用排序性质
- 多查询考虑预处理
- 有 parent pointer 可转链表相交

### PDF 工程 Gotcha

没确认 p、q 是否一定存在树中；某些题目需要额外存在性判断。

### PDF 面试官在听什么

是否会根据问题模型变化推导方案。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- 树递归
- parent/depth
- binary lifting
- 离线/在线查询

### 4.2 核心心智模型

LCA 不只有一道递归题。单次普通二叉树可 O(N) DFS；若大量查询，应预处理 parent/depth，使用 binary lifting、Euler Tour + RMQ 或 Tarjan offline。面试要先问查询规模。

### 4.3 底层机制：逐层拆开

- 单次递归：若左右子树各返回一个目标，则当前节点是 LCA；若只一侧有结果则向上传递。
- 有 parent pointer 时先对齐深度再同步上跳，O(height)。
- Binary lifting 预计算 `up[v][k]=2^k` 祖先，预处理 O(NlogN)，每 query O(logN)。
- Euler tour 记录深度序列，LCA 变成两个首次出现位置间最小深度 RMQ。

### 4.4 必须守住的不变量 / 正确性条件

- 若题目不保证 p/q 都存在，递归版本要额外记录 found count。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 一次查询用简单 DFS；海量查询才值得复杂预处理。
- 动态树会让静态 RMQ/lifting 更新复杂，需要其他数据结构。

### 4.6 在真实游戏引擎中的落点

- Scene hierarchy 查共同 ancestor。
- Bone hierarchy 关系分析。
- UI/widget tree 事件路径。

### 4.7 最小实现 / 数学骨架

```cpp
Node* lca(Node* r, Node* a, Node* b){
 if(!r||r==a||r==b) return r;
 auto L=lca(r->left,a,b), R=lca(r->right,a,b);
 return L&&R ? r : (L?L:R);
}
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 对极深树避免递归栈风险；可转 iterative。

### 4.9 常见错误答案与为什么错

- “LCA 永远 O(logN)。”——只有平衡/预处理方案；普通树单 query DFS 是 O(N)。
- “递归返回非空就一定 p/q 都存在。”——可能只找到一个。

### 4.10 Senior 级追问与参考思路

1. **百万次 LCA query 怎么做？**  
   静态树 binary lifting 或 Euler+RMQ；根据内存和 query 数选择。
2. **有 parent pointer 的最简单方案？**  
   对齐 depth 后一起向上，O(height)，O(1) extra space。

### 4.11 推荐实战

> 同一棵 1e5 节点树实现 DFS、binary lifting 两版，比较 1 次与 1e6 次 query 的总成本。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 先写正确性测试与边界样例，再做复杂度/性能基线
- 记录 N、K、分布等输入特征，避免脱离规模谈算法
- 对空间结构同时测 build/update/query 成本

### 推荐实战

> 实现算法并构造随机/极端测试；同时记录输入规模与耗时曲线。
