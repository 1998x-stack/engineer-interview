## 2. 30 秒回答（PDF 核心内容）

栈方案以 -1 作为最近非法边界；遇左括号压索引，遇右括号弹栈，若栈空则当前索引成为新边界，否则长度为 i-stack.top。

---

## 3. PDF 深入拆解（Source-derived）

这个技巧的本质是保存“当前合法段之前的最近无效位置”。也可用 DP：dp[i] 表示以 i 结尾的最长合法长度，并根据前一个匹配位置递推；还可左右两次扫描计数，用 O(1) 空间。面试中若能给两种方案并比较，更容易体现算法理解。

### PDF 核心抓手
- 栈保存索引而不是字符
- 哨兵 -1 统一边界
- DP/双向扫描是替代方案

### PDF 工程 Gotcha

遇到栈空后忘记压入当前右括号索引，后续长度会跨过非法边界。

### PDF 面试官在听什么

是否理解边界状态设计。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- stack
- 动态规划
- 字符串扫描
- 边界哨兵

### 4.2 核心心智模型

O(N) 解法的关键是把 stack 当作“当前合法区间之前最后一个未匹配位置”的索引结构。哨兵 -1 让长度公式统一。也可以用 DP，面试最好知道两种。

### 4.3 底层机制：逐层拆开

- 栈法遇 `(` push index；遇 `)` 先 pop。若栈空，当前 `)` 成为新 invalid base；否则合法长度 `i-stack.top()`。
- 初始压入 -1，处理从字符串开头形成的合法串。
- DP 可定义 `dp[i]` 为以 i 结尾的最长合法长度，针对 `...()` 和 `...))` 两种转移。
- 两次扫描计数法 O(1) space 也可求长度，但不直接给区间/结构信息。

### 4.4 必须守住的不变量 / 正确性条件

- 只在 `)` 位置可能形成新的合法后缀。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- stack O(N) space 易理解、能找边界；DP 也 O(N) space；双扫描 O(1) space。

### 4.6 在真实游戏引擎中的落点

- 主要是算法基本功；可类比 parser 中 delimiter matching 与错误恢复。

### 4.7 最小实现 / 数学骨架

```text
stack=[-1]
for i,c:
  if '(' push(i)
  else pop(); if empty push(i) else ans=max(ans,i-top)
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 覆盖 `""`, `")("`, `"(()"`, `")()())"`, 全合法、全非法。

### 4.9 常见错误答案与为什么错

- “只数左右括号总数就能得到最长连续长度。”——连续性和嵌套结构会破坏。
- 忘记 sentinel 导致开头合法串长度计算错误。

### 4.10 Senior 级追问与参考思路

1. **如何返回所有最长区间？**  
   在更新 ans 时保存 start=stack.top()+1；等于 ans 时追加。
2. **为什么双向扫描可 O(1)？**  
   左→右防 right>left，右→左对称防 left>right。

### 4.11 推荐实战

> 同时实现 stack/DP/O(1) 双扫描，写随机字符串 brute-force oracle 做 property test。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 先写正确性测试与边界样例，再做复杂度/性能基线
- 记录 N、K、分布等输入特征，避免脱离规模谈算法
- 对空间结构同时测 build/update/query 成本

### 推荐实战

> 实现算法并构造随机/极端测试；同时记录输入规模与耗时曲线。
