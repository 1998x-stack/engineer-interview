# Q039 · Quadtree、Octree、BVH 有什么区别？

## 1. 这道题在考什么

这题属于 **数据结构与算法**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；

本章常见工程落点：开放世界寻路/空间查询、碰撞 broad phase、可见性与加速结构。

## 2. 30 秒回答（PDF 核心内容）

Quadtree/Octree 规则地划分空间；BVH 根据对象/几何构造包围体层级。前者适合空间查询与相对均匀分布，BVH 更贴合几何分布并广泛用于 ray tracing。

---

## 3. PDF 深入拆解（Source-derived）

规则树的优势是位置天然决定节点，更新和邻域查询直观；缺点是空区域也可能产生层级且非均匀分布会造成深树。BVH 叶节点直接包围 primitive/object，节点边界可重叠，构建成本更高但 traversal 通常能快速排除大量几何。不能仅用“八叉树每层 8 个孩子所以一定更浅”判断性能。

### PDF 核心抓手
- 空间划分 vs 对象层次
- BVH 节点可重叠
- 树深不是唯一性能指标
- 数据分布决定结构选择

### PDF 工程 Gotcha

把 BVH 说成空间被严格切成不相交区域。

### PDF 面试官在听什么

是否理解空间数据结构的建模差异。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- 空间划分
- 包围体
- 树遍历
- 构建成本

### 4.2 核心心智模型

Quadtree/Octree 是规则空间细分；BVH 是对象驱动的层级包围。选择取决于维度、几何分布、动态更新和查询类型，而不是“BVH 最新所以最好”。

### 4.3 底层机制：逐层拆开

- Quadtree 每节点 2D 四分；Octree 3D 八分，节点区域固定，物体按空间落入。
- BVH 每内部节点包围一组 primitive/object，子节点划分可根据几何分布和 SAH 优化。
- 规则树在空旷/稀疏空间可能产生许多空节点或深度不均；loose octree 用放大 cell 减少跨边界对象频繁移动。
- BVH traversal 通过 ray/AABB 或 query/AABB 剪枝；高质量 tree 能显著减少 primitive tests。

### 4.4 必须守住的不变量 / 正确性条件

- 树的价值来自“用 cheap bound test 排除大批 expensive leaf tests”。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- Octree 更新对象位置较直观；高质量 BVH rebuild 更贵但查询通常更紧。
- 静态几何可投入更昂贵 SAH build；动态对象偏 fast build/refit。

### 4.6 在真实游戏引擎中的落点

- Scene culling：BVH/loose octree。
- Ray tracing：BLAS/TLAS BVH。
- 2D 大地图/terrain quadtree LOD。

### 4.7 最小实现 / 数学骨架

```text
Regular spatial tree: split space first -> assign objects
BVH               : group objects first -> bound groups
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 节点访问数、leaf candidate 数、tree depth、build/update time、memory/node。

### 4.9 常见错误答案与为什么错

- “Octree 每个对象只能在一个 leaf。”——跨节点大对象需要特殊策略。
- “BVH 查询一定 O(logN)。”——退化树/重叠严重时可接近 O(N)。

### 4.10 Senior 级追问与参考思路

1. **loose octree 为什么有用？**  
   扩大节点包围范围，使移动对象在 cell 附近移动时不必频繁 reinsert，代价是查询 overlap 增大。
2. **SAH 在优化什么？**  
   用表面积近似 traversal 命中概率，最小化期望 traversal + primitive intersection 成本。

### 4.11 推荐实战

> 对 clustered、uniform、linear 三种点云构建 octree/BVH，比较节点访问和更新时间。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 先写正确性测试与边界样例，再做复杂度/性能基线
- 记录 N、K、分布等输入特征，避免脱离规模谈算法
- 对空间结构同时测 build/update/query 成本

### 推荐实战

> 实现算法并构造随机/极端测试；同时记录输入规模与耗时曲线。
