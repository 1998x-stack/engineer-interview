# Q040 · 动态对象很多时 BVH 怎么更新？

## 1. 这道题在考什么

这题属于 **数据结构与算法**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：开放世界寻路/空间查询、碰撞 broad phase、可见性与加速结构。

---

## 2. 30 秒回答（PDF 核心内容）

常见策略是 refit 更新节点 bounding box， 成本低但树质量会逐渐恶化；必要时局部/全局 rebuild。 实践中常采用 refit + periodic rebuild 的混合策略。

---

## 3. PDF 深入拆解（Source-derived）

如果拓扑不变、对象只轻微运动，bottom-up refit 很有效；若对象跨越很大范围，原本邻近的 leaf 已不再邻近，overlap 增加导致 traversal 变慢。可通过质量指标（SAH cost、overlap ratio） 触发 rebuild，或把动态/静态对象分成不同结构。硬件光追常见 TLAS 每帧更新、BLAS 对静态 mesh 复用。

### PDF 核心抓手
- refit 便宜但会退化
- rebuild 恢复质量但昂贵
- 动静分离
- 用质量指标决定何时重建

### PDF 工程 Gotcha

每帧无脑全重建，或只 refit 永不监控退化。

### PDF 面试官在听什么

是否理解动态加速结构的长期性能。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- BVH refit/rebuild
- SAH
- dynamic scene
- TLAS/BLAS

### 4.2 核心心智模型

动态 BVH 的核心 trade-off 是“更新便宜 vs 树质量”。Refit 只改 bounds 很快，但对象移动后 sibling 关系变差、overlap 增大；Rebuild 恢复质量但构建贵。工程上常做 refit + 局部旋转/周期 rebuild。

### 4.3 底层机制：逐层拆开

- leaf 物体变换后更新 leaf AABB，再自底向上 union 子 bounds 完成 refit。
- refit 不改变 topology，因此大幅移动会让 parent bounds 膨胀、节点互相重叠，查询访问数增加。
- tree rotations/local rebuild 可在局部降低 SAH cost。
- 硬件 RT 常把静态 mesh BLAS 与实例 TLAS 分离：mesh 内部不变只更新 instance transform/TLAS。

### 4.4 必须守住的不变量 / 正确性条件

- 更新成本和 traversal 成本要一起看，不能只优化 build time。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 每帧 rebuild 适合对象少/GPU fast builder；大量对象通常 refit + quality threshold。
- fat AABB 可减少小移动更新次数，但增加 broad-phase false positives。

### 4.6 在真实游戏引擎中的落点

- Physics dynamic AABB tree。
- Ray tracing TLAS update/refit。
- Scene BVH：静态与动态对象分层，避免动态更新污染静态树。

### 4.7 最小实现 / 数学骨架

```text
Every frame: refit changed leaves
if SAH_cost / baseline > threshold:
    schedule rebuild (possibly async)
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 记录 refit time、rebuild time、average nodes visited/query、SAH cost drift。
- 定义质量阈值触发后台 rebuild，不按固定“每100帧”拍脑袋。

### 4.9 常见错误答案与为什么错

- “Refit 后 BVH 和 rebuild 一样好。”——topology 不变。
- “动态对象必须每帧重建整个 BVH。”——通常太贵且没有必要。

### 4.10 Senior 级追问与参考思路

1. **为什么 TLAS/BLAS 分离适合动画/实例？**  
   大量实例只变 transform，可更新 TLAS 而复用 mesh BLAS；skinned mesh 则可能需要 BLAS update/rebuild。
2. **如何异步 rebuild 而不中断查询？**  
   构建新树副本，完成后在安全同步点原子交换 root/version，并延迟释放旧树。

### 4.11 推荐实战

> 实现 BVH refit + SAH drift metric；让对象逐渐从簇中散开，观察 traversal degradation 并自动触发 rebuild。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 先写正确性测试与边界样例，再做复杂度/性能基线
- 记录 N、K、分布等输入特征，避免脱离规模谈算法
- 对空间结构同时测 build/update/query 成本

### 推荐实战

> 实现算法并构造随机/极端测试；同时记录输入规模与耗时曲线。
