# Q042 · 齐次坐标为什么需要第四维？

## 1. 这道题在考什么

这题属于 **3D 数学与几何**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；

本章常见工程落点：camera/view/projection、碰撞与 picking、raster attribute interpolation。

## 2. 30 秒回答（PDF 核心内容）

把 3D 点扩展成 (x,y,z,w) 后，平移、投影等仿射/射影变换都能统一写成矩阵乘法；点通常 w=1， 方向通常 w=0。

---

## 3. PDF 深入拆解（Source-derived）

最重要的是 perspective projection：投影矩阵把与深度相关的量写入 w，随后除以 w 产生远小近大的效果。齐次坐标还让无穷远方向、projective equivalence 和 clipping 有统一数学表达。面试回答不应停在“为了平移” ，因为真正渲染价值在整个 projective pipeline。

### PDF 核心抓手
- 平移可纳入矩阵
- 方向 w=0 不受平移影响
- perspective divide 使用 w
- 同一欧氏点可由比例等价齐次坐标表示

### PDF 工程 Gotcha

认为 w 永远等于 1。经过投影后 w 通常与 view-space depth 相关。

### PDF 面试官在听什么

是否真正理解投影几何。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- 仿射变换
- 矩阵乘法
- 投影几何
- 点与方向

### 4.2 核心心智模型

第四维 w 让平移也能写成线性矩阵乘法，并进一步容纳透视投影。w 还区分点和方向：点 w=1 受平移影响，方向 w=0 不受平移影响。

### 4.3 底层机制：逐层拆开

- 3×3 只能表达线性变换，无法把任意向量统一加上 translation；扩到 4×4 后 translation 放在最后一列/行。
- 齐次坐标 `(x,y,z,w)` 表示同一 projective point 的比例类，`(kx,ky,kz,kw)` 与原点等价（k≠0）。
- 透视投影把深度信息编码进 clip w，perspective divide `xyz/w` 产生近大远小。
- 方向/法向等几何量使用 w=0，可以自然避免 translation。

### 4.4 必须守住的不变量 / 正确性条件

- 齐次坐标只在 w≠0 时能回到普通欧氏点 `xyz/w`。
- w=0 还可表示 projective infinity direction，不只是“随便填0”。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 统一 4×4 方便 SIMD/GPU pipeline，但对法线仍不能简单用普通 model matrix（见 Q043）。

### 4.6 在真实游戏引擎中的落点

- Transform hierarchy 统一组合平移/旋转/缩放。
- Perspective projection 与 clip plane。
- Position/Direction shader semantic：避免错误把 translation 加到方向。

### 4.7 最小实现 / 数学骨架

```math
\begin{bmatrix}R&t\\0&1\end{bmatrix}\begin{bmatrix}p\\1\end{bmatrix}
=\begin{bmatrix}Rp+t\\1\end{bmatrix},\quad
\begin{bmatrix}R&t\\0&1\end{bmatrix}\begin{bmatrix}v\\0\end{bmatrix}
=\begin{bmatrix}Rv\\0\end{bmatrix}
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 构造点/方向同时乘 translation matrix，验证只有点移动。

### 4.9 常见错误答案与为什么错

- “w 只是为了补成4个数方便 GPU。”——它有明确 projective geometry 意义。
- “所有向量都用 w=1。”——方向会被错误平移。

### 4.10 Senior 级追问与参考思路

1. **为什么 perspective divide 发生在 clipping 后？**  
   clip plane 判定可以在线性齐次空间完成，避免先除法导致穿过 near plane 的 primitive 处理困难。
2. **w 接近0意味着什么？**  
   对应接近投影无穷远/数值不稳定，需要 clipping 与数值保护。

### 4.11 推荐实战

> 从 pinhole camera 推导一个简化 perspective matrix，明确哪一项让 clip.w 与 view-space z 相关。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用已知几何构造单元测试：单位矩阵、极端角度、退化三角形
- 显式固定坐标系 convention 并在 debug draw 中可视化
- 检查浮点 epsilon、归一化与数值稳定性

### 推荐实战

> 用 Python/C++ 写数值单元测试，并做 debug draw 可视化几何结果。
