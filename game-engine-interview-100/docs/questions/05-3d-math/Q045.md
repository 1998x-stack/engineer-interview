# Q045 · SLERP 和 LERP 有什么区别？

## 2. 30 秒回答（PDF 核心内容）

LERP 在四维坐标中直线插值，归一化后可近似旋转插值；SLERP 沿单位四元数球面大圆插值， 保持恒定角速度。

---

## 3. PDF 深入拆解（Source-derived）

SLERP 公式包含 sin((1-t))/sin 与 sin(t)/sin。 很小时直接公式数值不稳定，工程中通常退化为 NLERP。游戏动画大量使用 NLERP，因为更快且视觉上足够；只有需要严格恒定角速度或较大角度时才必须 SLERP。若 dot(q0,q1)<0，应翻转其中一个四元数避免走长弧。

### PDF 核心抓手
- SLERP 恒定角速度
- NLERP 快且常够用
- 小角度做线性近似
- 处理 q 与 -q 双覆盖

### PDF 工程 Gotcha

所有旋转插值都无脑 SLERP，忽略性能与近似。

### PDF 面试官在听什么

是否会从视觉需求和成本选择插值方法。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- quaternion
- 球面插值
- dot/angle
- nlerp

### 4.2 核心心智模型

LERP 是欧氏空间直线插值，SLERP 是单位四元数球面上的大圆弧插值。SLERP 提供恒定角速度；NLERP 是便宜近似，短角度下常用于实时动画。

### 4.3 底层机制：逐层拆开

- 对 unit q0/q1，`cosθ=dot(q0,q1)`；若 dot<0 先翻转 q1 以选择短弧。
- SLERP 权重为 `sin((1-t)θ)/sinθ` 与 `sin(tθ)/sinθ`。
- θ 很小时 `sinθ` 数值不稳定，实践中切换 nlerp。
- 普通 quaternion lerp 后必须 normalize；否则离开单位球不再表示纯旋转。

### 4.4 必须守住的不变量 / 正确性条件

- 插值前保证端点单位化；处理 antipodal sign。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- SLERP 精确恒角速但 trig 较贵；NLERP 快且无 trig，但角速度不完全恒定。
- 动画系统多层 blend 常大量用 nlerp/近似，而关键相机/少量节点可用 slerp。

### 4.6 在真实游戏引擎中的落点

- Animation blend tree。
- Camera smooth rotation。
- Network snapshot interpolation。

### 4.7 最小实现 / 数学骨架

```math
\mathrm{slerp}(q_0,q_1,t)=
\frac{\sin((1-t)\theta)}{\sin\theta}q_0+
\frac{\sin(t\theta)}{\sin\theta}q_1
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 画 t→旋转角曲线比较 lerp/nlerp/slerp；测试 dot≈1 和 dot≈-1 边界。

### 4.9 常见错误答案与为什么错

- “LERP quaternion 也可以不 normalize。”——会离开单位四元数集合。
- “SLERP 总沿最短弧。”——只有先处理 q/-q 符号。

### 4.10 Senior 级追问与参考思路

1. **为什么动画常用 nlerp？**  
   大量骨骼多重混合时更便宜，短角度误差小且具有交换性更友好的一些工程性质。
2. **多于两个 quaternion 怎么 blend？**  
   没有唯一简单“线性平均”；可用 normalized weighted sum、log/exp map 或分层 blend，根据误差/成本选择。

### 4.11 推荐实战

> 实现阈值切换 slerp/nlerp，测试 10万骨骼插值吞吐与最大角误差。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用已知几何构造单元测试：单位矩阵、极端角度、退化三角形
- 显式固定坐标系 convention 并在 debug draw 中可视化
- 检查浮点 epsilon、归一化与数值稳定性

### 推荐实战

> 用 Python/C++ 写数值单元测试，并做 debug draw 可视化几何结果。
