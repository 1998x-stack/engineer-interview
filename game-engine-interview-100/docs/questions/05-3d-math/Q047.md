## 2. 30 秒回答（PDF 核心内容）

Möller-Trumbore 把 Ray 与三角形的重心参数联立，直接求 t,u,v；检查 t>=0、u>=0、v>=0、 u+v<=1 即可判断命中。

---

## 3. PDF 深入拆解（Source-derived）

算法避免显式计算三角形平面方程，核心用叉乘/点乘解一个 3x3 线性系统。实现需处理 determinant 接近 0 的平行情况、back-face culling 选项和 epsilon。批量 ray tracing 中，ray-triangle 本身往往不是最大成本，真正关键是 BVH traversal 能否减少绝大多数 triangle tests。

### PDF 核心抓手
- Ray: O+tD
- 重心坐标 u/v
- determinant 判断平行
- epsilon 与浮点鲁棒性

### PDF 工程 Gotcha

用 ==0 判断 determinant，容易受浮点误差影响。

### PDF 面试官在听什么

是否理解几何求交的数值问题。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- ray parameter
- cross/dot
- barycentric
- Möller–Trumbore

### 4.2 核心心智模型

Ray-Triangle intersection 要同时解交点距离 t 和三角形重心坐标 u/v。Möller–Trumbore 通过 determinant/cross product 直接解线性方程，无需先求平面再做 point-in-triangle。

### 4.3 底层机制：逐层拆开

- 令 `e1=v1-v0`, `e2=v2-v0`, `p=D×e2`, `det=e1·p`；det≈0 表示 ray 与三角形平行/退化。
- `u=(O-v0)·p/det`，检查 0≤u≤1。
- 再算 `q=(O-v0)×e1`, `v=D·q/det`，检查 v≥0 且 u+v≤1。
- `t=e2·q/det`；根据 ray 类型要求 t≥tmin 且 ≤tmax。

### 4.4 必须守住的不变量 / 正确性条件

- epsilon 应与数值尺度/robustness 设计相关，不能机械写 `1e-6`。
- backface culling 与 double-sided test 会改变 det 的符号判定。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- Möller–Trumbore 指令少适合 ray tracing；watertight intersection 需要更稳健算法避免共享边裂缝。
- 预计算 triangle edge data 可换取内存。

### 4.6 在真实游戏引擎中的落点

- CPU picking。
- BVH leaf intersection。
- Offline/path tracer reference。

### 4.7 最小实现 / 数学骨架

```math
O+tD=v_0+u e_1+v e_2,\quad u\ge0,v\ge0,u+v\le1
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 测试 grazing rays、共享边、极小/巨大坐标、degenerate triangle。
- 对 RT kernel 统计 rays/sec 与 leaf triangle tests。

### 4.9 常见错误答案与为什么错

- “先算平面交点一定更简单且一样快。”——多一次步骤/point-in-triangle，M-T 直接解。
- “det=0 用浮点精确比较。”——需数值阈值/robust predicate。

### 4.10 Senior 级追问与参考思路

1. **watertight 为什么重要？**  
   相邻三角形共享边时浮点误差可能让 ray 同时错过两边，产生漏光/裂缝。
2. **实例变换下 ray 怎么处理？**  
   常把 world ray 变换到 object space 与 BLAS 求交，再把 t/normal 正确转换。

### 4.11 推荐实战

> 实现 Möller–Trumbore 与 watertight variant，对共享边随机 rays 做差分测试。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用已知几何构造单元测试：单位矩阵、极端角度、退化三角形
- 显式固定坐标系 convention 并在 debug draw 中可视化
- 检查浮点 epsilon、归一化与数值稳定性

### 推荐实战

> 用 Python/C++ 写数值单元测试，并做 debug draw 可视化几何结果。
