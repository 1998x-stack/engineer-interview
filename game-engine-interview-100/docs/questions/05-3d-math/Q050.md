# Q050 · 为什么纹理属性必须做透视矫正插值？

## 1. 这道题在考什么

这题属于 **3D 数学与几何**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：camera/view/projection、碰撞与 picking、raster attribute interpolation。

---

## 2. 30 秒回答（PDF 核心内容）

因为 perspective divide 是非线性的，屏幕空间线性插值不对应 3D 空间中的线性变化。正确方法是插值 attribute/w 和 1/w，再做除法恢复。

---

## 3. PDF 深入拆解（Source-derived）

设顶点属性 a_i 与 clip w_i，屏幕重心权重 _i 下，正确 a = (Σ _i a_i/w_i)/(Σ _i 1/w_i)。直观上，远处顶点在屏幕上被压缩，如果直接线性插 UV，会出现纹理“游动/扭曲” 。硬件 rasterizer 会自动完成 perspective-correct interpolation；shader 可用 noperspective 等修饰符选择不同规则。

### PDF 核心抓手
- 透视投影破坏屏幕空间线性关系
- 插值 a/w 与 1/w
- 硬件默认通常是 perspective-correct
- 某些屏幕空间量反而需要 noperspective

### PDF 工程 Gotcha

会背公式但不知道 w 来自 clip-space projection。

### PDF 面试官在听什么

能否从投影变换推导 raster interpolation。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- barycentric
- clip w
- perspective projection
- rational interpolation

### 4.2 核心心智模型

屏幕空间线性并不等于3D透视空间线性。透视投影除以 w 后破坏了普通属性的线性关系；正确做法是线性插值 `a/w` 和 `1/w`，最后相除恢复属性。

### 4.3 底层机制：逐层拆开

- 投影前，属性沿三角形在齐次/3D 空间按 barycentric 线性变化。
- perspective divide 把顶点位置除以 w，使屏幕 barycentric 与原始空间 barycentric 不再一致。
- 对属性 a，先在屏幕上插值 `a_i/w_i` 和 `1/w_i`，再 `a = interp(a/w)/interp(1/w)`。
- GPU rasterizer 通常自动对普通 varying 做 perspective-correct；`noperspective` 等 qualifier 可要求屏幕线性。

### 4.4 必须守住的不变量 / 正确性条件

- 只要顶点 w 不同，直接屏幕线性插值纹理坐标就会产生“纹理游泳/扭曲”。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 某些屏幕空间量（线段距离、UI effect）反而需要 noperspective。

### 4.6 在真实游戏引擎中的落点

- Texture UV、world/view position、normal 前的 varyings。
- 软件 rasterizer。
- MSAA/sample interpolation qualifier。

### 4.7 最小实现 / 数学骨架

```math
a=\frac{\sum_i \lambda_i a_i/w_i}{\sum_i \lambda_i /w_i}
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 画一个倾斜巨大 quad，使用 checkerboard 对比 affine vs perspective-correct UV，视觉差异非常明显。

### 4.9 常见错误答案与为什么错

- “重心插值天然就是透视正确。”——屏幕 barycentric 需要 w 校正。
- “只对 UV 校正，其他属性不用。”——凡原空间线性属性通常都需相同机制。

### 4.10 Senior 级追问与参考思路

1. **为什么 depth 插值看起来特殊？**  
   硬件对特定深度表示进行满足 raster/depth test 的插值，具体 z/w 与 API depth mapping 要区分。
2. **noperspective 什么时候有用？**  
   希望量在屏幕空间线性，例如线框到边缘的屏幕距离、某些 post effect varyings。

### 4.11 推荐实战

> 写 CPU triangle rasterizer，同时实现 affine/perspective-correct UV，输出对比图并推导公式。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用已知几何构造单元测试：单位矩阵、极端角度、退化三角形
- 显式固定坐标系 convention 并在 debug draw 中可视化
- 检查浮点 epsilon、归一化与数值稳定性

### 推荐实战

> 写一个软件 raster 小实验，对比 affine UV 与 perspective-correct UV 的视觉差异。
