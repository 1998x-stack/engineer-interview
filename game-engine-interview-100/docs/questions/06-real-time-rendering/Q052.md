# Q052 · Rasterization 本质上在做什么？

## 1. 这道题在考什么

这题属于 **实时渲染管线**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：base pass / depth / lighting、GPU overdraw 与 bandwidth、draw submission / visibility。

## 2. 30 秒回答（PDF 核心内容）

把连续几何 primitive 转换为离散 framebuffer sample 的 coverage，并为覆盖 sample 生成插值属性。

---

## 3. PDF 深入拆解（Source-derived）

三角形 raster 常用 edge function 判断 sample 是否在三条边内，同时根据 signed area 得到 barycentric weights。硬件通常以 2x2 quad 组织 fragment 执行，以支持 derivative/ddx/ddy 和纹理 LOD，这会产生 helper lanes。MSAA 进一步把 coverage sample 与 shading sample 分开， 因此“一个 pixel 就执行一次 shader”并非严格成立。

### PDF 核心抓手
- coverage 与 shading 是两个概念
- edge function/重心坐标
- fragment 常以 quad 执行
- MSAA 对 coverage 与 shading 分离

### PDF 工程 Gotcha

把 rasterization 简化成“把三角形变成像素” ，没有讨论 sample/coverage。

### PDF 面试官在听什么

是否理解 rasterizer 的硬件执行模型。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- triangle coverage
- edge function
- sample location
- barycentric

### 4.2 核心心智模型

Rasterization 是把连续 primitive 转成离散 sample coverage，并为每个 covered sample 生成可插值的 barycentric/attributes。现代三角形光栅化的数学核心是 edge functions 与 top-left fill rule。

### 4.3 底层机制：逐层拆开

- 对三角形三条边定义有向 edge function `E(x,y)=Ax+By+C`，sample 同时位于三条内侧则 covered。
- edge function 在相邻 pixel 上可增量更新，因此硬件能高吞吐扫描 tile/quad。
- Top-left rule 解决共享边三角形既不重复填充也不产生缝。
- 插值得到 barycentric，进一步 perspective-correct varying；GPU 常以 2×2 quad 执行 fragment shader 以计算 derivatives。

### 4.4 必须守住的不变量 / 正确性条件

- coverage 是 sample-level 概念；MSAA 一个 pixel 有多个 coverage samples。
- 共享边 fill convention 必须一致。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 保守光栅 conservative raster 扩大 coverage，适合 voxel/collision-like用途但增加 false positives。

### 4.6 在真实游戏引擎中的落点

- Software occlusion rasterizer。
- Shadow/depth prepass。
- 理解 derivatives、helper lanes 和 small triangle inefficiency。

### 4.7 最小实现 / 数学骨架

```math
E_{ab}(p)=(p_x-a_x)(b_y-a_y)-(p_y-a_y)(b_x-a_x)
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 统计 triangles、clipped primitives、covered samples、small triangle rate。
- 软件实现可画 edge function heatmap 验证 top-left rule。

### 4.9 常见错误答案与为什么错

- “Rasterization 就是把三角形中心落到最近 pixel。”——实际是 coverage test。
- “Pixel Shader 一次对应最终一个 pixel。”——overdraw/MSAA/helper invocation 都不成立。

### 4.10 Senior 级追问与参考思路

1. **为什么小三角形性能差？**  
   每个 primitive 有 setup 成本，且 quad-based shader 执行会产生大量无效/helper lanes。
2. **derivative 为什么需要 quad？**  
   相邻 lanes 的值差用于估算 ddx/ddy，纹理 LOD 等依赖这些导数。

### 4.11 推荐实战

> 写 edge-function triangle rasterizer，加入 top-left rule 与 4x MSAA sample pattern。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用 RenderDoc/Nsight/RGP 检查 pass、draw、overdraw 与 shader cost
- 用 GPU timestamp 分离 geometry/pixel/bandwidth bottleneck
- 修改一项渲染策略后比较同场景同相机基线

### 推荐实战

> 在一个最小 renderer 中实现或切换该技术，用 GPU timestamp + frame capture 对比。

## 6. 工程 Gotchas（扩展）

- 不要把 API 语义顺序等同于硬件严格串行顺序
- 只看 draw call 数量无法证明 GPU 更快，bandwidth/overdraw/shader 可能才是瓶颈
