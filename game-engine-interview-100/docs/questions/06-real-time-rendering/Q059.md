# Q059 · 为什么 Deferred GBuffer 可以不保存 World Position？

## 2. 30 秒回答（PDF 核心内容）

屏幕 UV + depth + inverse projection/view 足以重建 view/world position，因此可以省掉高带宽 position render target。

---

## 3. PDF 深入拆解（Source-derived）

从 NDC 构造 clip 坐标，把 depth 放到正确 API 范围，再乘 inverse projection 得 view position， 做齐次除法；需要 world position 时再乘 inverse view。更高效做法可以用 view ray 与线性深度重建，避免完整矩阵。注意硬件 depth 常是非线性且可能使用 Reverse-Z，必须按实际 projection 反推。

### PDF 核心抓手
- Depth 保存了沿 view ray 的位置信息
- 重建需尊重 API depth convention
- Reverse-Z/无限远投影会改变公式
- 省 RT 意味着省带宽

### PDF 工程 Gotcha

直接把 depth 当线性 view-space z。

### PDF 面试官在听什么

是否能从数据冗余和带宽角度优化 GBuffer。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- depth reconstruction
- inverse projection
- screen UV
- GBuffer bandwidth

### 4.2 核心心智模型

Deferred 不保存 position 是典型“用计算换带宽”。屏幕坐标给 x/y，depth 给 z，再用 inverse projection/view 重建 view/world position，通常比每像素额外存12-16B position 更划算。

### 4.3 底层机制：逐层拆开

- 由 pixel/UV 生成 NDC x/y，depth 转 NDC z（考虑 API/reverse-Z），组成 clip/NDC point。
- 乘 inverse projection 得 view homogeneous position，再除 w；如需 world 再乘 inverse view。
- 某些 projection 下可更快：view ray × linear depth，避免完整矩阵乘。
- depth buffer 常非线性，若要 view-space linear z 需正确反推 near/far/projection。

### 4.4 必须守住的不变量 / 正确性条件

- 必须匹配实际 projection、depth range 和 reverse-Z。
- 重建精度受 depth format 与远近面分布影响。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 省 GBuffer 带宽/容量，增加少量 ALU；现代 GPU 常愿意做这种交换。
- 若许多 pass 重复重建，可缓存 linear depth 但又增加 RT。

### 4.6 在真实游戏引擎中的落点

- Deferred lighting。
- SSAO/SSR/SSGI。
- Decal screen-space projection。

### 4.7 最小实现 / 数学骨架

```math
p_{view}=P^{-1}p_{ndc},\qquad p_{view}\leftarrow p_{view}/p_{view}.w
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 比较存 position RT 与重建方案的 bandwidth/GPU ms。
- 用已知 world point 投影→depth→重建做数值误差测试。

### 4.9 常见错误答案与为什么错

- “depth 就是 world-space z。”——通常是投影后的非线性 depth。
- “inverse VP 一乘就行，不需要除 w。”——齐次坐标仍需 perspective divide。

### 4.10 Senior 级追问与参考思路

1. **reverse-Z 对重建有什么影响？**  
   depth→NDC z 映射公式变化，但用正确 inverse projection 可自然恢复。
2. **为何 view-space position 常够用？**  
   许多 lighting/SS effect 在 view space进行，可少乘一次 inverse view。

### 4.11 推荐实战

> 实现 D3D/Vulkan normal-Z/reverse-Z 四种 depth reconstruction 单元测试，误差控制到可解释范围。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用 RenderDoc/Nsight/RGP 检查 pass、draw、overdraw 与 shader cost
- 用 GPU timestamp 分离 geometry/pixel/bandwidth bottleneck
- 修改一项渲染策略后比较同场景同相机基线

### 推荐实战

> 在一个最小 renderer 中实现或切换该技术，用 GPU timestamp + frame capture 对比。

## 6. 工程 Gotchas（扩展）

- 不要把 API 语义顺序等同于硬件严格串行顺序
- 只看 draw call 数量无法证明 GPU 更快，bandwidth/overdraw/shader 可能才是瓶颈
