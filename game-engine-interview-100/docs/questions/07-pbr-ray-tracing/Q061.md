## 1. 这道题在考什么

这题属于 **PBR、阴影、GI 与 Ray Tracing**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

## 2. 30 秒回答（PDF 核心内容）

Lo(x,wo)=Le(x,wo)+Ω fr(x,wi,wo) Li(x,wi) (n·wi) dwi。它把“自发光 + 所有入射方向经材质散射后的贡献”统一起来。

---

## 3. PDF 深入拆解（Source-derived）

Lo/Li 是 radiance；fr 是 BRDF，描述单位入射 irradiance 如何变成出射 radiance；cosine 项来自投影面积。递归关系在于 Li 往往来自其他表面的 Lo，这就是全局光照。实时渲染的各种技巧，本质上都在近似这个积分：direct lighting 只取显式光源，IBL 把环境积分预计算，path tracing 用 Monte Carlo 随机估计。

### PDF 核心抓手
- radiance 是核心传输量
- BRDF + cosine
- Li 递归来自场景
- 各种 GI/IBL/PT 都是方程的不同近似

### PDF 工程 Gotcha

只会写公式，不会解释每一项单位与物理意义。

### PDF 面试官在听什么

这是判断图形学是否形成统一理论框架的核心题。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- radiance/irradiance
- solid angle
- BRDF
- hemisphere integral

### 4.2 核心心智模型

Rendering Equation 是统一光传输框架：一个表面向观察方向的出射 radiance = 自发光 + 来自半球所有方向的入射 radiance 经 BRDF 和余弦权重散射后的积分。实时渲染、IBL、path tracing 都是在用不同预算近似同一个积分。

### 4.3 底层机制：逐层拆开

- `L_i(x,wi)` 是从方向 wi 到达 x 的 radiance；它通常来自另一表面的 `L_o`，因此方程递归。
- BRDF `f_r` 的单位与物理约束决定材质如何把 incident irradiance 分配到 outgoing direction。
- `n·wi` 来自投影面积：斜入射同样 solid angle 覆盖的有效表面积更小。
- 积分域是表面法线朝外的 hemisphere；visibility 和 geometry term 可显式拆出，也可隐含在 Li/path transport 中。

### 4.4 必须守住的不变量 / 正确性条件

- 理想被动 BRDF 需满足能量守恒；常见非磁性材料还满足 Helmholtz reciprocity。
- Radiance 沿真空直线传播保持不变，这是光线追踪可递归传递 radiance 的关键。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 实时 raster 通常分 direct/indirect 近似；path tracing 用随机采样换通用性。
- 更多近似缓存降低实时成本，但引入 bias、temporal lag 或有限频率响应。

### 4.6 在真实游戏引擎中的落点

- Direct lighting：显式枚举 light，估计积分中的少数高贡献方向。
- IBL：环境光积分通过 prefiltered environment/BRDF LUT 近似。
- Path tracer：Monte Carlo 随机选择 wi 并递归 Li。

### 4.7 最小实现 / 数学骨架

```math
L_o(x,\omega_o)=L_e(x,\omega_o)+\int_{\Omega^+} f_r(x,\omega_i,\omega_o)L_i(x,\omega_i)(n\cdot\omega_i)d\omega_i
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 使用 reference path tracer 对实时近似做 ground-truth comparison。
- 分别测 bias（系统性误差）、variance（噪声）和 GPU cost，不只看“画面像不像”。

### 4.9 常见错误答案与为什么错

- “Li 是光源强度。”——它是沿某方向到达点的 radiance，可能经过多次反射。
- “cosine term 属于 BRDF。”——通常是几何投影因子，与材质散射函数分开。

### 4.10 Senior 级追问与参考思路

1. **Radiance 和 irradiance 的关系？**  
   Irradiance 是对入射 radiance 乘 cosine 在 hemisphere 上积分后的面密度；radiance 还带方向。
2. **为什么 path tracing 可递归？**  
   Li 沿反向 ray 命中下一个表面后等于该表面对相反方向的 Lo，再继续应用同一方程。

### 4.11 推荐实战

> 实现一个 Lambertian CPU path tracer，只支持 emissive sphere + diffuse bounce；验证和解析 direct-light 情况一致。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用 reference/path tracer 或离线 ground truth 做视觉对比
- 同时观察 variance、bias、sample count 与 GPU cost
- 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

### 推荐实战

> 从一个 diffuse surface 开始，把 direct lighting、IBL、path tracing 分别标注为 Rendering Equation 的不同估计。

4. 主动补 **1 个 Gotcha / 失败条件**；
