# Q064 · Normal Map 为什么通常存在 Tangent Space？

## 1. 这道题在考什么

这题属于 **PBR、阴影、GI 与 Ray Tracing**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

## 2. 30 秒回答（PDF 核心内容）

Tangent-space normal 与模型表面局部 UV 基一起定义，因此同一法线纹理可以复用到不同位置/朝向和动画后的表面；shader 用 TBN 把贴图法线转到目标空间。

---

## 3. PDF 深入拆解（Source-derived）

T 通常来自 position/UV 导数，B 可通过 handedness 与 cross(N,T) 重建；必须注意模型导入工具与 shader 的 tangent basis 约定一致，否则会出现接缝或高光翻转。采样 normal map 后还要把 [0,1] 解码到 [-1,1] 并 normalize。非均匀缩放下 TBN 的正交性也需要谨慎维护。

### PDF 核心抓手
- TBN 是局部坐标基
- bitangent 常由 sign 重建
- tangent basis 必须与烘焙工具一致
- 法线纹理解码后归一化

### PDF 工程 Gotcha

只会写 TBN*n，却不知道 tangent 如何从 UV 求。

### PDF 面试官在听什么

是否能连接 asset pipeline 与 shader 数学。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- TBN basis
- UV parameterization
- normal encoding
- tangent handedness

### 4.2 核心心智模型

Tangent-space normal map 把细节方向定义在表面局部 UV frame 中，因此同一纹理可随模型旋转/变形复用。关键是 TBN 的构建和 handedness 一致，否则 seam、镜像 UV 和法线方向会错。

### 4.3 底层机制：逐层拆开

- Tangent T 沿 UV 的 u 方向，bitangent B 沿 v，N 是几何/插值法线；三者形成局部基。
- 纹理 RGB 通常解码到 [-1,1] tangent normal，再通过 TBN 变到 world/view。
- 实际资产常只存 tangent.xyz + sign，B 由 `sign * cross(N,T)` 重建，减少顶点数据。
- 非均匀 scale 后 T/N 需正确变换并正交化；MikkTSpace 等标准用于确保 DCC 烘焙与引擎解码一致。

### 4.4 必须守住的不变量 / 正确性条件

- 烘焙 tangent basis 与运行时 tangent basis 必须匹配。
- 镜像 UV 会改变 handedness，不能简单 `B=cross(N,T)` 忽略 sign。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- Object-space normal map 解码简单但不可复用、动画变形不方便。
- Tangent-space 多一个 basis 转换和 seam 管理，但资产工作流最通用。

### 4.6 在真实游戏引擎中的落点

- Normal mapping。
- Parallax/anisotropy 也依赖 tangent frame。
- Skinned mesh tangent basis 需随骨骼变换。

### 4.7 最小实现 / 数学骨架

```hlsl
float3 nTS = normalize(texNormal*2-1);
float3 B = tangentSign * cross(N,T);
float3 nWS = normalize(T*nTS.x + B*nTS.y + N*nTS.z);
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 显示 tangent/bitangent/normal debug colors，检查 UV seam/mirror。
- 与 DCC/MikkTSpace reference mesh 做法线一致性对比。

### 4.9 常见错误答案与为什么错

- “B 永远等于 cross(N,T)。”——镜像 UV 需要 handedness sign。
- “normal texture 可以用 sRGB 采样。”——通常应 linear data texture。

### 4.10 Senior 级追问与参考思路

1. **为什么要 Gram-Schmidt T against N？**  
   插值/变换后 T 与 N 可能不再正交；正交化减少 basis distortion。
2. **BC5 为什么适合法线？**  
   只存XY两个高精度通道，Z由单位长度重建，通常比RGB压缩质量/带宽更好。

### 4.11 推荐实战

> 导入一个镜像 UV 模型，故意忽略 tangent sign 复现 seam，再修复并加入 debug tangent view。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用 reference/path tracer 或离线 ground truth 做视觉对比
- 同时观察 variance、bias、sample count 与 GPU cost
- 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

### 推荐实战

> 实现一个 CPU reference 或 shader demo，对照公式和可视化结果验证。
