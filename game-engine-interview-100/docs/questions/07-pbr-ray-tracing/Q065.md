## 1. 这道题在考什么

这题属于 **PBR、阴影、GI 与 Ray Tracing**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：material shading、shadow/GI、ray tracing / offline reference。

## 2. 30 秒回答（PDF 核心内容）

先从光源视角渲染深度图；主视角 shading 时把世界点变换到 light clip/texture space， 与 shadow map 中最近深度比较，判断是否被遮挡。

---

## 3. PDF 深入拆解（Source-derived）

它是“可见性查询”的离散近似。 关键问题包括 light projection、 depth precision、 bias、 级联 filtering、 和 atlas。Directional light 的大场景常用 CSM 把相机 frustum 分段，每段使用不同 shadow map； Point light 可能用 cubemap。Shadow map 的纹理分辨率和投影范围共同决定 texel footprint。

### PDF 核心抓手
- 两 pass：light depth + camera compare
- shadow 是可见性而非“画黑色”
- 精度和投影范围决定质量
- 大范围需 CSM/VSM 等扩展

### PDF 工程 Gotcha

忘记做 perspective divide/texture-space remap，或认为 shadow map 保存世界距离而非投影深度。

### PDF 面试官在听什么

是否理解 shadow 系统是空间采样问题。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- light-space depth
- projective transform
- depth comparison
- bias

### 4.2 核心心智模型

Shadow Mapping 是“从光源视角记录最近深度，再从相机像素询问自己是否比光源看到的最近表面更远”。本质是可见性查询的离散深度近似。

### 4.3 底层机制：逐层拆开

- Shadow pass 用 light view-projection 渲染 caster depth 到 shadow map。
- Camera shading 时把 world point 变换到 light clip/NDC/texture coordinates。
- 读取 shadow depth `z_s` 与当前 light-space depth `z_p` 比较；若 z_p 超过 z_s+bias 则处于遮挡。
- Directional light 常需 Cascaded Shadow Maps，因为单张固定分辨率覆盖巨大视锥导致近处 texel 密度不足。

### 4.4 必须守住的不变量 / 正确性条件

- Shadow map 只近似 light visibility，不包含完整光照。
- 采样坐标、depth convention、clip range、bias 必须一致。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 分辨率提高降低 aliasing 但耗显存/带宽。
- PCF/PCSS 增加采样改善边缘，但 soft shadow 仍是近似。

### 4.6 在真实游戏引擎中的落点

- CSM sun shadow。
- Spot light 2D depth；point light cube/dual paraboloid/atlas。
- Shadow atlas/cache 管理大量 lights。

### 4.7 最小实现 / 数学骨架

```text
Light Pass: scene -> depth map
Camera Pass: worldPos -> lightUV/depth -> compare -> visibility
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- 查看 shadow texel density、atlas occupancy、shadow pass draw count、samples/pixel。
- 用 debug mode 显示 cascade index 和 light-space UV。

### 4.9 常见错误答案与为什么错

- “Shadow map 存的是到光的欧氏距离。”——常存投影后的 depth，point light 可用距离但不是统一规则。
- “比较深度不需要 bias。”——离散化/浮点/斜率会产生自阴影。

### 4.10 Senior 级追问与参考思路

1. **CSM split 如何选？**  
   uniform/log split 的混合，平衡 near texel density 和远处覆盖；还要稳定级联防 shimmering。
2. **为什么 shadow map 会 perspective aliasing？**  
   camera pixel footprint 与 light-space texel footprint 不匹配，特别是斜视和远距离。

### 4.11 推荐实战

> 实现单 spot shadow map，再加入 PCF 与 debug UV/depth view；最后分析 bias 与分辨率关系。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 用 reference/path tracer 或离线 ground truth 做视觉对比
- 同时观察 variance、bias、sample count 与 GPU cost
- 对阴影/BRDF 参数做极端值测试，避免只看“正常材质”

### 推荐实战

> 实现一个 CPU reference 或 shader demo，对照公式和可视化结果验证。
