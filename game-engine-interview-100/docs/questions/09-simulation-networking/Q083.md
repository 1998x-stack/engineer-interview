# Q083 · FK 与 IK 有什么区别？

## 1. 这道题在考什么

这题属于 **动画、物理、AI 与网络**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：character animation、physics simulation、network latency hiding / determinism。

---

## 2. 30 秒回答（PDF 核心内容）

FK 从根到末端给定关节旋转，直接得到末端姿态；IK 给定末端目标，反求一组关节参数。

---

## 3. PDF 深入拆解（Source-derived）

两骨骼手臂/腿可用解析法快速求解；复杂链常用 CCD、FABRIK、Jacobian 等迭代算法。实际动画系统通常“基础动画/FK + IK 修正”，例如脚贴地、手抓武器。IK 还要处理 joint limits、 pole vector、不可达目标和 temporal stability。

### PDF 核心抓手
- FK 是 forward transform propagation
- IK 是约束求解
- 解析法快但适用结构有限
- 动画常混合 FK 与 IK

### PDF 工程 Gotcha

把 IK 说成“让动画更自然”，没有说明求解目标和约束。

### PDF 面试官在听什么

是否理解动画系统是约束求解问题。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- bone hierarchy
- forward kinematics
- inverse problem
- iterative solver

### 4.2 核心心智模型

FK 是给关节参数求末端位置，直接沿 hierarchy 乘变换；IK 是给末端目标反求关节参数，通常非唯一、受约束、需要解析或迭代求解。

### 4.3 底层机制：逐层拆开

- FK 从 root 开始 `global_i=global_parent*local_i`，确定且高效。
- 2-bone IK 可用余弦定理解析求 shoulder/elbow angles，同时需要 pole vector 决定弯曲平面。
- CCD 从末端向根逐关节旋转使 end effector 靠近 target；简单但可能收敛慢。
- FABRIK 在位置空间前后迭代满足骨长约束，收敛稳定但需最终恢复 rotations/constraints。

### 4.4 必须守住的不变量 / 正确性条件

- IK 目标可能不可达；solver 必须定义 stretch/clamp 行为。
- 关节 limit/pole/foot orientation 等约束决定“哪一个解”可接受。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 解析解快且稳定但只适特定链；迭代 solver 通用但预算/收敛复杂。
- IK 通常叠加在 authored animation 上，而非完全替代动画。

### 4.6 在真实游戏引擎中的落点

- Foot IK/grounding。
- Hand reach/weapon grip。
- Look-at/aim rig。

### 4.7 最小实现 / 数学骨架

```text
Animation Pose -> FK global pose -> IK constraints -> corrected pose -> skinning
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- solver iterations、position/orientation error、joint limit violations。
- 不可达/目标瞬移 stress test 防抖。

### 4.9 常见错误答案与为什么错

- “IK 就是把骨骼朝目标旋转。”——多关节约束和非唯一解需要 solver。
- “FK 会 gimbal lock。”——取决于旋转表示，不是 FK 本身。

### 4.10 Senior 级追问与参考思路

1. **Foot IK 如何避免脚滑？**  
   结合 root motion、plant phase、ground contact lock、pelvis adjustment；单帧把脚投到地面会滑。
2. **IK 如何和动画 blend？**  
   在局部/组件空间计算 correction，再按 weight/plant state blend，必要时 maintain effector trajectory。

### 4.11 推荐实战

> 实现 analytic 2-bone IK，加入 pole vector、joint limit 和不可达 target clamp。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 固定随机种子/输入录制，保证问题可复现
- 区分 simulation state 与 render interpolation state
- 记录 latency、correction magnitude、contact/joint error 等领域指标

### 推荐实战

> 构造可重复 simulation/network demo，记录 state error、latency 或 contact/joint metrics。
