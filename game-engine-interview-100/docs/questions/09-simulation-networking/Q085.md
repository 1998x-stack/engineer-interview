# Q085 · Physics Fixed Timestep 为什么重要？

## 1. 这道题在考什么

这题属于 **动画、物理、AI 与网络**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：character animation、physics simulation、network latency hiding / determinism。

## 2. 30 秒回答（PDF 核心内容）

固定 Δt 让数值积分、碰撞和约束求解的稳定性更可控，也更利于可复现模拟；渲染帧率变化时用 accumulator 跑 0/1/多次 physics step。

---

## 3. PDF 深入拆解（Source-derived）

经典 loop：accumulator += frameDt；while accumulator>=fixedDt 执行 physics；渲染时可在前后两个物理状态间 interpolation。若单帧卡顿导致 accumulator 巨大，可能出现“spiral of ，因此应限制最大 catch-up steps。固定步长也不保证完全 deterministic：浮点、线程调 death” 度、平台指令仍会造成差异。

### PDF 核心抓手
- 固定步长提高稳定性
- accumulator loop
- 渲染可插值
- 限制 catch-up 防止 spiral of death

### PDF 工程 Gotcha

认为 fixed timestep 自动意味着跨机器 bitwise deterministic。

### PDF 面试官在听什么

是否把数值模拟放在 real-time loop 中考虑。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- numerical integration
- delta time
- determinism
- render interpolation

### 4.2 核心心智模型

Fixed timestep 把物理积分的 dt 固定，避免 frame time 抖动直接改变数值稳定性和游戏行为。经典 accumulator loop 可一帧执行0/多次 physics step，再用 alpha 对渲染姿态插值。

### 4.3 底层机制：逐层拆开

- 累积 real frame dt；while accumulator≥fixedDt 执行 physics step 并扣减。
- 渲染在 previous/current physics states 之间按 `alpha=accumulator/fixedDt` 插值。
- 若帧严重掉速，积压 steps 会形成 spiral of death；需要最大 steps/时间裁剪策略。
- 固定 dt 提高可重复性但不自动保证跨平台 bitwise deterministic，浮点/并行/solver order 仍影响。

### 4.4 必须守住的不变量 / 正确性条件

- 物理 solver 的稳定性参数/约束通常按固定 dt 调校。
- simulation time 与 render time 必须区分。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 更小 dt 稳定精确但 CPU 更贵；更大 dt 便宜但 tunneling/constraint error 增加。
- 可用 substep 只对高速/复杂对象局部提高频率。

### 4.6 在真实游戏引擎中的落点

- 60Hz gameplay physics，120Hz vehicle。
- Network rollback/lockstep 依赖稳定 tick。
- Render interpolation 平滑 144Hz 显示。

### 4.7 最小实现 / 数学骨架

```cpp
acc += frameDt;
while (acc >= h && steps < maxSteps) { prev=cur; simulate(h); acc -= h; }
alpha = acc / h; render(lerp(prev,cur,alpha));
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- physics steps/frame histogram、accumulator backlog、constraint error、tunneling count。
- 低帧率 15FPS stress test spiral-of-death。

### 4.9 常见错误答案与为什么错

- “Fixed timestep 让游戏完全 deterministic。”——还需控制浮点、线程顺序、随机数等。
- “render 也必须固定60FPS。”——渲染可独立频率并插值。

### 4.10 Senior 级追问与参考思路

1. **掉到5FPS时怎么办？**  
   限制 catch-up steps，选择慢动作/丢模拟时间/降质量；不能无限追赶导致永久卡死。
2. **CCD 与 timestep 关系？**  
   固定小dt减少 tunneling但不能根治高速穿透；CCD 做 swept test/toi。

### 4.11 推荐实战

> 实现 accumulator physics loop，制造 200ms hitch，比较无限 catch-up 与 capped steps 的行为。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 固定随机种子/输入录制，保证问题可复现
- 区分 simulation state 与 render interpolation state
- 记录 latency、correction magnitude、contact/joint error 等领域指标

### 推荐实战

> 构造可重复 simulation/network demo，记录 state error、latency 或 contact/joint metrics。
