# Q086 · Collision Detection 为什么分 Broad Phase 和 Narrow Phase？

## 1. 这道题在考什么

这题属于 **动画、物理、AI 与网络**。面试官通常不是只听一个定义，而是在判断你能否把答案推进到：

1. **机制**：数据/状态究竟怎样流动；
2. **成本**：CPU、GPU、内存、同步或数值误差的成本在哪里；
3. **Trade-off**：什么场景适合，什么场景会失败；
4. **Engine Context**：在真实 renderer / core / asset / simulation 中怎么落地；
5. **Evidence**：如何通过 profiler、测试、frame capture 或汇编证明判断。

本章常见工程落点：character animation、physics simulation、network latency hiding / determinism。

---

## 2. 30 秒回答（PDF 核心内容）

N 个对象两两精确测试是 O(N²) 且单次成本高；Broad Phase 用 AABB/BVH/SAP/Spatial Hash 快速找潜在 pair，Narrow Phase 再做精确 shape test。

---

## 3. PDF 深入拆解（Source-derived）

Broad Phase 的目标是高召回：不能漏掉真实碰撞，但允许 false positive。动态刚体常用 Dynamic AABB Tree、 Sweep-and-Prune；大量粒子可用 uniform grid。 Narrow Phase 再用 SAT、 GJK/EPA、 convex-convex 或 mesh contact。最终还要进入 contact manifold 与 constraint solver。

### PDF 核心抓手
- Broad phase 只生成候选
- 允许 false positive 不允许漏碰撞
- 不同运动分布适合不同结构
- collision pipeline 不止“相交判断”

### PDF 工程 Gotcha

在 broad phase 就使用复杂 OBB/mesh 精确求交，失去分层意义。

### PDF 面试官在听什么

是否理解物理引擎的分层性能设计。

## 4. 专业扩展（Repository v2）

这一节不再重复 PDF 的“定义答案”，而是把问题推进到 **可实现、可测量、可讨论 trade-off** 的层级。面试时不要求把下面所有内容一次讲完；更好的策略是先给结论，再根据面试官追问选择其中 2–3 个层次深入。

### 4.1 先修知识与概念边界

- pair complexity
- AABB broadphase
- exact collision
- temporal coherence

### 4.2 核心心智模型

Broad Phase 用廉价包围体把 N² 对减少到少量候选；Narrow Phase 再对候选做昂贵精确形状测试/接触点生成。两阶段是“高召回粗筛 + 高精度复核”的经典系统结构。

### 4.3 底层机制：逐层拆开

- Broad phase 结构可用 sweep-and-prune、dynamic AABB tree、grid/spatial hash。
- 输出 potential overlapping pairs，允许 false positive 但不能漏真碰撞。
- Narrow phase 根据 shape pair 选择 sphere/capsule/SAT/GJK/EPA/mesh contact 等算法。
- 接触 manifold 通常缓存以利用 temporal coherence，减少每帧从零求接触。

### 4.4 必须守住的不变量 / 正确性条件

- Broad phase false negative 会直接穿透，是不可接受的。
- 碰撞 filter/layer 应尽早在 broad phase 候选生成时裁剪。

这些不变量比“记住某个 API”更重要：平台、实现或引擎版本可以变化，但只要不变量没变，你就能重新推导正确方案。

### 4.5 Trade-off：什么时候该用，什么时候不该用

- 更紧 bounds 减候选但更新更贵。
- 静态与动态对象分开结构可减少更新。

### 4.6 在真实游戏引擎中的落点

- Dynamic AABB tree for rigid bodies。
- Static triangle mesh BVH。
- Trigger/query layer filtering。

### 4.7 最小实现 / 数学骨架

```text
N objects -> BroadPhase cheap bounds -> K candidate pairs (K << N²) -> NarrowPhase exact -> contacts
```

> **面试建议**：代码或公式不是为了炫技。写完后要解释：输入是什么、输出是什么、最贵的步骤在哪里、哪个条件一旦破坏就会出错。

### 4.8 Profiling / Validation：如何证明你的判断

- candidate pairs、actual contacts、false-positive ratio、broad/narrow ms。
- 密集堆叠/高速对象/大对象 stress test。

### 4.9 常见错误答案与为什么错

- “Broad Phase 算出碰撞点。”——它通常只生成候选。
- “Narrow Phase 只判断相交。”——还常需 normal、penetration、contact manifold。

### 4.10 Senior 级追问与参考思路

1. **为什么缓存 manifold？**  
   接触在连续帧高度相似，可 warm-start solver并减少特征搜索。
2. **SAP 适合什么？**  
   对象移动连续、轴排序变化小的场景；可利用 insertion sort temporal coherence。

### 4.11 推荐实战

> 实现 uniform-grid broad phase + sphere narrow phase，统计密度变化下 candidate ratio。

完成实战时建议保留 **baseline、指标、实验变量、结果、结论** 五项记录。真正能在面试中形成 Senior signal 的不是“我写过”，而是“我能解释为什么这个实现更快/更稳，以及证据是什么”。

## 5. 如何验证，而不是“凭感觉优化”

- 固定随机种子/输入录制，保证问题可复现
- 区分 simulation state 与 render interpolation state
- 记录 latency、correction magnitude、contact/joint error 等领域指标

### 推荐实战

> 构造可重复 simulation/network demo，记录 state error、latency 或 contact/joint metrics。
