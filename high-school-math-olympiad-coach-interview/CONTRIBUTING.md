# Contributing Guide

感谢参与维护。本仓库同时包含“原 PDF 迁移内容”和“后续专业扩展”，因此贡献重点是 **数学正确性、来源边界、教学可执行性和可维护性**。

## 1. 内容分层原则

1. `PDF 核心内容` 不应被静默改写成不同观点；发现问题请以“勘误”形式提交。
2. 新增解释、例子、证明、教学设计进入 `仓库增强 / Professional v2`。
3. 不把外部学校/机构未公开材料描述为“真实泄题”。
4. 若新增外部研究或公开招聘信息，应在 references 或对应说明中标明来源与核验日期。

## 2. 数学内容标准

每次修改数学部分至少检查：

- [ ] 定义域、正性、整数性；
- [ ] 定理前提；
- [ ] 等号和边界；
- [ ] 必要 / 充分 / 等价方向；
- [ ] 除零、开方、取对数是否合法；
- [ ] 几何点序、有向角/有向长度；
- [ ] 数论中的素数、互素、估值条件；
- [ ] 组合是否漏计/重计。

如果引用一个高阶定理，最好说明它在本题中的功能，以及是否存在更适合高中竞赛教学的初等版本。

## 3. Professional v2 标准

新增内容不能只是“把原答案写长”。优先提供下列实质增量之一：

- 完整证明或关键推导；
- 反例 / 方法失效边界；
- 同题两法比较；
- 具体课堂脚本、三级提示、exit ticket；
- 可测量学情指标与观察窗；
- 题库/讲义/测评等真实 artifact schema。

## 4. 写作风格

### 推荐

- 先中心句，再展开；
- 公式附近明确条件；
- 使用小标题让页面可扫描；
- 用“为什么选择”解释方法，而不是只列定理；
- 教学建议写成动作和指标。

### 避免

- “显然”“易知”承担关键证明；
- “多刷题、因材施教、提高思维”作为最终建议；
- 为显得高级而堆叠大学数学名词；
- 无来源地写“某校真题”；
- 大段复制受版权保护的外部题解。

## 5. 新增题目的 YAML

```yaml
---
id: Q101
title: "..."
chapter: "..."
difficulty: "难度 ★★★★☆"
tags:
  - "数学专业"
  - "核心主题、能力"
source: "editorial"
status: draft
---
```

题号一旦公开不复用。删除题目时优先标记 deprecated。

## 6. PR 描述建议

请说明：

- 修改的是 source-derived 还是 editorial；
- 数学结论如何核验；
- 若修改教学建议，解决了什么问题；
- 是否影响其他关联题/模块 README；
- 是否需要更新 metadata。

## 7. 提交前校验

```bash
python scripts/validate_repo.py
```

建议同时运行 MkDocs build（若已安装文档依赖）：

```bash
mkdocs build --strict
```

## 8. Review 优先级

1. 数学实质错误；
2. 来源边界错误；
3. 内部链接/构建错误；
4. 教学逻辑与可执行性；
5. 表达与排版优化。
