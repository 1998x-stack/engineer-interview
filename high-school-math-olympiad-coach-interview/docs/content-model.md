# 内容模型与维护约定

每道题的 Markdown 分为两层：

1. **PDF 核心内容（source-derived）**：完整迁移原 PDF 的题目、面试官为什么问、高分答题框架、追问、常见失分、教练视角、10 分 Rubric。
2. **仓库增强（editorial expansion）**：新增技术补充、口述法、压力训练与自检清单。
3. **Professional v2（question-specific expansion）**：每题独立编写，不使用仅按模块复用的通用段落；数学题优先补完整推导、条件、反例、方法比较，试讲题补分钟级教学脚本，教研/学生题补可执行指标与决策规则。

这样做的目的，是防止后续维护时把“原书内容”和“新扩展内容”混在一起，方便做勘误、版本 diff 和引用。

## 文件命名

- 题目文件固定为 `Q001.md` … `Q100.md`，避免中文文件名在不同系统中出现编码问题。
- 标题、模块、难度、标签放在 YAML front matter 中。
- 题号永不复用；删除题目应标记 deprecated，而不是把后续题目整体重编号。


## Professional v2 编写标准

每个 Q 文件的 v2 内容至少满足以下一项“实质增量”，不能只重复原 PDF：

- 给出一段可审查的完整证明或关键推导；
- 给出方法选择的必要条件、等号/边界与反例；
- 给出一个可以直接上课使用的例题、时间轴或三级提示；
- 给出可量化诊断指标、观察窗和下一步决策规则；
- 给出同题不同方法的优劣比较和迁移边界。

### 数学内容质量检查

1. 公式前提是否齐全；
2. 从“等价”到“蕴含”的方向是否正确；
3. 除零、开方、对数、排序等步骤是否合法；
4. 几何是否依赖未说明的点序/有向角约定；
5. 数论定理是否检查整数性、素数、互素等条件；
6. 组合计数是否明确对象、避免漏计/重计。

### 教学与教研内容质量检查

避免“多练、多沟通、因材施教”等不可操作表述。每个建议尽可能写成：

```text
可观察行为 → 诊断假设 → 教学动作 → 指标 → 复盘时间点
```
