# Chapter 01 - Blockchain 基础与密码学直觉

从“为什么需要链”开始，而不是从项目名开始。面试官关注你是否理解信任模型、状态复制、最终性和密码学承诺。

## 本章能力目标

- 先说明信任假设：谁可能作恶、谁需要验证、系统依赖什么资源或多数假设。
- 把概念落到状态机：输入是什么、状态如何转移、冲突如何裁决、何时视为最终。
- 区分密码学保证、共识保证、经济保证和社会层保证，避免把它们混成“不可篡改”。
- 回答系统问题时主动指出业务层还需要确认策略、reorg 处理和数据来源治理。

## 本章专业学习框架

### 前置知识
- 分布式状态机与复制
- 密码学 hash / signature 的基本安全性质
- 共识、最终性与网络分区的区别

### 统一分析模型

先把协议抽象成 `S_{t+1}=F(S_t, T_t)`：节点需要对输入交易的有效性、排序以及最终采用的历史达成一致。随后再标注哪些性质来自密码学、哪些来自共识、哪些来自经济激励。

### 从基础到高级的学习顺序

- **建立模型**：Q01、Q02、Q03 —— 先确保基础对象与状态边界不混淆。
- **形成工程闭环**：完成本章全部题目的 failure mode、测试和 observability 小节。
- **冲击高级面试**：Q05、Q10、Q01 —— 尝试用 invariant / trust model 在白板上连续讲 5～10 分钟。

### 本章实验建议

1. 选 2 道题写最小可运行 demo；
2. 为其中 1 道加入 fuzz/invariant 或 failure injection；
3. 写一份 1 页 incident note：现象、根因、影响、修复、长期预防；
4. 把结果放进个人 GitHub，面试时作为可验证工程证据。

### 本章生产 Checklist

- [ ] 状态机确定性测试：同一状态和交易序列必须得到同一结果
- [ ] reorg/partition 仿真：验证业务层能回滚或延迟确认
- [ ] 跨链/跨域重放测试：chainId、domain、nonce 必须进入安全边界

## 建议学习方式

1. 第一遍只读每题的 **30 秒标准回答 + 记忆锚点**。
2. 第二遍关闭答案，手画白板图并口述“定义 -> 原理 -> Failure Mode -> Mitigation”。
3. 第三遍只做追问、自测题和测试清单。
4. Core 30 题必须达到能在 2-5 分钟内连续深挖的程度。
