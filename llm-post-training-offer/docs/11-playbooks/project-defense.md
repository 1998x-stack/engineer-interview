# 项目题万能答法：研究决策链

不要只用 STAR。算法终面更适合下面的研究决策链：

1. **Problem**：真实业务/研究问题是什么？为什么 baseline 不够？
2. **Metric**：成功标准是什么？离线、在线、成本、安全如何量化？
3. **Data**：数据从哪里来？如何筛选？覆盖哪些 failure modes？
4. **Reward**：reward/verifier 为什么可信？怎样防 hacking？
5. **Algorithm**：为什么选 SFT / DPO / PPO / GRPO / DAPO / GSPO？替代方案为什么不选？
6. **System**：模型多大、多少卡、rollout/learner 怎么分、吞吐瓶颈是什么？
7. **Failure**：训练中真正遇到什么坏现象？你如何定位？
8. **Ablation**：如何证明提升来自你的设计，而不是更多 compute/data？
9. **Lessons**：如果重做一次，你会重构哪里？

最有识别度的材料通常是：**一个失败案例 + 一个错误假设 + 一个推翻假设的实验 + 最终修正**。

## 使用建议

把本页内容与具体问题文件联动使用：先选一个 Qxxx，按本页模板做白板/实验/项目复盘；记录自己无法回答的变量、指标和反例，再回到对应章节补齐。目标是形成**可迁移的问题解决结构**，而不是增加背诵量。
