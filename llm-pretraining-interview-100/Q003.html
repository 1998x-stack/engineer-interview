为什么大模型主流选择 Decoder-only？

定位：B 类等价追问题 · 难度 中 · 频率 ★★★★☆ 章节：Transformer 与模型架构

1. 面试官为什么问

检验你能否从目标函数、数据可扩展性和推理形态解释架构趋势。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 数学尺度：公式是否解释了数值尺度、梯度和表示能力？
  • 结构成本：参数量、FLOPs、KV Cache 与 kernel shape 如何变化？
  • 生命周期：训练架构选择会如何影响推理成本？

2. 30 秒结论

Decoder-only 赢在“统一目标 + 海量无标注数据 + 统一生成接口”的可扩展性，而不是结构上绝对支配。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

Decoder-only 使用统一的 causal language modeling：任意文本都可转换为 next-token prediction，无需为不同任务设计专门目标；训练目标和自回归生成形式也天然一致。

3.2 关键 Trade-off / 边界

它的优势不是“理论上永远优于 Encoder/Encoder-Decoder”，而是数据来源最广、scale-up 路径简单、in-context learning 兼容性好、工程栈统一。对纯表示学习或强条件生成任务，其他结构仍可能更合适。

4. 深度展开：从定义走向 Production

本题的深挖重点是：Decoder-only 赢在“统一目标 + 海量无标注数据 + 统一生成接口”的可扩展性，而不是结构上绝对支配。

建议沿下面的因果链继续展开：

  1. 定义/状态语义：先把对象、tensor、数据分布或训练状态说准确；
  2. 机制：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
  3. 代价：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
  4. 可验证性：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
  5. 规模化边界：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：回答时先分任务：生成、理解、seq2seq，再谈为何 foundation model 偏向统一生成接口。
  2. 动作 2：指出 causal mask 带来的训练并行与推理串行差异。
  3. 动作 3：不要把产业选择误写成架构定理。

架构 Ablation

固定训练 Token 与大部分 recipe，只改变目标组件；同时比较 validation loss、下游能力、训练稳定性、参数/FLOPs 与推理成本。

  • 不要只比较最终 benchmark；记录收敛速度。
  • 至少做等参数或等 FLOPs 对照。
  • 改变 head/hidden 等 shape 时同时检查 kernel efficiency。
