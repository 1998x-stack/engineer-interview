Exact Dedup、MinHash、SimHash、Semantic Dedup 分别解决什么？

定位：B 类等价追问题 · 难度 中 · 频率 ★★★★★ 章节：Tokenizer 与预训练数据

1. 面试官为什么问

去重既影响数据质量，也改变有效数据分布与记忆风险。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 分布：每个过滤/采样动作怎样改变 p_train(x)？
  • 信息密度：单位 Token 的新颖性、正确性和覆盖度怎样衡量？
  • 可追溯：能否从训练异常追到具体 shard/domain/sample？

2. 30 秒结论

Dedup 本质是在修正隐式采样权重，而不仅是减少字节。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

Exact dedup 用内容 hash 去除完全重复；MinHash+LSH 估计集合/Jaccard 相似度，适合 near-duplicate 文档或 shingles；SimHash 将特征投影到指纹空间，适合快速相似检索；semantic dedup 用 embedding/聚类处理表面不同但语义重复。

3.2 关键 Trade-off / 边界

去重的价值不只是省存储。重复文档等价于给某些内容更高 sampling weight，会扭曲训练分布、增加 memorization，并浪费有限 compute。

4. 深度展开：从定义走向 Production

本题的深挖重点是：Dedup 本质是在修正隐式采样权重，而不仅是减少字节。

建议沿下面的因果链继续展开：

  1. 定义/状态语义：先把对象、tensor、数据分布或训练状态说准确；
  2. 机制：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
  3. 代价：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
  4. 可验证性：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
  5. 规模化边界：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：先做 URL/精确 hash，再做近重复可降低昂贵阶段的候选量。
  2. 动作 2：按 document 与 span 两种粒度处理，避免整篇因局部模板被误删。
  3. 动作 3：记录 cluster size，可用于重新加权而不是一律删除。

数据闭环

从样本级 provenance 到 domain-level held-out loss 建立闭环：数据变更必须能追溯到采样率、重复率、污染率和能力变化。

  • 所有过滤规则可版本化。
  • Mixture 调整用 proxy run 或受控消融。
  • benchmark contamination 与训练质量评估分开。
