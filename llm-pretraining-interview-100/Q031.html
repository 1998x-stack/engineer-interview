什么是 Scaling Law？预训练团队为什么需要它？

定位：A 类高频真题型 · 难度 难 · 频率 ★★★★★ 章节：Scaling Law 与预算设计

1. 面试官为什么问

从“训练一个模型”上升到“规划一族模型”的核心研究能力。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 约束优化：到底固定的是 FLOPs、GPU-hours、成本还是推理预算？
  • 外推：小规模曲线在哪些条件下可以外推？
  • 等成本比较：Dense/MoE/不同数据 recipe 是否真的比较公平？

2. 30 秒结论

Scaling law 是用小规模实验降低大规模决策不确定性的工具。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

Scaling law 描述 validation loss 与模型参数 N、数据量 D、训练 compute C 之间近似幂律关系。它让团队可以用较便宜的 proxy runs 拟合趋势，再预测大规模训练的 loss、最优 token/parameter 配比与预算风险。

3.2 关键 Trade-off / 边界

它不是物理定律：模型架构、tokenizer、数据 mixture、训练 recipe 改变后，拟合参数可能变化，因此必须在目标设置附近重新校准。

核心公式

L(N,D) ≈ L∞ + aN^-α + bD^-β

面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

4. 深度展开

Scaling Law 的用途不是“画一条漂亮直线”

预训练团队用 scaling 实验回答的是资源分配问题：在给定预算下，参数、数据、训练时长如何组合；以及更大 run 的结果能否在投入前被小规模实验预测。必须把拟合误差、数据分布变化和硬件效率变化视作模型外推的风险项。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：设计多个 N×D×recipe 的正交小实验，而不是只做一条 size curve。
  2. 动作 2：使用 held-out loss 且保证数据 pipeline 一致。
  3. 动作 3：报告拟合区间与外推距离，避免过度 extrapolation。

Scaling Proxy

用多个模型尺寸、Token 预算和 seed 构造 proxy grid，拟合 loss/compute 曲线，再用 hold-out 规模验证外推误差。

  • 拟合前确认数据 mixture 一致。
  • 报告置信区间/外推范围。
  • 区分训练 FLOPs optimum 与生命周期成本 optimum。

6. 高频追问与回答方向

追问 1：Scaling law 能预测 benchmark accuracy 吗？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 2：架构改变后还能复用曲线吗？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 3：如何判断 proxy model 足够代表大模型？

回答方向：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

7. 常见失分点：为什么错

  • ❌ 把幂律当成任何规模都精确成立。
  • 改进：回到“Scaling law 是用小规模实验降低大规模决策不确定性的工具。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
  • ❌ 只拟合两个点就外推百倍规模。
  • 改进：回到“Scaling law 是用小规模实验降低大规模决策不确定性的工具。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。

9. 自测与白板练习

闭卷完成下面练习，建议每题控制在 5–10 分钟：

  1. Scaling law 能预测 benchmark accuracy 吗？
  2. 架构改变后还能复用曲线吗？
  3. 如何判断 proxy model 足够代表大模型？
  4. 写出固定预算下的优化变量、约束和至少一个 proxy experiment。
