Expert Parallel 与 Tensor Parallel 如何相互影响？

定位：B 类等价追问题 · 难度 难 · 频率 ★★★★★ 章节：Mixture-of-Experts

1. 面试官为什么问

顶级 MoE 系统题，考察多维并行不是独立旋钮。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 稀疏性：total params、active params 与 active FLOPs 如何区分？
  • 路由学习：负载均衡如何与语义 specialization 共存？
  • 通信：A2A 是否把算术节省吃掉？

2. 30 秒结论

多维并行真正的难点是：每一次“再切一刀”都会改变本地矩阵大小和通信频率。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

EP 已经把不同 experts 放到不同 rank；若 expert MLP 内再用很大的 TP，单个 expert 的矩阵会进一步被切小，可能导致 GEMM 利用率下降，同时增加 collective。

3.2 关键 Trade-off / 边界

Attention 与 MoE 层的最佳 TP degree 可能不同。现代训练框架因此支持更灵活的 parallel folding/不同模块并行映射，目标是让 attention 大矩阵和 expert GEMM 都保持硬件友好。

4. 深度展开：从定义走向 Production

本题的深挖重点是：多维并行真正的难点是：每一次“再切一刀”都会改变本地矩阵大小和通信频率。

建议沿下面的因果链继续展开：

  1. 定义/状态语义：先把对象、tensor、数据分布或训练状态说准确；
  2. 机制：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
  3. 代价：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
  4. 可验证性：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
  5. 规模化边界：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：分别 profile attention 与 expert block 的 compute/comm。
  2. 动作 2：从 GEMM shape 反推最小高效 local matrix。
  3. 动作 3：让 EP/TP group 映射与节点拓扑一致。

MoE 端到端实验

同时监控 routing entropy、expert load、dropped tokens、A2A 时间、expert GEMM 利用率和模型 loss。

  • 负载均衡不是唯一目标。
  • 按 activated FLOPs 和 wall-clock 做公平比较。
  • 检查跨节点 EP 的网络代价。

6. 高频追问与回答方向

追问 1：为什么 MoE 常减少 expert TP？

回答方向：从“旧方案瓶颈 → 多维并行真正的难点是：每一次“再切一刀”都会改变本地矩阵大小和通信频率。 → 新代价/边界条件”三段式回答。

追问 2：EP×TP 能否随意相乘？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 3：Attention TP 与 expert TP 不同怎么实现？

回答方向：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

7. 常见失分点：为什么错

  • ❌ 把所有并行度看成互不影响的乘法因子。
  • 改进：回到“多维并行真正的难点是：每一次“再切一刀”都会改变本地矩阵大小和通信频率。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
