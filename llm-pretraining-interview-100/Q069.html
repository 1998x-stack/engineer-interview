MoE 为什么特别容易 Communication-Bound？

定位：A 类高频真题型 · 难度 难 · 频率 ★★★★★ 章节：Mixture-of-Experts

1. 面试官为什么问

考察稀疏 FLOPs 与网络数据移动的矛盾。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 稀疏性：total params、active params 与 active FLOPs 如何区分？
  • 路由学习：负载均衡如何与语义 specialization 共存？
  • 通信：A2A 是否把算术节省吃掉？

2. 30 秒结论

MoE 的“稀疏”省的是算术，不一定省网络；网络常成为新的墙。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

每个 token 在 expert 层前后需要按 router 结果重排并跨设备发送 hidden states。若专家小、top-k 多、EP 跨节点或 token 分布不均，All-to-All 时间可能接近甚至超过 expert GEMM。

3.2 关键 Trade-off / 边界

因此减少 active FLOPs 不保证 wall-clock 下降。MoE 系统优化常围绕 topology-aware EP、grouped GEMM、dispatch fusion、communication overlap 与负载均衡。

4. 深度展开

MoE 的三面墙

生产 MoE 不只是一道算法题： - Memory wall：大量 expert 参数和 optimizer states； - Communication wall：token dispatch/combine 的 All-to-All； - Compute-efficiency wall：每 expert token 数太少导致小 GEMM 低效。

因此“active FLOPs 更少”不推出“wall-clock 一定更快”。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：把 expert layer 时间拆成 route/dispatch/GEMM/combine。
  2. 动作 2：计算 bytes/token 与 FLOPs/token 的通信计算比。
  3. 动作 3：测试 intra-node vs inter-node EP。

MoE 端到端实验

同时监控 routing entropy、expert load、dropped tokens、A2A 时间、expert GEMM 利用率和模型 loss。

  • 负载均衡不是唯一目标。
  • 按 activated FLOPs 和 wall-clock 做公平比较。
  • 检查跨节点 EP 的网络代价。

6. 高频追问与回答方向

追问 1：怎样 overlap A2A 与 expert compute？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 2：为什么 token permutation 本身也有成本？

回答方向：从“旧方案瓶颈 → MoE 的“稀疏”省的是算术，不一定省网络；网络常成为新的墙。 → 新代价/边界条件”三段式回答。

追问 3：哪些模型规模更适合 MoE？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

7. 常见失分点：为什么错

  • ❌ 只看专家 FLOPs 判断加速比。
