为什么 Long-Context 通常还需要 Continued Pretraining？

定位：B 类等价追问题 · 难度 中 · 频率 ★★★★★ 章节：长上下文与高效 Attention

1. 面试官为什么问

区分位置可表示性与模型真正利用长上下文的能力。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 数学可见：位置/attention 机制是否允许看到更远？
  • 训练可用：模型是否在训练中学过远距离依赖？
  • 评测可信：128K 标签是否转化为真实有效上下文？

2. 30 秒结论

位置外推让模型“看得到”，长上下文训练让模型“学会用”。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

修改 RoPE 只解决“位置如何编码”的一部分问题。模型若从未在长文档上训练，就未必学会跨数万 token 检索、聚合、维持主题或处理远距离依赖。

3.2 关键 Trade-off / 边界

因此常在预训练后期加入长序列阶段，改变 context length 和长文档数据分布，并用较谨慎 LR 继续训练。Qwen3 官方资料也描述了阶段化预训练与长上下文阶段。

4. 深度展开：从定义走向 Production

本题的深挖重点是：位置外推让模型“看得到”，长上下文训练让模型“学会用”。

建议沿下面的因果链继续展开：

  1. 定义/状态语义：先把对象、tensor、数据分布或训练状态说准确；
  2. 机制：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
  3. 代价：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
  4. 可验证性：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
  5. 规模化边界：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：构造真实长文档与合成长距依赖混合数据。
  2. 动作 2：从短到长逐步扩展并监控通用能力回归。
  3. 动作 3：长序列阶段同步调整 batch tokens、CP 与 checkpointing。

长上下文有效性实验

不仅测最大可运行长度，还要测不同位置深度的检索、聚合和推理，外加真实长文档任务。

  • 长度扩展与能力扩展分开。
  • 按 sequence length 记录显存/吞吐。
  • 评测不同位置和不同信息密度。

6. 高频追问与回答方向

追问 1：为什么只训练长序列的短文拼接不够？

回答方向：从“旧方案瓶颈 → 位置外推让模型“看得到”，长上下文训练让模型“学会用”。 → 新代价/边界条件”三段式回答。

追问 2：CTP 会不会造成短上下文遗忘？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 3：长文本数据从哪里来？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

7. 常见失分点：为什么错

  • ❌ 把“支持 128K”只归功于 RoPE 参数。
  • 改进：回到“位置外推让模型“看得到”，长上下文训练让模型“学会用”。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
