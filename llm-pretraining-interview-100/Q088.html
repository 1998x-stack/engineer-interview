训练出现 NaN，你的排查顺序是什么？

定位：A 类高频真题型 · 难度 中 · 频率 ★★★★★ 章节：训练稳定性、Debug 与评测

1. 面试官为什么问

训练稳定性必问，要求从第一个坏 tensor 逆推。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • first bad event：能否定位第一个异常 step/rank/tensor？
  • 可复现：同 checkpoint+batch 是否重现？
  • 因果验证：修复是否有最小变量对照和回归？

2. 30 秒结论

NaN 调试的目标是找到第一个非法数值的出生地，而不是清理尸体。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

先定位第一个出现 NaN/Inf 的 step，再用 hooks/统计确定是 forward 还是 backward、哪个 layer、哪个 tensor 首先异常。随后检查输入数据、attention logits/softmax、norm、loss、gradient、optimizer update 和低精度 scale。

3.2 关键 Trade-off / 边界

关键是找到“第一个 NaN”，不是最后崩掉的 loss。必要时回到前一 checkpoint，关闭部分 fused/低精度路径做二分复现。

4. 深度展开

NaN 定位原则

不要从最终 loss 的 NaN 开始猜。利用 hooks / anomaly instrumentation 找到第一个 non-finite tensor：input → activation → attention logits → norm → loss → gradient → optimizer state。只要找到第一个坏值，就能把搜索空间从整个训练系统缩小到一个算子/层/数据路径。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：开启 finite-check 只在短 replay 中精细定位，避免 full run 巨大开销。
  2. 动作 2：逐层记录 max/min/RMS 和 finite ratio。
  3. 动作 3：修复后用异常 batch + 正常 batch 双回归。

故障可复现闭环

锁定 first bad step，保存 batch/rank/RNG/checkpoint，执行 deterministic replay，再用最小变量实验定位根因。

  • 先定位，不要先“调参试试”。
  • 保留正常 step 对照。
  • 修复后做回归与长期稳定性验证。

6. 高频追问与回答方向

追问 1：NaN 首先出现在 softmax 可能是什么？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 2：BF16 也会 NaN 吗？

回答方向：从 exponent range、overflow/underflow、accumulation dtype 与敏感算子保留高精度回答。

追问 3：为什么 torch.nan_to_num 不是修复？

回答方向：从“旧方案瓶颈 → NaN 调试的目标是找到第一个非法数值的出生地，而不是清理尸体。 → 新代价/边界条件”三段式回答。
