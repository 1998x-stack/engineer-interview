手写 Causal Mask：如何保证语义和数值都正确？

定位：B 类等价追问题 · 难度 易 · 频率 ★★★★☆ 章节：手撕、系统设计与项目拷打

1. 面试官为什么问

小题但能暴露 off-by-one 与 dtype 错误。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 正确性：代码/公式/系统是否在边界条件下仍正确？
  • 量化：参数、显存、吞吐、成本是否可手算/实测？
  • 证明：项目贡献是否有对照实验和可归因结果？

2. 30 秒结论

Causal mask 不是“把未来概率清零”，而是让未来 logit 在 softmax 前不可竞争。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

对 query 位置 i，只允许访问 key 位置 j≤i；未来位置加 -∞（或 dtype 安全的极小值）后再 softmax。若包含 padding，还要把 padding key 同时屏蔽。

3.2 关键 Trade-off / 边界

在 packed sequence 中，单纯下三角 mask 可能不够：如果不允许跨文档 attention，还要加入 document boundary mask。

核心公式

M_ij=0 if j≤i else -∞

面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

4. 深度展开

Mask 的两个不变量

  1. 语义：位置 $i$ 不能看到未来位置 $j>i$；
  2. 数值：被 mask 的 logit 在 softmax 后应为 0，且不能因为 dtype/全 mask row 产生 NaN。

真实训练还要考虑 padding/document boundary 与 causal mask 的组合。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：用 4×4 手工矩阵做 unit test。
  2. 动作 2：检查 diagonal 是否可见、padding query 的 loss 是否 mask。
  3. 动作 3：低精度下避免不安全常数导致 overflow/NaN。

白板到 Production

要求答案同时包含正确性、复杂度、测试、边界条件、工程约束和量化结果。

  • 代码题写 shape/assert/unit test。
  • 设计题先声明约束。
  • 项目题必须给数字和对照。

6. 高频追问与回答方向

追问 1：为什么 mask 加在 softmax 前？

回答方向：从“旧方案瓶颈 → Causal mask 不是“把未来概率清零”，而是让未来 logit 在 softmax 前不可竞争。 → 新代价/边界条件”三段式回答。

追问 2：packed docs 如何 block diagonal？

回答方向：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

追问 3：FlashAttention 的 causal flag 等价什么？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。
