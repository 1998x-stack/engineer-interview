手写 RoPE：代码之外必须证明什么？

定位：A 类高频真题型 · 难度 难 · 频率 ★★★★★ 章节：手撕、系统设计与项目拷打

1. 面试官为什么问

手撕位置编码时，数学与实现要互相验证。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 正确性：代码/公式/系统是否在边界条件下仍正确？
  • 量化：参数、显存、吞吐、成本是否可手算/实测？
  • 证明：项目贡献是否有对照实验和可归因结果？

2. 30 秒结论

RoPE 手撕要同时过三关：二维旋转、shape/broadcast、相对位置推导。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

实现通常把 head dimension 两两配对，用对应 position/frequency 的 cos、sin 做二维旋转，再应用到 Q/K。核心正确性不仅是 shape，还应证明旋转保持向量范数，并说明 QK 点积如何依赖相对位置。

3.2 关键 Trade-off / 边界

工程中要特别检查 position_ids、不同 batch offset、KV Cache decode 位置以及长上下文频率缩放。

核心公式

R(θ)[x₁,x₂]ᵀ = [x₁cosθ-x₂sinθ, x₁sinθ+x₂cosθ]ᵀ

面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

4. 深度展开

RoPE 代码题必须证明的式子

实现二维旋转只是“会写代码”；真正理解要能解释 $R_m^TR_n=R_{n-m}$，从而说明为什么 Q/K 内积携带相对位置。代码还要检查 rotary dimension 必须可成对、cos/sin 广播 shape、position offset 与 KV cache 一致。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：用小向量验证旋转前后 L2 norm 相同。
  2. 动作 2：数值验证相同相对距离在适当条件下产生一致结构。
  3. 动作 3：decode 时测试 position offset，避免 cache 位置错位。

白板到 Production

要求答案同时包含正确性、复杂度、测试、边界条件、工程约束和量化结果。

  • 代码题写 shape/assert/unit test。
  • 设计题先声明约束。
  • 项目题必须给数字和对照。

6. 高频追问与回答方向

追问 1：rotate_half 有哪些实现约定？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 2：为什么只对 Q/K 不对 V？

回答方向：从“旧方案瓶颈 → RoPE 手撕要同时过三关：二维旋转、shape/broadcast、相对位置推导。 → 新代价/边界条件”三段式回答。

追问 3：GQA 下 RoPE 如何广播？

回答方向：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

7. 常见失分点：为什么错

  • ❌ 只抄 cos/sin 代码，不能解释相对位置。
  • 改进：回到“RoPE 手撕要同时过三关：二维旋转、shape/broadcast、相对位置推导。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
