PRE-TRAINING · 97 / 101

手算 70B + Adam + BF16 的训练显存，并推到 ZeRO

定位：A 类高频真题型 · 难度 难 · 频率 ★★★★★ 章节：手撕、系统设计与项目拷打

1. 面试官为什么问

预训练岗位 S 级题：假设、公式和分片必须都对。

这道题真正区分的是：能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”。

本题的三层观察镜

  • 正确性：代码/公式/系统是否在边界条件下仍正确？
  • 量化：参数、显存、吞吐、成本是否可手算/实测？
  • 证明：项目贡献是否有对照实验和可归因结果？

2. 30 秒结论

显存手算模板：列状态 → 算 bytes → 标复制/分片 → 加 activation/峰值。

30 秒版本的目标不是覆盖所有细节，而是先给出正确结论 + 最关键因果关系，让面试官知道你掌握主线。

3. 3 分钟标准回答

3.1 核心机制

先声明一种常见假设：BF16 params 2B、BF16 grads 2B、FP32 master 4B、Adam m/v 各4B，总计 16 bytes/param。70B model states 约 1.12TB；这还不包括 activation、临时 buffer 和 fragmentation。

3.2 关键 Trade-off / 边界

然后按 ZeRO stage 分片：Stage1 只把 optimizer 部分按 DP 分；Stage2 再分 grad；Stage3 连 param 也按 DP 分。真正单卡峰值还要加入参数 all-gather、activation 和通信 workspace。

核心公式

示例基线：70×10⁹ × 16 bytes ≈ 1.12 TB（model states，未分片）

面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

4. 深度展开

70B 训练显存答题模板

  1. 声明 weight/grad/master/m/v 的 dtype；
  2. 按 bytes/param × 70B 算 model states；
  3. 指出 DP replica；
  4. 应用 ZeRO-1/2/3 或 FSDP 的分片因子；
  5. 再估 activation、临时 gather buffer、通信 buffer 和 allocator peak。

面试官更看重假设透明与分片语义正确，不是背一个固定 TB 数。

5. Know-how：如何落到实现与训练系统

  1. 动作 1：白板用表格列 state、dtype、总字节、是否 /DP。
  2. 动作 2：给出“理论常驻”与“运行峰值”两个数字。
  3. 动作 3：说明不同框架没有 master copy 时数字会变化。

白板到 Production

要求答案同时包含正确性、复杂度、测试、边界条件、工程约束和量化结果。

  • 代码题写 shape/assert/unit test。
  • 设计题先声明约束。
  • 项目题必须给数字和对照。

6. 高频追问与回答方向

追问 1：DP=64，ZeRO-2 常驻 model states 多少？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

追问 2：Stage3 为什么峰值不等于总状态/DP？

回答方向：从“旧方案瓶颈 → 显存手算模板：列状态 → 算 bytes → 标复制/分片 → 加 activation/峰值。 → 新代价/边界条件”三段式回答。

追问 3：加 activation checkpointing 影响哪一项？

回答方向：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

7. 常见失分点：为什么错

  • ❌ 不声明 dtype 假设。
  • 改进：回到“显存手算模板：列状态 → 算 bytes → 标复制/分片 → 加 activation/峰值。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
  • ❌ 把全部 16B/param 在 ZeRO-1 就除以 DP。
  • 改进：回到“显存手算模板：列状态 → 算 bytes → 标复制/分片 → 加 activation/峰值。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
