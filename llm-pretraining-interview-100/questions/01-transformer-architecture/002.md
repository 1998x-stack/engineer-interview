# Q002. MHA、MQA、GQA 的本质区别是什么？

> **定位**：A 类高频真题型 · 难度 **中** · 频率 **★★★★★**
> 章节：[Transformer 与模型架构](./README.md)

## 1. 面试官为什么问

考察你能否把表示能力、KV Cache、内存带宽和训练架构统一起来。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **数学尺度**：公式是否解释了数值尺度、梯度和表示能力？
- **结构成本**：参数量、FLOPs、KV Cache 与 kernel shape 如何变化？
- **生命周期**：训练架构选择会如何影响推理成本？

## 2. 30 秒结论

> GQA 的关键不是“少几个头”，而是用更少的 KV 表示换取更低的缓存与带宽成本。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

MHA 为每个 query head 配一组独立 K/V；MQA 让所有 query heads 共享一组 K/V；GQA 介于两者之间，让若干 query heads 共享一个 KV head。若 h_q 为 query heads、h_kv 为 KV heads，则 MHA: h_kv=h_q，MQA: h_kv=1，GQA: 1<h_kv<h_q。

### 3.2 关键 Trade-off / 边界

推理时 KV Cache 大小近似正比于 h_kv，因此减少 KV heads 能显著降低显存占用和内存带宽；代价是 K/V 表示自由度下降。GQA 是质量与 serving efficiency 的折中。

## 4. 深度展开

### KV Cache 手算模板
对 decoder-only 模型，忽略额外元数据时 KV Cache 近似：

$$
M_{KV}\approx B\times S\times L\times 2\times h_{kv}\times d_h\times bytes(dtype).
$$

MHA/MQA/GQA 的核心差异会直接落在 $h_{kv}$。这也是为什么 GQA 是架构层面的生命周期成本设计，而不是 serving 阶段临时加的技巧。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：手算 KV Cache 时显式写 batch、sequence、layers、2(K/V)、h_kv、head_dim、dtype。
2. **动作 2**：实现中注意 repeat_kv 只是逻辑广播；不应真的复制成 MHA 大小再做 attention。
3. **动作 3**：训练架构选型要结合预期推理吞吐，而不是只看 pretraining loss。

### 架构 Ablation

固定训练 Token 与大部分 recipe，只改变目标组件；同时比较 validation loss、下游能力、训练稳定性、参数/FLOPs 与推理成本。

- 不要只比较最终 benchmark；记录收敛速度。
- 至少做等参数或等 FLOPs 对照。
- 改变 head/hidden 等 shape 时同时检查 kernel efficiency。

## 6. 高频追问与回答方向

### 追问 1：GQA 为什么不只是一种推理优化？

**回答方向**：从“旧方案瓶颈 → GQA 的关键不是“少几个头”，而是用更少的 KV 表示换取更低的缓存与带宽成本。 → 新代价/边界条件”三段式回答。

### 追问 2：GQA 的参数量比 MHA 少多少？

**回答方向**：列出矩阵 shape 后逐项求和，不要凭经验比例；同时指出 weight tying/GQA/SwiGLU 等会改变结果。

### 追问 3：为什么 KV heads 太少可能伤质量？

**回答方向**：从“旧方案瓶颈 → GQA 的关键不是“少几个头”，而是用更少的 KV 表示换取更低的缓存与带宽成本。 → 新代价/边界条件”三段式回答。

## 7. 常见失分点：为什么错

- ❌ **只回答“GQA 更省显存”，不说明省的是 KV Cache 哪一维。**
  - 改进：回到“GQA 的关键不是“少几个头”，而是用更少的 KV 表示换取更低的缓存与带宽成本。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
- ❌ **把 query heads 也错误地一起减少。**
