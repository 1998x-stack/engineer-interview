# Q006. SwiGLU 为什么替代传统 ReLU/GELU FFN？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[Transformer 与模型架构](./README.md)

## 1. 面试官为什么问

考察 gated FFN 的表达能力与参数预算。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **数学尺度**：公式是否解释了数值尺度、梯度和表示能力？
- **结构成本**：参数量、FLOPs、KV Cache 与 kernel shape 如何变化？
- **生命周期**：训练架构选择会如何影响推理成本？

## 2. 30 秒结论

> SwiGLU 的关键词是 gating；参数预算必须按三块 projection 重新计算。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

SwiGLU 使用两条输入投影：一条经过 SiLU 形成 gate，另一条形成 value，二者逐元素相乘后再投影回 hidden dimension。门控让网络可以根据输入选择性调制特征。

### 3.2 关键 Trade-off / 边界

因为多了一组输入投影，若仍使用传统 4d intermediate dimension，参数与 FLOPs 会显著变大；实际架构常调整 intermediate size，使总预算与目标参数规模匹配。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：参数手算时分别计 gate/up/down 三个矩阵。
2. **动作 2**：比较 FFN 的 GEMM shape 是否硬件友好，不能只按参数最优。
3. **动作 3**：关注激活分布和 fused SwiGLU kernel。

### 架构 Ablation

固定训练 Token 与大部分 recipe，只改变目标组件；同时比较 validation loss、下游能力、训练稳定性、参数/FLOPs 与推理成本。

- 不要只比较最终 benchmark；记录收敛速度。
- 至少做等参数或等 FLOPs 对照。
- 改变 head/hidden 等 shape 时同时检查 kernel efficiency。
