# Q007. RoPE 为什么能把相对位置信息写进 Attention？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**

## 2. 30 秒结论

> RoPE 最关键的一行：旋转后的 QK 点积由 R_{n-m} 决定。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

RoPE 将每对隐藏维度视为二维平面，根据 token position 做旋转。位置 m 的 q 变成 R_m q，位置 n 的 k 变成 R_n k。由于旋转矩阵满足 R_mᵀR_n=R_{n-m}，二者点积只通过相对位移 n-m 进入。

### 3.2 关键 Trade-off / 边界

因此 RoPE 同时保留绝对位置施加在向量上的变换，又让 QK 内积天然具有相对位置结构。这比只说“旋转编码”更完整。

### 核心公式

```text
(R_m q)ᵀ(R_n k)=qᵀR_{n-m}k
```

> 面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

## 4. 深度展开

### RoPE 的相对位置恒等式
若位置 $m,n$ 分别应用旋转 $R_m,R_n$，则

$$
(R_mq)^T(R_nk)=q^TR_m^TR_nk=q^TR_{n-m}k.
$$

所以 attention 内积依赖位置差 $n-m$。高分回答还要说明：这不等于“无限长度外推自然成立”，训练频率范围之外仍可能发生分布外问题。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：白板至少推到 qᵀR_{n-m}k。
2. **动作 2**：实现时检查偶/奇维配对、频率表、position_ids 与 broadcasting。
3. **动作 3**：长上下文扩展时继续追问频率外推，而不是简单改 max_position_embeddings。

### 架构 Ablation

固定训练 Token 与大部分 recipe，只改变目标组件；同时比较 validation loss、下游能力、训练稳定性、参数/FLOPs 与推理成本。

- 不要只比较最终 benchmark；记录收敛速度。
- 至少做等参数或等 FLOPs 对照。
- 改变 head/hidden 等 shape 时同时检查 kernel efficiency。
