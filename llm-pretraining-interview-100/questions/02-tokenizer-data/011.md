# Q011. BPE、WordPiece、SentencePiece 的本质区别？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[Tokenizer 与预训练数据](./README.md)

## 1. 面试官为什么问

Tokenizer 是数据工程与算力效率的第一层接口，不能只背名词。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **分布**：每个过滤/采样动作怎样改变 p_train(x)？
- **信息密度**：单位 Token 的新颖性、正确性和覆盖度怎样衡量？
- **可追溯**：能否从训练异常追到具体 shard/domain/sample？

## 2. 30 秒结论

> Tokenizer 不是前处理小工具，它决定“每个训练 token 装了多少信息”。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

BPE 通过迭代合并高频符号对构建词表；WordPiece 的经典实现更偏向按语言模型/似然收益选择子词；SentencePiece 是直接从原始字符串训练与编码的框架，可承载 BPE、Unigram 等算法。

### 3.2 关键 Trade-off / 边界

对 LLM 来说，关键不是分类学，而是 tokenizer 如何改变序列长度、跨语言 fertility、数字/代码切分和词表参数。Tokenizer 设计会直接改变同一语料对应的训练 token 数。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**Tokenizer 不是前处理小工具，它决定“每个训练 token 装了多少信息”。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：在目标语料上统计 chars/token、bytes/token、不同语言 fertility。
2. **动作 2**：单独评估代码标识符、数字、小数、Unicode 与空白。
3. **动作 3**：词表升级要考虑旧 checkpoint embedding 的兼容。

### 数据闭环

从样本级 provenance 到 domain-level held-out loss 建立闭环：数据变更必须能追溯到采样率、重复率、污染率和能力变化。

- 所有过滤规则可版本化。
- Mixture 调整用 proxy run 或受控消融。
- benchmark contamination 与训练质量评估分开。
