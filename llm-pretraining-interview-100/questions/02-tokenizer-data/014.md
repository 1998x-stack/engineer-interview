# Q014. 从 Common Crawl 到训练 Token：完整预训练数据 Pipeline 怎么设计？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**
> 章节：[Tokenizer 与预训练数据](./README.md)

## 1. 面试官为什么问

这是预训练岗位最核心的 data-system 题，检验是否真正做过全链路。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **分布**：每个过滤/采样动作怎样改变 p_train(x)？
- **信息密度**：单位 Token 的新颖性、正确性和覆盖度怎样衡量？
- **可追溯**：能否从训练异常追到具体 shard/domain/sample？

## 2. 30 秒结论

> 预训练数据工程的专业度体现在：每个 token 都能解释“从哪里来、为何留下、被采样多少次”。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

典型链路包括：抓取/接入 → parsing 与正文抽取 → 语言识别 → 规则过滤 → quality scoring → 安全/PII 处理 → exact/near/semantic dedup → benchmark decontamination → domain tagging → mixture sampling → tokenization → packing → shuffle/sharding → dataloader。

### 3.2 关键 Trade-off / 边界

关键是每一步都要可追溯、可回滚、可量化。不要把“清洗”当一个黑盒脚本；每个 filter 都会改变数据分布，必须记录保留率、domain/language 变化与质量收益。

## 4. 深度展开

### 推荐的数据流水线
```text
Raw Sources
  → Parser / Boilerplate Removal
  → Language & Domain ID
  → Rule Filters
  → Quality Scorer
  → Exact / Near / Semantic Dedup
  → Safety / PII Controls
  → Benchmark Decontamination
  → Mixture & Sampling Policy
  → Tokenization
  → Packing / Shuffling / Sharding
  → Training + Data Telemetry
```
真正专业的 pipeline 需要把每一步的版本、阈值、输入输出统计写入 manifest，保证任意 checkpoint 都能还原其数据配方。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：给每条样本保留 source_id、版本、过滤原因和 hash，支持数据 lineage。
2. **动作 2**：建立 stage-by-stage retention dashboard，抽样做人审。
3. **动作 3**：在 proxy model 上验证过滤/配比变化，而不是仅用 quality classifier 分数决策。

### 数据闭环

从样本级 provenance 到 domain-level held-out loss 建立闭环：数据变更必须能追溯到采样率、重复率、污染率和能力变化。

- 所有过滤规则可版本化。
- Mixture 调整用 proxy run 或受控消融。
- benchmark contamination 与训练质量评估分开。
