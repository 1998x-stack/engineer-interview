# Q017. 预训练数据 Mixture 到底怎么调？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**
> 章节：[Tokenizer 与预训练数据](./README.md)

## 1. 面试官为什么问

数据配比是当代预训练的核心算法问题，决定不同能力的边际收益。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **分布**：每个过滤/采样动作怎样改变 p_train(x)？
- **信息密度**：单位 Token 的新颖性、正确性和覆盖度怎样衡量？
- **可追溯**：能否从训练异常追到具体 shard/domain/sample？

## 2. 30 秒结论

> 配比不是 recipe，而是“每增加一个 token，应放到哪个 domain”的边际收益优化。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

设 domain i 的采样概率为 p_i，目标不是给出固定百分比，而是让有限 token budget 在多个能力/验证目标上获得最大边际收益。实际可通过 proxy models、不同 mixture 的 controlled experiments、domain-conditioned validation loss 与 scaling trend 来估计。

### 3.2 关键 Trade-off / 边界

配比还受数据可用量、重复次数、阶段目标和 transfer effect 影响：同一 domain 在早期通用阶段与后期 reasoning/code 阶段的最优权重可能完全不同。

### 核心公式

```text
min_p Σ_j w_j L_j(p),  Σ_i p_i=1
```

> 面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

## 4. 深度展开

### 把 Mixture 写成优化问题
设 domain 权重为 $p_1,\dots,p_k$，$\sum_i p_i=1$。可以把目标抽象为

$$
\min_{p}\sum_j w_j L_j(p),
$$

但生产中不能只靠一次网格搜索：domain 之间存在迁移、重复上限和 stage dependency。更实用的方法是 proxy models + mixture ablation + domain-conditioned validation loss。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：先固定总 token 与模型大小，只改变 mixture 做正交对照。
2. **动作 2**：记录每 domain 实际 consumed tokens，防止数据 loader 与重复策略偏离目标比例。
3. **动作 3**：对稀缺高价值数据设置 epoch/repetition 上限并观察 overfit。

### 数据闭环

从样本级 provenance 到 domain-level held-out loss 建立闭环：数据变更必须能追溯到采样率、重复率、污染率和能力变化。

- 所有过滤规则可版本化。
- Mixture 调整用 proxy run 或受控消融。
- benchmark contamination 与训练质量评估分开。

## 6. 高频追问与回答方向

### 追问 1：怎样判断数学数据该从 5% 加到 10%？

**回答方向**：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

### 追问 2：不同 domain 的 loss 能直接比较吗？

**回答方向**：先统一比较维度（质量、FLOPs、memory、communication、wall-clock），再逐项对齐，避免只比一个指标。

### 追问 3：mixture 与 curriculum 有什么区别？

**回答方向**：先统一比较维度（质量、FLOPs、memory、communication、wall-clock），再逐项对齐，避免只比一个指标。

## 7. 常见失分点：为什么错

- ❌ **报一组“经验百分比”却没有实验方法。**
  - 改进：回到“配比不是 recipe，而是“每增加一个 token，应放到哪个 domain”的边际收益优化。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
- ❌ **忽略不同 tokenizer 对 domain token 数的影响。**
