# Q019. Packing 与 Padding 有什么区别？为什么 Packing 不是简单拼接？

> **定位**：A 类高频真题型 · 难度 **中** · 频率 **★★★★★**
> 章节：[Tokenizer 与预训练数据](./README.md)

## 1. 面试官为什么问

公开面经高频题，能深入到 attention mask、loss weighting 和数据效率。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **分布**：每个过滤/采样动作怎样改变 p_train(x)？
- **信息密度**：单位 Token 的新颖性、正确性和覆盖度怎样衡量？
- **可追溯**：能否从训练异常追到具体 shard/domain/sample？

## 2. 30 秒结论

> Packing 优化的是 token utilization；正确性取决于边界、mask、position 与 loss 四件事。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Padding 将不同长度样本补到统一长度，计算大量无效 PAD；Packing 把多个短文档装入同一固定长度 sequence，提高 token utilization。

### 3.2 关键 Trade-off / 边界

但直接 concatenate 会让后一个文档看到前一个无关文档。是否允许跨文档 attention 取决于训练设计；若不允许，需要 document-aware mask / position reset。还要处理 EOS、loss mask、样本权重和边界位置。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**面试现场最好画出 [A A EOS][B B EOS] 并解释每一块 attention mask。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：统计 useful_tokens / total_tokens，而不是只看 samples/sec。
2. **动作 2**：验证 packed sequence 的 attention mask 与 label shift，做小例子单元测试。
3. **动作 3**：分布式 dataloader 中保证不同 rank 的 token 数接近，避免 padding/packing 造成 straggler。

### 数据闭环

从样本级 provenance 到 domain-level held-out loss 建立闭环：数据变更必须能追溯到采样率、重复率、污染率和能力变化。

- 所有过滤规则可版本化。
- Mixture 调整用 proxy run 或受控消融。
- benchmark contamination 与训练质量评估分开。

- ❌ **把 packing 说成 concatenate 后加 EOS 就结束。**
