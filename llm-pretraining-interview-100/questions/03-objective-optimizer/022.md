# Q022. 为什么训练能并行预测所有 Token，而推理必须逐 Token 生成？

> **定位**：B 类等价追问题 · 难度 **易** · 频率 **★★★★☆**
> 章节：[目标函数、Optimizer 与 Training Recipe](./README.md)

## 1. 面试官为什么问

考察 teacher forcing、causal mask 与 prefill/decode 的区别。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **更新尺度**：LR、batch、momentum 如何共同决定参数更新？
- **token 对齐**：所有曲线是否按 consumed tokens 对齐？
- **稳定性**：warmup、clip、precision 与 optimizer state 如何相互作用？

## 2. 30 秒结论

> 训练的“并行”来自已知答案；推理的“串行”来自答案本身尚不存在。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

训练时完整 ground-truth sequence 已知，所有位置的 Q/K/V 可一次计算；causal mask 只阻止位置 t 访问未来 token，所以各位置 loss 可以并行。

### 3.2 关键 Trade-off / 边界

生成时 x_{t+1} 依赖刚生成的 x_t，未来 token 不存在，形成串行 autoregressive dependency。工程上 prefill 仍可并行处理已有 prompt，而 decode 阶段每步通常只新增一个 token，并复用 KV Cache。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：明确区分 training、prefill、decode 三种 kernel/瓶颈。
2. **动作 2**：训练通常 compute-bound，decode 更容易 memory-bandwidth/KV-cache bound。
3. **动作 3**：吞吐分析用 tokens/s 与 batch/sequence 共同说明。

### 优化曲线实验

保持模型与数据固定，比较 LR/batch/optimizer 变体的 token-normalized loss、grad norm、更新范数和稳定性。

- 以 consumed tokens 而非 step 对齐。
- 记录 effective batch tokens。
- 避免只看最终 loss 而忽略 wall-clock。
