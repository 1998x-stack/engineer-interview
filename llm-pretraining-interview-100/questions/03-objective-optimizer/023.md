# Q023. AdamW 为什么长期是 LLM 预训练默认优化器？

> **定位**：A 类高频真题型 · 难度 **中** · 频率 **★★★★★**
> 章节：[目标函数、Optimizer 与 Training Recipe](./README.md)

## 1. 面试官为什么问

能从优化、自适应状态与显存代价继续追问。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **更新尺度**：LR、batch、momentum 如何共同决定参数更新？
- **token 对齐**：所有曲线是否按 consumed tokens 对齐？
- **稳定性**：warmup、clip、precision 与 optimizer state 如何相互作用？

## 2. 30 秒结论

> AdamW 的价值是自适应更新；它的代价是昂贵的状态内存与 checkpoint。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Adam 维护一阶矩 m 与二阶矩 v，对不同参数维度做自适应缩放；AdamW 将 weight decay 与梯度更新解耦，使 L2-like regularization 不再被 Adam 的 adaptive denominator 扭曲。

### 3.2 关键 Trade-off / 边界

它的主要工程代价是 optimizer states：m、v 通常使用 FP32，加上 master weights/gradients 后每参数字节数很高，因此 ZeRO/FSDP/Distributed Optimizer 对大模型训练至关重要。

## 4. 深度展开

### AdamW 状态账本
AdamW 至少需要一阶矩 $m$ 与二阶矩 $v$；混合精度实现还可能维护 FP32 master weights。显存题中必须先声明 dtype 与实现，再谈“多少 bytes/param”。

工程上还应观察 update-to-weight ratio：只看 grad norm 不足以判断每层实际更新是否过大。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：回答公式后立刻手算 bytes/param，体现训练系统意识。
2. **动作 2**：监控 update norm / parameter norm，而不只看 gradient norm。
3. **动作 3**：大规模训练中 optimizer state checkpoint 也会成为 IO 瓶颈。

### 优化曲线实验

保持模型与数据固定，比较 LR/batch/optimizer 变体的 token-normalized loss、grad norm、更新范数和稳定性。

- 以 consumed tokens 而非 step 对齐。
- 记录 effective batch tokens。
- 避免只看最终 loss 而忽略 wall-clock。

**回答方向**：先统一比较维度（质量、FLOPs、memory、communication、wall-clock），再逐项对齐，避免只比一个指标。

### 追问 2：β1/β2 改变什么时间尺度？

**回答方向**：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

### 追问 3：为什么 optimizer state 要用更高精度？

**回答方向**：从“旧方案瓶颈 → AdamW 的价值是自适应更新；它的代价是昂贵的状态内存与 checkpoint。 → 新代价/边界条件”三段式回答。
