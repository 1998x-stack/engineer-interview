# Q029. 为什么 Label Smoothing 不是 LLM 预训练的默认配置？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★☆☆**
> 章节：[目标函数、Optimizer 与 Training Recipe](./README.md)

## 1. 面试官为什么问

检验概率建模目标与分类技巧的差别。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **更新尺度**：LR、batch、momentum 如何共同决定参数更新？
- **token 对齐**：所有曲线是否按 consumed tokens 对齐？
- **稳定性**：warmup、clip、precision 与 optimizer state 如何相互作用？

## 2. 30 秒结论

> 语言建模优化的是概率分布本身，因此随意修改 target distribution 要格外谨慎。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

语言建模希望拟合真实条件 token 分布；label smoothing 人为把 one-hot target 与均匀分布混合，会改变最大似然目标并降低模型对正确 token 的置信度。

### 3.2 关键 Trade-off / 边界

在大词表生成任务中，目标本身已经具有高不确定性，而且 calibration/regularization 可通过数据规模、weight decay 等其他手段实现，因此 label smoothing 不像图像分类那样普遍。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**语言建模优化的是概率分布本身，因此随意修改 target distribution 要格外谨慎。**

5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：若使用 smoothing，必须明确对特殊 token、padding 和词表大小的处理。
2. **动作 2**：比较 NLL、calibration 与生成质量，而不只看 top-1 accuracy。
3. **动作 3**：不要把 SFT 的 soft targets 与预训练 label smoothing 混为一谈。

### 优化曲线实验

保持模型与数据固定，比较 LR/batch/optimizer 变体的 token-normalized loss、grad norm、更新范数和稳定性。

- 以 consumed tokens 而非 step 对齐。
- 记录 effective batch tokens。
- 避免只看最终 loss 而忽略 wall-clock。
