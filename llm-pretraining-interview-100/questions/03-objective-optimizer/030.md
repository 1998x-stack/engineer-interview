# Q030. Multi-Token Prediction（MTP）为什么重新受到重视？

> **定位**：B 类等价追问题 · 难度 **难** · 频率 **★★★★☆**
> 章节：[目标函数、Optimizer 与 Training Recipe](./README.md)

## 1. 面试官为什么问

考察新一代预训练目标与训练效率。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **更新尺度**：LR、batch、momentum 如何共同决定参数更新？
- **token 对齐**：所有曲线是否按 consumed tokens 对齐？
- **稳定性**：warmup、clip、precision 与 optimizer state 如何相互作用？

## 2. 30 秒结论

> MTP 的核心是增加未来监督信号；它是否带来端到端收益必须按等成本比较。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

标准 CLM 每个位置直接预测下一个 token；MTP 增加若干预测头/模块，让当前表示同时承担未来多个 token 的预测信号。这样可提高单位上下文位置的监督密度，并推动表示学习更具前瞻性。

### 3.2 关键 Trade-off / 边界

DeepSeek-V3 将 MTP 纳入预训练设计。它带来额外参数/FLOPs和 loss weighting 问题；推理时这些辅助模块是否保留、如何用于 speculative decoding，则是另一层系统设计。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**MTP 的核心是增加未来监督信号；它是否带来端到端收益必须按等成本比较。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：分别记录主 LM loss 与各 MTP depth loss。
2. **动作 2**：做等 FLOPs 或等 wall-clock 对照，避免仅因多算导致提升。
3. **动作 3**：检查辅助目标是否损害主 next-token calibration。

### 优化曲线实验

保持模型与数据固定，比较 LR/batch/optimizer 变体的 token-normalized loss、grad norm、更新范数和稳定性。

- 以 consumed tokens 而非 step 对齐。
- 记录 effective batch tokens。
- 避免只看最终 loss 而忽略 wall-clock。
