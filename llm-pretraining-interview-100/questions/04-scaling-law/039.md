# Q039. 同样 FLOPs 下，Dense 与 MoE 怎么公平比较？

> **定位**：B 类等价追问题 · 难度 **难** · 频率 **★★★★★**
> 章节：[Scaling Law 与预算设计](./README.md)

## 1. 面试官为什么问

避免用 total parameters 制造错误比较。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **约束优化**：到底固定的是 FLOPs、GPU-hours、成本还是推理预算？
- **外推**：小规模曲线在哪些条件下可以外推？
- **等成本比较**：Dense/MoE/不同数据 recipe 是否真的比较公平？

## 2. 30 秒结论

> MoE 比较必须看 active compute 与通信，而不是只看总参数。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

MoE 的 total parameters 很大，但每个 token 只激活少数 experts。因此公平比较至少要对齐 training FLOPs/token、训练 tokens、wall-clock 或总预算，同时报告 total params 与 activated params。

### 3.2 关键 Trade-off / 边界

还必须计入 routing、All-to-All、load imbalance 和 kernel 效率。算法 FLOPs 相近不意味着集群成本相近。DeepSeek-V3 例如公开为 671B total、约 37B activated/token。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**MoE 比较必须看 active compute 与通信，而不是只看总参数。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：制作比较表：total/active params、FLOPs/token、tokens、MFU、network time、memory。
2. **动作 2**：用实际 accelerator-hours 做第二组成本指标。
3. **动作 3**：统一数据和 evaluation。

### Scaling Proxy

用多个模型尺寸、Token 预算和 seed 构造 proxy grid，拟合 loss/compute 曲线，再用 hold-out 规模验证外推误差。

- 拟合前确认数据 mixture 一致。
- 报告置信区间/外推范围。
- 区分训练 FLOPs optimum 与生命周期成本 optimum。
