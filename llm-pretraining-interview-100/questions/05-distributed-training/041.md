# Q041. DDP 到底做了什么？

> **定位**：A 类高频真题型 · 难度 **易** · 频率 **★★★★★**
> 章节：[分布式训练](./README.md)

## 1. 面试官为什么问

所有并行训练问题的基线，必须清楚 replica、gradient 与 collective。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **切分语义**：每个并行轴到底切哪个 tensor/state？
- **collective**：每一步需要 AG/RS/AR/A2A/P2P 中的什么？
- **拓扑**：高频通信是否留在 NVLink/NVSwitch 域？

## 2. 30 秒结论

> DDP 复制模型、切数据、同步梯度；它不是模型分片。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

DDP 在每个 data-parallel rank 保存完整模型，处理不同 micro-batch，独立 forward/backward；梯度生成后通过 AllReduce（或等价 reduce-scatter/all-gather 组合）求和/平均，使所有 replica 得到一致梯度并执行相同 optimizer update。

### 3.2 关键 Trade-off / 边界

DDP 降低的是“每步耗时通过并行数据”，并不降低每个 rank 的模型/optimizer state 显存，因此超大模型需要 FSDP/ZeRO 或模型并行。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**DDP 复制模型、切数据、同步梯度；它不是模型分片。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：画出 4 rank 的 gradient bucket 与 overlap。
2. **动作 2**：检查 effective global batch 与 gradient averaging 语义。
3. **动作 3**：通信瓶颈分析看 bucket size、网络拓扑和 compute/comm overlap。

### 分布式 Profiling

对每个并行轴画出“切分对象—rank 状态—collective—通信量—拓扑”，再用 trace 验证通信是否可 overlap。

- 先保证数值一致性再优化性能。
- 比较 per-rank peak memory 与 step time。
- 识别最慢 rank 和 collective hotspot。

## 6. 高频追问与回答方向

### 追问 1：AllReduce 在 backward 何时触发？

**回答方向**：明确通信发生在哪个 forward/backward 阶段、通信量随哪个维度增长、能否与计算 overlap，以及跨节点拓扑影响。

### 追问 2：为什么 DDP 不省参数显存？

**回答方向**：先声明 dtype 与 batch/seq/layers/heads 等变量，再拆 weights、states、activation、buffer；最后说明分片轴。

### 追问 3：如果一个 rank 梯度 NaN 会怎样？

**回答方向**：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

## 7. 常见失分点：为什么错

- ❌ **说 DDP 会把模型参数自动切到多卡。**
  - 改进：回到“DDP 复制模型、切数据、同步梯度；它不是模型分片。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
