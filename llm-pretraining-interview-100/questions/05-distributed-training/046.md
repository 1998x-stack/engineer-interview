# Q046. ZeRO-1、ZeRO-2、ZeRO-3 分别 Shard 什么？

> **定位**：A 类高频真题型 · 难度 **易** · 频率 **★★★★★**
> 章节：[分布式训练](./README.md)

## 1. 面试官为什么问

经典显存题，也是 FSDP/Distributed Optimizer 的基础。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **切分语义**：每个并行轴到底切哪个 tensor/state？
- **collective**：每一步需要 AG/RS/AR/A2A/P2P 中的什么？
- **拓扑**：高频通信是否留在 NVLink/NVSwitch 域？

## 2. 30 秒结论

> ZeRO 的本质是沿 DP 组消除 model-state replication，级别越高通信越多。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

ZeRO Stage 1 shard optimizer states；Stage 2 进一步 shard gradients；Stage 3 再 shard model parameters。目标是消除 data-parallel replicas 对 model states 的冗余。

### 3.2 关键 Trade-off / 边界

分得越彻底，单卡常驻显存越低，但 forward/backward 需要更频繁地 all-gather 参数或 reduce-scatter 梯度，通信与调度复杂性上升。

## 4. 深度展开

### ZeRO 的状态分片表
| Stage | 参数 | 梯度 | Optimizer states |
|---|---|---|---|
| ZeRO-1 | 复制 | 复制 | 分片 |
| ZeRO-2 | 复制 | 分片 | 分片 |
| ZeRO-3 | 分片 | 分片 | 分片 |

越高 stage 越省 model-state memory，但 parameter gather / communication 也更复杂。回答时需要区分“长期驻留状态”和“计算瞬间需要 gather 的完整 shard”。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：手算时分开 P（参数）、G（梯度）、O（optimizer）三类字节。
2. **动作 2**：明确每一类是 replicated 还是 /DP。
3. **动作 3**：评估 stage3 的 parameter prefetch / reshard 与网络带宽。

### 分布式 Profiling

对每个并行轴画出“切分对象—rank 状态—collective—通信量—拓扑”，再用 trace 验证通信是否可 overlap。

- 先保证数值一致性再优化性能。
- 比较 per-rank peak memory 与 step time。
- 识别最慢 rank 和 collective hotspot。
