# Q048. Sequence Parallel 与 Context Parallel 有什么区别？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**
> 章节：[分布式训练](./README.md)

## 1. 面试官为什么问

新一代长上下文训练的高频区分题。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **切分语义**：每个并行轴到底切哪个 tensor/state？
- **collective**：每一步需要 AG/RS/AR/A2A/P2P 中的什么？
- **拓扑**：高频通信是否留在 NVLink/NVSwitch 域？

## 2. 30 秒结论

> SP 更像减少 TP 周边 activation 冗余；CP 是把长 context 本身跨卡分治。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Sequence Parallel（Megatron 语境）通常把 LayerNorm、Dropout 等 TP 区域之外的 activation 沿 sequence 维切分，减少冗余 activation；Attention 的完整 context 语义仍由 TP 相关通信保证。

### 3.2 关键 Trade-off / 边界

Context Parallel 则把整个网络输入/activation 沿 sequence 维分到多个 rank，Attention 的 Q 需要访问全局 K/V，因此必须进行 KV 交换/环式通信。CP 针对长 context 的 activation memory 更直接。

## 4. 深度展开

### SP 与 CP 的根本区别
SP 通常只沿 sequence 维切分 LayerNorm/Dropout 等局部算子 activation；CP 则沿 sequence 切分网络输入和全部 activation。Attention 是 CP 的特殊点：本地 Query 仍需要与全序列 KV 交互，因此必须设计 KV 通信。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：回答前声明框架语境，不同库对“SP”命名可能不同。
2. **动作 2**：画出每 rank 持有的 sequence slice。
3. **动作 3**：指出 CP 的核心通信对象是 K/V，而不是普通 DDP gradient。

### 分布式 Profiling

对每个并行轴画出“切分对象—rank 状态—collective—通信量—拓扑”，再用 trace 验证通信是否可 overlap。

- 先保证数值一致性再优化性能。
- 比较 per-rank peak memory 与 step time。
- 识别最慢 rank 和 collective hotspot。

- ❌ **把 SP 与 CP 都说成“切 sequence”。**
