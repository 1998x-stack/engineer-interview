# Q060. 什么是 MFU？MFU 低应该怎样定位？

> **定位**：A 类高频真题型 · 难度 **中** · 频率 **★★★★★**
> 章节：[显存、数值精度与性能](./README.md)

## 1. 面试官为什么问

训练系统日常指标，考察从症状到根因的能力。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **bytes**：每种 state/activation 实际占多少字节？
- **IO**：瓶颈是计算还是 HBM/网络搬运？
- **峰值**：steady-state memory 与 transient peak 是否分开？

## 2. 30 秒结论

> MFU 是体检报告，不是诊断书；低 MFU 后面必须跟 profiler。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Model FLOPs Utilization 用模型实际完成的理论 FLOPs/sec 除以加速器峰值 FLOPs/sec，反映端到端训练距离硬件计算上限有多远。

### 3.2 关键 Trade-off / 边界

MFU 低不是结论。可能来自通信、pipeline bubble、dataloader、small GEMM、recompute、MoE imbalance、CPU 同步或 kernel 不匹配。需要用 profiler 将 step time 分解。

## 4. 深度展开

### MFU 定位树
```text
MFU 低
├─ GPU idle → dataloader / synchronization / pipeline bubble
├─ GPU busy but low tensor-core → small GEMM / bad shapes / launch overhead
├─ comm high → TP/EP/DP collective / topology / overlap
├─ recompute high → checkpoint policy
└─ MoE → load imbalance / A2A / grouped GEMM efficiency
```
MFU 只能告诉你“没有吃满理论算力”，不能直接告诉你为什么。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：先确保 FLOPs 口径与硬件峰值 dtype 对应。
2. **动作 2**：记录 tokens/s、GPU active、NCCL time、bubble、dataloader wait。
3. **动作 3**：从最大 time bucket 开始优化，避免为了 MFU 美化指标。

### Roofline / Memory Accounting

先做理论 bytes/FLOPs 预算，再用 profiler、memory snapshot 和 kernel trace 对账。

- 把参数/梯度/优化器/activation/临时 buffer 分开。
- 注明 dtype 与分片假设。
- 区分理论峰值与可持续吞吐。
