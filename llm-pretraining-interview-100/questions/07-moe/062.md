# Q062. Top-1 与 Top-2 Routing 有什么 Trade-off？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[Mixture-of-Experts](./README.md)

## 1. 面试官为什么问

考察质量、计算、鲁棒性与负载均衡。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **稀疏性**：total params、active params 与 active FLOPs 如何区分？
- **路由学习**：负载均衡如何与语义 specialization 共存？
- **通信**：A2A 是否把算术节省吃掉？

## 2. 30 秒结论

> Routing 的 k 是能力与系统成本的直接旋钮。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Top-1 每 token 只进入一个 expert，计算和通信更低，但路由错误或热点 expert 的影响更直接；Top-2 允许两个 expert 共同贡献，提高组合表达与鲁棒性，但 active compute、dispatch bytes 和负载管理成本上升。

### 3.2 关键 Trade-off / 边界

没有绝对优劣，最佳 k 取决于 expert granularity、routing quality、集群网络与目标成本。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**Routing 的 k 是能力与系统成本的直接旋钮。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：对齐 active FLOPs 比较不同 top-k。
2. **动作 2**：观察 expert entropy、load balance、token drop 与 wall-clock。
3. **动作 3**：用 quality-vs-cost Pareto，而非只看 loss。

### MoE 端到端实验

同时监控 routing entropy、expert load、dropped tokens、A2A 时间、expert GEMM 利用率和模型 loss。

- 负载均衡不是唯一目标。
- 按 activated FLOPs 和 wall-clock 做公平比较。
- 检查跨节点 EP 的网络代价。
