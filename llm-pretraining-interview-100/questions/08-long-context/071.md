# Q071. Self-Attention 为什么是 O(S²)？

> **定位**：B 类等价追问题 · 难度 **易** · 频率 **★★★★☆**
> 章节：[长上下文与高效 Attention](./README.md)

## 1. 面试官为什么问

长上下文所有优化的起点。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **数学可见**：位置/attention 机制是否允许看到更远？
- **训练可用**：模型是否在训练中学过远距离依赖？
- **评测可信**：128K 标签是否转化为真实有效上下文？

## 2. 30 秒结论

> Attention pair 数是 S²，但模型总成本由 S²d 与 Sd² 共同决定。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

QKᵀ 需要计算 S 个 query 与 S 个 key 的两两相似度，score matrix 为 S×S；若 head dimension d，则主要 attention matmul FLOPs 为 O(S²d)，naive score/probability 存储为 O(S²)。

### 3.2 关键 Trade-off / 边界

注意 Transformer 总 FLOPs 还包含 O(Sd²) 的 projection/MLP。当 d 很大、S 较短时线性项可能占主导；长 S 时二次项才逐渐成为关键。

### 核心公式

```text
QKᵀ: [S,d]×[d,S]→[S,S]
```

> 面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**Attention pair 数是 S²，但模型总成本由 S²d 与 Sd² 共同决定。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：比较不同 S 下 attention 与 MLP FLOPs crossover。
2. **动作 2**：不要把 O(S²) 直接等同整个模型总复杂度。
3. **动作 3**：使用 profiler 验证真实瓶颈。

### 长上下文有效性实验

不仅测最大可运行长度，还要测不同位置深度的检索、聚合和推理，外加真实长文档任务。

- 长度扩展与能力扩展分开。
- 按 sequence length 记录显存/吞吐。
- 评测不同位置和不同信息密度。
