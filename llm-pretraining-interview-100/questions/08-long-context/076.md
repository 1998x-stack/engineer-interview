# Q076. Context 从 4K 扩到 32K，为什么常采用阶段式训练？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[长上下文与高效 Attention](./README.md)

## 1. 面试官为什么问

考察训练分布、显存和优化稳定性的联动。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **数学可见**：位置/attention 机制是否允许看到更远？
- **训练可用**：模型是否在训练中学过远距离依赖？
- **评测可信**：128K 标签是否转化为真实有效上下文？

## 2. 30 秒结论

> 扩上下文不仅改 position；它同时改变数据、优化和系统三套分布。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Sequence 从 4K 直接跳到 32K 会同时改变 attention/activation 成本、每 step 样本数、长文档分布和有效 global batch。若保持显存不变，microbatch 往往下降，优化噪声也随之变化。

### 3.2 关键 Trade-off / 边界

阶段式 4K→8K→16K→32K 可逐步暴露数值与系统问题，让 RoPE/长文能力和并行配置一起迁移；但阶段数并非固定，需要按资源和稳定性实验决定。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**扩上下文不仅改 position；它同时改变数据、优化和系统三套分布。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：每个阶段按 consumed tokens 重新检查 LR、batch token 与 validation。
2. **动作 2**：提前做各长度的 memory/throughput capacity plan。
3. **动作 3**：在长度切换点保存 checkpoint 和完整 telemetry，便于归因。

### 长上下文有效性实验

不仅测最大可运行长度，还要测不同位置深度的检索、聚合和推理，外加真实长文档任务。

- 长度扩展与能力扩展分开。
- 按 sequence length 记录显存/吞吐。
- 评测不同位置和不同信息密度。
