# Q077. Sliding-Window Attention 的优缺点是什么？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[长上下文与高效 Attention](./README.md)

## 1. 面试官为什么问

考察用稀疏性换长上下文成本的基本思路。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **数学可见**：位置/attention 机制是否允许看到更远？
- **训练可用**：模型是否在训练中学过远距离依赖？
- **评测可信**：128K 标签是否转化为真实有效上下文？

## 2. 30 秒结论

> Sliding window 用稀疏连接换成本；最核心风险是远距离信息路径变长。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

若每个 token 只关注局部窗口 w，attention pair 从 S² 降到约 Sw，能显著降低长序列计算和显存。局部语言建模本身也有很强归纳偏置。

### 3.2 关键 Trade-off / 边界

代价是单层无法建立任意远距离直接连接；全局信息只能靠多层传播、周期性 global attention 或特殊 token。对于精确长距离检索可能成为能力瓶颈。

### 核心公式

```text
Attention pairs ≈ S×w,  w≪S
```

> 面试时不要只写公式。要逐个解释符号、shape/量纲，以及公式如何导出工程结论。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**Sliding window 用稀疏连接换成本；最核心风险是远距离信息路径变长。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：设计 local/global layer pattern 并测长距 retrieval。
2. **动作 2**：同时观察短上下文 perplexity 与真实长文 QA。
3. **动作 3**：kernel 是否真正利用 sparsity 决定墙钟收益。

### 长上下文有效性实验

不仅测最大可运行长度，还要测不同位置深度的检索、聚合和推理，外加真实长文档任务。

- 长度扩展与能力扩展分开。
- 按 sequence length 记录显存/吞吐。
- 评测不同位置和不同信息密度。
