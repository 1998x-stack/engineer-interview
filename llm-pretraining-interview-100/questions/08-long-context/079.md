# Q079. Context Parallel 下 Attention 是怎么计算的？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**
> 章节：[长上下文与高效 Attention](./README.md)

## 1. 面试官为什么问

考察长上下文分片后的全局 Attention 正确性。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **数学可见**：位置/attention 机制是否允许看到更远？
- **训练可用**：模型是否在训练中学过远距离依赖？
- **评测可信**：128K 标签是否转化为真实有效上下文？

## 2. 30 秒结论

> CP 的核心矛盾：Q 可以本地，但 exact attention 所需 K/V 必须跨 rank 流动。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

CP 将 sequence 维分到多个 ranks，每个 rank 持一部分 query/context。为了让本地 Q 仍能注意全局 key/value，需要在 ranks 间交换 K/V（常见 ring 或 all-gather 类方案），逐块累积 attention 结果与 softmax 统计。

### 3.2 关键 Trade-off / 边界

它降低每卡长序列 activation，但增加 forward/backward 的 context communication；CP degree 越高，本地 sequence 越短，同时网络占比上升。

## 4. 深度展开

### CP Attention 的数据依赖
本地 rank 只拥有部分 Query/context，但每个 Query 理论上仍需要全序列 KV。因此 CP 的核心工程问题不是线性层，而是如何让 KV 在 CP ranks 之间高效流动，并在 backward 中正确传播梯度。回答时应画出 sequence shard 与 KV exchange。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：画 rank0/rank1 的 Q-local、KV-rotating 数据流。
2. **动作 2**：关注 causal mask 在分块/环式顺序中的正确性。
3. **动作 3**：同时 profile memory gain 与 network time。

### 长上下文有效性实验

不仅测最大可运行长度，还要测不同位置深度的检索、聚合和推理，外加真实长文档任务。

- 长度扩展与能力扩展分开。
- 按 sequence length 记录显存/吞吐。
- 评测不同位置和不同信息密度。
