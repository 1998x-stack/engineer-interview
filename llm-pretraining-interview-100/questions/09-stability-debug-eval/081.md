# Q081. 100B 模型训练到 42k Step 突然 Loss Spike，怎么排查？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**
> 章节：[训练稳定性、Debug 与评测](./README.md)

## 1. 面试官为什么问

最能区分“读过论文”和“真正训过模型”的故障题。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **first bad event**：能否定位第一个异常 step/rank/tensor？
- **可复现**：同 checkpoint+batch 是否重现？
- **因果验证**：修复是否有最小变量对照和回归？

## 2. 30 秒结论

> Loss spike 的专业处理是“冻结现场 → 可复现 → 单变量实验 → 根因 → 回归”，而不是经验调参。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

第一原则是定位与保全证据，而不是马上降 LR。先确定第一个异常 step/rank，保存 batch IDs、数据来源、loss、grad norm、activation statistics、optimizer state 与 NCCL/硬件日志。然后按 Data / Numerical / Optimizer / Distributed / Hardware 五类建立假设。

### 3.2 关键 Trade-off / 边界

若有 spike 前 checkpoint，使用同一 batch deterministic replay。可复现则更偏数据/forward/numerical；不可复现或多个 batch 持续异常，则检查 optimizer state、并行同步和硬件。修复后用小范围 replay/回归证明根因。

## 4. 深度展开

### Loss Spike 故障树
```text
First bad step
├─ same batch replay reproduces?
│  ├─ yes → data / deterministic numerical path
│  └─ no  → state / distributed / hardware / nondeterminism
├─ one rank first or all ranks together?
├─ forward first or backward first?
├─ which layer/tensor first diverges?
└─ rollback + controlled ablation → causal fix
```
第一目标不是“把 loss 压回去”，而是找到**第一个异常事件**。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：建立自动 anomaly snapshot：异常 step 把 batch hash 与关键 tensor stats 落盘。
2. **动作 2**：先恢复到 spike 前 checkpoint 做受控复现，避免在昂贵 full run 上试错。
3. **动作 3**：每次只改变一个变量：skip batch、lower LR、disable node、换数据 shard。

### 故障可复现闭环

锁定 first bad step，保存 batch/rank/RNG/checkpoint，执行 deterministic replay，再用最小变量实验定位根因。

- 先定位，不要先“调参试试”。
- 保留正常 step 对照。
- 修复后做回归与长期稳定性验证。
