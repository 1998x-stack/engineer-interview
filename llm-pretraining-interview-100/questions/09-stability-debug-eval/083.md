# Q083. Gradient Norm 突然变大意味着什么？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[训练稳定性、Debug 与评测](./README.md)

## 1. 面试官为什么问

考察是否会从单一指标跳到联合诊断。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **first bad event**：能否定位第一个异常 step/rank/tensor？
- **可复现**：同 checkpoint+batch 是否重现？
- **因果验证**：修复是否有最小变量对照和回归？

## 2. 30 秒结论

> Grad norm 是烟雾报警器；先定位哪间房起火。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

Grad norm 升高可能来自真正的 gradient explosion，也可能是一个罕见高损失 batch、sequence/domain 切换、router imbalance、activation scale drift 或某层数值异常。单点指标不能直接给根因。

### 3.2 关键 Trade-off / 边界

应联合看 loss、per-layer grad norm、activation RMS、parameter/update norm、data metadata，并判断异常是全局还是集中在某层/某 expert。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**Grad norm 是烟雾报警器；先定位哪间房起火。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：保存 global + layerwise grad stats。
2. **动作 2**：对 spike step 做 top-k layer/module 排名。
3. **动作 3**：检查 clipping 前后 norm，避免 clipping 隐藏长期异常。

### 故障可复现闭环

锁定 first bad step，保存 batch/rank/RNG/checkpoint，执行 deterministic replay，再用最小变量实验定位根因。

- 先定位，不要先“调参试试”。
- 保留正常 step 对照。
- 修复后做回归与长期稳定性验证。

## 7. 常见失分点：为什么错

- ❌ **看到 grad norm 高就立即加大 clipping。**
  - 改进：回到“Grad norm 是烟雾报警器；先定位哪间房起火。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
