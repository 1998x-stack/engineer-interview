# Q090. 如何定义一个预训练模型“训练成功”？

> **定位**：B 类等价追问题 · 难度 **中** · 频率 **★★★★☆**
> 章节：[训练稳定性、Debug 与评测](./README.md)

## 1. 面试官为什么问

开放题，考察目标函数以外的完整成功标准。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **first bad event**：能否定位第一个异常 step/rank/tensor？
- **可复现**：同 checkpoint+batch 是否重现？
- **因果验证**：修复是否有最小变量对照和回归？

## 2. 30 秒结论

> 预训练成功 = 质量达标、预算可控、系统可靠、结果可信。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

至少包含五类：optimization 稳定收敛；capability 达到目标 benchmark/held-out loss；generalization 覆盖关键 domain；efficiency 满足 tokens/s、MFU、成本预算；reliability 没有不可接受的污染、记忆与恢复风险。

### 3.2 关键 Trade-off / 边界

“成功”必须相对项目目标和 compute budget 定义。一个 loss 更低但多花 2 倍成本、推理难部署的模型未必是更成功的产品。

## 4. 深度展开：从定义走向 Production

本题的深挖重点是：**预训练成功 = 质量达标、预算可控、系统可靠、结果可信。**

建议沿下面的因果链继续展开：

1. **定义/状态语义**：先把对象、tensor、数据分布或训练状态说准确；
2. **机制**：解释为什么该设计会改变 loss、memory、FLOPs、通信或稳定性；
3. **代价**：指出它牺牲了什么，不把工程 trick 说成“免费午餐”；
4. **可验证性**：说明你会用什么指标、profile 或 ablation 判断结论是否成立；
5. **规模化边界**：把 1 GPU/小模型结论推进到千卡、长序列或 MoE 场景。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：项目立项时预先写 success criteria，而不是训练后挑指标。
2. **动作 2**：同时保留质量、成本、风险三个 dashboard。
3. **动作 3**：做 baseline 与同预算比较。

### 故障可复现闭环

锁定 first bad step，保存 batch/rank/RNG/checkpoint，执行 deterministic replay，再用最小变量实验定位根因。

- 先定位，不要先“调参试试”。
- 保留正常 step 对照。
- 修复后做回归与长期稳定性验证。

## 6. 高频追问与回答方向

### 追问 1：能力与成本冲突时怎么选？

**回答方向**：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

### 追问 2：什么时候应该提前停止训练？

**回答方向**：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

### 追问 3：如何定义 data-quality success？

**回答方向**：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

## 7. 常见失分点：为什么错

- ❌ **只回答“benchmark 更高”。**
  - 改进：回到“预训练成功 = 质量达标、预算可控、系统可靠、结果可信。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。

## 8. 面试评分 Rubric

| 层级 | 表现 |

| 1 — 基础 | 能复述：预训练成功 = 质量达标、预算可控、系统可靠、结果可信。 |
