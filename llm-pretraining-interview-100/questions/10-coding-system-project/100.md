# Q100. 你在预训练项目中真正解决的最难问题是什么？

> **定位**：A 类高频真题型 · 难度 **难** · 频率 **★★★★★**
> 章节：[手撕、系统设计与项目拷打](./README.md)

## 1. 面试官为什么问

终局题：检验研究闭环、工程深度、所有权和量化结果。

这道题真正区分的是：**能否把“知道概念”推进到“解释机制、量化成本、落到训练系统并设计验证”**。

### 本题的三层观察镜

- **正确性**：代码/公式/系统是否在边界条件下仍正确？
- **量化**：参数、显存、吞吐、成本是否可手算/实测？
- **证明**：项目贡献是否有对照实验和可归因结果？

## 2. 30 秒结论

> 最强项目回答不是“我解决了什么”，而是“我怎样证明为什么它坏、为什么这个修复有效”。

30 秒版本的目标不是覆盖所有细节，而是先给出**正确结论 + 最关键因果关系**，让面试官知道你掌握主线。

## 3. 3 分钟标准回答

### 3.1 核心机制

推荐用 Observation → Hypothesis → Experiment → Root Cause → Fix → Ablation → Quantitative Result 讲述。先给异常现象和业务/训练成本，再列 2-3 个竞争假设；说明你用什么 profile/replay/对照实验排除它们，最后给根因。

### 3.2 关键 Trade-off / 边界

修复后必须有回归：质量是否保持？tokens/s、MFU、显存、故障率改善多少？若只是“改了配置然后好了”，说明因果证据仍不够。

## 4. 深度展开

### 项目拷打的黄金结构
**Observation → Hypothesis → Instrumentation/Experiment → Root Cause → Fix → Ablation → Quantitative Result → What I would do next**。

“难”不是故事性，而是因果链是否完整。最好准备至少一个算法问题和一个系统问题：前者体现研究判断，后者体现大规模训练工程能力。

## 5. Know-how：如何落到实现与训练系统

1. **动作 1**：提前准备至少三个故事：数据、训练稳定性、系统性能各一个。
2. **动作 2**：每个故事控制在 3 分钟主线，追问时再展开技术细节。
3. **动作 3**：量化 before/after，并说明实验控制变量。

### 白板到 Production

要求答案同时包含正确性、复杂度、测试、边界条件、工程约束和量化结果。

- 代码题写 shape/assert/unit test。
- 设计题先声明约束。
- 项目题必须给数字和对照。

## 6. 高频追问与回答方向

### 追问 1：你如何证明这就是 root cause？

**回答方向**：给出可执行步骤，并补充至少一个可观测指标和一个对照实验，避免只给概念。

### 追问 2：有没有更便宜的替代方案？

**回答方向**：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

### 追问 3：这个经验能迁移到更大模型吗？

**回答方向**：回到定义、数学/状态语义、工程代价和可验证实验四层作答。

## 7. 常见失分点：为什么错

- ❌ **讲成流水账，没有竞争假设。**
  - 改进：回到“最强项目回答不是“我解决了什么”，而是“我怎样证明为什么它坏、为什么这个修复有效”。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。
- ❌ **只有“结果更好”，没有等成本/回归实验。**
  - 改进：回到“最强项目回答不是“我解决了什么”，而是“我怎样证明为什么它坏、为什么这个修复有效”。”这一主线，并补充可量化的状态/公式/实验，而不是只给结论。

## 8. 面试评分 Rubric

| 层级 | 表现 |
|---|---|
| 0 — 不合格 | 只会名词或结论，定义/公式/状态语义存在明显错误。 |
| 1 — 基础 | 能复述：最强项目回答不是“我解决了什么”，而是“我怎样证明为什么它坏、为什么这个修复有效”。 |
| 2 — 良好 | 能解释 Why + How，回答至少一个追问，并指出主要 trade-off。 |
| 3 — 强 | 能手算/画通信或数据流/给出实验设计，把算法与系统联系起来。 |
| 4 — 研究/Production | 能说明失效边界、诊断指标、等成本对照和规模化约束，并结合真实项目给数字。 |

## 9. 自测与白板练习

闭卷完成下面练习，建议每题控制在 5–10 分钟：

1. 你如何证明这就是 root cause？
2. 有没有更便宜的替代方案？
3. 这个经验能迁移到更大模型吗？
4. 把答案写成可运行代码/可核算公式/可量化项目复盘之一。

## 10. 一句话记忆

> **最强项目回答不是“我解决了什么”，而是“我怎样证明为什么它坏、为什么这个修复有效”。**

### 深挖关键点

建议把这一题录音练 10 次：任何“我们觉得/应该是”都替换成可观测证据或受控实验。

## 11. 题源与可信度说明

公开面经中出现或高度近似的高频题型；题干在本项目中做了规范化重写。

> 本项目将“公开面经题型”和“能力等价追问题”明确分开；公开面经用于观察招聘分布，不视为公司官方试卷。
