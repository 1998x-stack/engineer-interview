# 真实性、来源与“真题”口径

## 1. 本仓库不是什么

本仓库不是任何公司的内部题库，也不声称拥有未公开面试题。对于无法验证的公司内部来源，不使用“官方真题”“内部原题”之类表述。

## 2. “公开题型”的定义

本项目中的“公开题型”主要来自：

- 公开候选人面试经验；
- 开源 NLP / ML Interview 题库；
- 公开职位能力描述；
- 多家公司算法面试中长期重复出现的经典问题；
- 论文 / 官方文档对应的高频原理题。

为了形成可学习知识体系，Repo 会对不同公开问法进行统一、重写和结构化，因此题目措辞不应理解为某一家公司的逐字原题。

## 3. PDF 基线与 v2 扩展如何区分

- `assets/pdf/`：v1.0 PDF 基线；
- `sources/questions_raw/`：从 PDF 提取的逐题原始文本；
- 每题第 3–5 节：尽量保留 PDF 的核心答案 / Know-Why；
- `data/deepdives_v2.mdpack`：v2.0 新增的逐题专业深挖；
- 每题第 6–7 节：扩展原理、边界、工程和验证；
- `references.md`：经典论文 / 官方项目入口。

## 4. 扩展内容的原则

扩展时优先：

1. 不改变 PDF 原题核心结论；
2. 对公式给出假设和变量含义；
3. 对系统设计给出资源/工程边界；
4. 对经验性结论避免写成数学定理；
5. 对有版本敏感性的实现细节优先链接官方文档 / 原论文；
6. 对无法从来源验证的公司归属不做强化声明。

## 5. 如何提交事实修正

若发现：

- 公式错误；
- 论文引用错误；
- 过时实现；
- 公司题型来源表述过强；
- 代码与当前框架行为不一致；

建议提交 Issue / PR，并给出论文、官方文档或可复现实验依据。
