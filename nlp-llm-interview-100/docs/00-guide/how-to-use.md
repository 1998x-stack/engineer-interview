# 如何使用这 100 道题

这套题库不是按照“读完 = 学会”设计的。真正的目标是把每道题训练成一个可以在面试现场稳定调用的 **知识单元**：先有短答案，再能推导，再能处理追问和工程约束。

---

## 1. 三层回答法

### Level 1 — 30–60 秒

只回答三个东西：

1. **它是什么**；
2. **核心公式 / 机制是什么**；
3. **为什么要这样设计**。

示例：问 RoPE，不要从 Transformer 历史开始讲，而应先说：

> RoPE 对 Q/K 做位置相关二维旋转，因为 $R_m^TR_n=R_{n-m}$，所以相对位移自然进入 QK 点积。

### Level 2 — 2–3 分钟

在 Level 1 基础上增加：

- 一个公式推导 / tensor shape；
- 一个 trade-off；
- 一个 failure mode；
- 一个实现或复杂度结论。

### Level 3 — 连续追问

面试官继续深入时，回答应切到：

- 训练和推理是否一样？
- 数值上哪里会炸？
- 大规模系统里的瓶颈是什么？
- 上一个方法哪里不够？
- 有没有反例？
- 怎么证明你的实现是对的？

---

## 2. 每题的推荐学习顺序

不要从第 1 节顺着读到最后。更高效的顺序是：

```text
题目
 ↓
30–60 秒标准回答
 ↓
白板公式 / 结构
 ↓
闭卷复述
 ↓
第一性原理 / 专业深挖
 ↓
高频失分点
 ↓
追问树
 ↓
工程验证
```

第一次读题时先不要看“专业深挖”，否则容易产生“看懂了”的错觉。

---

## 3. 五种题型，五种答法

### A. 数学 / 概率题

必须回答：

- 随机变量是什么？
- 假设是什么？
- 目标函数从哪里来？
- 最后公式的概率解释是什么？

典型：Q001、Q003、Q010、Q012。

### B. 模型结构题

必须回答：

- 输入 / 输出 shape；
- 关键矩阵或状态；
- 为什么需要这个模块；
- 对训练 / 推理的影响。

典型：Q035、Q043、Q050、Q064。

### C. 算法 / 检索题

必须回答：

- Exact 还是 Approximate？
- 时间 / 空间复杂度；
- Recall / Precision trade-off；
- 索引和更新成本。

典型：Q021、Q079、Q080、Q086。

### D. 系统设计题

先画 Pipeline，再讨论模块。

至少写：

```text
Input
 ↓
Stage 1
 ↓
Stage 2
 ↓
State / Cache / Index
 ↓
Metric + Monitoring
```

典型：Q084、Q085、Q094、Q096。

### E. Coding / Debug 题

顺序必须是：

1. 写 reference；
2. 写不变量；
3. 写边界测试；
4. 再优化。

典型：Q097–Q100。

## 4. 不建议的刷题方式

### 只读，不闭卷

阅读产生 recognition，不等于 recall。面试需要的是无提示提取。

### 只背结论

“RoPE 是相对位置编码”“GQA 省 KV Cache”“DPO 不需要 RM”都只是标题，不是答案。

### 只写公式，不解释变量

公式必须连接到模型行为或系统资源，否则很容易在追问中断裂。

### 只说优点

高阶面试一定会问：代价呢？什么时候失败？为什么不选另一个？

### 把“当前主流”说成“理论最优”

技术选择高度依赖数据规模、硬件、延迟、质量目标和训练预算。

---

## 5. 主动检索练习

每完成 10 题，做一次随机复盘：

- 随机抽 5 题；
- 每题 60 秒；
- 不允许看题解；
- 每题必须给一个 trade-off；
- 至少 2 题写白板公式或 shape。

建议评分：

| 分数 | 标准 |
|---:|---|
| 0 | 不知道 / 结论错误 |
| 1 | 只会一句定义 |
| 2 | 有结论和公式，但 Why 弱 |
| 3 | 能解释 Why 和 trade-off |
| 4 | 能处理边界、实现、追问 |
| 5 | 能连接真实系统并设计验证 |

目标不是所有题都 5 分，而是高频 ★★★★ / ★★★★★ 题稳定达到 4 分以上。

---

## 6. 一道题什么时候算真正掌握

满足下面至少 6 项：

- [ ] 60 秒内给出正确结论；
- [ ] 能写核心公式 / shape；
- [ ] 能解释为什么；
- [ ] 能说一个 trade-off；
- [ ] 能给一个失败模式；
- [ ] 能回答两个追问；
- [ ] 能写最小实现 / 伪代码；
- [ ] 能设计一个验证实验；
- [ ] 能连接至少两道关联题。

---

## 7. 推荐循环

```text
阅读
→ 合上答案复述
→ 白板推导
→ 追问
→ 代码 / 系统化
→ 隔天检索
→ 一周后随机复习
```

把“不会的题”记录成错误簿，比继续刷新题更重要。
