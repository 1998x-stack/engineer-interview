# Q021 BM25 相比 TF‑IDF 改进了什么？

## 1. 题目

BM25 中 k1 与 b 分别控制什么？为什么要做 TF saturation 和文档长度归一化？

## 2. 面试官到底在考什么

搜索与 RAG 的核心基础题。

### 评分维度

- 先说模型建模对象与条件独立假设。
- 能写出动态规划/打分函数并解释复杂度。
- 能和神经网络/LLM 时代方案比较适用边界。

## 3. 30-60 秒标准回答

BM25 认为词频收益应递减，并根据文档长度相对平均长度做归一化。k1 控制 TF 饱和速度，b 控 制长度归一化强度。

## 4. 白板核心公式

- $\mathrm{BM25}(D,Q)=\sum_{q\in Q}\mathrm{IDF}(q)\frac{f(q,D)(k_1+1)}{f(q,D)+k_1(1-b+b|D|/\mathrm{avgdl})}$

## 5. 第一性原理与 Know-Why

- **PDF 基线要点**：同一个 query term 出现 20 次不应比 2 次“重要十倍”。
- **PDF 基线要点**：长文更容易偶然包含查询词，需长度校正。
- **PDF 基线要点**：BM25 对实体、数字、稀有术语往往非常强，因此现代 RAG 常保留 sparse retrieval。
- **扩展理解**：BM25 的两大改进是 TF saturation 与文档长度归一化。
- **扩展理解**：k1 控制 TF 饱和速度，b 控制长度归一化强度，参数含义比背公式更重要。
- **扩展理解**：BM25 在实体、数字、专名检索上常是强基线，应与 dense retrieval 互补。

## 6. 专业深挖：原理、边界与工程

### BM25 的两个关键修正
- $k_1$ 控制 TF 饱和：词从出现 1 次到 2 次很重要，从 100 次到 101 次不应继续线性加分；当 tf 很大时贡献趋于上界。
- $b$ 控制文档长度归一化：长文更容易偶然包含 query term，同样 tf 在超长文中应被适度折扣。
- BM25 仍是词面模型，因此对精确实体和新词非常强；现代 RAG 常用 BM25 + dense 做互补召回。
### 边界与工程
- $k_1,b$ 没有统一最优值；标题、正文、短 chunk、长文档可能需要不同配置或 BM25F。
- Chunking 会直接改变 |D| 和 avgdl，因此切块策略与 BM25 排名强耦合。
- Hybrid 不建议直接把 BM25 raw score 和 cosine 按 0.5/0.5 相加；RRF 或经过校准的 fusion 更稳。

## 7. 实现、复杂度与工程验证

- 给出状态/标签空间、独立性假设和训练/解码复杂度。
- 区分局部 score、全局归一化与解码约束。
- 真实 NLP 数据要考虑 OOV、标注规范、领域词典和 span 对齐。

### 推荐验证清单

- **Correctness**：与最小 reference/手算结果对拍。
- **Numerics**：加入极端输入、低精度与长序列测试。
- **Complexity**：同时写时间、空间以及关键系统资源。
- **Ablation**：只改变一个设计变量，固定数据/compute/评测口径。
- **Slices**：不要只看总体均值，检查长尾、长度、语言/领域或 hard cases。

## 8. 高频失分点

- 把 BM25 说成“加权 TF-IDF”而无细节。
- 忘记 query term 可累加。
