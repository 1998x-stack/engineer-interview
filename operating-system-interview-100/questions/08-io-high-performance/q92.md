# Q92 为什么 HDD 时代的 Disk Scheduling 在 SSD 上重要性下降？

> **一句话核心结论**：HDD 延迟高度受机械 seek/rotation 影响，因此 SSTF、SCAN 等算法通过重排请求减少磁头移动；SSD 没有机械寻道，这一目标显著弱化。

## 1. 为什么面试官喜欢问这题

这道题不是单独考一个名词，而是在检查候选人是否能把 **SSTF → SCAN → SSD → NVMe** 放进完整的操作系统因果链。优秀回答应同时覆盖：概念边界、底层机制、Why、trade-off，以及至少一个 Linux/工程落点。

## 2. 核心结论（原 PDF）

HDD 延迟高度受机械 seek/rotation 影响，因此 SSTF、SCAN 等算法通过重排请求减少磁头移动；SSD 没有机械寻道，这一目标显著弱化。

## 3. 深度解析（原 PDF）

SSD/NVMe 更关注队列深度、并行通道、尾延迟、公平性、写放大和设备内部 FTL。现代 block layer 调度器目标因此从“减少磁头移动”转向更综合的 latency/fairness/merging。

## 4. 仓库增强：从机制而不是术语理解

- 先区分 readiness 与 completion，再讨论 select/poll/epoll/io_uring；这比背 API 差异更能应对追问。
- I/O 性能是 queueing、copy、syscall、context switch、interrupt/DMA 与设备并行度共同决定的。
- 所谓 zero-copy 通常是减少 CPU 参与的内存复制，不代表数据在硬件中从未移动。

### 9.2 机制级推演：把每一步说清楚

面试中建议先给出这一条**总调用链**：

```text
submission/readiness → kernel queue → device/DMA → completion → event loop
```

再展开本题的具体状态变化：

1. HDD随机I/O包含机械seek和旋转延迟。
2. 调度器重排相邻请求可显著减少机械移动。
3. SSD无机械头，随机访问差距缩小。
4. 现代NVMe可并行处理深队列。
5. 调度重点转向公平、延迟、合并、QoS与设备并发。

> **关键不变量**：SSD上调度器并非“完全没用”；公平性、限速和合并仍有价值。

### 9.3 性能模型：不要只说“快/慢”

HDD关注seek/顺序性；SSD/NVMe关注queue depth、tail latency、write amplification和controller parallelism。

建议在回答中至少显式区分下面四类成本：

| 成本类型 | 本题应该追问什么 |
|---|---|
| CPU | 是否存在额外指令、扫描、copy、原子重试、内核路径？ |
| Cache / TLB | 是否破坏局部性、触发 cache-line migration、TLB miss/shootdown？ |
| 调度 / 等待 | 是否会 sleep/wakeup、context switch、排队、throttling？ |
| I/O / 持久化 | 是否会触发设备访问、writeback、flush、network round trip？ |

**面试技巧**：如果不能定量到具体纳秒，也不要编数字。更专业的表达是给出“成本由哪些变量决定”，并说明要通过 benchmark/perf/trace 在目标机器上验证。

不要试图背完整源码。先沿对象关系找到“状态放在哪里、谁改变它”。

| 对象 / 接口 | 阅读重点 |
|---|---|
| `blk-mq` | 沿调用链确认它保存的状态、引用关系、快/慢路径以及可从用户态观察到的结果。 |

### 9.5 边界条件、反例与“不要这样回答”

- **本题最重要边界**：SSD上调度器并非“完全没用”；公平性、限速和合并仍有价值。
- 不要把“常见实现”说成“POSIX/硬件永远保证”；架构、文件系统、内核版本和配置都可能改变细节。
- 不要把**机制存在**等同于**性能一定更好**。只有 workload、竞争度、数据规模和硬件条件确定后，性能结论才成立。
- 不要跳过错误路径：权限失败、资源耗尽、超时、signal、进程退出、设备错误等经常是高级追问来源。

### 9.10 90 秒高级回答：把定义、机制、性能和边界连成一段

> **可直接口述的参考结构**：
> 
> HDD 延迟高度受机械 seek/rotation 影响，因此 SSTF、SCAN 等算法通过重排请求减少磁头移动；SSD 没有机械寻道，这一目标显著弱化。机制上，我会把它拆成：HDD随机I/O包含机械seek和旋转延迟；调度器重排相邻请求可显著减少机械移动；SSD无机械头，随机访问差距缩小；现代NVMe可并行处理深队列；调度重点转向公平、延迟、合并、QoS与设备并发。性能上，HDD关注seek/顺序性；SSD/NVMe关注queue depth、tail latency、write amplification和controller parallelism。 Linux/工程实现上要关注 `blk-mq / none|mq-deadline|bfq schedulers / NVMe queues`。最后我会主动补充边界：SSD上调度器并非“完全没用”；公平性、限速和合并仍有价值。 这样回答的重点不是堆术语，而是让面试官看到“语义 → 状态变化 → 成本 → 实现 → 边界”的完整因果链。

### 9.11 如何把这道题做成一个小型系统实验

把实验设计成 **hypothesis → variable → observation → falsification** 四步：

1. **Hypothesis**：先写一句可证伪假设，例如“当某个关键资源/路径进入慢路径时，本题描述的成本会显著上升”。
2. **Independent variable**：只改变一个变量，例如并发度、工作集大小、CPU affinity、I/O 深度、cache 冷热、cgroup limit。
3. **Observation**：同时记录业务结果与 OS 证据，至少包含延迟/吞吐中的一个，以及本题对应的 kernel counter/trace。
4. **Falsification**：如果指标没有按预期变化，不要修改结论去迎合结果；检查是否测错层、是否被缓存/批处理掩盖、是否实际没有进入目标慢路径。

**实验报告最少应包含**：

```text
环境：kernel / CPU / memory / filesystem / container limits
负载：输入规模 / 并发 / 持续时间
变量：本轮只改变什么
结果：throughput / avg / P95 / P99（按适用场景选择）
OS证据：perf / proc / PSI / iostat / strace / tracepoint 中相关指标
结论：支持还是推翻原假设
```
