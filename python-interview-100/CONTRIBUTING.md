# Contributing

感谢对题库的改进。

## 内容 PR 最低要求

1. 指明修改的题号，例如 `Q63`。
2. 版本敏感结论必须给 Python 官方文档或 PEP。
3. 新增代码应尽量是最小可运行示例。
4. 明确区分语言规范、CPython 实现、工程经验。
5. 不提交无法核验来源的“某公司内部原题”描述。
6. 修改后运行：`python scripts/validate_repo.py`。

## Markdown 结构

每个题目文件至少保留：

- 题目定位
- 30-60 秒标准回答
- 原理拆解
- 易错点 / Gotchas
- 工程实践检查表
- 面试官连续追问
- 举一反三
- 自测标准
- 参考资料
