# Q16. 为什么实现 __eq__ 后必须认真考虑 __hash__？

> **难度**：★★★  ·  **频率**：高  ·  **关键词**：`data model`, `equality`, `hash contract`

## 30-60 秒标准回答

> 哈希容器依赖契约：若 a == b，则 hash(a) 必须等于 hash(b)。违反契约会让“逻辑上相等”的对象落到不同查找路径。

## 最小可运行实验

```python
class UserKey:
    def __init__(self, uid): self.uid = uid
    def __eq__(self, other):
        return isinstance(other, UserKey) and self.uid == other.uid
    def __hash__(self):
        return hash(self.uid)
```

### 实验怎么读

代码共 6 个非空行，建议逐行观察“名字绑定/对象状态/控制流”的变化，而不是只看最终输出。 类相关示例建议配合 `type()`、`__dict__`、`__mro__` 或 descriptor 方法调用顺序观察。

### 1. 机制链路：这道题到底在系统的哪一层发生？

哈希表要求相等对象具有相同 hash；Python 在用户定义 __eq__ 时会对 __hash__ 做保护性处理，避免轻易创建错误契约。

### 2. 边界条件：什么时候“标准答案”会失效？

“hash 不同一定不等”可用于快速排除，但 hash 相同不代表对象相等；碰撞必须由 equality 区分。

面试中主动给出边界，通常比多背三个 API 更能体现成熟度。可以使用下面的句式：
