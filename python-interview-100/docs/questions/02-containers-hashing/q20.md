# Q20. 浅拷贝和深拷贝有什么区别？

> **难度**：★★  ·  **频率**：极高  ·  **关键词**：`copy`, `aliasing`, `deepcopy`

## 题目定位

判断候选人能否把容器 API 与底层数据结构、复杂度和哈希契约连接起来。

### 面试官真正想确认什么

本题的中心不是记忆一个结论，而是建立 **copy / aliasing / deepcopy** 的可推导模型。回答容器题时，必须同时给出数据结构、典型复杂度、语义约束与内存代价；不要只背 API。 面试时建议先给结论，再说明边界条件，最后用一个最小例子证明自己的解释。

这类题的高分标准通常不是“知道答案”，而是能在 30-60 秒内先给清晰结论，并在追问时继续下钻到机制、边界和工程代价。

## 30-60 秒标准回答

> 浅拷贝创建新的外层容器，但通常复用内部对象引用；深拷贝会递归复制可复制的对象图，并维护 memo 处理共享引用/循环。

## 高分回答的四层结构

- **第一层 - 结论**：浅拷贝创建新的外层容器，但通常复用内部对象引用；深拷贝会递归复制可复制的对象图，并维护 memo 处理共享引用/循环。
- **第二层 - 原因**：挑选“原理拆解”中的 2-3 个关键点解释为什么，而不是重复定义。
- **第三层 - 边界**：主动说出至少一个 Gotcha，证明你知道结论并非无条件成立。
- **第四层 - 工程化**：把结论落到 API 设计、性能、并发、可维护性或调试策略。

## 最小可运行实验

```python
import copy
a = [[1], [2]]
b = copy.copy(a)
c = copy.deepcopy(a)
a[0].append(9)
print(b)  # [[1, 9], [2]]
print(c)  # [[1], [2]]
```

### 实验怎么读

代码共 7 个非空行，建议逐行观察“名字绑定/对象状态/控制流”的变化，而不是只看最终输出。 运行时先预测输出，再执行验证；预测错误的地方通常就是心智模型缺口。

### 1. 机制链路：这道题到底在系统的哪一层发生？

浅拷贝复制最外层容器结构但复用内部对象引用；深拷贝递归复制对象图并用 memo 处理共享引用/循环。

建议面试时把机制画成一条因果链，而不是堆术语：

```text
输入 / 语法 / API
        ↓
协议或对象模型
        ↓
CPython/标准库实现路径
        ↓
可观察行为
        ↓
性能、正确性与工程后果
```

对于 **Q20. 浅拷贝和深拷贝有什么区别？**，高分回答的关键是指出上面每一层之间的因果关系，并明确哪些属于语言保证，哪些只是当前 CPython 的实现选择。

### 2. 边界条件：什么时候“标准答案”会失效？

deepcopy 不等于“序列化后重建”，也不保证所有资源可复制；文件、socket、锁等对象有特殊限制。

面试中主动给出边界，通常比多背三个 API 更能体现成熟度。可以使用下面的句式：

> “这个结论在 ___ 前提下成立；如果换成 ___，需要重新评估 ___。”

这样可以避免把“平均复杂度”“默认 CPython”“当前标准库实现”说成绝对规律。

### 3. 成本模型：不要只说对错，还要说代价

容器题必须同时回答**时间复杂度、空间成本、常数因子与退化条件**。平均 O(1) 不等于最坏 O(1)，摊还 O(1) 不等于每次 O(1)。

回答成本问题时至少考虑以下维度：

| 维度 | 应回答的问题 |
|---|---|
| 正确性 | 是否有隐藏副作用、竞态、生命周期或协议约束？ |
| 时间 | 单次、平均、摊还、最坏复杂度分别是什么？ |
| 空间 | 是否复制、缓存、持有对象或制造峰值内存？ |
| 可维护性 | 行为是显式 API 还是隐藏在 magic method / decorator / runtime hook 中？ |
| 可移植性 | 结论属于 Python 语言规范、CPython，还是某个平台/第三方库？ |

### 4. 生产工程场景

配置快照可用 immutable/浅拷贝；复杂对象图应优先明确 ownership，而不是用 deepcopy 掩盖共享状态设计问题。

一个合格的工程回答不应停在“可以/不可以”，而应给出**选择依据**。推荐使用：

需求约束 → 候选方案 → 成本/风险 → 观测指标 → 回退方案
