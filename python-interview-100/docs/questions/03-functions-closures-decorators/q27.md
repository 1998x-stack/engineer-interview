# Q27. 为什么 decorator 通常需要 functools.wraps？

> **难度**：★★  ·  **频率**：高  ·  **关键词**：`wraps`, `metadata`, `introspection`

## 题目定位

判断候选人是否理解函数对象、作用域与调用包装，而不仅会写装饰器模板。

### 面试官真正想确认什么

本题的中心不是记忆一个结论，而是建立 **wraps / metadata / introspection** 的可推导模型。所有函数机制题都问两个时间点：定义时发生什么、调用时发生什么。闭包、默认参数、装饰器、缓存都能用这个框架统一。 面试时建议先给结论，再说明边界条件，最后用一个最小例子证明自己的解释。

这类题的高分标准通常不是“知道答案”，而是能在 30-60 秒内先给清晰结论，并在追问时继续下钻到机制、边界和工程代价。

## 30-60 秒标准回答

> `functools.wraps` 让 wrapper 保留被包装函数的重要元数据，并设置 `__wrapped__`，便于 introspection、调试、文档和某些框架正确工作。

## 高分回答的四层结构

所有函数机制题都问两个时间点：定义时发生什么、调用时发生什么。闭包、默认参数、装饰器、缓存都能用这个框架统一。

## 最小可运行实验

```python
from functools import wraps

def deco(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper
```

### 实验怎么读

代码共 6 个非空行，建议逐行观察“名字绑定/对象状态/控制流”的变化，而不是只看最终输出。

### 2. 边界条件：什么时候“标准答案”会失效？

wraps 不会自动让 wrapper 的真实调用语义与原函数完全一致；类型系统还需 ParamSpec/TypeVar 等表达。

面试中主动给出边界，通常比多背三个 API 更能体现成熟度。可以使用下面的句式：

> “这个结论在 ___ 前提下成立；如果换成 ___，需要重新评估 ___。”
