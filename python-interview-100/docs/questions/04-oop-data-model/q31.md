# Q31. __new__ 和 __init__ 有什么区别？

> **难度**：★★★  ·  **频率**：高  ·  **关键词**：`object creation`, `__new__`, `__init__`

## 题目定位

判断候选人是否理解 Python 对象模型与属性查找协议，能否处理框架/ORM/元编程问题。

### 面试官真正想确认什么

本题的中心不是记忆一个结论，而是建立 **object creation / __new__ / __init__** 的可推导模型。把属性访问看作协议而非“点号语法”。descriptor、MRO、super、metaclass 都是在控制对象模型中的查找与构造流程。 面试时建议先给结论，再说明边界条件，最后用一个最小例子证明自己的解释。

这类题的高分标准通常不是“知道答案”，而是能在 30-60 秒内先给清晰结论，并在追问时继续下钻到机制、边界和工程代价。

## 30-60 秒标准回答

> `__new__` 负责创建/返回实例；`__init__` 接收已经创建的实例并初始化它。不可变类型的定制通常要在 __new__ 阶段决定最终值。

## 高分回答的四层结构

- **第一层 - 结论**：`__new__` 负责创建/返回实例；`__init__` 接收已经创建的实例并初始化它。不可变类型的定制通常要在 __new__ 阶段决定最终值。
- **第二层 - 原因**：挑选“原理拆解”中的 2-3 个关键点解释为什么，而不是重复定义。
- **第三层 - 边界**：主动说出至少一个 Gotcha，证明你知道结论并非无条件成立。
- **第四层 - 工程化**：把结论落到 API 设计、性能、并发、可维护性或调试策略。

### 1. `__init__` 不是构造函数意义上的“分配对象”步骤，也不应返回其它值。

## 最小可运行实验

```python
class PositiveInt(int):
    def __new__(cls, value):
        value = max(0, int(value))
        return super().__new__(cls, value)
```

### 实验怎么读

代码共 4 个非空行，建议逐行观察“名字绑定/对象状态/控制流”的变化，而不是只看最终输出。 类相关示例建议配合 `type()`、`__dict__`、`__mro__` 或 descriptor 方法调用顺序观察。

### 1. 机制链路：这道题到底在系统的哪一层发生？

__new__ 负责创建/返回实例，__init__ 只初始化已创建实例；__new__ 可以返回其他类型对象，此时 __init__ 调用规则会变化。

建议面试时把机制画成一条因果链，而不是堆术语：

```text
输入 / 语法 / API
        ↓
协议或对象模型
        ↓
CPython/标准库实现路径
        ↓
可观察行为
        ↓
性能、正确性与工程后果
```

对于 **Q31. __new__ 和 __init__ 有什么区别？**，高分回答的关键是指出上面每一层之间的因果关系，并明确哪些属于语言保证，哪些只是当前 CPython 的实现选择。

### 2. 边界条件：什么时候“标准答案”会失效？

__init__ 必须返回 None；不可变类型定制通常需要在 __new__ 阶段决定值。

面试中主动给出边界，通常比多背三个 API 更能体现成熟度。可以使用下面的句式：

> “这个结论在 ___ 前提下成立；如果换成 ___，需要重新评估 ___。”

这样可以避免把“平均复杂度”“默认 CPython”“当前标准库实现”说成绝对规律。

### 3. 成本模型：不要只说对错，还要说代价

对象模型题的核心成本是**属性查找链和抽象复杂度**。descriptor/metaclass 能力很强，但每增加一层隐式协议都会提高调试和维护成本。

| 维度 | 应回答的问题 |

| 正确性 | 是否有隐藏副作用、竞态、生命周期或协议约束？ |
| 时间 | 单次、平均、摊还、最坏复杂度分别是什么？ |
| 空间 | 是否复制、缓存、持有对象或制造峰值内存？ |

### 4. 生产工程场景

实现不可变 value type、对象池/单例等高级构造策略时才常触碰 __new__；普通业务类优先简单 __init__。

一个合格的工程回答不应停在“可以/不可以”，而应给出**选择依据**。推荐使用：

```text
需求约束 → 候选方案 → 成本/风险 → 观测指标 → 回退方案
```

这会自然把 Python 语法题提升到系统设计和可维护性层面。

### 6. 面试追问：完整回答示范

**追问：如果面试官故意把条件改掉，应该怎么回答？**

追问“为什么 int 子类改值要 __new__”时答：int 对象内容在创建时即固定，__init__ 无法原地改变其数值。

**推荐回答结构：**

1. 先指出新条件改变了哪个前提；
2. 保留仍然成立的语义；
3. 撤回不再成立的实现/性能结论；
4. 给一个最小反例或测量方法。

这种回答方式比“我记得文档说……”更稳健，也更容易应对陌生变体。
