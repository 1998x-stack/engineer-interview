# Q54. weakref 适合解决什么问题？

> **难度**：★★★  ·  **频率**：中  ·  **关键词**：`weakref`, `cache`, `ownership`

## 题目定位

判断候选人是否能区分语言规范和 CPython 实现，并据此诊断内存与导入问题。

## 30-60 秒标准回答

> weak reference 不阻止目标对象被回收，适合缓存、注册表、observer 或 parent pointer 等“不拥有对象”的关系。

## 最小可运行实验

```python
import weakref
class Item: pass
x = Item()
r = weakref.ref(x)
assert r() is x
del x
# r() 之后可能为 None
```

### 实验怎么读

代码共 7 个非空行，建议逐行观察“名字绑定/对象状态/控制流”的变化，而不是只看最终输出。 类相关示例建议配合 `type()`、`__dict__`、`__mro__` 或 descriptor 方法调用顺序观察。

### 3. 成本模型：不要只说对错，还要说代价

### 4. 生产工程场景

对象缓存、插件 registry、父指针常适合 weakref；若业务逻辑必须确保对象存在，就不能只持 weak reference。

一个合格的工程回答不应停在“可以/不可以”，而应给出**选择依据**。推荐使用：
