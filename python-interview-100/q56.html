Q56. sys.getsizeof 为什么不是对象“总内存”？

难度：★★ · 频率：高 · 关键词：getsizeof, shallow size, memory

题目定位

判断候选人是否能区分语言规范和 CPython 实现，并据此诊断内存与导入问题。

面试官真正想确认什么

本题的中心不是记忆一个结论，而是建立 getsizeof / shallow size / memory 的可推导模型。先声明“以下是 CPython 实现细节”。对象生命周期、GC、RSS、import cache 都不能用语言规范层面的结论偷换。 面试时建议先给结论，再说明边界条件，最后用一个最小例子证明自己的解释。

这类题的高分标准通常不是“知道答案”，而是能在 30-60 秒内先给清晰结论，并在追问时继续下钻到机制、边界和工程代价。

30-60 秒标准回答

sys.getsizeof(obj) 主要报告对象自身的浅层大小，不递归统计它引用的其它对象，也不等于进程实际 RSS 增量。

高分回答的四层结构

  • 第一层 - 结论：sys.getsizeof(obj) 主要报告对象自身的浅层大小，不递归统计它引用的其它对象，也不等于进程实际 RSS 增量。
  • 第二层 - 原因：挑选“原理拆解”中的 2-3 个关键点解释为什么，而不是重复定义。
  • 第三层 - 边界：主动说出至少一个 Gotcha，证明你知道结论并非无条件成立。
  • 第四层 - 工程化：把结论落到 API 设计、性能、并发、可维护性或调试策略。

最小可运行实验

import sys
xs = [b'x' * 1000 for _ in range(100)]
print(sys.getsizeof(xs))  # 主要是 list 自身，不含所有 bytes 内容

实验怎么读

代码共 3 个非空行，建议逐行观察“名字绑定/对象状态/控制流”的变化，而不是只看最终输出。 运行时先预测输出，再执行验证；预测错误的地方通常就是心智模型缺口。

1. 机制链路：这道题到底在系统的哪一层发生？

getsizeof 通常报告对象本体的浅层大小并调用 sizeof，不递归统计其引用图，也可能不含第三方 native buffer。

建议面试时把机制画成一条因果链，而不是堆术语：

输入 / 语法 / API
        ↓
协议或对象模型
        ↓
CPython/标准库实现路径
        ↓
可观察行为
        ↓
性能、正确性与工程后果

对于 Q56. sys.getsizeof 为什么不是对象“总内存”？，高分回答的关键是指出上面每一层之间的因果关系，并明确哪些属于语言保证，哪些只是当前 CPython 的实现选择。

2. 边界条件：什么时候“标准答案”会失效？

共享对象若递归求和还会重复计数；“deep size”本身必须定义所有权边界。

面试中主动给出边界，通常比多背三个 API 更能体现成熟度。可以使用下面的句式：

“这个结论在 ___ 前提下成立；如果换成 ，需要重新评估 。”

这样可以避免把“平均复杂度”“默认 CPython”“当前标准库实现”说成绝对规律。

3. 成本模型：不要只说对错，还要说代价

CPython 内存题要区分对象生命周期、Python heap、allocator、native heap 与 OS RSS；import 题要区分查找、编译缓存和模块执行。

回答成本问题时至少考虑以下维度：

维度 应回答的问题
正确性 是否有隐藏副作用、竞态、生命周期或协议约束？
时间 单次、平均、摊还、最坏复杂度分别是什么？
空间 是否复制、缓存、持有对象或制造峰值内存？
可维护性 行为是显式 API 还是隐藏在 magic method / decorator / runtime hook 中？
可移植性 结论属于 Python 语言规范、CPython，还是某个平台/第三方库？

4. 生产工程场景

内存预算应按数据结构整体和生命周期测量，工具可用 tracemalloc、Pympler 等但仍需解释共享关系。

一个合格的工程回答不应停在“可以/不可以”，而应给出选择依据。推荐使用：

需求约束 → 候选方案 → 成本/风险 → 观测指标 → 回退方案

这会自然把 Python 语法题提升到系统设计和可维护性层面。

5. CPython / 标准库源码阅读入口

建议阅读入口： sysmodule.c / object sizeof 协议。

源码阅读不要求面试现场背文件内容，而是要建立三个习惯：

  1. 先从官方文档确定语言/API 契约；
  2. 再去 CPython 源码确认当前实现为什么产生这种成本与行为；
  3. 最后用 dis、inspect、timeit、tracemalloc、最小并发实验等手段做可重复验证。

注意：CPython 内部函数名、文件组织和优化策略可能跨版本变化；源码细节只能用于解释当前实现，不能反向扩大为语言规范。

6. 面试追问：完整回答示范

追问：如果面试官故意把条件改掉，应该怎么回答？

追问“list getsizeof 为什么随元素数量变”时答：它包含内部指针数组 capacity，但不包含每个元素对象深层大小。

推荐回答结构：

  1. 先指出新条件改变了哪个前提；
  2. 保留仍然成立的语义；
  3. 撤回不再成立的实现/性能结论；
  4. 给一个最小反例或测量方法。

这种回答方式比“我记得文档说……”更稳健，也更容易应对陌生变体。

建议实验遵循：
