# Contributing

## 内容原则

1. 优先原论文、官方文档与可验证公开资料。
2. 面经只用于证明问题出现过，不作为模型定义的唯一依据。
3. 每个新增观点尽量落到：假设、机制、工程权衡、验证。
4. 不把 offline metric improvement 写成 online business improvement。
5. 重要数字标明来源和年份。

## Markdown 结构

每题至少保留：题目定位、30 秒回答、深入拆解、工程视角、常见失分、连续追问、相关题目、参考资料。
