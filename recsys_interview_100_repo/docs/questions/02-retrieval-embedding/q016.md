# Q016. 双塔通常怎么训练？InfoNCE 在做什么？

> **难度**：★★★　 **来源标签**：面经高频　 **章节**：第 2 章 · 召回、Embedding、双塔与负采样

## 题目定位

这道题位于 **第 2 章：召回、Embedding、双塔与负采样**。面试官通常希望候选人能给出可落地方案、权衡与验证路径；最终要落到 **模型/数据/系统/指标** 四个层面的约束，而不是停留在术语复述。

**本章主线**：理解候选生成的覆盖率/延迟权衡，以及表示学习、负采样分布与 ANN 索引之间的耦合。

## 30 秒回答

常用对比学习把正样本拉近、负样本推远。InfoNCE 将正 Item 与一组候选负 Item 共同归一化，相当于让模型在候选集合中识别真实正例。

## 深入拆解

训练质量高度依赖负样本集合；网络加深不一定比负采样优化更有效。 相似度可用 dot-product/cosine，temperature 控制 softmax 尖锐程度。 大规模训练可结合 in-batch negatives、跨卡 negatives、memory queue。

### 数学 / 机制补充

典型 InfoNCE / sampled softmax：

$$L=-\log\frac{\exp(s(u,i^+)/\tau)}{\sum_{j\in\mathcal N\cup\{i^+\}}\exp(s(u,j)/\tau)}$$

这里模型结构、负样本分布 $q(j)$、温度 $\tau$ 是耦合的；只调网络而不审视 sampling policy 往往不是工业最优。

### PDF 原始公式 / 工程抓手

`L=-log exp(s(u,i+)/τ) / Σ_j exp(s(u,i_j)/τ)`

## V2 深度版：从“会答”到“能落地”

### 召回系统的第一性原理

召回不是“找相似向量”这么简单，而是在严格 latency/memory 预算下最大化**可排序的有效候选覆盖**。模型、负采样和 ANN 索引三者必须联合设计：

$$\text{Training Distribution}\rightarrow \text{Embedding Geometry}\rightarrow \text{Index Approximation}\rightarrow \text{Online Candidates}$$

任何一环偏移都会让离线 embedding 指标与线上候选质量脱节。面试时应至少区分 **model recall、exact retrieval recall、ANN recall、end-to-end recall**。

### 针对本题的关键推导

InfoNCE 可以视为候选集合上的分类问题，也可看成互信息/对比学习目标的工程化形式。真正决定边界的是 score、temperature、negative distribution 和 correction。

这里建议把回答进一步拆成四层证据链：

1. **定义层**：一句话说明“双塔通常怎么训练？InfoNCE 在做什么？”讨论的对象和优化目标；
2. **机制层**：给出公式、数据生成过程或计算复杂度，解释为什么会有效；
3. **系统层**：指出它在完整推荐链路中的上游输入、下游依赖、成本和失败传播路径；
4. **验证层**：给出 offline slice、线上 A/B、guardrail 与回滚条件。

### 90 秒标准回答（建议练到可以脱稿）

> InfoNCE 可以视为候选集合上的分类问题，也可看成互信息/对比学习目标的工程化形式。真正决定边界的是 score、temperature、negative distribution 和 correction。 具体到工程上，可以用下面的数量级来理解：batch=4096 时，每个正样本天然得到约 4095 个 in-batch negatives；若 8 卡 all-gather，负样本可扩大到约 32767，但通信、热门偏差和 false negative 同时上升。 因此我不会只看单一离线指标，而会把这项方法放回完整链路，联合检查候选/特征分布、P95/P99、成本以及线上主指标。如果出现“离线好、线上差”，我会优先检查数据与 serving 一致性、截断/近似误差和策略覆盖。最后还要说明边界：如果负样本并非从目标分布采样，未做 logQ/importance correction 时，训练出的 score 不应直接解释成真实概率。

这段 90 秒回答的顺序是 **结论 → 机制 → 数量级 → 工程验证 → 边界**。对于大多数推荐算法题，这比从论文历史开始讲更稳。

### 容易混淆的概念

训练负样本 vs 真负反馈；exact retrieval vs ANN retrieval；embedding 相似度 vs 概率；model recall vs route marginal recall。

### 上线验证与监控

分别测 model exact Recall@K、ANN Recall@K、端到端候选命中；线上同时看 candidate count、route overlap、dedup ratio、P99 和超时降级。若换 sampling policy，应做版本隔离而不是直接与旧模型混训。

**建议至少记录这些字段：** positive source、negative source、sampling version、temperature、embedding norm、index version、ANN visited/probe 参数、candidate count、route overlap、retrieval latency。日志字段不是越多越好，关键是能把一次线上曝光追溯到样本、特征、模型、索引和实验版本。

### 一个可用于面试的具体例子

batch=4096 时，每个正样本天然得到约 4095 个 in-batch negatives；若 8 卡 all-gather，负样本可扩大到约 32767，但通信、热门偏差和 false negative 同时上升。

面试里具体数字的价值不是“显得真实”，而是迫使方案满足数量级约束。即使没有真实业务数据，也可以明确说“下面用数量级举例”，然后说明候选数、样本量、维度、QPS 或延迟如何影响设计。

### 工程决策矩阵

| 决策维度 | 典型观测量 |
|---|---|
| 训练 | positive rate、negative source、batch size、temperature |
| 表示 | norm、collapse、类目/兴趣 slice、drift |
| 检索 | exact Recall@K、ANN Recall@K、QPS、P99 |
| 索引 | memory、build/update time、delete/refresh 能力 |
| 线上 | candidate overlap、dedup、route marginal recall |

回答时不要把所有维度都平均展开。先指出当前题目的**第一瓶颈**，再解释为什么其他维度是二阶约束，这会比罗列术语更像真实工程决策。

### 边界条件与反例

如果负样本并非从目标分布采样，未做 logQ/importance correction 时，训练出的 score 不应直接解释成真实概率。

一个强候选人应该主动说明**什么时候不应该使用当前方法**。这能证明你理解的是归纳偏置与业务条件，而不是模型名称。

## 连续追问参考答案

### 追问 1：为什么需要 temperature？

temperature 缩放 logits，控制 softmax 熵与梯度集中度。τ 小会强化 hard negatives 但放大 false negative/噪声；τ 的选择与 embedding norm、batch size、负例难度耦合，应该通过分桶 recall 与训练稳定性调参。

### 追问 2：负例越多越好吗？

不是。更多负例通常提高边界信息，但会有边际收益递减，同时增加 false negatives、热门偏差、通信和显存。应比较 effective negatives：去重后难度分布、正负相似度和每新增 1k 负例的 Recall 增益。

### 追问 3：跨卡 in-batch 会带来什么问题？

跨卡 all-gather 可扩大 negatives，但会带来通信同步、重复 item、跨域 batch distribution 和更高 false-negative 率。工程上常 mask duplicate positives，记录 global batch sampling 分布，并评估通信是否抵消 GEMM 收益。

### 追问 4：sampled softmax 与 InfoNCE 的目标差异是什么？

sampled softmax 目标更接近对巨大类别 softmax 似然的采样近似，通常显式考虑 sampling probability；InfoNCE 更常表述为正例对一组 negatives 的对比分类。工业实现可非常接近，但解释 score/calibration 时要看是否做了 q(i) correction。

### 追问 5：何时需要 logQ correction？

若负样本按 q(i) 被非均匀采样，训练 logits 会混入“容易被采到”的频率。常见做法从 logit 中减去 log q(i)（具体形式依目标而定），校正 sampling prior，使 score 更接近目标分布下的相对偏好。
