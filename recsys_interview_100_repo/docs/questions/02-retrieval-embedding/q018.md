# Q018. In-batch Negative 有什么严重问题？

> **难度**：★★★　 **来源标签**：面经高频　 **章节**：第 2 章 · 召回、Embedding、双塔与负采样

## 题目定位

这道题位于 **第 2 章：召回、Embedding、双塔与负采样**。面试官通常希望候选人能先给定义，再把机制连接到工程后果；最终要落到 **模型/数据/系统/指标** 四个层面的约束，而不是停留在术语复述。

**本章主线**：理解候选生成的覆盖率/延迟权衡，以及表示学习、负采样分布与 ANN 索引之间的耦合。

## 30 秒回答

核心是 False Negative 和 sampling bias：其他用户的正例可能也是当前用户潜在喜欢的 Item，且高频 Item 更容易出现在 batch 中，导致负样本分布偏离目标分布。

## 深入拆解

可用同 ID 去重、已交互 mask、类目/语义近邻软标签、多正例建模。 热门 Item 作为负例出现概率与其采样频率相关，可使用 logQ/importance correction。 更稳妥的是 random + hard + debiased in-batch 混合。

### 数学 / 机制补充

False Negative 的本质是观测标签不完备：没有与当前 user 构成正 pair，并不等价于“用户不喜欢”。当 batch 越大、语义越集中、热门 item 越多时，假负例概率往往上升。

### PDF 原始公式 / 工程抓手

`Observed negative ≠ true negative；训练实际优化的是采样分布下的判别任务。`

## V2 深度版：从“会答”到“能落地”

### 召回系统的第一性原理

召回不是“找相似向量”这么简单，而是在严格 latency/memory 预算下最大化**可排序的有效候选覆盖**。模型、负采样和 ANN 索引三者必须联合设计：

$$\text{Training Distribution}\rightarrow \text{Embedding Geometry}\rightarrow \text{Index Approximation}\rightarrow \text{Online Candidates}$$

任何一环偏移都会让离线 embedding 指标与线上候选质量脱节。面试时应至少区分 **model recall、exact retrieval recall、ANN recall、end-to-end recall**。

### 针对本题的关键推导

严重问题主要有 false negative、popularity bias、跨卡重复和 batch distribution bias。因为“别人的正样本”并不自动等于“我的真负样本”。

这里建议把回答进一步拆成四层证据链：

1. **定义层**：一句话说明“In-batch Negative 有什么严重问题？”讨论的对象和优化目标；
2. **机制层**：给出公式、数据生成过程或计算复杂度，解释为什么会有效；
3. **系统层**：指出它在完整推荐链路中的上游输入、下游依赖、成本和失败传播路径；
4. **验证层**：给出 offline slice、线上 A/B、guardrail 与回滚条件。

### 90 秒标准回答（建议练到可以脱稿）

> 严重问题主要有 false negative、popularity bias、跨卡重复和 batch distribution bias。因为“别人的正样本”并不自动等于“我的真负样本”。 具体到工程上，可以用下面的数量级来理解：两个用户都点击同一爆款手机，去重后同 item 可能既作为正例又出现在负列；若不 mask，loss 会给出相互矛盾梯度。 因此我不会只看单一离线指标，而会把这项方法放回完整链路，联合检查候选/特征分布、P95/P99、成本以及线上主指标。如果出现“离线好、线上差”，我会优先检查数据与 serving 一致性、截断/近似误差和策略覆盖。最后还要说明边界：一味过滤相似 item 也会把真正困难的负例全部去掉，模型失去细粒度判别能力；应区分 false negative 与 hard negative。

这段 90 秒回答的顺序是 **结论 → 机制 → 数量级 → 工程验证 → 边界**。对于大多数推荐算法题，这比从论文历史开始讲更稳。

### 容易混淆的概念

训练负样本 vs 真负反馈；exact retrieval vs ANN retrieval；embedding 相似度 vs 概率；model recall vs route marginal recall。

### 上线验证与监控

分别测 model exact Recall@K、ANN Recall@K、端到端候选命中；线上同时看 candidate count、route overlap、dedup ratio、P99 和超时降级。若换 sampling policy，应做版本隔离而不是直接与旧模型混训。

**建议至少记录这些字段：** positive source、negative source、sampling version、temperature、embedding norm、index version、ANN visited/probe 参数、candidate count、route overlap、retrieval latency。日志字段不是越多越好，关键是能把一次线上曝光追溯到样本、特征、模型、索引和实验版本。

### 一个可用于面试的具体例子

两个用户都点击同一爆款手机，去重后同 item 可能既作为正例又出现在负列；若不 mask，loss 会给出相互矛盾梯度。

面试里具体数字的价值不是“显得真实”，而是迫使方案满足数量级约束。即使没有真实业务数据，也可以明确说“下面用数量级举例”，然后说明候选数、样本量、维度、QPS 或延迟如何影响设计。

- 可用同 user 多正例、语义近邻 mask、teacher filtering 或 soft label 缓解假负例。

## 连续追问参考答案

### 追问 1：logQ correction 为什么有效？

若负样本按 q(i) 被非均匀采样，训练 logits 会混入“容易被采到”的频率。常见做法从 logit 中减去 log q(i)（具体形式依目标而定），校正 sampling prior，使 score 更接近目标分布下的相对偏好。

### 追问 2：多正例 loss 怎么写？

把同一 user 的多个真实正例都放入 numerator，例如 -log(Σ_{p∈P} exp(s_p/τ) / Σ_{a∈P∪N} exp(s_a/τ))，或对每个正例分别求 supervised contrastive loss。要 mask 同 item 重复，避免一个正例同时出现在 denominator 的负位置。

### 追问 3：怎样判断 hard negative 是不是假负例？

先用 item-id duplicate mask、同用户多正例、语义/类目相似度与后续真实交互估计 false-negative 风险；不要把所有相似负例都过滤，否则会丢 hard negatives。可用 soft label/多正例 loss 做折中。

### 追问 4：如何估计 false negative rate？

先用 item-id duplicate mask、同用户多正例、语义/类目相似度与后续真实交互估计 false-negative 风险；不要把所有相似负例都过滤，否则会丢 hard negatives。可用 soft label/多正例 loss 做折中。

### 追问 5：多兴趣用户为什么更容易出现假负例？

先用 item-id duplicate mask、同用户多正例、语义/类目相似度与后续真实交互估计 false-negative 风险；不要把所有相似负例都过滤，否则会丢 hard negatives。可用 soft label/多正例 loss 做折中。
