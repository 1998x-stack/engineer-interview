    01          请完整介绍一个工业级推荐系统的链路

  ★★★        面经高频



30 秒回答
 核心回答                工业级推荐不是单模型，而是“数据闭环 + 多阶段检索排序 + 在线服务 + 实验平台”的系统。典型在线链
                     路是多路召回→粗排→精排→重排/混排；离线侧同时维护样本、特征、Embedding、索引、训练和评估，并
                     由曝光/点击/停留/转化日志回流形成闭环。


深入拆解
     召回追求高覆盖，在数亿到数十亿物料里快速缩小到千级候选；粗排用很小计算预算砍到百级；精排使用最丰富特征和
   复杂多目标模型；重排处理列表级多样性、业务规则和生态约束。
     真正的工程重点是 train-serving consistency：离线特征、线上特征、模型版本、ANN 索引与样本口径必须一致。
     高分回答要主动补充 SLA/QPS/特征新鲜度/灰度发布/A-B 实验/监控，而不是只画四个框。

公式 / 工程抓手
 KEY                 N_item: 10^8~10^10 → Recall: 10^3~10^4 → Pre-rank: 10^2~10^3 → Rank: 10^1~10^2


 常见失分                只背“召回-排序-重排”四个名词，不解释各层为什么存在、计算预算和指标差异。

连续追问
     1. 为什么不能直接精排全库？
     2. 召回和排序分别看什么离线指标？
     3. 哪个阶段最容易造成线上 latency 尖峰？

    02          召回、粗排、精排、重排分别解决什么问题？

  ★★★        面经高频



30 秒回答
 核心回答                四阶段本质是“效果与计算预算”的分层优化。越靠前越强调覆盖率和吞吐，越靠后越强调精确性与列表整

深入拆解
     召回：高 Recall、低延迟，可容忍较多噪声；粗排：用低成本模型筛掉明显不合适候选；精排：强交叉、长序列、多

公式 / 工程抓手
 KEY                 目标可概括为：前层 maximize coverage / cost，后层 maximize utility / constraint。


 常见失分                把重排理解成“再跑一次精排”。重排通常需要列表级状态和约束。

    03          为什么推荐系统要做多路召回？

  ★★★        面经高频

 核心回答                单一召回路只能覆盖一种相似性假设；真实用户兴趣是多兴趣、多时间尺度、多意图，因此用

    12          ItemCF 有哪些经典改进？

30 秒回答

    15          双塔最大的缺点是什么？如何改？

                         双塔瓶颈 / 多兴趣 /
  ★★★        面经高频
                             蒸馏



30 秒回答
 核心回答                最大问题是交互发生太晚：user 与 item 在最后点积前没有细粒度特征交叉，表达力受限。改进方向是在不
                     破坏可索引性的前提下增强表示，或用多阶段架构把强交互留给排序。

     可用更强序列编码器、多兴趣向量、知识蒸馏、teacher-student、query-aware user tower。

    40          DIN 的 Attention 具体怎么计算？

    44          DIEN 为什么需要 Auxiliary Loss？

  ★★★        面经高频



30 秒回答

                     pair。例如一个用户整体分数偏高、另一个偏低，跨用户 pair
                     会影响指标；真实推荐只需在同一用户候选内排序。


深入拆解
     GAUC 对每个 user/group 单独算 AUC 再加权，更贴近 per-user ranking。
     加权可按曝光数、点击数或业务价值，但口径要固定。
     极少正负样本的 user 无法计算 AUC，需要过滤或平滑。

公式 / 工程抓手
 KEY                 GAUC=Σ_u w_u AUC_u / Σ_u w_u


 常见失分                把 GAUC 简单说成“更准确的 AUC”，不解释 group 的意义。

连续追问
     1. group 应该按 user 还是 request？
     2. 如何处理全正/全负 group？

    68          GAUC 具体怎么算？权重怎么选？

  ★★★        面经高频          GAUC calculation



30 秒回答
 核心回答                先按 user/request 分组计算组内

深入拆解

    69          Precision、Recall、F1 在推荐中怎么用？

  ★★★        面经高频



30 秒回答
 核心回答                Precision 衡量推荐出来的有多少是相关，Recall 衡量真实相关中找回多少。召回阶段更重
                     Recall@K，最终 TopK 也可看 Precision/NDCG；F1 适合需要单值平衡的场景。


深入拆解
     推荐离线往往只有观测到的少量正反馈，未交互不一定是不相关，因此绝对 Precision/Recall 受评估协议影响。

 KEY                 Precision=TP/(TP+FP); Recall=TP/(TP+FN)


 常见失分                把分类任务的阈值 Precision 直接套进 TopK 推荐，不说明 K。

    70          NDCG 为什么适合推荐排序？

  ★★★        面经高频

                     同时考虑相关性等级和位置折扣，高相关结果排得越靠前贡献越大，并用理想排序归一化到可比较区间。

    71          离线评价为什么必须重视 Time Split？

  ★★★        面经高频



30 秒回答

    77          Position Bias 怎么解决？

  ★★★        面经高频



30 秒回答
 核心回答                先承认点击是“看见 × 喜欢”的结果。可将 position 作为特征、用随机交换位置估 propensity、训练

 KEY                 P(click)=P(examine|position)·P(relevant|u,i)


 常见失分                把位置 feature 加进模型就声称“去偏”。那可能只是更好地利用偏差。

    85          Embedding 表太大怎么办？

   ★★        面经高频



30 秒回答
 核心回答                大规模推荐的参数主要可能来自 embedding table。常见方案有
                     hash、频率裁剪、mixed-dimension、量化、低秩分解、冷热分层、分布式参数服务器和淘汰机制。


深入拆解
     十亿级 ID × 128 dim × FP32 已是数百 GB。
     高频 ID 值得独立表示，低频 ID 可共享 hash bucket 或更低维。

附录 B：7 天 / 30 天冲刺路线
如果时间有限，优先建立主线，再补模型细节。下面按“能应对面试”的收益排序。

周期                  重点                               每天输出

7 天 Day1            完整链路 + 项目复盘                      画出自己的召回→排序→重排图，准备 3 分钟项目介绍

Day2                双塔 / InfoNCE / 负采样 / ANN         手写 loss，解释 false negative 与 hard negative

Day3                FM / DeepFM / DCNv2              手推 FM 二阶优化与 DCN cross

Day4                DIN / DIEN / SIM / Transformer   比较四者的目标、复杂度、长序列方案

Day5                MMoE / PLE / ESMM                画结构图，讲清 negative transfer 与 SSB

Day6                AUC / GAUC / A-B / Bias          用一个真实项目解释离线到线上

Day7                100 题模拟 + 前沿                     只看题目口述；重点补 HSTU / RankMixer / Generative Rec

30 天                前 14 天系统学习；后 16 天项目深挖 +          每两天做一次 45 分钟模拟面试，记录被追问断点
                    mock interview
