# 如何使用这套 Redis 面试题库

这不是一本按命令字母顺序组织的 Redis 手册，而是一套面向“面试判断力”的题库。

建议先尝试在 **60 秒内口述答案**，再阅读原理拆解；第二遍只看追问链和易错点；第三遍用工程落地部分把知识串成系统设计。

## 难度标签

| 标签 | 面试目标 |
|---|---|
| 基础必会 | 能够给出定义、关键机制和一个正确工程例子。 |
| 中级 / 中高级 | 能够解释底层机制、复杂度与失效边界。 |
| 高级 / 场景压轴 / 系统设计 | 能够从需求/SLO 出发给方案、取舍、容量和故障演练。 |
| 新版加分 | 能把经典 Redis 语义与当前 Redis 8.x 增量能力区分开。 |

## 推荐回答结构

1. **先给结论**：30 秒内说清是什么、为什么。
2. **再给机制**：指出关键数据结构、线程/进程、协议或状态机。
3. **再给边界**：说出网络分区、崩溃、Big Key、延迟峰值等失效条件。
4. **最后落地**：给监控指标、命令、容量或补偿方案。

## 能力地图：从“背 Redis”到“设计 Redis”

最终目标不是记住 100 个孤立答案，而是形成四条主线：

- 数据结构与内存；
- 缓存与一致性；
- 持久化与高可用；
- 性能与系统设计。

面试官改变业务条件时，应能沿主线重新推导答案。
