# 单题 Markdown 编辑标准（v2）

本仓库不以“字数多”为目标，而要求每道题至少覆盖以下层次：

1. PDF 母版的 30–60 秒标准回答；
2. 机制与数据结构；
3. 复杂度、字节成本和容量边界；
4. 生产案例与故障时序；
5. Big Key / Hot Key / Cluster / replication 等跨主题约束；
6. 可观测指标与可复现实验；
7. 源码阅读入口；
8. Redis 版本差异；
9. 追问及标准应答；
10. 明确说明“什么时候不该用”。

## 内容来源层级

- **PDF 母版**：第 1–5 节，保持原有主线。
- **GitHub 深挖**：第 6 节以后，可结合 Redis 官方文档、源码与生产工程实践扩展。
- **版本敏感事实**：必须给 Redis 官方链接，并标明最低/当前基线版本。

## 禁止的低质量扩写

- 只把一句话拆成很多 bullet；
- 100 道题复制同一套“边界/监控”模板而没有题目特异信息；
- 只背命令，不解释成本与失效条件；
- 声称 Redis/Sentinel/Cluster/WAIT 提供其实际不保证的强一致性；
- 把内部 encoding 阈值当稳定 API；
- 系统设计从固定节点数开始，而不是从 SLO/容量/故障模型开始。
