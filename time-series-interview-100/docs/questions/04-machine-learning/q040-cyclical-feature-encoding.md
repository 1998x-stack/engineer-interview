## 20 秒面试回答

用正余弦把周期变量映射到单位圆，使周期首尾相邻，例如 23:00 与 00:00 距离自然接近。

## PDF 基线：核心公式 / 结构

$$
sin(2πt/m), cos(2πt/m)
$$

## PDF 基线：原理深挖

对树模型，直接类别或整数也可能有效；sin/cos 更适合线性/神经模型，但不是唯一正确编码。

### 1. 这道题真正考什么

## 最小可运行示例

```python
import numpy as np

df["hour_sin"] = np.sin(2*np.pi*df["hour"]/24)
df["hour_cos"] = np.cos(2*np.pi*df["hour"]/24)
```

## 深度专业版 v2：从“会答”到“能推导、能上线”

> 这一节是 GitHub 版第二轮扩展，不改写上面的 PDF 基线。目标是把题目扩展到高级算法岗 / Forecasting Scientist / Staff DS 面试所要求的深度。

### 1. 核心机制拆解

1. 周期变量用 sin/cos 将首尾相连：$sin(2\pi x/P), cos(2\pi x/P)$。
2. 两维编码同时表达相位，避免 month=12 与 month=1 被线性模型视为距离 11。
3. 对 tree model，原始类别/整数有时也可工作，是否使用周期编码应通过验证。

### 2. 一条可复用的推理链

回答 **“如何编码周期性时间特征？”** 时，推荐按下面顺序组织，而不是先抛模型名：

1. **定义对象与信息边界**：目标变量、时间粒度、forecast origin、horizon、当前可用信息分别是什么。
2. **写最小数学结构**：指出核心随机关系、损失函数或约束。
3. **说明成立条件**：平稳性、独立性、未来协变量可用性、样本长度、分布假设等。
4. **给反例或失败模式**：至少说明一种“理论上成立但工程上失败”的情况。
5. **落到 OOS 证据**：用 rolling / expanding backtest 和强 baseline 证明选择，而不是靠模型复杂度。

### 3. 典型反例、边界与故障模式

- **边界 1：** 只用 sin 不用 cos，导致不同相位映射冲突。
- **边界 2：** 周期 P 设错，例如业务周不是 7 天而是 5 个交易日。

> **面试习惯：** 只会描述模型“优点”通常是中级答案；主动说出失效条件、可观测症状和修复动作，才更接近高级答案。

### 4. 具体业务例子

hour=23 与 hour=0 在圆上接近，适合线性/神经模型学习午夜连续性。
