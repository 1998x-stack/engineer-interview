Local Model 和 Global Model 有什么区别？

章节： 机器学习与大规模 Global Forecasting
难度： ★★★★☆ ｜ 频率： ★★★★★
关键词： local / global / cross-learning

[!NOTE] 内容来源说明： “PDF 基线”部分来自仓库附带的《时间序列面试100题_专业详细版_2026.pdf》；“专业扩展”及代码是为 GitHub 版新增的讲解与工程化补充。二者明确分开，便于回溯。

20 秒面试回答

Local 每条序列独立；Global 在大量相关序列间共享参数，利用 cross-learning 提升低数据量 series 的泛化。

PDF 基线：核心公式 / 结构

$$ Local: one model per series; Global: shared f across series $$

若上面的内容是流程或文字而不是严格 LaTeX 公式，请按 PDF 原意理解；PDF 中的记号在此保持不变。

PDF 基线：原理深挖

Global model 尤其适合 retail、traffic、cloud metrics。挑战是不同尺度、异质性与 ID 泄漏，需要 scaling、static features 与合适采样。

PDF 易错点

简单认为“global 一定更强”。

PDF 高级加分点

Global model 的核心不是“一个模型省事”，而是跨序列共享统计强度。

专业扩展（GitHub 增强版）

1. 这道题真正考什么

机器学习预测的核心不是换模型，而是构造 point-in-time 正确的监督学习样本，并决定 local/global、多步策略与业务 covariates。

  • Global model 是跨 series 共享参数，不代表所有序列共享同一分布；可通过静态特征、scaling、embedding 和分层采样表达异质性。

2. 建议使用的“剑指 Offer 式”回答层次

  1. 先定义：用一句话说明对象、假设或目标。
  2. 给核心数学结构：能写公式就写公式；不能写时明确输入、状态和输出。
  3. 解释统计直觉：说明为什么成立，以及它改变了什么信息。
  4. 指出失败模式：样本太短、非平稳、结构突变、协变量不可用、泄漏等。
  5. 落到验证与工程：给出时间正确的 backtest、baseline、监控或 decision metric。

3. 面试官追问树

1. 什么时候 local 更好？

回答方向： 用数据生成机制和部署约束回答，而不是只给模型名字；最好给一个成立案例和一个反例。

2. global 如何避免大序列支配 loss？

回答方向： 先给可执行流程：诊断数据与可用信息 -> 建 baseline -> 时间正确的回测 -> 误差分解 -> 再决定模型或修复动作。

4. 工程检查清单

  • [ ] 特征构造统一遵循 point-in-time contract。
  • [ ] 对每个 horizon 说明 recursive/direct/MIMO 策略。
  • [ ] Global model 要评估跨实体泛化、cold start 与 scale normalization。

深度专业版 v2：从“会答”到“能推导、能上线”

这一节是 GitHub 版第二轮扩展，不改写上面的 PDF 基线。目标是把题目扩展到高级算法岗 / Forecasting Scientist / Staff DS 面试所要求的深度。

1. 核心机制拆解

  1. Local model 每个序列独立拟合；Global model 在多个序列上共享参数。
  2. global 的核心收益是 statistical strength sharing，尤其对短历史、稀疏 series 和 cold start 有利。
  3. global 也可能出现 negative transfer，因此需要 series identity、static covariates、分群或 mixture-of-experts。

2. 一条可复用的推理链

回答 “Local Model 和 Global Model 有什么区别？” 时，推荐按下面顺序组织，而不是先抛模型名：

  1. 定义对象与信息边界：目标变量、时间粒度、forecast origin、horizon、当前可用信息分别是什么。
  2. 写最小数学结构：指出核心随机关系、损失函数或约束。
  3. 说明成立条件：平稳性、独立性、未来协变量可用性、样本长度、分布假设等。
  4. 给反例或失败模式：至少说明一种“理论上成立但工程上失败”的情况。
  5. 落到 OOS 证据：用 rolling / expanding backtest 和强 baseline 证明选择，而不是靠模型复杂度。

3. 典型反例、边界与故障模式

  • 边界 1： 认为 global 一定优于 local。
  • 边界 2： 把极异质 series 无条件混在一起且无身份信息。

面试习惯： 只会描述模型“优点”通常是中级答案；主动说出失效条件、可观测症状和修复动作，才更接近高级答案。

4. 具体业务例子

100 万 SKU-store 不适合维护 100 万复杂深度模型；global GBDT/DeepAR/TFT 更常见。

把例子继续追问到工程层时，至少要回答：这个变量在预测 cutoff 当时真的可见吗？这个 horizon 的误差由谁承担？模型失败时 fallback 是什么？

5. 高级加分点

“local vs global”不是模型族之争：ARIMA 可做 local，线性/GBDT/NN 都能做 global；还可构建 clustered/semi-global。

这一点不是为了“炫术语”，而是为了说明你能把统计原理、验证协议和生产约束放在同一个框架里。

6. 监督学习流水线 Checklist

  • [ ] 构造 point-in-time correct features
  • [ ] 明确 future covariate availability
  • [ ] 按 horizon/segment 做滚动回测

建议把 checklist 真正落实到实验记录中：每个候选模型保存 data_snapshot / cutoff / feature_version / model_version / horizon / metrics_by_segment，才能复现实验和定位线上偏差。

8. 2～3 分钟完整口述参考

第一句先给结论。 Local 每条序列独立；Global 在大量相关序列间共享参数，利用 cross-learning 提升低数据量 series 的泛化。

第二层解释机制。 Global model 尤其适合 retail、traffic、cloud metrics。挑战是不同尺度、异质性与 ID 泄漏，需要 scaling、static features 与合适采样。

第三层补边界。 这个结论只有在数据生成机制、信息可用性和验证协议匹配时才有意义；我会主动检查本题上面列出的失败模式。

第四层落到工程。 最后我会用与生产一致的 rolling backtest、强 baseline 和 horizon/segment 分解指标验证，并记录 point-in-time feature lineage，确保离线提升可以复现到线上。
