Q009 Attention 与 FFN 分别承担什么功能？

章节：1. Transformer 总体架构与设计动机
难度：2/5 · 频率：高频 · 形式：概念 / 推导 / 追问
内容分层：PDF Core 来自原 PDF 的观点重排；Professional Expansion 为在不改变 PDF 主结论基础上的原创扩展。

1. 面试官在考什么 — PDF Core

理解 Transformer 为什么既需要 token mixing 又需要 channel/feature mixing。

2. 30 秒回答 — PDF Core

Attention 主要决定“从哪些 token 读取信息”，FFN 主要决定“对每个 token 的特征做什么非线性计算”。前者跨 token，后者逐 token。 Attention: token mixing | FFN: feature mixing

3. 核心公式 / Shape

Attention: $Y_i=\sum_j\alpha_{ij}V_j$；FFN: $W_2\phi(W_1x)$。

4. 深度拆解 — PDF Core

  • Attention 输出是对 V 的输入依赖加权组合。
  • FFN 通常是 d→d_ff→d 的两层或 gated MLP。
  • 即使 Attention 完美聚合上下文，没有强非线性 MLP 也会限制特征变换能力。

5. Professional Expansion：为什么这题值得深挖

Attention 负责跨 token 路由和聚合，FFN 在每个 token 上做高容量非线性变换；两者组合形成 communication + computation。

5.1 工程实现 / 系统视角

profile 参数量与 FLOPs，很多 LLM 中 MLP 参数/FLOPs 占比非常高。

5.2 边界条件与反例

‘Attention 是全部计算’是错误直觉。

5.3 建议亲手做的验证实验

  • 删除 FFN 或 Attention 做小模型消融，比较拟合速度与任务表现。
  • 记录至少一种 correctness metric 与一种 performance metric；不要只凭“代码能运行”判定实现正确。

5.4 3 分钟专业版答法

面试时可以按下面节奏展开：

第一句给结论：Attention 主要决定“从哪些 token 读取信息”，FFN 主要决定“对每个 token 的特征做什么非线性计算”。前者跨 token，后者逐 token。 Attention: token mixing | FFN: feature mixing
第二层讲机制：Attention 输出是对 V 的输入依赖加权组合。；FFN 通常是 d→d_ff→d 的两层或 gated MLP。；即使 Attention 完美聚合上下文，没有强非线性 MLP 也会限制特征变换能力。
第三层补工程条件：把本题放到真实 Tensor Shape、训练/推理阶段与硬件约束下重新检查；如果结论涉及“更快/更省/更稳定”，必须说明比较基线和适用条件。
最后主动给验证：用最小行为测试、数值 parity、profiler 或 ablation 证明，而不是停留在直觉。

5.5 复杂度与资源矩阵

维度 本题应如何分析
参数量 关注 Attention / FFN / embedding 的参数主项；head 数与总 hidden size 的关系必须说清。
FLOPs 同时比较 $O(Td^2)$ 的投影/MLP 与 $O(T^2d)$ 的 token-pair 交互。
Activation 训练阶段保存中间激活；层数与 sequence length 都会放大显存。
并行性 训练 sequence 维可并行，但自回归生成仍存在 token-level dependency。
主要验证 shape invariant、gradient path、tiny overfit。

5.6 本题关键不变量

  • Residual 子层的输入输出 hidden width 必须一致。
  • 训练并行性与 autoregressive decode 串行性要分开陈述。
  • 对任何“更快/更强”的结论都注明 T、d、batch 与任务条件。

6. 面试中的推导顺序

  1. 先定义：一句话说明对象是什么、输入输出是什么。
  2. 再公式：写最小核心公式，并标出关键维度。
  3. 解释 Why：它解决前一代方案的什么瓶颈。
  4. 算成本：参数、FLOPs、activation/KV memory、IO/通信分别看。
  5. 讲 Gotcha：至少指出一个数值或实现陷阱。
  6. 收束 Trade-off：明确什么条件下它不一定更优。

7. 常见失分点 — PDF Core

  • 说“FFN 用来增加参数”而没有解释功能。

13. 深入推导：把结论变成可验证的模型

一个实用心智模型是：Attention 做 token mixing，MLP 做 channel mixing。Attention 的输出是 value 的数据依赖加权组合；FFN 对每个 token 独立，但通过非线性扩维/门控改变其特征表示。

因此删除任一部分都会损失关键能力：只有 MLP 缺少跨 token 通信；只有 Attention 则每层的大部分变换仍受加权线性组合限制。现代 block 的参数大头往往在 FFN，而长序列 runtime 瓶颈可能在 Attention。

13.1 本章心智模型

从“为什么需要 Transformer”一路回答到 block、shape、residual 与模块职责。核心是建立计算图和张量图。

这意味着面试时不要停在术语层。每个结论至少回答四个问题：成立所需假设是什么？张量/概率对象是什么？成本落在哪里？怎样设计反例或单测证伪？

14. 题目特异的工程 Checklist

attention 检查表

  • 写出 Q/K/V 与 score 的完整 shape，尤其区分 $T_q$、$T_k$、$H_q$、$H_{kv}$。
  • 明确 softmax 的归一化轴、mask 语义与 fully-masked row 行为。
  • 用一个朴素 reference implementation 对 fused/optimized kernel 做数值 parity。
  • 性能分析同时报告 FLOPs、HBM bytes、kernel launch 与是否 materialize $T^2$ 中间量。

ffn 检查表

  • 参数量、FLOPs 要按实际 gate/up/down 矩阵计算，不能机械套 4d。
  • activation/gating 改动应控制 parameter/FLOPs budget 做公平 ablation。
  • 记录 FFN 占总参数、总训练 FLOPs 和 kernel time 的比例。
  • MoE 场景再加入 router、capacity 与 all-to-all 成本。

15. 推荐验证协议

  1. Reference parity：用小尺寸 FP32 手写 attention 与 scaled_dot_product_attention 对比。
  2. Mask invariance：改变被 mask token 的内容，合法 query 输出不应变化。
  3. Probability invariant：非 fully-masked 行的 attention probability sum 应约为 1。

验证结果建议至少记录：

类型 最低要求
Correctness reference parity / invariant / leakage test 至少一项
Numerical NaN/Inf、max/RMS、dtype 差异
Performance wall-clock、显存/bytes、P95/P99（系统题）
Quality loss/perplexity/任务指标；结构改动必须做回归

16. 面试官真正想听到的“边界条件”

  • 不要把渐进复杂度等同于实际速度：kernel、batch、长度、硬件与 IO 会改变主导项。
  • 不要把一种实现当成数学定义：mask 语义、layout、fused kernel、cache allocator 都可能变化。
  • 不要把单点 benchmark 当成普遍规律：至少说明 $B,T,d,H$、dtype、device 和任务分布。
  • 不要把“能运行”当成“正确”：Transformer 很多 bug 会正常降 loss，但存在未来泄漏、错误广播或 cache position 错位。

17. Whiteboard / Coding 表达模板

当面试官要求现场推导或编码，可按以下顺序：

  1. 写输入输出 shape 与符号定义；
  2. 写最小核心公式，不先写优化；
  3. 写 2–3 个 invariants/assertions；
  4. 给 reference 实现或手算小例子；
  5. 再讨论 fused kernel、cache、并行或量化；
  6. 最后给测试与 benchmark 设计。

Strong Hire 信号：不仅能解释“为什么”，还能说出“什么情况下不成立，以及我会怎么证明”。
