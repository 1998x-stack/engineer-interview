Q052 Cross-Attention 为什么适合机器翻译？

章节：5. BERT、GPT 与 Encoder-Decoder
难度：3/5 · 频率：高频 · 形式：概念 / 推导 / 追问
内容分层：PDF Core 来自原 PDF 的观点重排；Professional Expansion 为在不改变 PDF 主结论基础上的原创扩展。

1. 面试官在考什么 — PDF Core

从 soft alignment 和 conditional generation 解释。

2. 30 秒回答 — PDF Core

Decoder 当前 query 可以对 Encoder 的所有 source token 动态分配权重，从而实现“生成当前目标 token 时应该读 输入的哪部分”。这相当于可学习的 soft alignment。 Cross score shape: [T_target × T_source]

3. 核心公式 / Shape

$Q_{dec}$ 查询 $K_{enc},V_{enc}$ 形成 soft alignment。

4. 深度拆解 — PDF Core

  • Encoder memory 在生成过程中固定，可缓存 K/V。
  • 不同 decoder position 可选择不同 source 区域。
  • 语言顺序不一致时这种动态对齐尤其重要。

5. Professional Expansion：为什么这题值得深挖

Cross-attention 让 decoder 每个输出位置动态查询 encoder 表示，天然对应 source-target soft alignment。

5.1 工程实现 / 系统视角

encoder K/V 可跨整个 decode 复用。

5.2 边界条件与反例

现代翻译也可 decoder-only，问题是归纳偏置和效率取舍。

5.3 建议亲手做的验证实验

  • 可视化 source-target attention 与对齐。
  • 记录至少一种 correctness metric 与一种 performance metric；不要只凭“代码能运行”判定实现正确。

5.4 3 分钟专业版答法

面试时可以按下面节奏展开：

第一句给结论：Decoder 当前 query 可以对 Encoder 的所有 source token 动态分配权重，从而实现“生成当前目标 token 时应该读 输入的哪部分”。这相当于可学习的 soft alignment。 Cross score shape: [T_target × T_source]
第二层讲机制：Encoder memory 在生成过程中固定，可缓存 K/V。；不同 decoder position 可选择不同 source 区域。；语言顺序不一致时这种动态对齐尤其重要。
第三层补工程条件：把本题放到真实 Tensor Shape、训练/推理阶段与硬件约束下重新检查；如果结论涉及“更快/更省/更稳定”，必须说明比较基线和适用条件。
最后主动给验证：用最小行为测试、数值 parity、profiler 或 ablation 证明，而不是停留在直觉。

5.5 复杂度与资源矩阵

维度 本题应如何分析
监督密度 MLM 只在 mask 位计主要监督；CLM 通常几乎每个有效 token 都贡献 next-token loss。
Mask 双向/causal 可见性决定信息流，不要只从“模型名字”判断。
训练-推理差异 Teacher Forcing 与 autoregressive rollout 的条件分布不同。
任务匹配 分类/检索/生成/seq2seq 的接口和延迟要求会影响架构选择。
主要验证 label alignment、mask 可见性、下游任务与生成行为。

5.6 本题关键不变量

  • 当前预测位置不能直接看到其监督目标。
  • padding/无效 token 不应污染 attention 或 loss。
  • 训练目标与推理方式的差异必须显式说明。

6. 面试中的推导顺序

  1. 先定义：一句话说明对象是什么、输入输出是什么。
  2. 再公式：写最小核心公式，并标出关键维度。
  3. 解释 Why：它解决前一代方案的什么瓶颈。
  4. 算成本：参数、FLOPs、activation/KV memory、IO/通信分别看。
  5. 讲 Gotcha：至少指出一个数值或实现陷阱。
  6. 收束 Trade-off：明确什么条件下它不一定更优。

7. 常见失分点 — PDF Core

13. 深入推导：把结论变成可验证的模型

Cross-attention 让 decoder 在每个生成位置用当前 query 动态读取 encoder memory，相当于 learned soft alignment。与把 source/target 全拼到 decoder-only prompt 相比，encoder-decoder 明确分离 source representation 与 target causal state。

推理时 encoder output 固定，因此其 cross-attention K/V 可缓存；复杂度随 target length 与 source length 的乘积增长。

13.1 本章心智模型

从 attention 可见性与概率分解理解 BERT/GPT/encoder-decoder，而不是只背模型名。

这意味着面试时不要停在术语层。每个结论至少回答四个问题：成立所需假设是什么？张量/概率对象是什么？成本落在哪里？怎样设计反例或单测证伪？

14. 题目特异的工程 Checklist

attention 检查表

  • 写出 Q/K/V 与 score 的完整 shape，尤其区分 $T_q$、$T_k$、$H_q$、$H_{kv}$。
  • 明确 softmax 的归一化轴、mask 语义与 fully-masked row 行为。
  • 用一个朴素 reference implementation 对 fused/optimized kernel 做数值 parity。
  • 性能分析同时报告 FLOPs、HBM bytes、kernel launch 与是否 materialize $T^2$ 中间量。

15. 推荐验证协议

  1. Reference parity：用小尺寸 FP32 手写 attention 与 scaled_dot_product_attention 对比。
  2. Mask invariance：改变被 mask token 的内容，合法 query 输出不应变化。
  3. Probability invariant：非 fully-masked 行的 attention probability sum 应约为 1。

验证结果建议至少记录：

类型 最低要求
Correctness reference parity / invariant / leakage test 至少一项
Numerical NaN/Inf、max/RMS、dtype 差异
Performance wall-clock、显存/bytes、P95/P99（系统题）
Quality loss/perplexity/任务指标；结构改动必须做回归

16. 面试官真正想听到的“边界条件”

  • 不要把渐进复杂度等同于实际速度：kernel、batch、长度、硬件与 IO 会改变主导项。
  • 不要把一种实现当成数学定义：mask 语义、layout、fused kernel、cache allocator 都可能变化。
  • 不要把单点 benchmark 当成普遍规律：至少说明 $B,T,d,H$、dtype、device 和任务分布。
  • 不要把“能运行”当成“正确”：Transformer 很多 bug 会正常降 loss，但存在未来泄漏、错误广播或 cache position 错位。

17. Whiteboard / Coding 表达模板

当面试官要求现场推导或编码，可按以下顺序：

  1. 写输入输出 shape 与符号定义；
  2. 写最小核心公式，不先写优化；
  3. 写 2–3 个 invariants/assertions；
  4. 给 reference 实现或手算小例子；
  5. 再讨论 fused kernel、cache、并行或量化；
  6. 最后给测试与 benchmark 设计。

Strong Hire 信号：不仅能解释“为什么”，还能说出“什么情况下不成立，以及我会怎么证明”。
