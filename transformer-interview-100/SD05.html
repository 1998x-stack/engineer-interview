SD05 训练一个 70B Transformer

1. 先写显存预算

仅 BF16 权重：

[ 70B\times2\ bytes\approx140\ GB ]

训练还需要 gradients、optimizer states、master weights（视实现）、activation。因此单卡显然不够。

不要死背“每参数多少 bytes”，因为 Adam state、mixed precision 和 ZeRO/FSDP shard 方式不同。应列账本再代入当前 recipe。

2. 并行维度

Data Parallel / FSDP / ZeRO

切 optimizer/gradient/parameter state。

Tensor Parallel

切 attention/MLP 大矩阵，通信频繁，优先放在高速同节点互联。

Pipeline Parallel

按层切 stage；需要 micro-batch pipeline，关注 bubble。

Context / Sequence Parallel

长序列下切 sequence/activation。

Expert Parallel

MoE 需要 all-to-all。

真实方案通常：

[ WorldSize=DP\times TP\times PP\times CP ]

3. 拓扑映射

原则：通信最频繁的并行维优先映射到最快互联。

例如 TP 通常优先单节点 NVLink；DP 可跨节点；PP stage 边界要考虑节点拓扑。

4. Activation Memory

长 sequence / 大 micro-batch 时 activation 可能成为主要显存压力。

策略：

  • activation checkpointing；
  • sequence parallel；
  • selective recompute；
  • FlashAttention；
  • micro-batch 调整。

5. Global Batch

[ B_{global}=B_{micro}\times accumulation\times DP ]

修改任何一项后要同步 LR schedule、optimizer steps/token 和日志归一方式。

6. 数据与 Token Budget

70B 并不意味着 token 越少越好。训练方案需共同确定：

  • total tokens；
  • data mixture；
  • tokenizer；
  • curriculum；
  • dedup / contamination；
  • checkpoint cadence。

7. 稳定性

记录：

  • loss；
  • grad norm；
  • activation RMS by layer；
  • overflow/NaN；
  • LR；
  • tokens/s；
  • MFU；
  • data source distribution。

一旦 loss spike，要能定位到数据 batch / rank / layer / optimizer step。

8. Checkpoint

70B checkpoint 很大，需要：

  • sharded save；
  • async checkpoint；
  • optimizer state；
  • RNG state；
  • dataloader position；
  • exact model/tokenizer/config revision。

“能恢复权重”不等于“能精确恢复训练”。

9. 故障容错

  • node failure；
  • NCCL timeout；
  • silent data corruption；
  • bad shard；
  • checkpoint partial write。

应设计自动重试和最近健康 checkpoint 回滚。

10. 面试加分

不要只回答 Megatron/DeepSpeed 名词。给出：为什么某并行维放在某拓扑、哪个状态占显存、通信在什么位置发生、怎样验证 scaling efficiency。
