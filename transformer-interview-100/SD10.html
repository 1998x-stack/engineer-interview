SD10 如何回答一个没见过的 Transformer 变体

高级算法岗真正想看的是：面对未知结构，你能否从不变量推导，而不是是否背过论文名。

1. 第一步：重写成最小数学对象

问：

  • 输入/输出 shape？
  • 哪些 projection？
  • attention score 如何定义？
  • normalization 在哪里？
  • residual 是否保留？
  • training objective 是否变化？

把新名字还原成公式。

2. 第二步：找它改变了哪一层

通常属于：

  1. Objective：MLM/CLM/denoising；
  2. Connectivity：full/sparse/local/cross；
  3. Position：RoPE/bias/interpolation；
  4. Channel computation：FFN/GLU/MoE；
  5. State/cache：MHA/GQA/recurrent memory；
  6. Kernel/system：FlashAttention/paged memory；
  7. Parallelism：TP/CP/expert parallel。

3. 第三步：四张账表

参数

[ Params=f(d,L,H,H_{kv},d_{ff},E,...) ]

FLOPs

分 train / prefill / decode。

Memory

分 weights / optimizer / activation / KV。

Communication / IO

分 HBM、NCCL、all-to-all、allocator。

4. 第四步：问它解决什么瓶颈

如果作者声称“更快”，先问：

  • 哪个阶段？
  • 哪个长度？
  • 哪种硬件？
  • 是否保持 exact output？
  • 是否重新训练？

如果声称“更长上下文”，问：

  • API 支持还是有效能力？
  • 训练外推？
  • KV 成本？

5. 第五步：找反例

例如：

  • 稀疏 attention 对长程任务可能漏边；
  • MQA 可能压缩 K/V 表示；
  • quantization 对 outlier 层敏感；
  • MoE 在通信差的集群上反而慢；
  • linear attention 在短序列可能不如 fused softmax attention。

6. 第六步：设计验证

至少一个 correctness + 一个 performance + 一个 quality：

Reference parity
+ Microbenchmark
+ End-to-end task eval

7. Whiteboard 模板

Definition
→ Formula / Shape
→ What changed vs baseline
→ Param/FLOPs/Memory/IO
→ Train vs Prefill vs Decode
→ Failure modes
→ Experiment
→ Trade-off conclusion

8. 示例：面试官突然说“我们把 K/V 压到低秩”

不要先猜论文。

你可以推导：

  • K/V cache storage 是否由 $H_{kv}D_h$ 降成 rank $r$；
  • decode 是否需要重构 K/V；
  • 重构 FLOPs 是否抵消 bandwidth 节省；
  • attention score 是否 exact；
  • 低秩瓶颈是否伤质量；
  • 与 GQA/quantized KV 比较；
  • 做 full-vs-modified quality + TPOT benchmark。

这就是高级面试需要的迁移推理能力。
