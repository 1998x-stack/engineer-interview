# Q003 · 请完整描述 Transformer Decoder

> **章节**：1. Transformer 总体架构与设计动机  
> **难度**：2/5 · **频率**：高频 · **形式**：概念 / 推导 / 追问  
> **内容分层**：`PDF Core` 来自原 PDF 的观点重排；`Professional Expansion` 为在不改变 PDF 主结论基础上的原创扩展。

## 1. 面试官在考什么 — PDF Core

区分 masked self-attention、cross-attention 与 FFN，并理解 Decoder-only 与经典 Encoder- Decoder 的差异。

## 2. 30 秒回答 — PDF Core

> 经典 Transformer Decoder 先做 causal self-attention，再用 decoder hidden state 作为 Query 对 encoder output 做 cross-attention，最后经过 FFN。Decoder-only LLM 通常没有 cross-attention，只保留 causal self- attention 与 MLP。

## 3. 核心公式 / Shape

Cross-Attention: $\mathrm{softmax}(Q_{dec}K_{enc}^T/\sqrt{d_h})V_{enc}$。

## 4. 深度拆解 — PDF Core

- Masked self-attention 保证位置 t 只能使用 ≤t 的 token。
- Cross-attention 中 Q 来自 Decoder，K/V 来自 Encoder，是“输出序列向输入序列检索”。
- 训练时 teacher forcing 允许整段并行；推理时仍需增量生成。
- Decoder-only 把 prompt、上下文、答案统一成一个 token stream。

## 5. Professional Expansion：为什么这题值得深挖

经典 Decoder 有 causal self-attention、cross-attention、FFN；decoder-only LLM 去掉 cross-attention，把条件信息序列化进同一 token stream。

### 5.1 工程实现 / 系统视角

Encoder-Decoder 推理可预先投影并缓存 encoder K/V；decoder 自注意力则随输出长度递增维护 cache。

### 5.2 边界条件与反例

不要把‘Decoder’默认等同于 GPT block。

### 5.3 建议亲手做的验证实验

- 分别画出 seq2seq decoder 与 decoder-only block 的 Q/K/V 来源。
- 记录至少一种 **correctness metric** 与一种 **performance metric**；不要只凭“代码能运行”判定实现正确。

### 5.4 3 分钟专业版答法

面试时可以按下面节奏展开：

> **第一句给结论**：经典 Transformer Decoder 先做 causal self-attention，再用 decoder hidden state 作为 Query 对 encoder output 做 cross-attention，最后经过 FFN。Decoder-only LLM 通常没有 cross-attention，只保留 causal self- attention 与 MLP。  
> **第二层讲机制**：Masked self-attention 保证位置 t 只能使用 ≤t 的 token。；Cross-attention 中 Q 来自 Decoder，K/V 来自 Encoder，是“输出序列向输入序列检索”。；训练时 teacher forcing 允许整段并行；推理时仍需增量生成。  
> **第三层补工程条件**：把本题放到真实 Tensor Shape、训练/推理阶段与硬件约束下重新检查；如果结论涉及“更快/更省/更稳定”，必须说明比较基线和适用条件。  
> **最后主动给验证**：用最小行为测试、数值 parity、profiler 或 ablation 证明，而不是停留在直觉。

### 5.5 复杂度与资源矩阵

| 维度 | 本题应如何分析 |
|---|---|
| 参数量 | 关注 Attention / FFN / embedding 的参数主项；head 数与总 hidden size 的关系必须说清。 |
| FLOPs | 同时比较 $O(Td^2)$ 的投影/MLP 与 $O(T^2d)$ 的 token-pair 交互。 |
| Activation | 训练阶段保存中间激活；层数与 sequence length 都会放大显存。 |
| 并行性 | 训练 sequence 维可并行，但自回归生成仍存在 token-level dependency。 |
| 主要验证 | shape invariant、gradient path、tiny overfit。 |

### 5.6 本题关键不变量

- Residual 子层的输入输出 hidden width 必须一致。
- 训练并行性与 autoregressive decode 串行性要分开陈述。
- 对任何“更快/更强”的结论都注明 T、d、batch 与任务条件。

## 6. 面试中的推导顺序

1. **先定义**：一句话说明对象是什么、输入输出是什么。
2. **再公式**：写最小核心公式，并标出关键维度。
3. **解释 Why**：它解决前一代方案的什么瓶颈。
4. **算成本**：参数、FLOPs、activation/KV memory、IO/通信分别看。
5. **讲 Gotcha**：至少指出一个数值或实现陷阱。
6. **收束 Trade-off**：明确什么条件下它不一定更优。

## 7. 常见失分点 — PDF Core

- 把“Decoder 必有 Cross-Attention”当成现代 LLM 的通用结论。

## 13. 深入推导：把结论变成可验证的模型

经典 Transformer Decoder 有 masked self-attention、cross-attention、FFN 三个子层；decoder-only LLM 则删除 cross-attention，只保留 causal self-attention + MLP。回答时必须先确认面试官说的是“2017 encoder-decoder Decoder”还是“现代 decoder-only block”。

Cross-attention 中 $Q$ 来自 decoder state，$K,V$ 来自 encoder output，因此 encoder 的 K/V 在自回归解码期间可预先计算并复用；这与 decoder self-attention 的 KV cache 是两个不同的 cache 复用机会。

### 13.1 本章心智模型

> 从“为什么需要 Transformer”一路回答到 block、shape、residual 与模块职责。核心是建立计算图和张量图。

这意味着面试时不要停在术语层。每个结论至少回答四个问题：**成立所需假设是什么？张量/概率对象是什么？成本落在哪里？怎样设计反例或单测证伪？**

## 14. 题目特异的工程 Checklist

**inference 检查表**

- 分开 prefill 与 decode：前者偏大 GEMM，后者偏 KV bandwidth/调度。
- 指标至少报告 TTFT、TPOT/ITL、throughput 与 P95/P99。
- 容量估算从权重、KV、workspace、allocator overhead 四部分扣显存。
- full-forward 与 incremental/cache 路径必须做 logits parity。

## 15. 推荐验证协议

1. **Full-vs-cache parity**：逐 token logits 与 full forward 相同。
2. **Length sweep**：从短到长记录 TTFT/TPOT/KV bytes，验证复杂度趋势。
3. **Concurrency sweep**：增加并发直到 P99/SLA 或显存首先触顶，得到真实容量曲线。

验证结果建议至少记录：

| 类型 | 最低要求 |
|---|---|
| Correctness | reference parity / invariant / leakage test 至少一项 |
| Numerical | NaN/Inf、max/RMS、dtype 差异 |
| Performance | wall-clock、显存/bytes、P95/P99（系统题） |
| Quality | loss/perplexity/任务指标；结构改动必须做回归 |

## 16. 面试官真正想听到的“边界条件”

- **不要把渐进复杂度等同于实际速度**：kernel、batch、长度、硬件与 IO 会改变主导项。
- **不要把一种实现当成数学定义**：mask 语义、layout、fused kernel、cache allocator 都可能变化。
- **不要把单点 benchmark 当成普遍规律**：至少说明 $B,T,d,H$、dtype、device 和任务分布。
- **不要把“能运行”当成“正确”**：Transformer 很多 bug 会正常降 loss，但存在未来泄漏、错误广播或 cache position 错位。

## 17. Whiteboard / Coding 表达模板

当面试官要求现场推导或编码，可按以下顺序：

1. 写输入输出 shape 与符号定义；
2. 写最小核心公式，不先写优化；
3. 写 2–3 个 invariants/assertions；
4. 给 reference 实现或手算小例子；
5. 再讨论 fused kernel、cache、并行或量化；
6. 最后给测试与 benchmark 设计。

> **Strong Hire 信号**：不仅能解释“为什么”，还能说出“什么情况下不成立，以及我会怎么证明”。
