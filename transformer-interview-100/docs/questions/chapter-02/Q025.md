# Q025 · 写出经典 Sinusoidal Position Encoding

> **章节**：2. Attention 数学与实现细节  
> **难度**：2/5 · **频率**：高频 · **形式**：概念 / 推导 / 追问  
> **内容分层**：`PDF Core` 来自原 PDF 的观点重排；`Professional Expansion` 为在不改变 PDF 主结论基础上的原创扩展。

## 1. 面试官在考什么 — PDF Core

要求知道原始 Transformer 的位置注入方式与多频率设计。

## 2. 30 秒回答 — PDF Core

> 原始 Transformer 使用固定正弦/余弦函数，在不同维度放置不同频率，使每个位置具有确定性向量并可计算任意位 置。 PE(pos,2i)=sin(pos/10000^(2i/d)); PE(pos,2i+1)=cos(…)

## 3. 核心公式 / Shape

$PE(pos,2i)=\sin(pos/10000^{2i/d}),\;PE(pos,2i+1)=\cos(\cdot)$。

## 4. 深度拆解 — PDF Core

- 偶数维使用 sin，奇数维使用 cos。
- 频率按 10000 的指数尺度变化。
- 位置向量与 token embedding 相加。
- 固定位置编码没有额外可训练参数。

## 5. Professional Expansion：为什么这题值得深挖

Sinusoidal PE 为每个频率维度提供确定性正余弦相位，使位置可由多尺度频率组合表示。

### 5.1 工程实现 / 系统视角

实现时注意 position×inv_freq 的 dtype 和广播。

### 5.2 边界条件与反例

10000 是设计超参，不是理论唯一值。

### 5.3 建议亲手做的验证实验

- 画不同维度的频率曲线并观察相对位移。
- 记录至少一种 **correctness metric** 与一种 **performance metric**；不要只凭“代码能运行”判定实现正确。

### 5.4 3 分钟专业版答法

面试时可以按下面节奏展开：

> **第一句给结论**：原始 Transformer 使用固定正弦/余弦函数，在不同维度放置不同频率，使每个位置具有确定性向量并可计算任意位 置。 PE(pos,2i)=sin(pos/10000^(2i/d)); PE(pos,2i+1)=cos(…)  
> **第二层讲机制**：偶数维使用 sin，奇数维使用 cos。；频率按 10000 的指数尺度变化。；位置向量与 token embedding 相加。  
> **第三层补工程条件**：把本题放到真实 Tensor Shape、训练/推理阶段与硬件约束下重新检查；如果结论涉及“更快/更省/更稳定”，必须说明比较基线和适用条件。  
> **最后主动给验证**：用最小行为测试、数值 parity、profiler 或 ablation 证明，而不是停留在直觉。

### 5.5 复杂度与资源矩阵

| 维度 | 本题应如何分析 |
|---|---|
| 参数量 | 标准 MHA 投影约 $4d^2$；若涉及 GQA/MQA 则单独计算 K/V 投影。 |
| FLOPs | $QK^T$ 与 $PV$ 约 $O(T_qT_kd)$；投影仍有 $O(Td^2)$。 |
| 显存 / IO | 朴素 attention 可能 materialize score/probability；高性能实现重点减少 HBM traffic。 |
| 数值稳定 | scale、mask、Softmax max-subtraction、fully-masked row 是高频风险。 |
| 主要验证 | 概率和、causal leakage、naive-vs-fused parity。 |

### 5.6 本题关键不变量

- Softmax 通常沿 key 维归一化。
- Mask 必须与 score 可广播，非法 key 概率应为 0。
- 输出 shape 必须回到 residual stream 所需的 hidden width。

## 6. 面试中的推导顺序

1. **先定义**：一句话说明对象是什么、输入输出是什么。
2. **再公式**：写最小核心公式，并标出关键维度。
3. **解释 Why**：它解决前一代方案的什么瓶颈。
4. **算成本**：参数、FLOPs、activation/KV memory、IO/通信分别看。
5. **讲 Gotcha**：至少指出一个数值或实现陷阱。
6. **收束 Trade-off**：明确什么条件下它不一定更优。

## 7. 常见失分点 — PDF Core

- 只会说“sin/cos 让模型知道顺序”，写不出频率结构。

## 13. 深入推导：把结论变成可验证的模型

Sinusoidal PE 为不同频率的正弦/余弦基函数。位置 $pos$ 的每一对维度使用不同波长，从而同时表达短距离与长距离变化。其一个重要性质是相对位移可通过三角恒等式由当前位置表示线性组合得到。

实现时需注意频率公式中的指数、偶奇维切片和 dtype；若直接用低精度计算很长 position 的 sin/cos，可能出现数值误差，通常先用较高精度生成再 cast。

### 13.1 本章心智模型

> 把 Attention 当作可推导的数值算法：score、scale、mask、softmax、复杂度和解释边界。

这意味着面试时不要停在术语层。每个结论至少回答四个问题：**成立所需假设是什么？张量/概率对象是什么？成本落在哪里？怎样设计反例或单测证伪？**

## 14. 题目特异的工程 Checklist

**position 检查表**

- 分清 position signal 进入哪里：embedding、Q/K rotation、attention bias，还是 cache index。
- full forward 与 incremental decode 的 position id 必须一致。
- “支持更长输入”必须配合超训练长度质量评测。
- 长位置下检查 sin/cos 计算精度、频率缩放和 cache offset。

**coding 检查表**

- 先写 shape/assertion 和行为不变量，再写优化代码。
- 使用参数化测试覆盖 $B=1,T=1,H=1$、非方形 $T_q
e T_k$、padding、GQA 和 dtype。
- reference 路径优先清晰正确，optimized 路径必须对 oracle 做 parity。
- profiler 中区分真正 kernel 时间与隐式 `.contiguous()` / copy / allocation。

## 15. 推荐验证协议

1. **Parameterized unit tests**：覆盖不同 B/T/H/dtype/mask。
2. **Behavioural test**：测试未来泄漏、padding invariance、cache reset 等语义。
3. **Oracle comparison**：优化代码与朴素 reference 比较输出和梯度。

验证结果建议至少记录：

| 类型 | 最低要求 |
|---|---|
| Correctness | reference parity / invariant / leakage test 至少一项 |
| Numerical | NaN/Inf、max/RMS、dtype 差异 |
| Performance | wall-clock、显存/bytes、P95/P99（系统题） |
| Quality | loss/perplexity/任务指标；结构改动必须做回归 |

## 16. 面试官真正想听到的“边界条件”

- **不要把渐进复杂度等同于实际速度**：kernel、batch、长度、硬件与 IO 会改变主导项。
- **不要把一种实现当成数学定义**：mask 语义、layout、fused kernel、cache allocator 都可能变化。
- **不要把单点 benchmark 当成普遍规律**：至少说明 $B,T,d,H$、dtype、device 和任务分布。
- **不要把“能运行”当成“正确”**：Transformer 很多 bug 会正常降 loss，但存在未来泄漏、错误广播或 cache position 错位。

## 17. Whiteboard / Coding 表达模板

当面试官要求现场推导或编码，可按以下顺序：

1. 写输入输出 shape 与符号定义；
2. 写最小核心公式，不先写优化；
3. 写 2–3 个 invariants/assertions；
4. 给 reference 实现或手算小例子；
5. 再讨论 fused kernel、cache、并行或量化；
6. 最后给测试与 benchmark 设计。

> **Strong Hire 信号**：不仅能解释“为什么”，还能说出“什么情况下不成立，以及我会怎么证明”。
