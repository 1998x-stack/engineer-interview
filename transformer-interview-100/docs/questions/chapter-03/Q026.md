# Q026 · 为什么原始 Transformer 使用固定 Sin/Cos？

> **章节**：3. 位置编码与 RoPE  
> **难度**：2/5 · **频率**：高频 · **形式**：概念 / 推导 / 追问  
> **内容分层**：`PDF Core` 来自原 PDF 的观点重排；`Professional Expansion` 为在不改变 PDF 主结论基础上的原创扩展。

## 1. 面试官在考什么 — PDF Core

考察设计权衡，而非把固定编码误说成唯一选择。

## 2. 30 秒回答 — PDF Core

> 固定 Sin/Cos 无需学习位置表，能为任意位置生成编码，并具有规则的相对位移结构。它是一个工程/归纳偏置选择，而 不是“位置编码不能训练”。

## 3. 核心公式 / Shape

固定频率基提供多尺度确定性 position signal。

## 4. 深度拆解 — PDF Core

- learned absolute embedding 也是常见方案。
- 固定函数理论上更方便外推到未见位置，但模型是否真正能利用仍受训练分布限制。
- 现代 LLM 更常见 RoPE 等相对位置机制。

## 5. Professional Expansion：为什么这题值得深挖

固定 Sin/Cos 无需学习额外表，可计算任意位置，并具有规则的相对位移结构；但不等价于‘天然解决所有长度外推’。

### 5.1 工程实现 / 系统视角

和 learned table 对比 max position、参数量与 extrapolation 行为。

### 5.2 边界条件与反例

不要说 position encoding 不能训练。

### 5.3 建议亲手做的验证实验

- 训练短序列 toy task，测试超训练长度。
- 记录至少一种 **correctness metric** 与一种 **performance metric**；不要只凭“代码能运行”判定实现正确。

### 5.4 3 分钟专业版答法

面试时可以按下面节奏展开：

> **第一句给结论**：固定 Sin/Cos 无需学习位置表，能为任意位置生成编码，并具有规则的相对位移结构。它是一个工程/归纳偏置选择，而 不是“位置编码不能训练”。  
> **第二层讲机制**：learned absolute embedding 也是常见方案。；固定函数理论上更方便外推到未见位置，但模型是否真正能利用仍受训练分布限制。；现代 LLM 更常见 RoPE 等相对位置机制。  
> **第三层补工程条件**：把本题放到真实 Tensor Shape、训练/推理阶段与硬件约束下重新检查；如果结论涉及“更快/更省/更稳定”，必须说明比较基线和适用条件。  
> **最后主动给验证**：用最小行为测试、数值 parity、profiler 或 ablation 证明，而不是停留在直觉。

### 5.5 复杂度与资源矩阵

| 维度 | 本题应如何分析 |
|---|---|
| 参数量 | Sin/Cos/RoPE 可无 learned position table；learned absolute PE 约 $T_{max}d$ 参数。 |
| FLOPs | 位置变换通常不是总 FLOPs 主项，但可能影响 fused kernel 与 cache 路径。 |
| KV Cache | RoPE 类方法必须保证增量 K 的 position offset 与 full forward 一致。 |
| 外推 | “可计算更长位置”与“有效长上下文”必须分开评估。 |
| 主要验证 | position sweep、needle/retrieval、full-vs-cache parity。 |

### 5.6 本题关键不变量

- full forward 与 incremental decode 使用的 position id 必须语义一致。
- 长度外推必须用超训练长度评测，而不是只看模型能否接收输入。
- 位置机制改变的位置必须明确：embedding、Q/K、attention bias 或其他。

## 6. 面试中的推导顺序

1. **先定义**：一句话说明对象是什么、输入输出是什么。
2. **再公式**：写最小核心公式，并标出关键维度。
3. **解释 Why**：它解决前一代方案的什么瓶颈。
4. **算成本**：参数、FLOPs、activation/KV memory、IO/通信分别看。
5. **讲 Gotcha**：至少指出一个数值或实现陷阱。
6. **收束 Trade-off**：明确什么条件下它不一定更优。

## 7. 常见失分点 — PDF Core

- 说“固定 PE 一定比 learned PE 泛化更好”。

## 8. 面试官继续追问 — PDF Core

> 为什么有些 learned absolute PE 模型也能在训练长度内表现很好？

### 扩展追问树

- 如果把关键超参数扩大 4 倍，**参数量 / FLOPs / 显存 / latency** 哪一项最先成为瓶颈？
- 如果在 **训练** 与 **增量推理** 两个阶段分别使用，本题结论有哪些不同？
- 如何写一个最小单元测试或 ablation，证明你的解释而不是只靠直觉？

## 9. 一语中的 — PDF Core

**固定 Sin/Cos 无需学习位置表，能为任意位置生成编码，并具有规则的相对位移结构。**

## 13. 深入推导：把结论变成可验证的模型

固定 Sin/Cos 的优点是零额外位置参数、任意位置可计算以及规则频谱结构；但“可计算任意位置”不等于训练外长度一定有效。原始 Transformer 选择它更多是简洁且满足序列顺序建模需求，而非证明 learned PE 不好。

实际比较 learned absolute PE 时，应控制训练长度和数据；learned PE 在训练范围内可能很强，但超过表长需要插值/扩展。

### 13.1 本章心智模型

> 把位置问题当作 pairwise geometry：绝对位置、相对位置、RoPE、外推与长上下文验证。

这意味着面试时不要停在术语层。每个结论至少回答四个问题：**成立所需假设是什么？张量/概率对象是什么？成本落在哪里？怎样设计反例或单测证伪？**

## 14. 题目特异的工程 Checklist

**position 检查表**

- 分清 position signal 进入哪里：embedding、Q/K rotation、attention bias，还是 cache index。
- full forward 与 incremental decode 的 position id 必须一致。
- “支持更长输入”必须配合超训练长度质量评测。
- 长位置下检查 sin/cos 计算精度、频率缩放和 cache offset。

## 15. 推荐验证协议

1. **Shift test**：对可分析的小序列移动 position，观察相对关系是否符合设计。
2. **Cache parity**：full forward 与逐 token RoPE/cache logits 对齐。
3. **Extrapolation sweep**：按位置桶报告训练长度内外的质量，而非只报总体均值。

验证结果建议至少记录：

| 类型 | 最低要求 |
|---|---|
| Correctness | reference parity / invariant / leakage test 至少一项 |
| Numerical | NaN/Inf、max/RMS、dtype 差异 |
| Performance | wall-clock、显存/bytes、P95/P99（系统题） |
| Quality | loss/perplexity/任务指标；结构改动必须做回归 |

## 16. 面试官真正想听到的“边界条件”

- **不要把渐进复杂度等同于实际速度**：kernel、batch、长度、硬件与 IO 会改变主导项。
- **不要把一种实现当成数学定义**：mask 语义、layout、fused kernel、cache allocator 都可能变化。
- **不要把单点 benchmark 当成普遍规律**：至少说明 $B,T,d,H$、dtype、device 和任务分布。
- **不要把“能运行”当成“正确”**：Transformer 很多 bug 会正常降 loss，但存在未来泄漏、错误广播或 cache position 错位。

## 17. Whiteboard / Coding 表达模板

当面试官要求现场推导或编码，可按以下顺序：

1. 写输入输出 shape 与符号定义；
2. 写最小核心公式，不先写优化；
3. 写 2–3 个 invariants/assertions；
4. 给 reference 实现或手算小例子；
5. 再讨论 fused kernel、cache、并行或量化；
6. 最后给测试与 benchmark 设计。

> **Strong Hire 信号**：不仅能解释“为什么”，还能说出“什么情况下不成立，以及我会怎么证明”。
