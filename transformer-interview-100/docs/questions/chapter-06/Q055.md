# Q055 · Decoder LM 的 label 为什么必须 shift？

> **章节**：6. 训练、优化与分布式  
> **难度**：2/5 · **频率**：高频 · **形式**：概念 / 推导 / 追问  
> **内容分层**：`PDF Core` 来自原 PDF 的观点重排；`Professional Expansion` 为在不改变 PDF 主结论基础上的原创扩展。

## 1. 面试官在考什么 — PDF Core

Coding 面试基础，直接决定训练目标是否正确。

## 2. 30 秒回答 — PDF Core

> 输入位置 t 的 hidden state 应预测下一个 token x_{t+1}，因此常见做法是 logits[:, :-1] 对 labels[:, 1:]。若 label 与 input 同位置，模型可能学成错误的 identity-like objective。 input: x₀…x_{T-2} → labels: x₁…x_{T-1}

## 3. 核心公式 / Shape

通常 $inputs=x_{0:T-1},\;labels=x_{1:T}$（具体框架可内部 shift）。

## 4. 深度拆解 — PDF Core

- 许多 Hugging Face causal LM model 内部会自动 shift，重复手动 shift 反而出错。
- padding/EOS 的 loss mask 要与 shift 后位置对齐。
- packed sequence 还需处理不同样本边界。

## 5. Professional Expansion：为什么这题值得深挖

next-token 监督必须让 position t 的 logits 对齐 token t+1；框架有时模型内部自动 shift，需要防止双 shift。

### 5.1 工程实现 / 系统视角

检查 loss API 契约和 labels shape。

### 5.2 边界条件与反例

最常见 bug 是重复 shift。

### 5.3 建议亲手做的验证实验

- 用 4-token 序列手写输入/label 对齐。
- 记录至少一种 **correctness metric** 与一种 **performance metric**；不要只凭“代码能运行”判定实现正确。

### 5.4 3 分钟专业版答法

面试时可以按下面节奏展开：

> **第一句给结论**：输入位置 t 的 hidden state 应预测下一个 token x_{t+1}，因此常见做法是 logits[:, :-1] 对 labels[:, 1:]。若 label 与 input 同位置，模型可能学成错误的 identity-like objective。 input: x₀…x_{T-2} → labels: x₁…x_{T-1}  
> **第二层讲机制**：许多 Hugging Face causal LM model 内部会自动 shift，重复手动 shift 反而出错。；padding/EOS 的 loss mask 要与 shift 后位置对齐。；packed sequence 还需处理不同样本边界。  
> **第三层补工程条件**：把本题放到真实 Tensor Shape、训练/推理阶段与硬件约束下重新检查；如果结论涉及“更快/更省/更稳定”，必须说明比较基线和适用条件。  
> **最后主动给验证**：用最小行为测试、数值 parity、profiler 或 ablation 证明，而不是停留在直觉。

### 5.5 复杂度与资源矩阵

| 维度 | 本题应如何分析 |
|---|---|
| 显存 | 权重、梯度、optimizer state、activation 四类必须分开估算。 |
| 数值 | FP16/BF16、loss scaling、grad clipping、NaN 定位都要看 first non-finite。 |
| 步数语义 | gradient accumulation 后 scheduler/clip/optimizer 应按 optimizer-step 定义。 |
| 通信 | DP/TP/PP/CP 的收益受网络拓扑与 collective 开销约束。 |
| 主要验证 | 固定 batch 参数 delta、layerwise grad、throughput/MFU、恢复一致性。 |

### 5.6 本题关键不变量

- 任何 NaN 都先找 first non-finite，而不是先调参。
- optimizer/scheduler/clip 的 step 语义必须与 accumulation 一致。
- 多 GPU 方案要同时满足显存约束和通信可承受。

## 6. 面试中的推导顺序

3. **解释 Why**：它解决前一代方案的什么瓶颈。
4. **算成本**：参数、FLOPs、activation/KV memory、IO/通信分别看。

## 7. 常见失分点 — PDF Core

- 在模型已自动 shift 的 API 外再 shift 一次。

## 13. 深入推导：把结论变成可验证的模型

若 logits 与同位置输入 token 对齐而不 shift，模型会被训练成复制当前 token；正确 next-token loss 是 `logits[:, :-1]` 对 `labels[:, 1:]`（具体 API 也可能内部完成 shift）。

面试 coding 时一定确认框架契约：Hugging Face 某些 causal LM `forward(labels=...)` 会内部 shift，自己再 shift 一次会造成 off-by-one。

### 13.1 本章心智模型

> 建立训练故障树：objective、loss mask、数值精度、optimizer、并行和 scaling。

这意味着面试时不要停在术语层。每个结论至少回答四个问题：**成立所需假设是什么？张量/概率对象是什么？成本落在哪里？怎样设计反例或单测证伪？**

## 14. 题目特异的工程 Checklist

**training 检查表**

- 每次异常先定位首个非有限 activation/gradient，再调整超参数。
- 记录 optimizer step、effective batch、LR schedule 与 gradient norm。
- 分布式场景确认全局 norm、参数 shard 和 collective 语义。
- 做 tiny-overfit + fixed-seed 单卡基线，作为大规模训练的 correctness oracle。

**inference 检查表**

- 分开 prefill 与 decode：前者偏大 GEMM，后者偏 KV bandwidth/调度。
- 指标至少报告 TTFT、TPOT/ITL、throughput 与 P95/P99。
- 容量估算从权重、KV、workspace、allocator overhead 四部分扣显存。
- full-forward 与 incremental/cache 路径必须做 logits parity。

## 15. 推荐验证协议

1. **Full-vs-cache parity**：逐 token logits 与 full forward 相同。
2. **Length sweep**：从短到长记录 TTFT/TPOT/KV bytes，验证复杂度趋势。
3. **Concurrency sweep**：增加并发直到 P99/SLA 或显存首先触顶，得到真实容量曲线。

验证结果建议至少记录：

| 类型 | 最低要求 |
|---|---|
| Correctness | reference parity / invariant / leakage test 至少一项 |
| Numerical | NaN/Inf、max/RMS、dtype 差异 |
| Performance | wall-clock、显存/bytes、P95/P99（系统题） |
| Quality | loss/perplexity/任务指标；结构改动必须做回归 |

## 16. 面试官真正想听到的“边界条件”

- **不要把渐进复杂度等同于实际速度**：kernel、batch、长度、硬件与 IO 会改变主导项。
- **不要把一种实现当成数学定义**：mask 语义、layout、fused kernel、cache allocator 都可能变化。
- **不要把单点 benchmark 当成普遍规律**：至少说明 $B,T,d,H$、dtype、device 和任务分布。
- **不要把“能运行”当成“正确”**：Transformer 很多 bug 会正常降 loss，但存在未来泄漏、错误广播或 cache position 错位。

## 17. Whiteboard / Coding 表达模板

当面试官要求现场推导或编码，可按以下顺序：

1. 写输入输出 shape 与符号定义；
2. 写最小核心公式，不先写优化；
3. 写 2–3 个 invariants/assertions；
4. 给 reference 实现或手算小例子；
5. 再讨论 fused kernel、cache、并行或量化；
6. 最后给测试与 benchmark 设计。

> **Strong Hire 信号**：不仅能解释“为什么”，还能说出“什么情况下不成立，以及我会怎么证明”。
