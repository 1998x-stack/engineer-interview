# SD01 · 设计 Transformer 机器翻译系统

> 目标：把“Encoder-Decoder + Beam Search”升级成一个能落地、可容量估算、可监控回归的生产级回答。

## 1. 先澄清需求，而不是先选模型

至少问清：

- 语言对：单语对、100+ 多语、是否零样本语言迁移；
- 领域：通用、法律、医疗、客服、代码/技术文档；
- 质量目标：BLEU/COMET、术语准确率、人评 MQM；
- SLA：P50/P95 延迟、QPS、最大输入/输出长度；
- 约束：专有名词、数字、格式、不可翻译片段；
- 部署：在线句级翻译还是离线文档批处理。

如果这些条件不同，架构和 decoding 方案可能完全不同。

## 2. 数据流与核心架构

```text
Raw Source
   ↓
Normalization / Language ID
   ↓
Subword Tokenizer
   ↓
Encoder: bidirectional self-attention
   ↓
Encoder Memory
   ↓
Decoder: causal self-attention + cross-attention
   ↓
Logits
   ↓
Constrained Beam / Greedy / Sampling
   ↓
Detokenize / Terminology Restore / Format Repair
```

### 2.1 数学主干

Encoder 得到：

\[
H_{enc}=Encoder(x_{1:S})
\]

Decoder 第 $t$ 步的 cross-attention：

\[
Q_t = H^{dec}_tW_Q,\quad
K=H_{enc}W_K,\quad
V=H_{enc}W_V
\]

\[
C_t=softmax(Q_tK^T/\sqrt{d_k})V
\]

其中 encoder 的 K/V 在整个 target decode 中不变，因此可缓存。

## 3. 训练设计

训练通常使用 teacher forcing：

\[
\mathcal L=-\sum_t\log p(y_t\mid y_{<t},x)
\]

需要额外考虑：

- label smoothing；
- multilingual sampling；
- noisy parallel corpus filtering；
- length curriculum；
- back-translation / synthetic parallel data；
- domain-adaptive continued training。

### 数据质量检查

| 风险 | 检查 |
|---|---|
| 错语言对 | LID + embedding similarity |
| source/target 不对齐 | sentence alignment score |
| 复制 source | copy ratio |
| 数字/实体漂移 | entity/number exact checks |
| boilerplate | n-gram / template dedup |

## 4. 推理与解码

### Greedy

最快，但可能产生局部最优。

### Beam Search

维护 $K$ 个 hypothesis。需要 length normalization，否则总 log-prob 倾向短序列：

\[
score(y)=\frac{\log P(y\mid x)}{LP(|y|)}
\]

### Constrained Decoding

专业翻译常比单纯扩大 beam 更重要：

- terminology constraints；
- protected spans；
- number/date preservation；
- markup/HTML tags；
- glossary injection。

## 5. 容量与性能估算

在线服务至少拆成：

- Encoder/prefill compute；
- Decoder self-attention KV；
- Cross-attention encoder K/V；
- beam factor；
- batch scheduler。

Beam size 从 1 增到 $K$ 会显著放大 decoder state/KV 和搜索开销。encoder memory 可在 beams 间共享，不能机械复制所有 source state。

指标：

- TTFT / sentence latency；
- output token latency；
- tokens/s；
- P95/P99；
- GPU memory；
- batch utilization。

## 6. 质量评估

自动指标不能只看 BLEU：

- COMET / learned metric；
- terminology accuracy；
- entity/number preservation；
- hallucination rate；
- human MQM/error taxonomy。

要按语言对、领域、句长、低资源语言分桶。

## 7. 线上监控与回滚

监控：

- 输入语言分布漂移；
- OOV/subword length；
- 解码长度异常；
- 实体/数字差错；
- P95 latency；
- fallback rate。

上线必须支持模型版本、tokenizer、词表/术语表一起回滚。

## 8. 典型追问

### Q：为什么 decoder-only 也能翻译？

把 source 和 target 放在同一 causal stream 即可建模 $p(y\mid x)$。但 encoder-decoder 可以双向编码 source，并在多步 target decode 时复用 encoder representation；对严格 seq2seq 和 source/target 结构清晰的任务仍有优势。

### Q：为什么 beam 越大不一定越好？

搜索更接近模型概率最大序列，不等于更接近人类偏好；还会增加长度偏置、重复和 latency。

### Q：如何证明一次 serving 优化没有改变翻译质量？

固定 tokenizer、随机种子与 decoding config，对 logits/sequence 做回归；再运行完整质量集和实体/术语专项测试。

## 9. 强回答模板

`需求/SLA → 数据质量 → Encoder-Decoder 数据流 → 训练目标 → 解码 → 容量 → 质量回归 → 监控/回滚`
