# SD04 · 设计长上下文训练方案

## 1. 明确“长上下文”的目标

不同目标需要不同数据与评测：

- 只是容纳长文；
- 长距离 needle retrieval；
- 多段证据整合；
- 长代码依赖；
- 多轮 agent memory。

“max context=128K”不是能力定义。

## 2. Position Strategy

可选：

- RoPE scaling / interpolation；
- frequency-aware scaling；
- ALiBi；
- 新训练位置机制。

必须保证训练与推理的 position id / cache offset 一致。

## 3. Data Curriculum

直接把所有 batch 都改成 128K 极昂贵且数据不足。常用 curriculum：

```text
短上下文预训练
  ↓
中长度 continued training
  ↓
高质量长文 / 拼接 / 结构化长任务
  ↓
长上下文 SFT / retrieval tasks
```

需要控制 packing，避免随机拼接让跨文档 attention 学到无意义关系。

## 4. 训练系统成本

标准 attention 算术 $O(T^2d)$；长序列还放大 activation memory。

优化：

- FlashAttention；
- activation checkpointing；
- sequence/context parallel；
- selective recompute；
- sliding/local attention（若架构允许）；
- sequence packing。

## 5. Context Parallel

沿 sequence 切分，让不同 GPU 持有不同 token 段；Attention 需要通信 K/V 或采用 ring 类策略。重点不是名字，而是说明：

- 通信量；
- causal handling；
- load balance；
- topology。

## 6. 数据质量

长文必须保留真实长依赖，而不是简单把独立短文 concat 到 128K。建议保留：

- document boundary；
- heading / code file structure；
- related-document groups；
- retrieval-required examples。

## 7. 评测矩阵

| 能力 | 测试 |
|---|---|
| 位置外推 | perplexity by position bucket |
| Retrieval | needle at 0/25/50/75/100% |
| Multi-hop | 多段证据 QA |
| Long code | repo/file dependency tasks |
| Robustness | distractor density sweep |
| Systems | TTFT, peak memory, tokens/s |

## 8. Lost-in-the-Middle

不能只把 needle 放开头和结尾。必须扫描 needle position，否则模型可能在中间区域严重掉点却被平均指标掩盖。

## 9. 上线风险

- 超长 prompt 造成 TTFT 峰值；
- KV cache 侵占并发；
- 用户把“128K”理解成“128K 都同样可靠”；
- long-context fine-tune 伤害短上下文质量。

因此要同时做 retention eval。

## 10. 强回答

`能力目标 → Position → 长数据 curriculum → Attention/CP 系统 → 位置分桶评测 → 短上下文 retention → Serving 成本`
