# SD06 · Transformer 预训练数据 Packing

## 1. 为什么需要 Packing

固定最大长度 $T$ 时，若每篇文档单独 padding，会浪费大量 token compute。Packing 把多篇短文填入同一训练 sequence，提高 token utilization。

\[
utilization=\frac{real\ tokens}{allocated\ tokens}
\]

## 2. 最关键语义：文档边界

简单 concat 有两种选择：

### 允许跨文档 attention

更简单、吞吐高，但模型可看到无关下一文档。

### Block-diagonal attention / document mask

每篇文档只看本篇历史，语义更干净，但 mask/kernel 更复杂。

要明确你采用哪一种，不能只说“pack 到 4K”。

## 3. EOS / BOS

文档之间至少需要 EOS/boundary signal。是否添加 BOS、是否对 EOS 计 loss、空文档如何处理，都需固定 tokenizer recipe。

## 4. Loss Mask

- padding 不计 loss；
- boundary token 是否计 loss要定义；
- SFT packing 还要 mask user/system token，只训练 assistant 部分（取决于目标）。

Attention mask 和 loss mask 不同。

## 5. Packing 算法

可视作 bin packing：

- first-fit / best-fit；
- sort by length；
- streaming buffer；
- bucketed packing。

追求 utilization 的同时不能导致过大 CPU preprocessing 和 shuffle 偏差。

## 6. 数据混合

若把不同 domain 混在同一 pack，要确认：

- sampling ratio；
- document IDs；
- provenance；
- contamination；
- domain boundary。

## 7. 分布式数据加载

每个 rank 应消费不重叠 shard；恢复训练时要保存数据位置。packing 若依赖随机 buffer，resume determinism 更难，需要记录 RNG/buffer state 或接受近似恢复。

## 8. 质量测试

- token utilization；
- documents/pack 分布；
- length histogram；
- boundary leakage test；
- label shift sanity；
- data source mix；
- duplicate rate。

## 9. 性能测试

比较：

```text
unpacked vs packed
→ tokens/s
→ MFU
→ host CPU
→ dataloader wait
→ peak memory
```

如果 GPU 利用率没提高，瓶颈可能已在 attention/IO，而不是 padding。

## 10. 追问

**为什么 packing 有时会伤质量？** 边界处理错误、跨文档无意义依赖、sampling/shuffle 改变。

**为什么 SFT packing 更难？** 需要 conversation boundary、assistant-only loss、不同模板和 sequence truncation 语义。
