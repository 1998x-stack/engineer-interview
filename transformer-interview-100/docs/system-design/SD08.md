# SD08 · 从公式到 GPU：为什么 Attention 是算法 + 系统共同问题

## 1. 数学公式并不能预测真实速度

\[
Attention(Q,K,V)=softmax(QK^T/\sqrt d)V
\]

看起来只有两个矩阵乘和 softmax，但 GPU 上还包括：

- QKV projection；
- layout transform；
- mask；
- HBM read/write；
- SRAM/shared memory；
- kernel launch；
- synchronization。

## 2. Roofline 心智模型

性能受：

\[
\min(Compute\ Throughput, Memory\ Bandwidth\times Arithmetic\ Intensity)
\]

Prefill 大矩阵更容易 compute-bound；decode query 很短，KV 读取常使其 bandwidth-bound。

## 3. Naive Attention 的 IO

若显式写：

\[
S=QK^T,\quad P=softmax(S)
\]

$S,P$ 都是 $T^2$ 中间量，需要反复写入/读取 HBM。

## 4. FlashAttention

通过 tiling，把 Q/K/V block 搬到片上 memory，使用 online softmax，减少完整 score/probability materialization。

**不改变 exact attention 数学结果；改变 IO schedule。**

## 5. FlashAttention-2 的进一步方向

在相同 exact attention 上继续改 work partition、occupancy 和 warp communication。说明“算法已相同”仍可有巨大系统性能差。

## 6. Decode 为什么不同

单步 query `[B,H,1,Dh]`：

- matmul 很瘦；
- 读取历史 `[B,Hkv,T,Dh]` KV；
- batch scheduler 决定矩阵规模。

因此 decode 优化重点是 GQA/MQA、batching、KV layout/quantization，而非只看 $T^2$。

## 7. Layout 与隐式 Copy

`transpose` 常只是 stride 变化，但某些 kernel 需要 contiguous layout；`.contiguous()` 会产生 HBM copy。优化前先 profiler，避免“为了 shape 正确”引入大规模复制。

## 8. Benchmark 方法

固定：

- GPU 型号；
- dtype；
- B/H/T/Dh；
- causal/non-causal；
- dropout；
- warmup；
- 同步计时。

报告：

- wall-clock；
- TFLOPs/s；
- HBM bytes（若可测）；
- peak memory；
- numerical parity。

## 9. 面试高分点

任何“复杂度优化”都继续问：

1. 常数项？
2. 算术强度？
3. kernel 是否规则？
4. 内存 layout？
5. 训练和 decode 是否同样受益？
