# SD09 · 优化一个 Transformer：如何先定位瓶颈

## 1. 先问“慢在哪里”

不要一上来换 FlashAttention。先拆 stage：

```text
Data Loader
Tokenizer
H2D
QKV/Attention/MLP
Communication
Optimizer
Checkpoint
Serving Queue
Prefill
Decode
Sampling
```

## 2. 建立基线

固定：

- commit / model config；
- seed；
- input length distribution；
- batch；
- dtype；
- GPU/driver；
- correctness output。

没有 baseline 的优化无法归因。

## 3. Profiler 分层

### CPU

- dataloader wait；
- tokenizer；
- Python overhead。

### GPU

- kernel time；
- occupancy；
- HBM utilization；
- hidden copies；
- synchronization。

### Distributed

- AllReduce；
- AllGather；
- ReduceScatter；
- All-to-All；
- pipeline bubble。

## 4. 判断 Compute-bound / Memory-bound / Communication-bound

- Compute-bound：提高 matmul efficiency、fusion、batch；
- Memory-bound：量化、layout、fusion、KV 优化；
- Communication-bound：并行拓扑、overlap、shard 重构；
- Scheduler-bound：continuous batching / admission。

## 5. 优化顺序

1. Correctness bug；
2. 明显无效工作/拷贝；
3. 算法级大项；
4. kernel/fusion；
5. 并行与 overlap；
6. 微小常数优化。

## 6. Amdahl's Law

若某 stage 只占总时间 5%，即使优化到无限快，端到端最多约提升 5%。因此 profiler 占比比“技术热门度”更重要。

## 7. 性能与质量双回归

任何优化 PR 必须同时记录：

- output/logits parity 或任务质量；
- peak memory；
- latency/throughput；
- P95/P99；
- 测试环境。

## 8. 常见错误

- 只用 `time.time()` 不 GPU synchronize；
- cold-start 与 steady-state 混合；
- 不控制 sequence length；
- benchmark 只测 batch=1；
- 换了 dtype 却声称纯 kernel 加速；
- 忽略 accuracy regression。

## 9. 面试官追问

**为什么理论 FLOPs 降低但更慢？** 可能算术强度下降、kernel 不规则、launch/索引开销增大、无法利用 Tensor Core。

**怎么证明瓶颈是 HBM？** profiler/roofline，观察 compute utilization 低而 memory bandwidth 接近上限，并通过减少 bytes 的改动验证。
