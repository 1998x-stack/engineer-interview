建立浏览器/服务器边界、HTTP 状态、Cookie、SOP/CORS、TLS、Trust Boundary 与风险模型。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：浏览器安全模型、HTTP 状态传递、Origin/Site 边界与传输层边界
- **核心资产**：会话身份、跨源数据、请求语义、敏感响应与信任上下文
- **典型失败模式**：把浏览器行为、服务器信任和网络传输混为一谈，导致控制放错层级
- **推荐架构原则**：浏览器策略负责限制客户端能力；服务端仍必须独立完成身份、授权和输入语义验证

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 浏览器/开发者工具验证 Cookie、Origin、重定向与请求携带行为
- 服务端集成测试验证认证与授权不依赖前端状态
- 反向代理/网关测试验证 Host、Scheme、Forwarded 等上下文一致
- 日志中保留 request-id、主体、来源与策略决策结果

### 4. Senior / Staff 级讨论点

兼容性、跨域体验、单点登录与严格浏览器策略之间需要显式权衡。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
