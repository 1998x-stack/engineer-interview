## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：Subject × Action × Resource × Context 的授权决策模型
- **核心资产**：对象数据、敏感操作、租户边界、受保护字段与业务状态
- **典型失败模式**：把对象标识、路由路径、前端可见性或登录状态误当成授权
- **推荐架构原则**：Policy Decision Point 与 Policy Enforcement Point 分离；默认拒绝，并在资源附近做最终校验

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 建立角色/主体 × 资源 × 动作权限矩阵
- 覆盖同角色不同账户、跨租户、批量接口与异步任务
- 对字段级输出/更新做 allowlist 与回归测试
- 审计日志记录 subject、resource、action、policy/result

### 4. Senior / Staff 级讨论点

授权越集中越一致，但越靠近领域对象越能表达业务语义；成熟系统通常需要两者结合。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
