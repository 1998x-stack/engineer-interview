# 认证、Session、JWT 与 OAuth

围绕会话生命周期、密码存储、JWT、Token 分层、OAuth 2.0 + PKCE、redirect URI 与 step-up。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：身份凭据、会话令牌、授权委托与敏感操作再认证的生命周期
- **核心资产**：密码、会话标识、访问令牌、刷新令牌、授权码、MFA 状态
- **典型失败模式**：把“令牌存在”误当成“令牌当前仍可信”，忽略签发、绑定、过期、撤销与重放
- **推荐架构原则**：认证、会话、授权委托分层；短期令牌、长期凭据和高风险操作使用不同保护强度

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 覆盖登录前后会话状态转换与旧令牌失效
- 验证过期、撤销、重放、登出、密码修改后的令牌行为
- OAuth 流程校验 issuer/audience/state/PKCE/redirect URI 等安全不变量
- 敏感操作验证 step-up/reauthentication 与审计事件

### 4. Senior / Staff 级讨论点

安全性、用户体验、跨设备登录和会话连续性之间存在直接张力，应由风险分级决定。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
