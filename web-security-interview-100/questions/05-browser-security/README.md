# XSS、CSRF、CORS 与浏览器安全

从浏览器解析上下文理解 XSS、CSP、Trusted Types、CSRF、SameSite、CORS 与 XS-Leaks。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：Origin/Site、DOM Source/Sink、自动携带凭据与浏览器执行策略
- **核心资产**：用户会话、页面 DOM、跨源敏感响应、浏览器可执行上下文
- **典型失败模式**：把字符串放入可执行上下文，或错误依赖浏览器自动行为来表达用户意图
- **推荐架构原则**：上下文安全输出 + 安全 DOM API + 浏览器防御纵深（CSP/Trusted Types/SameSite）

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 审计危险 DOM sink 与原始 HTML 渲染点
- CSP/Trusted Types 在报告模式与强制模式下验证
- CSRF 测试覆盖 Cookie 自动携带、Origin/Token/SameSite 组合
- 跨源测试区分“请求能否发送”和“响应能否读取”

### 4. Senior / Staff 级讨论点

严格客户端策略可能影响第三方脚本、兼容性和前端开发效率，需要平台化治理。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
