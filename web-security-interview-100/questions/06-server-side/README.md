# SSRF、文件、路径与反序列化

围绕服务器出站能力、文件系统命名空间、上传处理与反序列化建立服务器侧安全模型。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：服务器代替用户执行网络、文件、解析与对象恢复能力时的能力委托边界
- **核心资产**：内部网络、云元数据、文件系统、对象存储、解析器和高权限运行环境
- **典型失败模式**：把用户可控位置/类型/对象直接交给具有更高权限的服务器能力
- **推荐架构原则**：最小化服务器可达能力：网络 egress allowlist、文件根目录约束、隔离存储、受限解析器与沙箱

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 验证 URL/路径规范化后再执行策略判断
- 文件/归档测试覆盖最终 canonical path 与存储隔离
- 外连策略验证 DNS、重定向与最终解析地址仍受控
- 解析器/反序列化配置使用最小类型和最小协议集合

### 4. Senior / Staff 级讨论点

功能越通用（任意 URL、任意文件、任意对象），安全验证成本越高；应尽量收窄能力面。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
