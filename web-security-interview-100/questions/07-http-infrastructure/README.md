# HTTP 解析、反向代理、缓存与高级漏洞

从 parser differential、协议转换、缓存 key、可信代理、规范化与并发不变量理解高级 Web 风险。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：Client → CDN/WAF/LB/Proxy → App 多解析器链中的语义一致性
- **核心资产**：请求边界、路由、缓存键、真实客户端身份、业务原子性
- **典型失败模式**：不同组件对同一字节流/参数/头部/路径产生不同语义，或并发状态转换缺少原子性
- **推荐架构原则**：统一解析与规范化策略，最小化协议转换；显式定义可信代理链、缓存 vary/key 与原子业务不变量

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 端到端验证代理链对重复头、重复参数、编码和协议降级的解释一致
- 缓存测试确认所有影响响应的输入都进入 key 或被禁止缓存
- 可信代理测试验证客户端不可伪造安全决策用 header
- 并发测试验证 check-and-update 的事务/原子约束

### 4. Senior / Staff 级讨论点

边缘层功能越多，性能越好但语义差异风险越大；需要用明确契约和集成测试控制。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
