# REST API、GraphQL、WebSocket

面向现代 API 的对象/属性/函数授权、资源消耗、业务流、Inventory、GraphQL 与 WebSocket。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：对象/功能/属性授权、资源成本、业务流程和长连接消息级控制
- **核心资产**：API 对象、敏感字段、业务配额、GraphQL 解析资源、WebSocket 会话
- **典型失败模式**：只保护 endpoint，而没有保护对象、字段、业务状态、成本或消息语义
- **推荐架构原则**：Schema/DTO 明确输入输出；每个业务动作独立授权；资源预算与业务反滥用作为一等控制

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- API 权限矩阵覆盖对象/功能/属性三个层级
- 批量/分页/搜索接口验证资源预算和速率维度
- GraphQL 覆盖 resolver 授权、深度/复杂度与 N+1 成本
- WebSocket 覆盖握手来源、会话过期与逐消息授权

### 4. Senior / Staff 级讨论点

API 灵活性与可组合性会增加授权和资源控制复杂度，应通过 schema、policy 与预算模型收敛。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
