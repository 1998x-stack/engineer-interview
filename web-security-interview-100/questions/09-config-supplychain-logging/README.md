# 配置、密码学、供应链、日志与异常处理

把安全从代码扩展到配置、供应链、密码学工程、Secrets、日志告警与异常处理。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：安全默认值、软件来源可信链、密钥生命周期与可检测性
- **核心资产**：部署配置、构建产物、依赖、密钥、审计证据与异常处理路径
- **典型失败模式**：默认配置过宽、来源不可验证、秘密长期暴露、日志只有“记录”没有检测与响应
- **推荐架构原则**：Policy-as-code + provenance + least privilege + secret rotation + structured security telemetry

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 配置基线与 IaC 策略自动校验
- 依赖/构建产物验证来源、版本、签名/证明与可追踪性
- 秘密扫描与轮换演练验证“删除代码”之外的失效处置
- 日志告警演练验证事件能从生成到响应闭环

### 4. Senior / Staff 级讨论点

更严格的供应链和配置策略会增加发布摩擦，应通过自动化与可审计例外流程降低成本。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
