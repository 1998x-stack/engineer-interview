# 代码审计、SDL 与综合架构设计

把单点漏洞提升为代码审计、风险优先级、安全测试流水线和 secure-by-default 架构能力。

## 本章目标

- 能给出定义，更能解释根因、信任边界与失败模式。
- 能把防御方案写成可验证的安全不变量。
- 能从代码审计、设计评审和测试三个视角验证控制。

## 专业学习框架

### 1. 本章统一抽象

- **分析镜头**：以风险为导向的代码审计、验证证据、修复优先级与 SDL 闭环
- **核心资产**：核心业务路径、敏感数据、部署流水线、漏洞发现与修复能力
- **典型失败模式**：工具替代方法论、只看单点 finding、缺少上下文和修复后验证
- **推荐架构原则**：Threat model → Requirements → Secure design → Verification → Operations 的闭环

### 2. 学习顺序

1. 先掌握本章所有题目的一句话结论。
2. 再尝试不用漏洞名，仅用“资产—信任边界—安全不变量”解释问题。
3. 第三遍从代码审计视角定位入口、策略点与 sink。
4. 第四遍为每题写至少一个 negative regression test。
5. 最后练习 30 秒、2 分钟、5 分钟三档面试回答。

### 3. 本章验证基线

- 审计先构建入口、信任边界、身份、授权和危险能力地图
- 工具结果必须关联可达性、业务影响与现有控制
- 修复后增加单元/集成/回归测试作为长期证据
- 把发现率、修复时延、重复缺陷和控制覆盖率纳入度量

### 4. Senior / Staff 级讨论点

安全测试覆盖与交付速度之间应通过风险分层、自动化和“高价值手工检查”来优化。

高级候选人应能说明：控制为什么放在当前层、其它层还能提供什么纵深防御、异常路径如何处理、控制如何被持续验证，以及当架构演进时如何避免策略漂移。
